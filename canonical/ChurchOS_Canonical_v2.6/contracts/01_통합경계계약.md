# 독립 제품 통합 계약 v2.0

각 API는 제공자가 소유한다. 아래는 ChurchOS 소비자 요구사항이며 제공자 구현 완료나 양측 계약 승인을 뜻하지 않는다. 계약 상태는 contracts/integrations.yaml에 명시한다.

| 제공자 | 허용 수신 | 금지 |
|---|---|---|
| 너랑나랑 | 동의된 초대·세션 상태·안전한 딥링크 | 문답·은혜 기록·서명 원문 |
| 생명일기 | 사용자 요청의 일회용 handoff URI | 작성 여부·회차·7문항·개인 원문 |
| JLPrayer | 공개 캠페인·허용 최소 요약·handoff | 비공개 기도·간증·상담 원문 |
| JLBible | 계획 ref·오늘 읽기 ref·허용 진도·handoff | 라이선스 없는 본문 복제 |
| JLAcademy | 강좌 ref·공개 강좌 요약·동의된 수강 상태·handoff | 답안·상담·비공개 학습 원문 |
| CHGO | 최소 10명 공동체 집계·coverage·suppression metadata | 개인 인사이트·영적 점수·원문 |

연결·기능 허용은 별개다. 연결되지 않은 앱은 감추거나 준비 중으로 표시하며 API 실패 시 마지막 갱신 시각과 재시도를 표시한다. 소규모 집계·상보적 차분·반복 질의로 개인이 추정되면 억제하고 데이터 없음은 0으로 바꾸지 않는다.

## 인증과 철회
OIDC provider는 내부 교체 가능 인프라로 둔다. 계정·인증 정본은 인증 제공자가 소유하고 각 전문 앱이 자신의 목적별 동의·철회를 소유한다. ChurchOS 소속·역할 정본은 ChurchOS가 소유한다. 연결 해제 시 새 토큰 발급·상태 갱신을 중단하고 최소 캐시와 미사용 handoff를 폐기한다. 타 제품의 개인 원문은 삭제 명령으로 대신 소유하지 않는다.

## Handoff
원 토큰은 저장·로그하지 않고 해시만 저장한다. 단회 사용, 최대 10분 만료, 등록된 return URI 정확 일치, tenant·actor·provider·capability 결속, 제공자 측 재검증을 요구한다. 브라우저 임의 리다이렉트나 토큰 전달 URL을 만들지 않는다. 앱 링크와 최종 return URI의 플랫폼별 처리는 실제 앱 검증 전까지 NOT_RUN이다.

## API와 이벤트
ChurchOS API는 `/api/v1/church/*`다. 외부 제품 원문 API를 대리 구현하지 않는다. 이벤트 envelope은 events/schemas/event-envelope.schema.json과 카탈로그 payload schema를 함께 검사한다. 필드 이름은 envelope schema가 우선한다. 멱등성·서명·오류 응답·버전 호환·폐기 기간·제공자별 capability를 양측 계약 테스트로 확정한다.
