# PostgreSQL 16 자동 검증

v2.1 실행 결과: 환경 도구가 없어 INCOMPLETE. v2.2는 바이너리 확보 후 root 초기화 거부로 NOT_RUN. 이 절차·workflow의 DB 실행 자체는 NOT_RUN이다.

기존 DB가 없는 전용 임시 PostgreSQL 16 클러스터에서만 실행한다. 이 도구는 임의 이름의 기존 DB를 인자로 받지 않는다. 연결 정보는 PGHOST·PGPORT·PGUSER·PGPASSWORD·PGDATABASE 환경변수로 주입하고 원격 운영 연결을 사용하지 않는다.

```bash
python tools/db_verify.py --disposable-cluster --output /tmp/cos-db-evidence/result.json
```

1. 서버가 PostgreSQL 16인지 확인한다.
2. 임의 이름의 owner·backup 역할과 신규 source DB를 만든다.
3. non-superuser owner로 V001~V015을 실행한다.
4. 00~05를 non-superuser owner/앱 역할로 검사한다.
5. 합성 교회 한 행을 영속 저장해 빈 백업 통과를 방지한다.
6. 별도 non-superuser BYPASSRLS·pg_read_all_data 백업 역할로 dump한다.
7. 다른 신규 DB에 bootstrap 관리자 역할로 소유권·ACL을 보존해 restore한다.
8. 교회 행 checksum·행 수·RLS 적용 수를 비교하고 00~05를 다시 실행한다.
9. 임시 DB·전용 owner·backup 역할을 정리한다. 고정 앱 그룹 역할은 임시 클러스터 종료로 폐기한다.

0은 전체 필수 단계 완료, 1은 실행 실패·미완료, 2는 환경·실행 전제 누락이다. 하나의 PASS 문자열만으로 성공을 판정하지 않는다. 실행 중 실패하면 단계 ID와 종료코드를 남기며 연결 문자열·비밀번호·SQL 원문을 증거에 저장하지 않는다.

이 검증은 교회별 전체 데이터 이관·실제 사용자 권한 API·파일·암호화 키·시간 목표를 포함한 운영 DR 검증을 대신하지 않는다. v2.1의 fingerprint는 합성 교회 레코드와 테이블 RLS 수를 비교하는 제한된 검증이다. 운영 이관은 DB 계보 조사와 별도 승인된 이행 계획이 필요하다.

CI 파일은 패키지가 저장소 루트로 이관된 이후 실행할 수 있다. 현재 GitHub 반영·필수 검사 설정·실행은 하지 않았다. 코드 리뷰 전 실행 성공을 가정하지 않는다.
