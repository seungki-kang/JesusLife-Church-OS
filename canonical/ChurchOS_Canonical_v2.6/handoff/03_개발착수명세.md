# Church OS 개발 착수 명세

## 착수 결론

제품·경계·논리 계약·후보 DB·화이트라벨·화면·운영 설계는 개발자가 첫 구현 스프린트를 시작할 수 있는 수준이다. 다만 이는 실제 저장소 적용이나 런타임 검증 완료를 뜻하지 않는다.

## 첫 구현 순서

1. workspace와 CI skeleton
2. config validation 및 secret policy
3. 내부 공통 인증·계정 기반 OIDC 검증 어댑터
4. tenant context와 deny-by-default authorization
5. PostgreSQL migration runner와 clean DB test
6. tenant·membership·role 최소 API
7. Today read model
8. Pastor Overview aggregate read model
9. brand config validation과 preview
10. outbox, webhook, idempotency, DLQ
11. 여섯 독립 전문 제품의 계약별 adapter·handoff stub
12. 감사·관측·민감정보 redaction gate

## 구현 금지

- 생명일기·기도·너랑나랑 원문을 Church OS DB에 복제
- 개인 성장 점수 또는 교인 순위 생성
- 참여·완료를 성숙으로 환산
- 교회별 코드 fork
- ORM auto-sync 또는 production schema push
- 테넌트 문맥 없는 repository 호출
- 자유 입력 전체를 로그·이벤트에 기록
- 실제 실행 전 PASS 또는 ACTIVE 표기

## Definition of Ready

- 관련 OpenAPI operation과 error contract가 존재한다.
- 데이터 소유자, tenant key, privacy class가 정해졌다.
- 권한 matrix에 action이 등록됐다.
- 정상·거부·교차 테넌트·재시도 테스트가 정의됐다.
- migration과 backward compatibility 영향이 기록됐다.
- 관측 필드와 금지 필드가 정의됐다.

## Definition of Done

- 코드 review와 모든 CI gate 통과
- 실제 임시 DB에서 migration 및 rollback/restore 대체 검증
- 권한·테넌트·민감정보 부정 테스트 통과
- OpenAPI와 구현 route fingerprint 일치
- 운영 runbook과 변경 기록 갱신
- Candidate, NOT_RUN, PASS 상태가 증거와 일치

## 개발자에게 넘길 기준 파일

`README.md`, `decisions/`, `specs/`, `contracts/`, `api/`, `db/`, `security/`, `white-label/`, `ux/`, `operations/`, `rollout/`, `handoff/`, `ci/`, `governance/`를 함께 전달한다. 일부만 떼어 구현하지 않는다.
