# 구현 로드맵
| 단계 | 결과 | 완료 기준 |
|---|---|---|
| 0 | 이 정본 고정 | 방향·제품 경계·정적 회귀 통과 |
| 1 | DB 계보 조사 | 기존 GitHub/ZIP/배포 DB 적용 이력·checksum 확인; 기존 DB 교체 금지 |
| 2 | DB 실행 검증 | PostgreSQL 16 신규 설치 V001~V013·00~04·05 검사·백업·복원 통과 |
| 3 | ChurchOS 핵심 API·DI | 인증·소속·역할·테넌트·공지·일정·교인·감사 권한 테스트 |
| 4 | 중심 앱 MVP | 개설→브랜드→초대→Today→체크인→후속 업무 실기기 검증 |
| 5 | 전문 앱 순차 연결 | 각 제공자 계약 승인·sandbox·장애·철회·복귀 검증; 한 번에 하나씩 |
| 6 | 파일럿·출시 | 운영 지표·복구·개인정보·스토어·릴리스 증거 완료 |

전문 제품은 단계 3~4와 병행해 독립 개발할 수 있다. 연결 우선순위는 교회 파일럿의 요구와 제공자 준비 상태로 결정한다. CHGO 미완성도 ChurchOS MVP 출시를 막지 않는다. 통합 API 제공자 미구현 상태는 mock으로만 검증하며 출시 통과로 승격하지 않는다.

main 반영은 이 패키지 전체를 기존 저장소에 덮어쓰지 않고 작업 브랜치에서 파일별 이관한다. 기존 Git 이력과 DB migration 계보를 보존한다. PR·정적 CI 통과와 DB·앱 출시 검증은 별도 상태로 기록한다.
