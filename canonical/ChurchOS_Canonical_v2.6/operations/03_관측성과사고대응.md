# Church OS 관측성과 사고 대응

## 관측 원칙

로그·메트릭·트레이스는 문제를 재현할 만큼 충분해야 하지만 개인 원문을 포함해서는 안 된다. 모든 필드는 allowlist 방식으로 기록한다.

## 허용 필드

- timestamp, severity, service, deployment version
- request/correlation/message ID
- tenant opaque ID, actor type, purpose code
- route template, status class, latency
- policy decision code, retry count, DLQ state

금지 필드는 생명일기·기도·상담·관계 기록 원문, 자유입력 본문, access token, cookie, 비밀번호, 암호화 키, 성경 라이선스 본문이다.

## 대시보드

1. API 가용성·오류율·지연
2. DB connection·lock·replication·backup
3. webhook 재시도·서명 실패·DLQ
4. 테넌트별 rate limit과 비정상 접근 패턴
5. SSO·동의·권한 거부 사유 분포
6. 외부 서비스별 circuit breaker와 degraded mode

## 사고 등급

| 등급 | 예 | 초기 대응 목표 |
|---|---|---|
| SEV-1 | 교차 테넌트 노출, 인증 우회, 광범위 장애 | 즉시 호출·격리·배포 중단 |
| SEV-2 | 핵심 기능 장애, 백업 실패, 지속 DLQ | 30분 내 담당 시작 |
| SEV-3 | 일부 테넌트·모듈 오류, 성능 저하 | 업무시간 내 조사 |

## 대응 절차

탐지 → 범위 확인 → 데이터·트래픽 격리 → 증거 보존 → 사용자/교회 영향 판단 → 복구 → 검증 → 통지 판단 → 사후 분석 → 재발 방지 순으로 수행한다. 사고 중에도 민감 원문을 티켓이나 메신저에 복사하지 않는다.

보안·개인정보 사고는 기능팀 단독으로 종결하지 않는다. 승인된 개인정보·법률·목회 안전 책임자에게 에스컬레이션한다.
