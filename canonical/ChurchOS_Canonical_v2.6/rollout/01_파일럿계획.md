# Church OS 파일럿 계획

## 목적

파일럿은 신학적 성장 효과를 입증하는 실험이 아니라 Church OS 운영 기능, 사용성, 격리, 화이트라벨, 외부 연동의 안전성과 실용성을 검증한다.

## 권장 구성

- 소형 교회 1곳: Instant Church OS
- 중형 또는 다캠퍼스 교회 1곳: 교회 브랜드 앱
- 기존 앱 보유 교회 1곳: 교회별 네이티브 앱
- 기간: 준비 2주, 제한 운영 4주, 안정화 2주
- 데이터: 최소 인원으로 시작하고 단계별 확대

## 단계

| 단계 | 범위 | 통과 조건 |
|---|---|---|
| 0 준비 | 계약·DPA·역할·브랜드·연동 sandbox | 책임자와 데이터 경계 승인 |
| 1 내부 | 관리자·목회자·리더 소수 | 권한과 주요 운영 흐름 통과 |
| 2 제한 | 자원 교인 그룹 | Today, 일정, 출석, 공지, handoff 정상 |
| 3 확대 | 승인된 일반 교인 | 오류·지원·성능 기준 충족 |
| 4 종료 | export·연동 해제·회고 | 데이터 잔존과 권한 해제 확인 |

## 성공 지표

- 교인이 3초 안에 오늘 할 일을 찾는 비율
- 핵심 과업 완료율과 중도 이탈
- 목회자의 미처리 돌봄 업무 감소
- 권한 거부의 정확성과 교차 테넌트 사건 0건
- 외부 handoff 성공률, 중복 생성 0건
- 화이트라벨 접근성 대비 기준 충족
- 지원 요청의 유형과 해결 시간

출석률, 일기 작성률, 기도 참여량을 영적 성장 또는 성숙 점수로 해석하지 않는다.

## 중단 조건

- 개인 원문 또는 다른 교회의 정보 노출
- 사용자 동의 없는 개인화·공유
- 목회자 화면에서 개인 역추적 가능
- 학대·위기 흐름이 자기성찰로 잘못 전환
- 삭제·철회가 외부 연동에 전파되지 않음

## 사용자 보호

참여는 자발적이어야 하며 교회 직분·돌봄·사역 배정의 조건이 되어서는 안 된다. 파일럿 종료 후 교회 운영 데이터의 반환·보존·삭제와 개인 Vault의 독립성을 각각 설명한다.
