# Church OS 3.0 사용자 경험과 역할

## 1. 화면 원칙

교인은 Church OS에 들어오면 “내가 오늘 무엇을 해야 하는가”를 먼저 본다. 목회자와 승인된 리더는 “공동체에서 무엇을 돌봐야 하는가”를 먼저 본다. 같은 데이터베이스를 사용하더라도 역할별 첫 화면과 허용되는 정보의 해상도는 다르다.

## 2. 교인 Today

첫 화면은 최대 5개의 우선 카드로 구성한다.

1. 오늘의 교회 일정·예배·공지
2. JLBible 오늘 읽기 또는 성경 이어가기
3. 생명일기 열기(Church OS에는 작성 여부나 진행 상태를 저장·표시하지 않음)
4. JLPrayer 기도수첩 또는 참여 중 기도
5. 내가 속한 목장·팀·봉사에서 해야 할 일

카드는 원문이 아니라 상태와 다음 행동만 보여준다. 사용자가 카드를 누르면 해당 전문 앱 의 독립 화면로 이동한다. 아무 활동이 없으면 “0점”이나 “미성숙”을 표시하지 않는다.

## 3. 목회자 Overview

목회자의 첫 화면은 개인 감시 화면이 아니라 공동체 운영 상황판이다.

| 영역 | 허용 정보 | 금지 정보 |
|---|---|---|
| 새가족 | 미완료 후속 업무, 담당자, 경과일 | 개인 영적 상태 추정 |
| 돌봄 | 접수·배정·기한·연락 필요 상태 | 상담 원문 전체의 기본 노출 |
| 그룹 | 모임 운영 여부, 리더 공백, 후속 업무 | 구성원의 일기·기도 원문 |
| 예배·행사 | 운영 인원, 신청, 체크인, 결원 | 참여율을 영성으로 환산 |
| 봉사·사역 | 지원, 배치 대기, 일정 충돌 | CHGO 성장정보 기반 자동 배치 |
| 공동체 추세 | 최소 표본 이상 집계와 데이터 커버리지 | 개인 역추적, 소집단 식별 |
| 통합 상태 | JLPrayer·JLBible 등 연결 장애 | 외부 앱의 민감 데이터 복제 |

집계값에는 기간, 표본 수, 데이터 누락률, 억제 여부를 함께 표시한다. 소규모 집단은 k-익명성 기준 미달 시 숨긴다.

## 4. 역할과 권한

| 역할 | 기본 목적 | 핵심 권한 | 기본 금지 |
|---|---|---|---|
| 교인 | 개인 교회생활 | 본인 일정·소속·신청·연결 앱 상태 | 타인 개인정보·집계 역추적 |
| 그룹리더 | 그룹 운영 | 소속 그룹 일정·출석·후속 업무 | 개인 Vault·기도 원문 |
| 사역리더 | 팀 운영 | 팀원·일정·역할·지원 관리 | 성장정보 기반 자동 배치 |
| 목회자 | 공동체 목양과 운영 | 교회 집계, 승인된 돌봄 업무 | 개인 원문 기본 열람 |
| 관리자 | 테넌트 운영 | 사용자·역할·설정·통합·감사 | 목회적·성장적 해석 |
| 감사자 | 통제 검증 | 메타데이터와 감사기록 | 민감 본문 열람 |
| 통합서비스 | 제한된 기계 처리 | 명시된 scope와 tenant | 사용자 가장, 범용 조회 |

권한은 RBAC만으로 끝내지 않는다. `tenant + actor + role + resource + purpose + consent + time + policy`를 함께 평가한다.

## 5. 안전한 이동

외부 전문 앱 이동은 다음 순서를 따른다.

1. Church OS가 현재 세션과 tenant를 서버에서 검증한다.
2. 대상 앱의 연결 권한과 사용자 동의를 확인한다.
3. 짧은 수명의 1회용 handoff 토큰을 발급한다.
4. URL에는 원문이나 민감 식별자를 넣지 않는다.
5. 대상 앱이 토큰을 교환하고 자체 권한을 다시 평가한다.
6. 완료 후 최소 상태만 Church OS에 반환한다.

## 6. 화이트라벨 실제 범위

교회가 바꿀 수 있는 것:

- 교회명, 로고, 앱 이름, 승인된 색상 토큰
- 첫 화면의 허용된 카드 순서와 교회 콘텐츠
- 활성 모듈, 메뉴 순서, 도메인, 언어·시간대
- 공지, 설교·예배 링크, 교회별 양식과 용어 별칭

교회가 바꿀 수 없는 것:

- Canonical ID와 의미
- 개인정보·동의·접근통제 화면
- 안전 신고·계정·데이터 내보내기·삭제 경로
- 접근성 최소기준과 보안 헤더
- 감사로그와 테넌트 격리
