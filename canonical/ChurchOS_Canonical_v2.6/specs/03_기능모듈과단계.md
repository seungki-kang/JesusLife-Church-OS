# Church OS 3.0 기능 모듈과 개발 단계

## P0 첫 개발 기준선

P0는 Church OS 자체로 반드시 동작해야 하는 운영 핵심이다.

1. Tenant·campus·brand 설정
2. 내부 공통 인증·계정 기반 로그인 소비자와 계정 연결
3. 교인·가족·membership·role
4. 그룹·목장·부서·팀
5. 일정·예배·행사·공지
6. 신청·체크인·기본 출석
7. 새가족 후속 업무
8. 돌봄 요청·배정·상태 관리
9. 봉사·사역 지원·배치·일정
10. 교인 Today와 목회자 Overview
11. 알림·감사로그·파일 메타데이터
12. 화이트라벨 설정과 통합 연결 상태

## P1 전문 앱 연결

- JLPrayer: 기도수첩, 기도방, 캠페인, 응답의 최소 요약과 handoff
- JLBible: 오늘 읽기, 이어가기, 통독계획 상태와 handoff
- 생명일기: 사용자 요청 시 일회용 handoff만 제공하며 작성 상태와 원문은 수신·저장하지 않음
- 너랑나랑: 초대·진행 상태와 handoff
- JLAcademy: 공개 강좌 요약·동의된 수강 상태·학습 handoff
- CHGO: 최소 10명·2차 숨김이 적용된 공동체 집계만 사용하며 개인 인사이트는 수신하지 않음

P1 연동 실패는 P0 교회 운영 트랜잭션을 되돌리지 않는다. transactional outbox와 재시도·중복방지를 사용한다.

## P2 확장 기능

- 다중 캠퍼스와 복잡한 조직도
- 재정·헌금·회계 시스템 어댑터
- 시설·차량·공간 예약
- JLAcademy 교육·수료 연결 확장(정본은 JLAcademy)
- 선교·프로젝트·지역사회 봉사
- 전자문서·증명서·고급 리포트
- 전용 네이티브 앱 배포 자동화

재정과 회계는 규제·보안·정산 복잡성이 크므로 P0에 직접 구현하지 않고 검증된 외부 시스템 연동을 우선한다.

## 출시 Gate

| Gate | 통과 조건 |
|---|---|
| G0 경계 | 시스템별 정본과 금지 데이터가 명시됨 |
| G1 계약 | API·이벤트·오류·권한 계약이 버전 관리됨 |
| G2 DB | 교차 tenant 참조와 owner 우회 음성검사 통과 |
| G3 개인정보 | 원문 비복제, consent, purpose, retention 검증 |
| G4 UX | 교인 Today와 목회자 Overview 역할 테스트 통과 |
| G5 화이트라벨 | 설정만으로 최소 3개 교회 브랜드 적용 가능 |
| G6 복구 | outbox 재처리, 백업·복원, 장애 격리 통과 |
| G7 런타임 | 실제 실행 Evidence가 있고 정적 검증과 구분됨 |


JLAcademy는 독립 제품이며 강좌·수강·수료는 JLAcademy 소유다. ChurchOS는 공개 요약·동의된 수강 상태·handoff만 연결한다.
