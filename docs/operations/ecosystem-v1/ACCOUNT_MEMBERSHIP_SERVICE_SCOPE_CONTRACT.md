# 현재 적용 설계 계약: 가입 승인과 탈퇴·정지 범위

2026-10-24. 상태 DESIGN. C01/C02의 현재 업무 정책이며 배포된 API·실제 제공자 지원·운영 출시 완료를 뜻하지 않는다. 기존 결정 이력은 [설계 결정 기록](../../decisions/DESIGN_DECISIONS.md)에 보존한다. 이번 정책 묶음은 COS-SSO-001~048을 AGREED / DESIGN으로 정리했다. 하위 상세 계약·검증 미결은 마지막 과제표로 인계하며 제품 구현 완료를 뜻하지 않는다. API 상태명·HTTP 응답·DB 매핑은 구현 전 계약 과제다.

## 적용 순서와 읽는 방법

- 인증 구조와 기존 구현 근거: [공통 인증·SSO 검토](COMMON_AUTH_SSO_REVIEW.md).
- 현재 업무 규칙·기한·책임: 이 문서. 상세 선택 이유·대안·당시 미결 사항: 결정 기록의 같은 ID.
- 문서의 과거 결정에 적힌 남은 항목은 이력이다. 현재 합의는 이 문서와 후속 결정으로 확인하고, 아직 미확정인 과제는 마지막 표를 따른다.
- 후보 설계/YAML·적용된 마이그레이션·canonical v2.6은 보존한다. 초대 자동 활성화 등 충돌을 현재 구현과 동일하다고 보지 않는다.

## 초대 수락 충돌과 현재 규칙

| 보존할 후보 근거 | 충돌 내용 | 현재 적용할 설계 |
|---|---|---|
| [후보 설계 상태 모델](../../architecture/CHGO_Shared_Identity_Membership_and_Product_Consent_Contract_1.0.md#4-상태-모델) | PENDING_INVITE → PENDING_USER_ACCEPTANCE → ACTIVE, 교회 코드 방식에만 PENDING_REVIEW 추가 | 초대 경로와 무관하게 담당자 승인이 필요하다. 초대 수락만으로 유효 소속을 만들지 않는다 |
| [후보 설계 수용 테스트](../../architecture/CHGO_Shared_Identity_Membership_and_Product_Consent_Contract_1.0.md#11-수용-테스트) | 초대 수락 후 Membership ACTIVE | 초대 수락 후 승인 전 교인 권한 없음, 담당자 승인 후 일반 교인 권한만 부여하는 사례로 대체한다 |
| [후보 YAML](../../../api/contracts/shared-identity-membership-consent-v1.yaml) acceptMembershipInvitation 응답 | 200 Membership activated; no Vault grant created | 초대 수락은 신청 의사 확인/대기 요청 접수와 구분해 결과를 안내한다. HTTP 성공만으로 가입 승인·소속 활성화를 의미하지 않는다 |

일반 교인 초대와 별도 지정된 관리자 역할의 본인 수락은 다른 절차다. COS-JOIN-013/027의 관리자 수락 규칙을 일반 교인 초대 자동 승인으로 해석하지 않는다.

현재 업무 흐름:

1. 공통 인증 계정과 대상 교회·초대의 유효성을 확인한다. 계정 로그인 성공은 가입 승인이 아니다.
2. 아직 가입하지 않은 신청자는 담당자 심사를 기다린다. 동일 계정·교회의 대기 요청은 하나만 유지한다. 초대 수락 반복·다른 기기·재시도로 중복 요청·소속을 생성하지 않는다.
3. 승인 전에는 교회가 공개한 소개·예배 시간·공개 설교만 볼 수 있고 교인 명단·내부 자료·공동체 기도 접근은 허용하지 않는다.
4. 승인 확정 시 현재 담당자 권한·요청 상태/버전·정지/재가입 제한을 서버에서 다시 확인한다. 승인·소속 반영·최소 심사 이력을 원자적으로 처리하고 일반 교인 권한만 부여한다. 거절·본인 취소·동시 처리·재시도는 기존 COS-JOIN 결정을 따른다.
5. 이미 유효 소속인 사람은 새 소속·역할을 만들지 않고 현재 가입 상태를 안내한다. 정지 중 재신청/초대로 정지를 우회하지 못한다.

PENDING_REVIEW 등 구체 API 상태명과 HTTP 코드·기존 소속 상태 매핑은 후속 schema 개정에서 확정한다. 후보의 200 응답을 임의로 다른 코드로 확정하거나 실제 endpoint가 바뀌었다고 주장하지 않는다. 요청 접수·승인 결과·소속 활성 상태는 구별해 응답 계약을 작성해야 한다.

필수 후속 검증: 초대 수락만으로 내부 접근 불가, 담당자 승인 후 일반 교인만 부여, 타 교회 담당자 거부, 정지 우회 차단, 중복 수락·승인/취소·정보 수정 경합·철회된 심사 권한 차단. 테스트 실행 NOT_RUN.


## 인증과 제품 경계

ChurchOS·너랑나랑·생명일기·JLPrayer·JLBible·JLAcademy는 공통 계정과 SSO를 사용한다. 독립 개발·배포·데이터 소유는 유지한다. CHGO는 독립 엔진이며 이 사용자 SSO 범위에 추가하지 않는다. 계정 가입·서비스 이용 시작·교회 개설 승인·교인 가입 승인·역할 부여·개인 기록 공유를 별도로 검증한다. ChurchOS 내 연동은 유효한 공통 로그인으로 반복 인증을 최소화하되 각 API는 자신 대상 토큰과 현재 서비스 권한을 검증한다([COS-SSO-001](../../decisions/DESIGN_DECISIONS.md#cos-sso-001)).

교회 관리자 권한은 공통 계정·다른 제품 개인 기록의 삭제 권한이 아니다. 표시 이름·이메일·연락처 일치만으로 공통 계정에 자동 연결하거나 계정을 자동 병합하지 않는다. 기존 로컬 기록은 보존하고 본인 확인·명시 연결·충돌 처리 계약을 별도로 확인한다. 개인 원문·토큰·비밀을 공통 로그/이벤트/통계에 넣지 않는다. 생명일기 원문·작성 여부·회차는 ChurchOS가 받지 않는다. 원문 처리·공유 검증·삭제는 각 정본 제품에서 수행한다.

## 탈퇴·재이용 흐름

1. 확정 전 종료 범위·삭제 대상·영향·내보내기 가능 여부를 안내한다. 실제 지원되지 않는 내보내기를 제공한다고 약속하지 않는다.
2. 유효하게 확정하면 이용·공유를 종료하고 삭제 절차를 진행한다. 별도 복구 유예 없이 진행하되 확정/전달/진행/실패/운영본 삭제/백업 만료/종결은 구별한다. 접수·재시도 종료만으로 완료를 표시하지 않는다.
3. 서비스 탈퇴 후 SSO/연동 링크만으로 자동 재활성화하지 않는다. 본인의 명시 재이용과 당시 필요한 절차를 거친다. 이전 기록·동의·공유·역할은 자동 복원하지 않는다.
4. 안전한 대상 분리가 가능하고 재이용 자격이 있으면 이전 삭제 중에도 명시 재이용을 허용한다. 새 기록을 이전 삭제 대상과 분리하고 이전 삭제/백업 만료·보유기간은 원래대로 진행한다. 분리 미검증 상태를 준비 완료로 표시하지 않는다(COS-SSO-046).
5. 공통 탈퇴 후 일률 재가입 대기기간은 없다. 신규 요건을 충족하는 새 가입이며 이전 계정 복구가 아니다. 유효한 보안/교회 재가입 제한을 우회하지 않는다. 안전하게 검증된 근거로 현재 미해소 공통 보안 위험이 재가입 시도와 연결됨을 확인하면 가입 완료를 보류하고 지정 보안 담당자가 본인·위험 해소를 확인한다(COS-SSO-048). 이름/연락처 일치·과거 탈퇴·신고/AI 점수만으로 자동 연결/거절하지 않으며 불충분한 근거로 동일인/침해를 단정하지 않는다. 교회/개별 서비스의 제한만으로 공통 가입을 막지 않는다.
6. 마지막 교회 관리자도 공통 계정 탈퇴를 허용한다. 후임 지정·수락을 권장하되 미확보만으로 거부하지 않는다. 종료 개인의 접근을 유지하지 않고 관리 공백은 별도 복구한다. 교회 데이터 삭제나 후임 자동 권한 부여는 없다(COS-SSO-020). COS-JOIN-011의 일반 교회 탈퇴·역할 해제·소속 정지 시 마지막 관리자 보호는 유지한다.
7. 보안 정지 중에도 별도 충분한 본인 확인·전체 영향 확인·명시 확정으로 공통 탈퇴를 허용한다. 기존 정지 세션·이름/연락처 일치·교회 관리자 확인만으로 허용하지 않으며 확인 부족/탈취 의심 시 확정을 보류한다(COS-SSO-023).
8. 탈퇴 후 별도 확인·최소 목적 권한으로 본인 종료 건의 제품별 최소 처리 상태만 앱에서 조회한다. 일반 이용·원문 열람·탈퇴 취소/복구는 불가하다(COS-SSO-025).

외부 로그인 연결/사용 권한은 제공자 지원 계약에 따라 회수·해제하되 외부 계정 자체나 다른 서비스 로그인 관계는 삭제하지 않는다. 해제 미지원/실패도 내부 재로그인은 차단하고 외부 처리 상태를 따로 표시한다. 같은 외부 로그인으로 이전 종료 계정/권한/공유를 복원하지 않는다(COS-SSO-031).

## 보안 정지·복구 흐름

- 공통 인증 운영 주체가 별도 지정한 계정 보안 담당자만 정지·해제를 실행한다. 교회/개별 서비스 관리자라는 이유로 이 권한을 얻지 않는다. 서비스 담당자는 최소 근거로 요청할 수 있다(COS-SSO-013).
- 계정 탈취·인증 수단 유출·공통 인증 악용 등 공통 인증 보호 사유로 한정한다. 교회 분쟁/징계·서비스 정책 위반만으로 전체 계정을 정지하지 않는다. 신고/AI 결과만으로 자동 정지를 확정하지 않는다(COS-SSO-014).
- 정지 시 기존 세션/갱신 토큰을 회수하고 기존 접근 토큰도 재사용하지 못하게 한다. 해제 후 되살리지 않고 새 인증과 서비스별 현재 이용/권한 검증을 요구한다(COS-SSO-015).
- 정지 중 앱의 별도 제한 확인·복구·이의신청 경로를 제공한다. 일반 데이터/관리자 접근이나 접수만으로 해제하지 않는다. 담당자는 본인과 해당 위험 해소 근거를 확인한 뒤 해제한다. 개인 기록을 보안 증빙으로 수집하지 않는다. 시간 경과·교회 요청만으로 자동 해제하지 않는다(COS-SSO-017/033).
- 이의신청은 최초 결정자와 다른 지정 보안 담당자가 재검토한다. 최초 담당자는 근거만 제공한다. 인력 부재는 대기로 안내하고 동일인 확정/자동 해제로 대체하지 않는다(COS-SSO-018). 오정지 확인을 실제 침해 발생으로 단정하지 않는다.
- 소유 개인 기록 공유는 일시 차단하되 원문 삭제·영구 철회와 구분한다. 해제 후 새 인증으로 해당 제품에서 수신자·범위·목적·남은 기간을 확인해 본인이 명시 재개해야 한다. 만료/철회/서비스 탈퇴·삭제된 권한은 복원하지 않고 담당자가 대신 재개하지 않는다(COS-SSO-037/038).

삭제 절차 개시·운영본 삭제·백업 잔존·백업 만료·종결을 구별한다. 보관 예외가 없는 대상에 일반 기한을 적용하며 재이용/재가입/조회/재시도로 이전 건의 원래 기한이나 종결 후 이력 보유기간을 초기화하지 않는다. 1년은 원문 보유기간·법정 보유기간·일반 백업 연장 기준이 아니다. 이력 자체의 삭제 실행 시한/백업과 장기 미해결 건의 종결 기준은 미결이다.
