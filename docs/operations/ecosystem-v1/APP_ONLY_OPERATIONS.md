# ChurchOS 앱 전용 운영 기준 v1.4

2026-10-24. 사용자 지시: ChurchOS는 별도 웹과 앱을 연동하지 않고 앱만으로 교회 업무를 수행하도록 설계한다. 상태: 후속 개발 기준 반영, 앱 구현·실기기 검증 전.

## 1. 가능 여부와 의미

가능하다. 교인·목회자·관리자에게 Flutter 앱 안의 역할별 화면을 제공하면 교회 개설·설정·가입 승인·공지·일정·출석·기도·말씀·설교·나눔지·연결 관리의 기본 운영을 수행할 수 있다. 관리자 웹/PWA/교회 홈페이지를 필수 경로로 만들지 않는다. 앱에서 같은 서버 API를 호출하므로 앱 전용이라는 이유로 서버 업무 기능이 줄어들 필요는 없다. 다만 작은 화면에서 표 편집·장문 교정·대량 파일 작업은 별도 UX가 필요하다.

앱만이라는 것은 서버나 인터넷 없이 동작한다는 뜻이 아니다. ChurchOS API·DB·파일 저장소·알림·JLPrayer/JLBible/Academy/CHGO API는 필요하다. 서버 백업·보안 업데이트·스토어 심사·앱 서명·서비스 계정 발급까지 교회 휴대폰만으로 수행한다고 약속하지 않는다. 이것은 제품 운영자의 기반 업무이며 일상적인 교회 관리와 구분한다.

ChurchOS 관리자 웹은 만들지 않는다. 다른 독립 제품의 앱이나 교회 자체 홈페이지의 존재를 금지하는 지시는 아니지만, ChurchOS 핵심 업무를 그 웹에서 완료하도록 강제하지 않는다. Academy 교육 편집·강사 업무는 Academy 제품 설계에 속하며 이번 문서만으로 다른 제품 관리자 화면 구현을 선언하지 않는다.

## 2. 같은 앱의 역할별 화면

| 사용자 | 앱에서 제공할 범위 |
|---|---|
| 교인 | 교회 홈·공지·일정·출석·기도·성경/찬송·설교/나눔지·제품 연결·개인 설정 |
| 리더/목회자 | 허용된 공동체·출석·후속 업무·말씀 자료 검토·공개기도 검토 |
| 교회 관리자 | 교회 개설·브랜드·가입 승인·교인/역할·공지/일정 편집·제품 연결·사용량·감사 |
| 설교 자료 편집자/승인자 | 원고·음성/링크 등록·본문 참조·전사 교정·요약/나눔지 검토·게시·철회 |

관리 화면은 내정보의 '교회 관리' 또는 해당 콘텐츠의 관리 동작으로 진입한다. 역할에 맞는 메뉴만 보이게 하되 메뉴 숨김이 서버 권한 검증을 대체하지 않는다. 교회 전환 때 역할·캐시·초안을 재검증한다. 교회 관리 권한이 개인 기도수첩·일기를 열람하는 권한이 되지 않는다.

## 3. 앱에서 끝내야 할 관리자 흐름

| 업무 | 필수 앱 기능 | 완료 판단 |
|---|---|---|
| 교회 개설·브랜드 | 단계별 입력·사진/파일 선택·미리보기·승인 상태 | 웹 대시보드 없이 교회명·로고·색 설정 |
| 교인·가입·역할 | 검색·필터·선택·확인·권한 기간·변경 이력 | 가입 승인·담당자 지정·역할 철회 가능 |
| 공지·일정·출석 | 초안·자동저장·버전 충돌·게시 미리보기·QR/명단 확인 | 모바일에서 작성부터 정정까지 가능 |
| 기도 | JLPrayer API 기반 본인/교회 화면·공개 요청 검토 | 개인 수첩과 교회 공개 범위 구분 |
| 말씀 | JLBible 콘텐츠 뷰어·권리별 기능 | 본문/찬송 기본 열람에 외부 웹 필수 아님 |
| 설교·나눔지 | URL 붙여넣기·문서/음성 선택·진행률·전사 교정·승인·게시 | 링크/원고/음성 중 지원 형식으로 앱에서 등록·교정·게시 |
| 제품 연결 | 교회 연결 요청·개인 연결·철회·오류 안내 | 자체 관리자 웹 URL을 요구하지 않음 |
| 사용량·감사 | 교회별 파일 사용량·업무 감사·작업 실패/재시도 | 교회 관리자에게 필요한 정보만 표시 |

대량 명단 가져오기는 OS 파일 선택→양식 확인→열 매핑/미리보기→오류 목록→확정의 앱 흐름으로 설계한다. 대용량 입력은 서버 작업으로 처리하고 중복·부분 실패를 보고한다. 첫 출시 필수 여부는 파일럿 요구로 정한다. CSV 주입 등 내보내기 안전성·교회 경계도 검증한다. 무제한 대량 처리를 약속하지 않는다.

장문 설교/나눔지는 구간별 편집·초안 저장·원문/초안 전환·변경 확인을 제공한다. 휴대폰에서도 필수 교정이 가능해야 하며 태블릿의 넓은 화면·키보드 입력은 선택적 편의 기능으로 지원한다. 별도 Windows 앱이나 태블릿을 완료 조건으로 요구하지 않는다.

## 4. 파일과 장시간 작업

파일 선택은 휴대폰/태블릿의 OS 파일·공유 기능을 사용한다. 앱 중단·통신 단절·백그라운드 전환을 고려해 업로드 진행·재시도·가능한 재개 방식을 설계한다. 전사·CHGO·생성 작업은 서버에서 비동기로 수행하고 앱이 닫혀도 작업이 유실되지 않아야 한다. 앱 재실행 후 작업 상태와 검토 화면으로 복귀한다. OS별 백그라운드 업로드/재생 지원은 실제 기기로 검증하고 항상 보장한다고 표시하지 않는다.

기본형의 영상은 YouTube 연결이다. 교회가 영상을 YouTube에 업로드하거나 채널을 관리하는 작업은 외부 서비스 작업이다. ChurchOS에서는 주소/재생목록 연결과 앱 내 재생을 제공한다. 이것은 ChurchOS 관리자 웹에 의존하는 구조와 다르다. 직접 영상 업로드 선택 서비스는 별도 계약과 저장/전송 기반을 갖춘 뒤 앱에서 업로드하는 경로를 검증한다.

## 5. 외부 인증·재생과 웹의 구분

| 상황 | 처리 원칙 |
|---|---|
| ChurchOS 로그인/제품 연결 | 앱이 시작·완료·복귀를 관리. 외부 인증 제공자의 OS 인증창/브라우저가 필요한 경우 안내하고 안전하게 복귀 |
| YouTube | 앱 내 공식 플레이어 우선. 차단 시 오류/재시도, 원본 열기는 선택 대안이며 앱 내 재생 완료로 기록하지 않음 |
| 외부 전문 기능 | API 화면 또는 전문 앱 이동/복귀. 앱 내 기본 기능이 무조건 외부 웹으로 빠지지 않게 함 |
| 계정 복구/탈퇴/동의 | 앱 안에서 신청·상태 확인. 외부 서비스 고유 작업은 명시적으로 구분 |

어떤 외부 인증 화면도 뜨지 않는다는 보장은 하지 않는다. 원칙은 별도 ChurchOS 웹 제품을 만들지 않고 일상 업무가 그 웹에 의존하지 않는 것이다. 외부 인증은 교회별 비밀키를 앱에 입력·포함시키는 방식으로 대체하지 않는다. 플랫폼 운영자가 설정한 연동을 교회 관리자가 앱에서 활성화한다.

## 6. S23. 웹 대시보드 없는 교회 운영 검증

1. 새 휴대폰에 앱을 설치하고 관리자가 교회 개설·브랜드 설정·가입 초대를 수행한다.
2. 다른 계정으로 가입 요청 후 관리자가 앱에서 승인한다.
3. 관리자가 공지·행사를 초안 작성·게시하고 교인이 확인한다.
4. 설교 링크 또는 음성/원고를 등록하고 요약·나눔지를 검토·게시한다. CHGO 준비 전에는 수동 초안으로 검증하며 엔진 실행 PASS로 표시하지 않는다.
5. 교인은 성경·찬송·본인/교회 기도를 사용한다. 실제 제공자가 미연결이면 연결 미완료로 처리하고 성공으로 승격하지 않는다.
6. 출석·후속 업무·권한 철회를 앱에서 수행하고 역할/교회 변경 후 접근을 확인한다.
7. 업로드 중 단절·앱 종료, 생성 작업 중 앱 종료, 토큰 만료·권한 철회·동시 수정·재실행을 시험한다.

합격 조건: 교회 기본 운영을 완료하는 데 자체 웹 관리자 페이지가 한 번도 필요하지 않다. Android와 iOS에서 각각 전체 흐름을 검증한다. 접근성·작은 화면·느린 통신에서도 핵심 버튼과 상태를 구분할 수 있다. 미구현·연동 대기는 별도 상태로 남기고 전체 PASS로 표시하지 않는다. 파일럿 운영자에게 휴대폰만으로 실제 업무를 완료하게 하여 검증한다.

## 7. 범위 반영과 남은 일

기존 v2.6은 이미 관리자 웹·PWA를 초기 범위에서 제외했으나 구체적인 앱 내 관리자 흐름은 부족했다. 이번에 모든 핵심 작업의 모바일 관리 경로와 외부 서비스 예외를 명시했다. Flutter 코드·외부 API·실기기 검증은 아직 구현/실행하지 않았다. 백엔드 없는 오프라인 단독 앱이나 모든 전문 제품 관리 기능의 완성을 선언하지 않는다. v2.6 소스·마이그레이션·매니페스트는 보존한다.
