# ChurchOS 앱 전용 운영 기준 v1.4

2026-10-24. 사용자 지시: ChurchOS는 별도 웹과 앱을 연동하지 않고 앱만으로 교회 업무를 수행하도록 설계한다. 상태: 후속 개발 기준 반영, 앱 구현·실기기 검증 전.

## 1. 가능 여부와 의미

가능하다. 교인·목회자·관리자에게 Flutter 앱 안의 역할별 화면을 제공하면 교회 개설·설정·가입 승인·공지·일정·출석·기도·말씀·설교·나눔지·연결 관리의 기본 운영을 수행할 수 있다. 관리자 웹/PWA/교회 홈페이지를 필수 경로로 만들지 않는다. 앱에서 같은 서버 API를 호출하므로 앱 전용이라는 이유로 서버 업무 기능이 줄어들 필요는 없다. 다만 작은 화면에서 표 편집·장문 교정·대량 파일 작업은 별도 UX가 필요하다.

앱만이라는 것은 서버나 인터넷 없이 동작한다는 뜻이 아니다. ChurchOS API·DB·파일 저장소·알림·JLPrayer/JLBible/Academy/CHGO API는 필요하다. 서버 백업·보안 업데이트·스토어 심사·앱 서명·서비스 계정 발급까지 교회 휴대폰만으로 수행한다고 약속하지 않는다. 이것은 제품 운영자의 기반 업무이며 일상적인 교회 관리와 구분한다.

ChurchOS 관리자 웹은 만들지 않는다. 다른 독립 제품의 앱이나 교회 자체 홈페이지의 존재를 금지하는 지시는 아니지만, ChurchOS 핵심 업무를 그 웹에서 완료하도록 강제하지 않는다. Academy 교육 편집·강사 업무는 Academy 제품 설계에 속하며 이번 문서만으로 다른 제품 관리자 화면 구현을 선언하지 않는다.

## 2. 같은 앱의 역할별 화면

| 사용자 | 앱에서 제공할 범위 |
|---|---|
| 교인 | 교회 홈·공지·일정·출석·기도·성경/찬송·설교/나눔지·제품 연결·개인 설정 |
| 리더/목회자 | 허용된 공동체·출석·후속 업무·말씀 자료 검토·공개기도 검토 |
| 교회 관리자 | 교회 개설·브랜드·가입 승인·교인/역할·공지/일정 편집·제품 연결·사용량·감사 |
| 가입 승인 담당자 | 해당 교회 가입 요청 조회·승인·거절만 수행. 다른 담당자 지정·해제나 추가 역할 부여 권한 없음 |
| 설교 자료 편집자/승인자 | 원고·음성/링크 등록·본문 참조·전사 교정·요약/나눔지 검토·게시·철회 |

관리 화면은 내정보의 '교회 관리' 또는 해당 콘텐츠의 관리 동작으로 진입한다. 역할에 맞는 메뉴만 보이게 하되 메뉴 숨김이 서버 권한 검증을 대체하지 않는다. 교회 전환 때 역할·캐시·초안을 재검증한다. 한 계정이 여러 교회의 유효 소속을 동시에 가질 수 있으며 각 교회에서 별도 가입 승인을 받는다. 앱에서는 선택한 활성 교회 하나의 권한·데이터로 업무를 수행한다. 역할·정지·재가입 제한은 해당 교회에만 적용하며 한 교회 관리자는 다른 교회의 소속·역할·정지 정보를 관리 권한만으로 조회할 수 없다. 근거: [COS-JOIN-021](../../decisions/DESIGN_DECISIONS.md#cos-join-021). 이미 유효 소속인 교회에 다시 가입을 신청하면 새 요청·소속을 생성하지 않고 이미 가입된 상태와 해당 교회 홈으로 이동하는 경로를 안내한다. 기존 소속·역할은 변경하지 않으며 초대 링크·다른 기기를 통한 제출에도 동일하게 적용한다. 근거: [COS-JOIN-022](../../decisions/DESIGN_DECISIONS.md#cos-join-022). 초기 가입 요청은 교회에서 확인할 이름만 필수 입력으로 받고 연락처는 선택 입력으로 둔다. 생년월일·주소·가족 정보·신앙 이력·자유 서술 사유는 초기 신청 항목에서 제외한다. 인증 계정 식별과 대상 교회는 서버가 확인하며 입력한 이름·연락처를 본인 인증이나 계정 자동 병합 근거로 사용하지 않는다. 근거: [COS-JOIN-023](../../decisions/DESIGN_DECISIONS.md#cos-join-023). 가입 승인 담당자는 해당 교회의 대기 요청에 대해 제출 이름·선택 연락처·신청 시각·현재 신청 상태만 열람한다. 인증 제공자 식별자·토큰·다른 교회 정보·전문 제품 개인 기록은 노출하지 않는다. 담당자 권한만으로 전체 교인 명단이나 과거 종료 요청 전체를 조회할 수 없다. 종료 요청의 최소 결과 안내는 COS-JOIN-025를 따르며 별도 과거 이력 열람 권한은 후속 계약에서 구체화한다. 근거: [COS-JOIN-024](../../decisions/DESIGN_DECISIONS.md#cos-join-024). 이미 열어 둔 가입 요청이 종료되면 현재도 해당 교회의 유효 심사 권한이 있는 사람에게 이미 처리됨과 해당 요청의 최신 결과(승인·거절·취소), 처리 시각만 안내한다. 신청자 이름·연락처는 다시 반환하지 않으며 처리자 신원·사유·다른 이력도 노출하지 않는다. 심사 권한·유효 소속을 상실한 경우에는 결과도 반환하지 않고 접근을 거부한다. 근거: [COS-JOIN-025](../../decisions/DESIGN_DECISIONS.md#cos-join-025). 가입 거절 시 미리 정한 사유 항목 하나를 선택하고 신청자 본인에게 해당 사유의 표준 안내와 재신청 경로를 제공한다. 자유 서술 심사 메모는 수집하지 않는다. 사유는 심사 이력의 업무 데이터로 관리하되 일반 로그·알림 미리보기에 상세 사유나 이름·연락처를 넣지 않는다. 다른 담당자에게 제공하는 종료 결과에는 사유를 추가하지 않는다. 초기 사유 항목과 문구는 COS-JOIN-034를 따른다. 근거: [COS-JOIN-033](../../decisions/DESIGN_DECISIONS.md#cos-join-033). 초기 거절 사유는 교인 확인 불가·대상 교회 착오 두 가지로 시작한다. 교인 확인 불가는 “입력하신 정보만으로 교인 여부를 확인하지 못했습니다. 교회에 확인 후 다시 신청해 주세요.”, 대상 교회 착오는 “신청하신 교회를 다시 확인해 주세요.”로 안내한다. 기타·자유 입력은 두지 않고 개인 신앙·성숙도·사생활 평가는 사유로 기록하지 않는다. 정지·재가입 제한·중복 제출·기술 오류는 기존 상태·오류 처리로 구분한다. 근거: [COS-JOIN-034](../../decisions/DESIGN_DECISIONS.md#cos-join-034). 교회 관리 권한이 개인 기도수첩·일기를 열람하는 권한이 되지 않는다. 해당 교회 관리자가 가입 승인 담당자를 지정·해제하며 직접 가입 심사도 할 수 있다. 가입 승인 담당자의 위임 범위는 가입 요청 조회·승인·거절뿐이며 다른 담당자 지정·해제나 추가 역할 부여 권한은 얻지 않는다. 이 권한은 해당 교회 안에서만 유효하다. 지정·해제와 승인·거절 이력을 남긴다. 담당자 권한 해제 시 서버에서 권한을 재검증하여 이후 심사를 차단하며 진행 중 요청도 재검증한다. 근거: [COS-JOIN-002](../../decisions/DESIGN_DECISIONS.md#cos-join-002). 가입 승인 담당자는 해당 교회에서 가입 승인된 유효 소속 교인만 지정할 수 있다. 대기·거절·탈퇴·정지 상태이거나 다른 교회에만 소속된 사람은 지정할 수 없다. 탈퇴·정지 등으로 유효 소속을 잃으면 서버가 즉시 가입 요청 조회·승인·거절 권한을 차단하며 진행 중 요청도 재검증한다. 재가입·정지 해제 후에도 담당자 권한을 자동 복원하지 않고 관리자가 다시 지정해야 한다. 외부 사무 담당자 위임은 현재 범위에서 제외한다. 근거: [COS-JOIN-003](../../decisions/DESIGN_DECISIONS.md#cos-join-003). 동시 심사는 먼저 유효하게 확정된 결과만 인정하고 뒤늦은 심사는 이미 처리됨과 최신 결과를 표시한다. 통신 재시도는 기존 결과를 반환한다. 확정 결과 정정 권한은 이번 결정으로 부여하지 않는다. 근거: [COS-JOIN-004](../../decisions/DESIGN_DECISIONS.md#cos-join-004). 가입이 거절된 본인은 새 가입 요청으로 재신청할 수 있다. 기존 거절 결과·이력은 보존하며 새 요청도 담당자 승인을 거친다. 재신청은 기존 결과의 정정이나 자동 승인이 아니다. 거절 안내에서 새 가입 요청으로 재신청하는 경로를 제공한다. 근거: [COS-JOIN-005](../../decisions/DESIGN_DECISIONS.md#cos-join-005). 동일 계정·교회에 대기 중인 가입 요청은 하나만 유지한다. 중복 제출에는 기존 요청과 최신 상태를 안내하며 초대 링크나 제출 기기가 달라도 새 대기 요청을 생성하지 않는다. 거절 후 본인의 명시적인 새 재신청은 COS-JOIN-005에 따라 구분한다. 근거: [COS-JOIN-006](../../decisions/DESIGN_DECISIONS.md#cos-join-006). 가입 대기 화면에 본인 신청 취소를 제공한다. 본인은 대기 중인 가입 요청을 직접 취소할 수 있다. 취소 이력은 보존하며 취소된 요청은 심사할 수 없다. 취소와 심사가 경합하면 서버에서 먼저 유효하게 확정된 처리만 인정하고 후속 요청에는 최신 상태를 안내한다. 이미 승인된 소속은 신청 취소로 종료하지 않고 별도 탈퇴 절차로 구분한다. 근거: [COS-JOIN-007](../../decisions/DESIGN_DECISIONS.md#cos-join-007). 취소 완료 화면에서 새 가입 요청으로 재신청하는 경로를 제공한다. 본인은 가입 요청 취소 후 새 요청으로 다시 신청할 수 있다. 기존 취소 요청·이력은 보존하고 새 요청도 담당자 심사를 거친다. 이전 요청을 되살리거나 자동 승인하지 않으며 동일 계정·교회의 대기 요청 하나 유지 원칙을 적용한다. 근거: [COS-JOIN-008](../../decisions/DESIGN_DECISIONS.md#cos-join-008). 해당 교회 소속이 정지된 동안에는 같은 교회의 새 가입 요청을 생성하거나 가입 승인으로 정지를 우회할 수 없다. 정지 해제는 가입 심사와 별도 절차로 구분하며 가입 승인 담당자 권한으로 정지 해제 권한을 얻지 않는다. 신청 화면은 정지 상태를 새 가입 대기와 구분해 안내한다. 근거: [COS-JOIN-009](../../decisions/DESIGN_DECISIONS.md#cos-join-009). 해당 교회 관리자만 교인 소속의 정지·해제를 처리하고 정지·해제 이력을 남긴다. 가입 승인 담당자·목회자·리더는 해당 직함이나 가입 심사 권한만으로 소속 정지·해제를 처리할 수 없다. 교인 관리 화면에서 정지·해제 및 이력을 제공한다. 근거: [COS-JOIN-010](../../decisions/DESIGN_DECISIONS.md#cos-join-010). 다른 유효 관리자가 없는 상태에서는 마지막 관리자의 역할 해제·소속 정지·교회 탈퇴를 확정할 수 없다. 별도 관리자 부여 절차로 후임이 유효 관리자가 된 뒤 처리하며 동시 변경에도 서버가 검증한다. 계정 보안 잠금·계정 삭제·운영 복구 정책은 별도 검토한다. 처리 불가 시 후임 관리자가 먼저 필요함을 앱에서 안내한다. 근거: [COS-JOIN-011](../../decisions/DESIGN_DECISIONS.md#cos-join-011). 교회 개설 이후 추가 관리자는 해당 교회의 현재 유효 관리자가 같은 교회의 유효 소속 교인 중에서 별도 절차로 지정하고 지정 이력을 남긴다. 가입 승인 담당자·목회자·리더는 해당 직함이나 가입 심사 권한만으로 관리자를 지정할 수 없다. 최초 관리자 확인은 별도 미결이다. 관리자 지정은 가입 승인 화면과 별도 절차로 제공한다. 근거: [COS-JOIN-012](../../decisions/DESIGN_DECISIONS.md#cos-join-012). 추가 관리자는 지정 대상이 앱에서 명시적으로 수락해야 권한이 활성화된다. 수락 전에는 관리 권한이 없고 마지막 관리자 보호에서 후임 유효 관리자로 계산하지 않는다. 수락 확정 시 지정의 유효성·지정자의 현재 관리자 권한·대상의 현재 유효 소속을 서버에서 다시 검증한다. 근거: [COS-JOIN-013](../../decisions/DESIGN_DECISIONS.md#cos-join-013). 수락 전 추가 관리자 지정은 해당 교회의 현재 유효 관리자 누구나 취소할 수 있고 지정 대상 본인은 거절할 수 있다. 취소·거절 이력은 보존하고 해당 지정으로 수락할 수 없다. 수락과 취소·거절이 경합하면 먼저 유효하게 확정된 처리만 인정하고 최신 상태를 안내한다. 이미 수락해 활성화된 관리자 권한은 별도 역할 해제 절차로 처리한다. 근거: [COS-JOIN-014](../../decisions/DESIGN_DECISIONS.md#cos-join-014). 추가 관리자 지정은 서버 지정 시각부터 7일(168시간) 동안 수락할 수 있고 기한 도달 시 수락을 차단한다. 만료 이력은 보존하고 해당 교회의 현재 유효 관리자가 새로 지정해야 한다. 만료 지정은 후임 유효 관리자로 계산하지 않으며 알림 재전송으로 기한을 연장하지 않는다. 최초 관리자 지정 수락 기한은 COS-JOIN-032를 따르며 교회 운영 권한 확인 자체의 유효기간은 별도 미결이다. 근거: [COS-JOIN-031](../../decisions/DESIGN_DECISIONS.md#cos-join-031). 해당 교회의 현재 유효 관리자는 본인 또는 다른 관리자의 관리자 역할을 별도 절차로 해제할 수 있다. 서버는 확정 시 현재 권한과 다른 유효 관리자가 남는지 검증한다. 역할 해제 이력을 남기고 이후 관리자 업무를 차단한다. 역할 해제만으로 교회 소속을 정지·탈퇴시키지 않는다. 근거: [COS-JOIN-015](../../decisions/DESIGN_DECISIONS.md#cos-join-015). 소속 정지 해제·탈퇴 후 재가입만으로 이전 관리자 권한을 자동 복원하지 않는다. 해당 교회의 현재 유효 관리자가 다시 지정하고 본인이 앱에서 수락해야 활성화된다. 소속 상실 및 이전 지정·해제 이력은 보존한다. 근거: [COS-JOIN-016](../../decisions/DESIGN_DECISIONS.md#cos-join-016). 해당 교회 관리자가 소속 정지를 해제하면 기존 소속을 유효 상태로 회복하고 일반 교인 권한을 별도 가입 요청·재승인 없이 다시 사용할 수 있게 한다. 관리자·가입 승인 담당자 권한은 자동 복원하지 않고 기존 재지정 원칙을 적용한다. 다른 추가 역할과 전문 제품 권한의 복원은 이 결정에 포함하지 않는다. 근거: [COS-JOIN-017](../../decisions/DESIGN_DECISIONS.md#cos-join-017). 탈퇴한 본인은 새 가입 요청으로 같은 교회에 재가입을 신청할 수 있다. 과거 소속·탈퇴·심사 이력과 정본 ID를 보존하며 담당자 승인 전에는 교인 권한을 부여하지 않는다. 승인 시 일반 교인 권한만 부여하고 관리자·가입 승인 담당자 권한은 자동 복원하지 않는다. 소속 레코드의 재사용·추가 방식은 후속 계약으로 정한다. 근거: [COS-JOIN-018](../../decisions/DESIGN_DECISIONS.md#cos-join-018). 유효 소속 교인은 본인이 앱에서 확인하면 관리자 승인 없이 교회 탈퇴를 확정한다. 해당 교회 권한을 차단하고 이력을 보존하며 전문 제품의 개인 계정·기록은 삭제하지 않는다. 마지막 유효 관리자는 COS-JOIN-011의 후임 확보 조건을 충족해야 한다. 정지 중 탈퇴와 재가입 제한은 COS-JOIN-020을 따른다. 근거: [COS-JOIN-019](../../decisions/DESIGN_DECISIONS.md#cos-join-019). 정지 중에도 본인 확인 후 관리자 승인 없이 교회 탈퇴를 허용한다. 소속 종료와 별개로 해당 교회의 미해제 정지에 따른 재가입 제한은 유지한다. 해당 교회 관리자가 제한을 해제한 뒤 새 가입 요청·승인을 거쳐야 하며 탈퇴한 소속이나 특수 권한을 자동 복원하지 않는다. 근거: [COS-JOIN-020](../../decisions/DESIGN_DECISIONS.md#cos-join-020).

## 3. 앱에서 끝내야 할 관리자 흐름

현재 개설 심사는 COS-CHURCH-040의 기본 두 서류·미확인 항목만 최소 보완을 적용한다. 플랫폼이 검토·채택하고 버전 관리하는 이용 허용 교단 목록을 운영한다. 등재 교회도 발급 기관·실제 소속·목회자 재직/자격·대표 권한과 공통 이용 기준을 사람이 확인한다. 미등재 교회도 추가 확인·예외 심사를 신청할 수 있으며 미등재만을 이유로 즉시 거절하지 않는다. 독립/신생/해외 별도 경로에도 확인 면제·자동 승인을 적용하지 않는다. 예외 접수는 승인 보장이 아니고 개별 승인이 교단 목록의 자동 추가를 뜻하지 않는다. 근거: COS-CHURCH-006. 허용 교단 목록은 플랫폼이 지정한 신학 검토 책임자가 근거를 검토해 추가·변경·제외안을 제안하고 별도의 서비스 정책 책임자가 근거·영향·적용 시점·목록 버전을 확인해 최종 채택한다. 두 책임자는 다른 사람으로 두며 개별 개설 심사자는 목록을 임의 변경할 수 없다. 목록 변경과 기존 이용 교회의 권한 변경은 구분한다. 근거: COS-CHURCH-007. 교단·노회 소속증명서를 발급받을 수 없는 독립교회는 교회 설립·운영 근거(정관 또는 이에 준하는 문서)와 신청 목회자의 안수·자격 확인 근거로 대체 제출한다. 교회 고유번호증과 재직·자격·대표 권한 확인은 유지하되 재직증명서 등 추가 자료는 미확인 항목에만 요청한다(COS-CHURCH-040). 발급 기관·실제 관계·자격 인정 기준을 사람이 확인하고 문서 제출만으로 승인하지 않는다. 특정 기관·문서의 법적 효력이나 목회자 자격을 이번 정책만으로 인정하지 않는다. 근거: COS-CHURCH-008. KAICAM이 발급한 해당 교회의 현재 소속을 확인할 수 있는 자료가 있으면 교회 소속증명서의 대응 근거로 심사한다. 목회자 개인 안수·회원 자격만으로 교회 소속을 갈음하지 않는다. 고유번호증·재직·목회자 자격·대표 권한은 각각 확인하고 기관 소속 근거가 부족하면 독립교회 대체 자료로 보완한다. 실제 발급 문서 종류·양식·발급 가능성과 개별 교회 소속은 추가 확인해야 한다. 근거: COS-CHURCH-023. 확인된 교회 대표자 본인뿐 아니라 현재 대표자로부터 명시적인 개설·관리 위임을 받은 목회자도 개설을 신청할 수 있다. 직접 대표자는 인증된 신청자 본인과 자료의 현재 대표 관계를 대조하고 위임 신청은 위임자의 현재 권한과 위임 근거를 확인한다. 재직증명서·담임목사 직함·이름 일치만으로 대표 권한이나 본인 확인을 자동 인정하거나 계정을 병합하지 않는다. 자료가 충돌하면 보완·분쟁 대기 원칙을 적용한다. 근거: COS-CHURCH-024. 공통 신학 기준 초안은 성경의 신앙 기준으로서 권위, 삼위일체, 예수 그리스도의 참 하나님 되심과 참 인간 되심, 십자가와 부활, 그리스도를 통한 은혜의 구원 다섯 항목을 출발점으로 삼는다. 세례 방식·교회 정치·은사 이해·예전의 교단별 차이 자체는 일률적 거절 사유로 삼지 않는다. CT-01~06 문구는 COS-CHURCH-029/030의 사용자 검토 초안으로 합의했으며 해석 범위·판단 근거·상충 처리·실제 운영 채택은 후속 검토한다. 근거: COS-CHURCH-025. 성령의 사역을 여섯 번째 항목으로 추가한다. 문구: 우리는 성령께서 우리 안에 거하시며, 진리를 깨닫게 하시고, 거룩한 삶과 복음의 증언을 위해 우리를 인도하시고 능력을 주심을 믿습니다. 특정 은사의 형태나 특정 체험을 모든 신청자의 필수 조건으로 삼지 않는다. CT-06의 검토 초안 합의이며 CT-01~05 문구의 일괄 승인이나 실제 운영 채택을 뜻하지 않는다. 근거: COS-CHURCH-030. 개설 신청 목회자에게 최종 채택한 공통 기준 원문·적용 버전을 안내하고 별도 명시 동의를 받는다. 동의 버전·시각·인증된 신청자 참조를 최소 기록하되 체크만으로 승인하지 않는다. 신학 검토자가 제출 자료·확인 근거와 기준 부합 여부를 사람 검토한다. 미동의는 신청 미완료·안내로 처리하고 그 사실만으로 이단·부적합 판정을 생성하지 않는다. 일반 교인의 가입 동의로 확대하지 않는다. 근거: COS-CHURCH-026. 신청 목회자 개인의 기준 동의와 신청 교회가 같은 기준을 고백한다는 대표·위임 권한에 따른 확인을 별도 항목으로 받는다. 개인 동의만으로 교회의 고백을 검증 완료로 보지 않고 지정 신학 검토자가 교회 공식 신앙고백·정관·소속 교단 자료 등 확인 가능한 근거를 검토한다. 교회 자료가 없거나 선언 주체·권한이 불명확하면 추가 확인 대기로 두고 진술·체크만으로 승인하지 않는다. 교인 개인의 동의나 기도·일기 기록은 요구하지 않는다. 근거: COS-CHURCH-031. 이용 중 교회의 소속 교단·대표·신청 목회자 변경이나 서류 허위 의심 등 승인 근거의 실질적 변화는 사람이 재검토한다. 기준·목록 변경만으로 자동 이용 중단하지 않고 변경 내용·적용 범위·의견/보완 기회를 안내하는 별도 절차로 다룬다. 단순 신고·AI 결과만으로 정지·자료 공개·관리자 교체하지 않는다. 실제 서비스 제한은 사유·범위·권한·이의신청을 별도 확정한 후 적용한다. 근거: COS-CHURCH-032. 플랫폼의 별도 심사 인사·권한 관리 책임자가 사실 확인 담당자·최종 심사 책임자를 지정·해제하고 신학 검토자는 신학 책임자의 자격 검토·추천을 받아 지정한다. 신청자·대상 교회 관리자는 심사자를 지정하거나 자기 건을 승인할 수 없다. 지정권만으로 원문 열람·자기 권한 확대를 허용하지 않고 지정·해제 이력과 현재 배정·권한 검증을 남긴다. 근거: COS-CHURCH-033. 이용 중 서비스 제한은 사실 확인·신학 검토 및 교회의 의견·보완 자료를 바탕으로 개설 심사 책임자가 필요성과 최소 범위를 제안하고 다른 사람인 서비스 정책 책임자가 최종 결정한다. 사유·범위·적용 시점·재검토/이의신청 경로를 안내하고 결정 이력을 남긴다. 단순 신고·AI 결과로 자동 제한하지 않으며 제한을 원문 공개·관리자 교체·개인 제품 기록 삭제 권한으로 해석하지 않는다. 근거: COS-CHURCH-034. 서비스 제한은 검증된 사유에 필요한 기능만 단계적으로 적용한다. 초대·신규 가입 승인·새 게시 등 확산/변경 기능과 기존 자료 열람·일상 업무 제한을 구분한다. 재검토 개시만으로 제한하지 않고 사람의 결정이 필요하며 더 넓은 제한은 필요성·영향을 별도로 기록·승인한다. 삭제·외부 공개·관리자 자동 교체·개인 제품 계정/기록 변경은 포함하지 않는다. 기능별 조합과 최소 이의신청 접근 경로는 후속 계약으로 명시한다. 근거: COS-CHURCH-035. 심사 원문은 현재 배정·권한을 서버가 검증하는 지정 심사 화면에서만 열람하고 다운로드·외부 공유·이메일 첨부·오프라인 저장은 기본 제공하지 않는다. 배정·권한 해제 후 새 열람을 거부하고 열린 화면도 다음 상태 검증 시 닫으며 임시 표시 데이터를 제거한다. 기존 열람 경로의 회수·잔여 유효시간은 후속 계약으로 검증한다. 실제 화면 촬영·외부 복제를 기술적으로 완전히 회수한다고 보장하지 않는다. 근거: COS-CHURCH-027. 공통 신학 기준은 지정 신학 검토 책임자가 구체 문구·해석 범위·판단 근거를 제안하고 다른 사람인 서비스 정책 책임자가 적용 범위·시점·버전을 확인해 최종 채택한다. 개별 심사자는 기준을 임의 추가·변경할 수 없다. 실제 문구는 별도 초안 검토·확정과 채택 이력을 거치며 책임 구조 확정만으로 배포하지 않는다. 근거: COS-CHURCH-028. 신생교회가 기본 서류를 아직 발급받지 못했더라도 미발급 서류별 확인 목적을 충족하는 대체 근거를 사람이 검증할 수 있으면 예외 심사로 개설 승인을 검토한다. 교단 소속 신생교회는 설립·파송 확인 등으로 실제 관계를 확인하고 독립 신생교회는 설립·운영 근거와 목회자 안수·자격 근거를 검토한다. 등록 정보·재직·대표 권한도 별도로 확인하며 부족하면 보완 대기한다. 구체 인정 자료는 미결이며 없는 고유번호를 만들어 입력하지 않는다. 근거: 여부·시각은 최소 이력으로 남기고 원문을 결과 이력에 복제하지 않는다. 백업 만료·복원 시 재삭제는 별도 정책이며 운영본 삭제를 전체 삭제 완료로 표기하지 않는다. 근거: COS-CHURCH-014. 개설 승인 결과가 신청자 앱에서 열람 가능하도록 정상 통지된 시점을 승인 건 서류 원문 보유기간의 기산점으로 둔다. 최초 관리자 수락·활성화 지연이나 지정 ## 4. 파일과 장시간 작업

파일 선택은 휴대폰/태블릿의 OS 파일·공유 기능을 사용한다. 앱 중단·통신 단절·백그라운드 전환을 고려해 업로드 진행·재시도·가능한 재개 방식을 설계한다. 전사·CHGO·생성 작업은 서버에서 비동기로 수행하고 앱이 닫혀도 작업이 유실되지 않아야 한다. 앱 재실행 후 작업 상태와 검토 화면으로 복귀한다. OS별 백그라운드 업로드/재생 지원은 실제 기기로 검증하고 항상 보장한다고 표시하지 않는다.

기본형의 영상은 YouTube 연결이다. 교회가 영상을 YouTube에 업로드하거나 채널을 관리하는 작업은 외부 서비스 작업이다. ChurchOS에서는 주소/재생목록 연결과 앱 내 재생을 제공한다. 이것은 ChurchOS 관리자 웹에 의존하는 구조와 다르다. 직접 영상 업로드 선택 서비스는 별도 계약과 저장/전송 기반을 갖춘 뒤 앱에서 업로드하는 경로를 검증한다.

| ChurchOS 로그인/제품 연결 | 앱이 시작·완료·복귀를 관리. 외부 인증 제공자의 OS 인증창/브라우저가 필요한 경우 안내하고 안전하게 복귀 |
| YouTube | 앱 내 공식 플레이어 우선. 차단 시 오류/재시도, 원본 열기는 선택 대안이며 앱 내 재생 완료로 기록하지 않음 |
| 외부 전문 기능 | API 화면 또는 전문 앱 이동/복귀. 앱 내 기본 기능이 무조건 외부 웹으로 빠지지 않게 함 |
| 계정 복구/탈퇴/동의 | 앱 안에서 신청·상태 확인. 외부 서비스 고유 작업은 명시적으로 구분 |

어떤 외부 인증 화면도 뜨지 않는다는 보장은 하지 않는다. 원칙은 별도 ChurchOS 웹 제품을 만들지 않고 일상 업무가 그 웹에 의존하지 않는 것이다. 외부 인증은 교회별 비밀키를 앱에 입력·포함시키는 방식으로 대체하지 않는다. 플랫폼 운영자가 설정한 연동을 교회 관리자가 앱에서 활성화한다.

## 6. S23. 웹 대시보드 없는 교회 운영 검증

1. 새 휴대폰에 앱을 설치하고 관리자가 교회 개설 요청·임시 브랜드 설정을 수행한다. 서비스 운영 담당자의 실제 교회 운영 권한 확인과 최초 관리자 활성화 후 가입 초대를 수행한다(COS-JOIN-026/027). 최초 관리자는 서비스 운영 담당자의 교회 운영 권한 확인·지정 후 대상 본인이 앱에서 명시적으로 수락해야 활성화된다. 서버가 확인·지정의 현재 유효성과 인증된 대상 본인을 검증하고 해당 교회 최초 유효 소속·관리자 권한·처리 이력을 함께 일관되게 반영한다. 기존 교회 관리자의 가입 승인을 요구하지 않는 최초 개설 전용 절차이며 일반 가입 승인이나 추가 관리자 지정에는 적용하지 않는다. 수락 전 공개 초대·가입 심사 등 관리자 업무는 불가하다. 근거: [COS-JOIN-027](../../decisions/DESIGN_DECISIONS.md#cos-join-027). 최초 관리자 지정도 서버 지정 시각부터 7일(168시간) 동안만 수락할 수 있다. 기한 도달 시 수락을 차단하고 만료 이력을 보존한다. 만료 후 서비스 운영 담당자가 기존 운영 권한 확인의 현재 유효성을 재검토한 뒤 새로 지정한다. 알림 재전송으로 기한을 연장하지 않으며 수락 전 관리자 업무 차단은 유지한다. 기존 확인 결과를 무조건 폐기하거나 증빙을 일괄 재제출하도록 요구하지 않는다. 근거: [COS-JOIN-032](../../decisions/DESIGN_DECISIONS.md#cos-join-032). 서비스 운영 담당자는 신청자가 입력한 연락처만 신뢰하지 않고 독립적으로 확인한 교회 공식 연락 경로로 대표자 또는 권한 있는 책임자에게 신청자의 관리 위임 여부를 확인한다. 공식 경로가 없거나 확인이 충돌하면 자동 승인하지 않고 추가 확인 대상으로 남긴다. 모든 신청자에게 신분증·증빙 원본 업로드를 기본 요구하지 않는다. 앱에서는 확인 대기와 추가 확인 필요를 구분해 안내한다. 근거: [COS-JOIN-028](../../decisions/DESIGN_DECISIONS.md#cos-join-028). 공식 연락 경로가 없는 교회도 일괄 거절하지 않고 서비스 운영 담당자의 개별 추가 확인을 허용한다. 신청자에게 필요한 최소 위임 근거를 안내하고 자기 신고 외에 교회 실재 및 대표자·권한 있는 책임자의 위임을 뒷받침할 근거를 검토한다. 근거가 부족하거나 충돌하면 확인 대기를 유지한다. 증빙 유형·수집·보유 범위는 별도 확정 전 임의로 확대하지 않는다. 근거: [COS-JOIN-029](../../decisions/DESIGN_DECISIONS.md#cos-join-029). 교회 개설 확인 중 대표권·운영권에 대한 상충 주장이 확인되면 어느 한쪽에 최초 관리자 권한을 부여하지 않고 신규 개설 확인·최초 관리자 활성화를 보류한다. 이 절차만으로 기존 교회 데이터를 병합하거나 관리자를 교체하거나 기존 운영을 자동 중단하지 않는다. 분쟁 해소 확인 기준과 재개 절차는 후속 검토한다. 근거: [COS-JOIN-030](../../decisions/DESIGN_DECISIONS.md#cos-join-030).
2. 다른 계정으로 가입 요청 후 관리자가 앱에서 승인한다.
3. 관리자가 공지·행사를 초안 작성·게시하고 교인이 확인한다.
4. 설교 링크 또는 음성/원고를 등록하고 요약·나눔지를 검토·게시한다. CHGO 준비 전에는 수동 초안으로 검증하며 엔진 실행 PASS로 표시하지 않는다.
5. 교인은 성경·찬송·본인/교회 기도를 사용한다. 실제 제공자가 미연결이면 연결 미완료로 처리하고 성공으로 승격하지 않는다.
6. 출석·후속 업무·권한 철회를 앱에서 수행하고 역할/교회 변경 후 접근을 확인한다.
7. 업로드 중 단절·앱 종료, 생성 작업 중 앱 종료, 토큰 만료·권한 철회·동시 수정·재실행을 시험한다.

합격 조건: 교회 기본 운영을 완료하는 데 자체 웹 관리자 페이지가 한 번도 필요하지 않다. Android와 iOS에서 각각 전체 흐름을 검증한다. 접근성·작은 화면·느린 통신에서도 핵심 버튼과 상태를 구분할 수 있다. 미구현·연동 대기는 별도 상태로 남기고 전체 PASS로 표시하지 않는다. 파일럿 운영자에게 휴대폰만으로 실제 업무를 완료하게 하여 검증한다.

## 7. 범위 반영과 남은 일

기존 v2.6은 이미 관리자 웹·PWA를 초기 범위에서 제외했으나 구체적인 앱 내 관리자 흐름은 부족했다. 이번에 모든 핵심 작업의 모바일 관리 경로와 외부 서비스 예외를 명시했다. Flutter 코드·외부 API·실기기 검증은 아직 구현/실행하지 않았다. 백엔드 없는 오프라인 단독 앱이나 모든 전문 제품 관리 기능의 완성을 선언하지 않는다. v2.6 소스·마이그레이션·매니페스트는 보존한다.


개설 신청 철회 후속 합의(COS-CHURCH-036): 승인 전 신청자는 앱에서 관리자 승인 없이 개설 신청을 철회할 수 있다. 서버가 현재 상태를 검증해 이후 심사 확정을 차단하고 최소 철회 이력을 남긴다. 별도 승인 보관 예외가 없으면 철회 후 7일(168시간) 이내 원문 운영본을 삭제하고 백업은 운영본 삭제 후 최대 30일 잔존 정책을 적용한다. 승인과 철회 경합은 최초 유효 확정만 인정하고 최신 상태를 안내한다. 이미 승인된 건에 이 철회를 소급 적용해 승인·교인·교회 데이터를 삭제하지 않는다. 상세는 [개설 심사 설계](CHURCH_ESTABLISHMENT_REVIEW.md)를 따른다. 구현·삭제 실행 검증 NOT_RUN.


보완 미응답 처리(COS-CHURCH-037): 보완 항목·응답 기한·미응답 시 종료와 자료 삭제 안내가 정상 통지된 시점부터 30일(720시간) 동안 응답이 없으면 거절이 아닌 미완료 종료로 처리한다. 종료 전 서버가 현재 응답·진행 절차·승인된 연장 여부를 확인한다. 다시 신청할 수 있으며 운영팀·외부 기관의 확인 지연을 신청자 무응답으로 처리하지 않는다. 보관 예외가 없으면 종료 후 7일 이내 원문 운영본을 삭제하고 백업은 운영본 삭제 후 최대 30일 잔존 정책을 적용한다. 상세는 [개설 심사 설계](CHURCH_ESTABLISHMENT_REVIEW.md). 구현·삭제 실행 검증 NOT_RUN.


개설 이의신청 횟수(COS-CHURCH-038): 동일 개설 결정에 대한 일반 이의신청은 정상 통지 후 30일 기한 내 1회 접수한다. 재검토 중 추가 자료는 같은 건의 보완으로 받고 재검토 결과로 해당 일반 절차를 종결한다. 종결 후 새로운 중대한 근거·절차상 오류 주장은 별도 예외 접수로 사람이 검토하며 같은 내용 반복은 기존 건과 연결해 안내한다. 접수만으로 기존 결과를 자동 변경하지 않는다. 상세는 [개설 심사 설계](CHURCH_ESTABLISHMENT_REVIEW.md). 구현·실행 검증 NOT_RUN.


개설 재검토 종결 자료(COS-CHURCH-039): 거절 유지 재검토 결과·사유·새 근거/절차 오류의 예외 경로가 정상 통지되고 진행 중 별도 검토·승인 보관 예외가 없으면 통지 후 7일(168시간) 이내 원문 운영본을 삭제한다. 일반 이의신청 30일을 반복 시작하지 않는다. 삭제 시 현재 상태를 서버가 검증하고 최소 결과·삭제 이력을 남기며 백업은 운영본 삭제 후 최대 30일 잔존 정책을 적용한다. 재검토에서 승인으로 전환되면 승인 정상 통지부터 30일 보관·이후 7일 내 운영본 삭제 정책을 적용한다. 상세는 [개설 심사 설계](CHURCH_ESTABLISHMENT_REVIEW.md). 구현·삭제 실행 검증 NOT_RUN.


교인 가입 대기 정보 수정(COS-JOIN-035 AGREED): 가입 대기 중 본인은 이름·선택 연락처를 수정할 수 있고 기존 요청 하나를 유지한다. 수정 시 요청 버전을 갱신하며 담당자는 최신 정보를 다시 확인해야 한다. 수정 전 버전으로 보낸 승인·거절은 확정하지 않고 최신 정보를 안내한다. 종료된 요청은 이 수정으로 확정 결과나 과거 신청 정보를 변경할 수 없다. 본인/대기 상태와 서버 요청 버전을 확정 시 검증하며 일반 계정 프로필 변경과 해당 요청 수정은 구분한다. 구현·실행 검증 NOT_RUN.


승인 교인 연락처 열람(COS-JOIN-036 AGREED): 승인된 교인의 연락처는 해당 교회 관리자와 명시적으로 연락 업무를 위임받은 담당자만 필요한 범위에서 열람한다. 담당자는 배정된 공동체·업무 대상 범위로 제한하며 목회자·리더 직함만으로 전체 연락처를 열람하지 못한다. 가입 승인 담당자는 기존 대기 요청 열람 범위를 유지하고 승인만으로 전체 교인 연락처 권한을 얻지 않는다. 일반 교인에게 연락처를 자동 공개하지 않는다. 신청 연락처의 승인 후 보유/사용 전환·위임 지정/해제·감사·구체 필드는 후속 확정한다. 서버는 현재 교회·업무 위임·배정 대상·필드 권한을 검증해야 하며 메뉴 표시만으로 권한을 구현했다고 보지 않는다. 구현·실행 검증 NOT_RUN.


신청 연락처 승인 후 사용(COS-JOIN-037 AGREED): 가입 신청 연락처의 심사 연락 목적과 승인 후 교회 운영 연락 목적을 구분해 안내하고 승인 후 사용은 본인의 별도 선택을 받는다. 선택하지 않아도 가입·승인을 막지 않고 운영 연락처로 자동 복사하지 않는다. 선택한 해당 교회에서만 COS-JOIN-036의 역할·업무 범위로 사용하며 다른 교회로 자동 공유하지 않는다. 심사 기록 보유·삭제는 별도 정책으로 정한다. 선택 주체·교회·목적·현재 선택 상태를 서버가 확인하고 메뉴만 숨겨 구현 완료로 보지 않는다. 변경/철회·구체 기간·연락처 종류는 후속 미결이다. 구현·실행 검증 NOT_RUN.


운영 연락 사용 철회(COS-JOIN-038 AGREED): 본인은 앱에서 해당 교회의 연락처 사용 선택을 관리자 확인 없이 철회할 수 있고 서버가 이후 관리자·담당자 열람 및 새 연락 발송을 차단한다. 철회만으로 소속·가입 승인·기본 교회 기능을 잃지 않으며 개인 계정과 다른 교회의 독립 선택은 변경하지 않는다. 해당 교회 운영 연락처 사본은 별도 확정할 기한에 따라 삭제하고 심사 결과·연락처 원문 없는 최소 철회 이력은 구분한다. 이미 발송한 연락·대기 발송/진행 요청·외부 주소록/반출본·삭제 기한은 후속 계약으로 구분한다. 실제 연락처/요청 본문을 철회 감사 기록에 복제하지 않는다. 구현·실행 검증 NOT_RUN.


연락 사용 철회 후 운영 사본 삭제(COS-JOIN-039 AGREED): 교회 연락 사용 철회는 즉시 효력을 적용하고 해당 교회 운영 연락 목적 사본은 철회 후 7일(168시간) 이내 운영 저장소에서 삭제한다. 삭제 직전 현재 선택·별도 승인 보관 예외를 서버가 재검증하고 연락처 원문 없는 삭제 여부·시각을 기록한다. 개인 계정 연락처·다른 교회의 독립 선택·심사 결과/별도 심사 기록을 포괄 삭제하지 않는다. 백업·복원 삭제와 이미 반출한 자료의 처리는 별도 계약으로 정한다. 예외 승인 권한·재선택/새 제출·백업 상한은 후속 미결이다. 실제 삭제·실패 재시도 증거 검증 NOT_RUN.

## 공통 인증·정지·탈퇴의 앱 흐름

[현재 설계 계약](ACCOUNT_MEMBERSHIP_SERVICE_SCOPE_CONTRACT.md)을 적용한다. 앱에서 공통 로그인·서비스 첫 이용/명시 재이용·종료 영향 확인·계정 정지 안내·제한된 본인 확인/복구/이의신청·탈퇴 후 해당 건 상태 조회를 구분한다. 정지/탈퇴 후 일반 세션을 살려 두지 않고 최소 목적 권한을 분리한다. 개인 공유 재개는 본인이 해당 제품에서 확인하며 교회 관리자가 대신하지 않는다.

마지막 관리자도 공통 탈퇴를 허용하고 공백은 별도 복구하되 일반 교회 탈퇴의 마지막 관리자 보호는 유지한다. 각 API가 현재 권한을 검증하며 메뉴 표시만으로 구현 완료라 하지 않는다. 별도 ChurchOS 관리자 웹을 요구하지 않는다. COS-SSO-048은 설계 합의했고 앱은 검증된 미해소 위험의 가입 보류/보안 확인을 일반 가입 완료와 구분한다. 구체 UI/제공자 과제는 미결이며 실행 검증 NOT_RUN이다.
