# 교회 개설 심사 설계

2026-10-24. 상태 DESIGN. 근거: [COS-CHURCH-001](../../decisions/DESIGN_DECISIONS.md#cos-church-001). 구현·실행 검증 NOT_RUN.

## 간소화안 재검토 (COS-CHURCH-040)

2026-10-24 현재 합의: 기본 두 서류·조건부 보완은 COS-CHURCH-040으로 확정했다. 교인 가입 COS-JOIN-035~039도 AGREED이며 가입 결과 정정 COS-JOIN-040은 별도 OPEN이다. 이후 공통 인증 정책은 COS-SSO-001~048로 정리했으며 실제 인증 제공자·연동은 미확인이다. 설계 검토의 순서가 운영 구현 완료를 뜻하지 않는다.

종전 합의는 COS-CHURCH-005의 기본 세 서류이며 COS-CHURCH-040으로 해당 범위를 대체했다. 현재 합의는 일반적인 교단 소속 교회에 소속증명서·고유번호증 두 서류를 기본으로 받고, 현재 재직·자격·대표/위임 권한의 미확인·충돌 항목에만 최소 추가 자료를 요청하는 방식이다. 두 서류 제출만으로 모든 항목을 확인했다고 보지 않는다. 신학 검토와 기존 대표/위임 확인·최초 관리자 수락·독립/신생/해외 대체 심사·자료 보호 정책은 유지한다.

상태는 AGREED / DESIGN이다. 사용자가 기본 두 서류·조건부 보완 방식에 동의했다. 근거·대안·영향·미확인 증거는 [COS-CHURCH-040](../../decisions/DESIGN_DECISIONS.md#cos-church-040)에 기록한다. 구현·제공자 연동·실행 검증 NOT_RUN.

## 범위와 기존 합의

심사 대상은 ChurchOS에 교회를 개설하려는 교회와 목회자·개설 신청자다. 일반 교인의 교회 가입 승인과 별도 업무다. 교인 가입 COS-JOIN-001~039의 확정 결정은 유지하며 COS-JOIN-035의 대기 정보 수정도 후속 합의로 확정했다. 가입 결과 정정 COS-JOIN-040은 별도 OPEN이다. 공통 인증/종료의 현재 정책은 [통합 설계 계약](ACCOUNT_MEMBERSHIP_SERVICE_SCOPE_CONTRACT.md)을 따른다.

기존 S01과 COS-JOIN-026~032에는 실제 운영 권한 사전 확인·공식 연락 경로 확인·경로 부재 시 개별 확인·분쟁 시 보류·최초 관리자 본인 수락 및 7일 수락 기한이 있다. 목회자 자격 확인과 신학적 이용 기준은 이후 COS-CHURCH-001~039로 검토했다. 신학 문구는 사용자 검토 초안 합의이며 실제 검토·운영 채택/담당자 자격은 후속 과제다. 이번 설계는 기존 확인 절차를 개설 심사의 일부로 연결하며 과거 결정이나 v2.6 구현을 소급 변경하지 않는다.

## 확정된 개설 심사 경계

1. 목회자 계정 가입·로그인이나 목회자 직함만으로 교회 개설 승인 또는 관리자 권한을 부여하지 않는다.
2. 플랫폼 운영팀이 교회 실재성·목회자 자격·대표 권한·서비스 이용 허용 기준을 확인한 후 정식 개설과 교인 초대를 허용한다. 네 확인 항목을 서로 대체하지 않는다. 교회가 실재하거나 대표 권한이 확인됐다는 이유만으로 신학적 이용 기준을 충족했다고 처리하지 않는다.
3. 승인 전에는 기존 합의의 임시 설정만 허용하며 공개 초대·교인 초대·가입 심사 등 관리자 업무는 차단한다. 심사 승인만으로 관리자 권한이 즉시 활성화되지 않는다. 유효한 승인·확인·최초 지정을 전제로 본인이 앱에서 수락해야 최초 소속·관리자 권한·처리 이력을 일관되게 반영한다(COS-JOIN-027/032).
4. 독립교회·신생교회·해외교회에는 각각 별도 확인 경로를 둔다. 독립·신생·해외 경로의 기본 방식은 COS-CHURCH-008/009/010을 따르며 구체 인정 기관·자격·국가별 자료는 미결이다. 기존의 공식 경로 부재 시 개별 추가 확인을 유지하며 자료가 부족하거나 충돌하면 자동 승인하지 않는다. 해당 유형이라는 이유만으로 자동 승인·자동 거절하는 기준을 이번 문서로 만들지 않는다.
5. AI·CHGO는 이단 여부를 자동 판정하지 않는다. 플랫폼 운영팀의 심사를 자동 승인·자동 거절로 대체하지 않으며, AI 점수나 생성 문구를 판정 권위로 삼지 않는다. 심사에 AI·CHGO를 보조 도입할지, 어떤 자료를 보낼지는 별도 미결이고 이번 설계로 연동·자료 전달 권한을 부여하지 않는다.
6. 교회 개설 심사의 신학적 서비스 이용 적합성과 일반 교인의 신앙·성숙도 평가는 구분한다. 기존 교인 가입 거절 사유 두 항목에 이단·신학 평가를 추가하지 않는다. 개인 기도·일기·관계 원문을 개설 심사 근거로 수집하지 않는다.
7. 기존 대표권·운영권 분쟁 시 보류 및 기존 교회 데이터 병합·관리자 교체·운영 자동 중단 금지는 유지한다(COS-JOIN-030). 향후 신학 기준 변경·재검토도 기존 운영 자동 중단을 이번 결정만으로 허용하지 않는다.

## 기본 서류 심사와 예외 경로

근거: [COS-CHURCH-005](../../decisions/DESIGN_DECISIONS.md#cos-church-005), 후속 [COS-CHURCH-040](../../decisions/DESIGN_DECISIONS.md#cos-church-040). 개설 심사는 기본 두 서류 확인과 미확인 항목의 최소 보완을 적용한다. 재직증명서는 일괄 필수가 아니며 재직·자격·대표/위임 권한 확인이 부족할 때 필요한 자료만 요청한다. 종전 COS-JOIN-028의 공식 연락 경로 중심 기본 확인과 증빙 원본 일괄 요구 제외는 이번 기본 서류 정책으로 해당 범위만 대체한다. 교인 가입의 최소 입력 정책은 변경하지 않는다. 신분증을 기본 제출물에 추가하지 않는다.

| 기본 제출 자료 | 확인 목적 | 이 자료만으로 확인 완료로 보지 않는 것 |
|---|---|---|
| 교단·노회 발급 교회 소속증명서 | 발급 기관과 교회의 실제 교단 소속 | 교회 등록 정보·목회자 재직·대표 권한·서비스 이용 허용 전체 |
| 교회 고유번호증 | 교회 등록 정보 | 교단 소속·신학적 적합성·목회자 재직·대표 권한 전체 |


재직과 대표 권한을 구분하고 신청자의 해당 교회 대표 권한을 별도로 확인한다. 확인된 교회 대표자 본인뿐 아니라 현재 대표자로부터 명시적인 개설·관리 위임을 받은 목회자도 개설을 신청할 수 있다. 직접 대표자는 인증된 신청자 본인과 자료의 현재 대표 관계를 대조하고 위임 신청은 위임자의 현재 권한과 위임 근거를 확인한다. 재직증명서·담임목사 직함·이름 일치만으로 대표 권한이나 본인 확인을 자동 인정하거나 계정을 병합하지 않는다. 자료가 충돌하면 보완·분쟁 대기 원칙을 적용한다. 근거: [COS-CHURCH-024](../../decisions/DESIGN_DECISIONS.md#cos-church-024). 허용 대표/위임 증빙 종류·필수 필드·다중 대표 및 목회자 자격 보완 자료는 미결이다. 서류 명칭만으로 법적 효력이나 모든 자격의 충족을 단정하지 않는다.

서류 제출·완비만으로 승인하지 않는다. 플랫폼 운영팀이 플랫폼의 이용 허용 교단 기준과 발급 기관·실제 소속을 확인하고 기존 사람 심사·책임 분리·최초 관리자 수락 절차를 적용한다. 필요하면 신청자 입력 연락처만 신뢰하지 않고 독립적으로 확인한 교단·노회 공식 연락처로 보완 확인한다. 연락 확인 불가·자료 상충은 확인 완료로 처리하지 않는다. 허용 교단/기관 후보 18개는 COS-CHURCH-021~023으로 기록했고 목록 변경/기준 버전과 이용 중 영향은 COS-CHURCH-007/011/032~035로 정했다. 후보의 실제 운영 목록 채택·동명 기관 구분·개별 교회 소속 확인은 미결이다. 플랫폼이 검토·채택하고 버전 관리하는 이용 허용 교단 목록을 운영한다. 등재 교회도 발급 기관·실제 소속·목회자 재직/자격·대표 권한과 공통 이용 기준을 사람이 확인한다. 미등재 교회도 추가 확인·예외 심사를 신청할 수 있으며 미등재만을 이유로 즉시 거절하지 않는다. 독립/신생/해외 별도 경로에도 확인 면제·자동 승인을 적용하지 않는다. 예외 접수는 승인 보장이 아니고 개별 승인이 교단 목록의 자동 추가를 뜻하지 않는다. 근거: [COS-CHURCH-006](../../decisions/DESIGN_DECISIONS.md#cos-church-006). 후보 18개와 CT-01~06 사용자 검토 초안 합의는 유지하며 실제 목록/신학 기준의 운영 채택·해석·예외 증빙 세부는 후속 확정한다.

독립교회·신생교회·해외교회는 별도 심사 경로를 둔다. 기본 서류를 동일하게 발급받기 어렵다는 이유만으로 자동 거절하거나, 예외 경로라는 이유만으로 확인 없이 승인하지 않는다. 독립교회 대체 제출 자료는 COS-CHURCH-008로 확정했다. 신생교회 미발급 처리는 COS-CHURCH-009를 따른다. 해외교회 현지 자료 심사는 COS-CHURCH-010을 따른다. 인정 기관·자료별 최소 필드·국가별 자료/추가 인증은 미결이다.

교단·노회 소속증명서를 발급받을 수 없는 독립교회는 교회 설립·운영 근거(정관 또는 이에 준하는 문서)와 신청 목회자의 안수·자격 확인 근거로 대체 제출한다. 교회 고유번호증과 재직·자격·대표 권한 확인은 유지하되 재직증명서 등 추가 자료는 미확인 항목에만 요청한다(COS-CHURCH-040). 발급 기관·실제 관계·자격 인정 기준을 사람이 확인하고 문서 제출만으로 승인하지 않는다. 특정 기관·문서의 법적 효력이나 목회자 자격을 이번 정책만으로 인정하지 않는다. 근거: [COS-CHURCH-008](../../decisions/DESIGN_DECISIONS.md#cos-church-008). 기존 지정 심사자 열람·불필요 개인정보 가림·보관/삭제 기준 후속 확정 원칙을 그대로 적용한다.

제출 서류는 해당 심사에 지정된 심사자만 열람한다. 플랫폼 운영자라는 이유만으로 원문에 일괄 접근하지 못하며 교회 관리자·가입 승인 담당자·다른 교회에 공개하지 않는다. 신청자는 심사에 불필요한 개인정보를 가려 제출할 수 있다. 필수 확인 항목의 가림으로 검증이 불가능하면 필요한 최소 항목의 보완을 요청하며 개인정보 무가림 전체 원본을 기본 요구하지 않는다. AI·CHGO로 서류를 보내거나 자동 판정하는 권한을 부여하지 않는다.

제출 서류 원문과 최소 심사 결과 이력을 분리해 보관한다. 원문은 심사·이의신청에 필요한 기간만 보관하고 정해진 종료 시점에 삭제한다. 결과 이력에는 적용 기준 버전·확인 항목별 결과·심사자/결정자 참조·시각·결정 상태 등 최소 정보만 남기며 원문 이미지나 불필요한 개인정보를 복제하지 않는다. 보유/삭제 기한·예외 보관 승인·백업·접근 경계는 후속 COS-CHURCH-013~020/027/036~039를 적용하며 구체 필드·예외 종료 실행 시한 등 미결만 별도 검토한다. 근거: [COS-CHURCH-012](../../decisions/DESIGN_DECISIONS.md#cos-church-012). 거절 후 이의신청 없는 건의 운영본 삭제는 COS-CHURCH-014로 확정했다. 승인 건 운영본 기간은 COS-CHURCH-015/016을 따른다. 철회 건은 COS-CHURCH-036을 따른다. 보완 무응답 미완료 종료는 COS-CHURCH-037, 지정 해제 후 열람 제한은 COS-CHURCH-027, 백업은 COS-CHURCH-018/019를 따른다. 재검토 거절 유지 종결은 COS-CHURCH-039를 따른다. 다른 미완료/보류 및 최소 결과 이력의 구체 필드는 미결이며 무기한 보관을 기본으로 확정하지 않는다. 증빙 원문과 개인정보를 로그·이벤트·알림 미리보기에 넣지 않는다. 이번 문서는 실제 업로드·심사·삭제를 실행한 근거가 아니다.

## KAICAM 소속 교회의 대응 근거

KAICAM이 발급한 해당 교회의 현재 소속을 확인할 수 있는 자료가 있으면 교회 소속증명서의 대응 근거로 심사한다. 목회자 개인 안수·회원 자격만으로 교회 소속을 갈음하지 않는다. 고유번호증·재직·목회자 자격·대표 권한은 각각 확인하고 기관 소속 근거가 부족하면 독립교회 대체 자료로 보완한다. 실제 발급 문서 종류·양식·발급 가능성과 개별 교회 소속은 추가 확인해야 한다. 근거: [COS-CHURCH-023](../../decisions/DESIGN_DECISIONS.md#cos-church-023). 개인 자격 증빙을 교회 소속 근거와 별도 분류하며 문서 이름만으로 검증 완료를 표시하지 않는다. 지정 심사자 열람·개인정보 가림·원문/결과 이력 분리와 상태별 보유 정책을 적용한다.

## 기본 서류 미발급 신생교회

신생교회가 기본 서류를 아직 발급받지 못했더라도 미발급 서류별 확인 목적을 충족하는 대체 근거를 사람이 검증할 수 있으면 예외 심사로 개설 승인을 검토한다. 교단 소속 신생교회는 설립·파송 확인 등으로 실제 관계를 확인하고 독립 신생교회는 설립·운영 근거와 목회자 안수·자격 근거를 검토한다. 등록 정보·재직·대표 권한도 별도로 확인하며 부족하면 보완 대기한다. 구체 인정 자료는 미결이며 없는 고유번호를 만들어 입력하지 않는다. 근거: [COS-CHURCH-009](../../decisions/DESIGN_DECISIONS.md#cos-church-009). 지정 심사자 열람·가림·보관/삭제 원칙과 최종 승인 책임 분리·최초 관리자 수락은 유지한다. 신생교회라는 유형이나 발급 대기 상태만으로 승인하지 않는다.

## 해외교회 현지 대응 자료

해외교회는 국내 서류 명칭을 일률 요구하지 않고 소속·등록·목회자 재직/자격·대표 권한의 확인 목적을 충족하는 현지 대응 자료를 지정 심사자가 검토한다. 원문을 제출받고 발급 기관·실제 관계를 확인하며 필요 시 독립 확인한 공식 연락 경로로 보완한다. 심사자가 언어를 검토하기 어려우면 필요한 번역을 요청하되 번역문만으로 진위를 확정하지 않는다. 모든 건에 공증·인증을 요구하지 않고 필요한 경우 추가 인증을 요청한다. 확인이 어려우면 추가 확인 대기로 남긴다. 국가별 인정 자료·추가 인증 요건은 후속 확정한다. 근거: [COS-CHURCH-010](../../decisions/DESIGN_DECISIONS.md#cos-church-010). 원문 제출에도 불필요 개인정보 가림을 허용한다. 번역자·언어 검토자의 서류 접근 자격과 외부 번역 제공 여부는 별도 미결이며 임의로 외부 번역 서비스·AI·CHGO에 자료를 전달하지 않는다. 현지 서류나 번역의 법적 효력을 이번 설계로 단정하지 않는다.

## 지정 심사자의 원문 열람과 권한 회수

심사 원문은 현재 배정·권한을 서버가 검증하는 지정 심사 화면에서만 열람하고 다운로드·외부 공유·이메일 첨부·오프라인 저장은 기본 제공하지 않는다. 배정·권한 해제 후 새 열람을 거부하고 열린 화면도 다음 상태 검증 시 닫으며 임시 표시 데이터를 제거한다. 기존 열람 경로의 회수·잔여 유효시간은 후속 계약으로 검증한다. 실제 화면 촬영·외부 복제를 기술적으로 완전히 회수한다고 보장하지 않는다. 근거: [COS-CHURCH-027](../../decisions/DESIGN_DECISIONS.md#cos-church-027). 복구 목적의 백업 접근·신청자 본인의 자료 확인/반환과는 구분한다. 권한 회수 시 기존 경로·화면·임시 데이터 처리의 실효성을 구현 후 검증해야 한다.

## 공통 신학 기준의 근거 체계

플랫폼이 명시적으로 채택하고 버전 관리하는 공통 신학적 서비스 이용 기준을 문서화해 사람이 심사한다. 특정 교단 소속이나 외부 이단 규정 목록만으로 자동 허용·거절하지 않는다. 독립교회·신생교회·해외교회에도 같은 기준을 적용하되 확인 경로는 별도로 둔다. 외부 교단·기관의 판단은 출처·대상·시점·현재 상태를 확인한 검토 자료로 활용한다. 공통 신학 기준 초안은 성경의 신앙 기준으로서 권위, 삼위일체, 예수 그리스도의 참 하나님 되심과 참 인간 되심, 십자가와 부활, 그리스도를 통한 은혜의 구원 다섯 항목을 출발점으로 삼은 뒤 성령 사역을 여섯 번째 항목으로 추가했다(COS-CHURCH-030). 성령의 사역을 여섯 번째 항목으로 추가한다. 문구: 우리는 성령께서 우리 안에 거하시며, 진리를 깨닫게 하시고, 거룩한 삶과 복음의 증언을 위해 우리를 인도하시고 능력을 주심을 믿습니다. 특정 은사의 형태나 특정 체험을 모든 신청자의 필수 조건으로 삼지 않는다. CT-06의 검토 초안 합의이며 성령 항목 추가 당시 나머지 문구 승인을 포함하지 않았으나 후속 COS-CHURCH-029에서 CT-01~05도 검토 초안으로 합의했다. 실제 운영 채택은 별도다. 세례 방식·교회 정치·은사 이해·예전의 교단별 차이 자체는 일률적 거절 사유로 삼지 않는다. CT-01~06 문구는 사용자 검토 초안으로 합의했으며 해석 범위·판단 근거·상충 처리·실제 운영 채택은 후속 검토한다. 근거: [COS-CHURCH-025](../../decisions/DESIGN_DECISIONS.md#cos-church-025). 범위뿐 아니라 여섯 문구를 검토 초안으로 합의했지만 실제 운영 기준 채택이나 개별 교단의 적합성 판정은 아니다. 일반 교인 가입 사유에는 추가하지 않는다. 심사 책임의 역할 분리는 COS-CHURCH-003으로 확정하고 실제 담당자 선임은 미결이다. 근거: [COS-CHURCH-002](../../decisions/DESIGN_DECISIONS.md#cos-church-002).

## 개설 신청 목회자의 기준 확인·동의

개설 신청 목회자에게 최종 채택한 공통 기준 원문·적용 버전을 안내하고 별도 명시 동의를 받는다. 동의 버전·시각·인증된 신청자 참조를 최소 기록하되 체크만으로 승인하지 않는다. 신학 검토자가 제출 자료·확인 근거와 기준 부합 여부를 사람 검토한다. 미동의는 신청 미완료·안내로 처리하고 그 사실만으로 이단·부적합 판정을 생성하지 않는다. 일반 교인의 가입 동의로 확대하지 않는다. 근거: [COS-CHURCH-026](../../decisions/DESIGN_DECISIONS.md#cos-church-026). 현재 여섯 항목은 검토 초안이므로 완성된 기준이 채택·버전 확정되기 전 실제 동의서가 배포됐다고 표시하지 않는다. 동의는 개인정보 처리 동의·대표 위임 증거·교회별 권한을 대신하지 않는다.

## 공통 신학 기준 문구의 채택·개정 책임

공통 신학 기준은 지정 신학 검토 책임자가 구체 문구·해석 범위·판단 근거를 제안하고 다른 사람인 서비스 정책 책임자가 적용 범위·시점·버전을 확인해 최종 채택한다. 개별 심사자는 기준을 임의 추가·변경할 수 없다. 실제 문구는 별도 초안 검토·확정과 채택 이력을 거치며 책임 구조 확정만으로 배포하지 않는다. 근거: [COS-CHURCH-028](../../decisions/DESIGN_DECISIONS.md#cos-church-028). [기준 문구 초안](COMMON_THEOLOGICAL_USE_CRITERIA_DRAFT.md)의 CT-01~06은 사용자 검토 초안 AGREED / DESIGN이며 실제 운영 채택·신청자 동의서 배포를 뜻하지 않는다.

## 허용 교단 목록의 채택·개정 책임

허용 교단 목록은 플랫폼이 지정한 신학 검토 책임자가 근거를 검토해 추가·변경·제외안을 제안하고 별도의 서비스 정책 책임자가 근거·영향·적용 시점·목록 버전을 확인해 최종 채택한다. 두 책임자는 다른 사람으로 두며 개별 개설 심사자는 목록을 임의 변경할 수 없다. 목록 변경과 기존 이용 교회의 권한 변경은 구분한다. 근거: [COS-CHURCH-007](../../decisions/DESIGN_DECISIONS.md#cos-church-007). 실제 담당자·자격·선임·정책 책임자와 개설 심사 책임자의 겸임·변경 통지/적용 절차는 후속 검토한다.

## 심사 책임의 분리

플랫폼 운영 담당자가 교회 실재성·목회자 자격 자료·대표 권한을 확인하고, 플랫폼이 지정한 신학 검토자가 공통 기준에 따른 검토 의견을 기록한다. 별도로 지정한 플랫폼 개설 심사 책임자가 두 검토 결과와 현재 유효성을 확인해 최종 승인·거절·추가 확인을 결정한다. 신학 검토자와 최종 승인자는 서로 다른 사람으로 두며 신청자나 대상 교회 관리자는 자기 개설 심사를 승인할 수 없다. 근거: [COS-CHURCH-003](../../decisions/DESIGN_DECISIONS.md#cos-church-003). 플랫폼의 별도 심사 인사·권한 관리 책임자가 사실 확인 담당자·최종 심사 책임자를 지정·해제하고 신학 검토자는 신학 책임자의 자격 검토·추천을 받아 지정한다. 신청자·대상 교회 관리자는 심사자를 지정하거나 자기 건을 승인할 수 없다. 지정권만으로 원문 열람·자기 권한 확대를 허용하지 않고 지정·해제 이력과 현재 배정·권한 검증을 남긴다. 근거: [COS-CHURCH-033](../../decisions/DESIGN_DECISIONS.md#cos-church-033). 실제 담당자·자격 세부 기준·인사 책임자 최초 선임·부재 대행·이해충돌·정책/신학 책임자 선임은 후속 미결이다. 기준 채택 책임은 COS-CHURCH-007/028을 따른다. 사실 확인 담당자와 다른 역할의 겸임 가능 여부는 이번 결정으로 추가 확정하지 않는다.

## 최소 심사 결과 이력의 보유기간

유효 개설 승인의 최소 근거는 해당 교회 서비스 이용 중 유지하고 이용 종료 후 1년 보관한 뒤 삭제한다. 거절·신청 철회 등 미개설 종결 건은 최종 처리 후 1년 보관한 뒤 삭제한다. 진행 중 재검토는 종결로 보지 않고 과거 기준·결정 이력을 덮어쓰지 않으며 원문 이미지는 포함하지 않는다. 구체 종결 시각·삭제 실행 기한·분쟁 예외·백업 처리는 후속 확정한다. 근거: [COS-CHURCH-020](../../decisions/DESIGN_DECISIONS.md#cos-church-020). 교회 정본 ID·기준 버전 정본·원문 삭제 상태 기록은 보유 목적이 다르므로 이 기간으로 포괄 삭제하지 않는다. 1년의 구체 날짜 계산과 삭제 실행 시한은 후속 계약으로 명시한다.

## 승인 건 원문 보유기간 기산점

개설 승인 결과가 신청자 앱에서 열람 가능하도록 정상 통지된 시점을 승인 건 서류 원문 보유기간의 기산점으로 둔다. 최초 관리자 수락·활성화 지연이나 지정 만료·재지정만으로 같은 자료의 보유기간을 자동 연장하지 않는다. 실제 재검토·새 사실 확인에 필요한 예외는 별도 승인·종료 기준으로 검토한다. 승인 건 서류 원문은 정상 승인 통지부터 30일(720시간) 보관하고 종료 후 7일(168시간) 이내 운영 저장소에서 삭제한다. 삭제 직전에 진행 중 재검토·확인 절차·별도 승인된 보관 예외가 없는지 서버가 재검증한다. 최소 결과와 삭제 여부·시각은 별도 보관하고 원문을 복제하지 않는다. 백업 만료·복원 재삭제와 결과 이력 보유기간은 별도 확정한다. 근거: [COS-CHURCH-016](../../decisions/DESIGN_DECISIONS.md#cos-church-016). 근거: [COS-CHURCH-015](../../decisions/DESIGN_DECISIONS.md#cos-church-015). 승인 통지 실패 시 정상 통지가 성립한 시각을 후속 계약으로 검증한다. 이 결정만으로 자료를 삭제하거나 예외 보관 권한을 부여하지 않는다.

## 거절 후 이의신청 없는 건의 운영본 삭제

개설 거절의 정상 통지 후 30일 이의신청 기간이 끝나고 접수된 재검토·진행 중 보완·별도 승인된 보관 예외가 없으면 기간 종료 후 7일(168시간) 이내 운영 저장소의 서류 원문을 삭제한다. 서버는 삭제 실행 시 현재 상태와 진행 중 절차를 재검증한다. 삭제 여부·시각은 최소 이력으로 남기고 원문을 결과 이력에 복제하지 않는다. 백업 만료·복원 시 재삭제는 별도 정책이며 운영본 삭제를 전체 삭제 완료로 표기하지 않는다. 근거: [COS-CHURCH-014](../../decisions/DESIGN_DECISIONS.md#cos-church-014). 삭제 실패 시 재시도·지연 기록을 후속 계약으로 명시하고 실행 증거 없이 삭제 완료로 쓰지 않는다. 예외 보관은 해당 건 지정 심사자가 확인 목적·대상 자료·최소 범위·종료 시각을 명시해 요청하고 다른 사람인 플랫폼 서비스 정책 책임자가 검토·승인한다. 승인·해제 이력을 남기며 무기한·자동 연장을 금지한다. 목적 종료 또는 승인 기한 도달 시 해제하고 일반 삭제 절차로 복귀한다. 연장은 근거와 새 종료 시각으로 재승인받으며 심사자 재지정·인력 부족만으로 자동 연장하지 않는다. 근거: [COS-CHURCH-017](../../decisions/DESIGN_DECISIONS.md#cos-church-017). 일반 삭제 기한이 이미 지난 경우 예외 종료 후 실행 기한·진행 중 재검토 대기 상한 등은 후속 확정한다.

## 백업 만료와 복원 재삭제

백업은 일상 심사에 사용하지 않고 승인된 복구 담당자만 복구 목적으로 접근한다. 운영본 삭제 상태를 원문 없는 최소 기록으로 유지하고 복원 시 서비스 공개 전에 최신 삭제 상태를 재적용해 삭제 원문을 다시 제거한다. 백업본은 확정한 순환 보유 상한에서 만료시키고 운영본 삭제·백업 잔존·백업 만료를 구분한다. 운영본 삭제 시점부터 최대 30일(720시간) 이내 해당 원문을 포함하는 모든 백업·복제 백업의 잔존을 종료한다. 새 백업 생성·복제·복원으로 상한을 재설정하지 않는다. 복원 후 공개 전 최신 삭제 상태 재적용을 유지하고 실제 만료 확인 전 전체 삭제 완료로 표기하지 않는다. 실제 기술·제공자의 지원 여부는 후속 검증한다. 근거: [COS-CHURCH-019](../../decisions/DESIGN_DECISIONS.md#cos-church-019). 복구 담당 권한·백업 주기·실패 대응은 후속 확정한다. 근거: [COS-CHURCH-018](../../decisions/DESIGN_DECISIONS.md#cos-church-018). 복구 접근은 심사 열람과 별도 권한이며 일반 관리자에게 백업 열람을 부여하지 않는다. 삭제 상태 재적용을 검증하지 못하면 공개하지 않는 계약을 후속 검증한다. 운영본 삭제만으로 백업 만료를 완료 처리하지 않는다.

## 이의신청과 독립 재검토

신청자는 적용 기준·결정 사유를 안내받고 이의신청 또는 보완 근거를 제출할 수 있다. 해당 건의 최초 신학 검토자·최종 결정자는 재검토의 신학 판단과 최종 결정에서 제외하고 다른 신학 검토자와 다른 최종 책임자가 재검토한다. 재검토 신학 검토자와 최종 결정자도 서로 다른 사람이다. 인력이 없으면 동일인이 대신 확정하지 않고 재검토 대기를 안내한다. 최초 담당자는 기존 자료·경과 설명만 제공할 수 있다. 근거: [COS-CHURCH-004](../../decisions/DESIGN_DECISIONS.md#cos-church-004). 재검토자도 해당 건 지정 심사자여야 서류를 열람할 수 있다. 기준 버전 적용은 COS-CHURCH-011을 따른다. 이의신청 기한은 COS-CHURCH-013을 따른다. 신청 횟수는 COS-CHURCH-038을 따른다. 통지 상세 범위·처리 목표는 미결이며 이번 확정으로 기존 이용 교회 권한을 자동 변경하지 않는다.

## 이의신청 기한과 통지

개설 거절·보류의 이의신청은 적용 기준·사유·신청 경로가 포함된 결과가 신청자 앱에서 열람 가능하도록 정상 통지된 시점부터 30일(720시간) 이내 접수한다. 통지 실패 시 기산하지 않으며 복구 후 정상 통지 시점을 기록한다. 기한 내 접수한 재검토는 기간이 지나도 계속 진행한다. 보완 요청에 대한 답변은 이의신청과 구분한다. 근거: [COS-CHURCH-013](../../decisions/DESIGN_DECISIONS.md#cos-church-013). 이 기한은 제품 운영 기준이며 구체 통지 성공 판정·기간 종료 후 새로운 근거 처리·계정 접근 장애는 후속 확정한다. 신청자의 실제 열람을 무기한 기다리는 기산 방식으로 정한 것은 아니다. 이의신청 기간 경과만으로 보류 결정을 거절로 바꾸거나 진행 중 보완·재검토 자료를 삭제하지 않는다.

## 심사와 재검토에 적용하는 기준 버전

개설 심사는 접수 시 신청자에게 안내한 공통 신학 기준·허용 교단 목록 버전을 고정하고 최초 결정과 그 결정의 이의신청 재검토에 적용한다. 신청자가 새 기준 심사를 원하면 변경 영향을 안내한 뒤 명시적으로 요청할 수 있게 한다. 묵시적 버전 전환·자동 거절·기존 운영 교회 권한 자동 변경은 하지 않는다. 허위 자료·대표권 분쟁 등 사실관계 재확인은 버전 고정과 별개로 유지한다. 근거: [COS-CHURCH-011](../../decisions/DESIGN_DECISIONS.md#cos-church-011). 접수 기준·결정 기준·새 기준 요청의 구체 식별/처리 계약과 변경 통지 방식은 후속 검토한다. 새 기준 요청이 기존 심사·결과 이력을 덮어쓰는 것으로 처리하지 않는다.

## 이용 중 교회의 승인 근거 변화 재검토

이용 중 교회의 소속 교단·대표·신청 목회자 변경이나 서류 허위 의심 등 승인 근거의 실질적 변화는 사람이 재검토한다. 기준·목록 변경만으로 자동 이용 중단하지 않고 변경 내용·적용 범위·의견/보완 기회를 안내하는 별도 절차로 다룬다. 단순 신고·AI 결과만으로 정지·자료 공개·관리자 교체하지 않는다. 이용 중 서비스 제한은 사실 확인·신학 검토 및 교회의 의견·보완 자료를 바탕으로 개설 심사 책임자가 필요성과 최소 범위를 제안하고 다른 사람인 서비스 정책 책임자가 최종 결정한다. 사유·범위·적용 시점·재검토/이의신청 경로를 안내하고 결정 이력을 남긴다. 단순 신고·AI 결과로 자동 제한하지 않으며 제한을 원문 공개·관리자 교체·개인 제품 기록 삭제 권한으로 해석하지 않는다. 근거: [COS-CHURCH-034](../../decisions/DESIGN_DECISIONS.md#cos-church-034). 서비스 제한은 검증된 사유에 필요한 기능만 단계적으로 적용한다. 초대·신규 가입 승인·새 게시 등 확산/변경 기능과 기존 자료 열람·일상 업무 제한을 구분한다. 재검토 개시만으로 제한하지 않고 사람의 결정이 필요하며 더 넓은 제한은 필요성·영향을 별도로 기록·승인한다. 삭제·외부 공개·관리자 자동 교체·개인 제품 계정/기록 변경은 포함하지 않는다. 기능별 조합과 최소 이의신청 접근 경로는 후속 계약으로 명시한다. 근거: [COS-CHURCH-035](../../decisions/DESIGN_DECISIONS.md#cos-church-035). 제한의 구체 조합·기한·해제·긴급 보안 조치는 후속 미결이다. 근거: [COS-CHURCH-032](../../decisions/DESIGN_DECISIONS.md#cos-church-032). 최초 개설 결정에 대한 이의신청과 이용 중 사실 변경 재검토를 구분한다. 재검토 개시만으로 기존 교회 데이터·교인 소속·개인 제품 기록을 삭제하지 않는다. 긴급 보안 사고 대응은 별도 미결이다.

## 후속 상태·권한·검증 계약

개설 신청·심사 대기·추가 확인·승인·거절·재검토의 구체 상태 코드와 전이는 아직 OPEN이다. 교인 가입 요청 상태와 같은 객체나 권한으로 처리하지 않는다. 플랫폼 심사 권한을 특정 교회 관리자·가입 승인 담당자 권한으로 자동 승계하지 않는다. 계정·교회·개설 심사·최초 관리자 지정의 식별과 승인 유효성·동시 처리 계약을 후속 설계한다.

검증 항목(모두 NOT_RUN): 목회자 계정만으로 관리자 권한 획득 불가, 개설 심사 전 초대·가입 심사 차단, 네 확인 항목 및 유형별 경로 분리, 승인 후 최초 본인 수락 검증, AI·CHGO 자동 판정/자동 승인·거절 불가, 다른 교회 심사 정보 격리, 중복 신청·동시 심사·재검토와 수락의 경합, 기준 버전 변경, 외부 확인 자료 부재·장애 시 미확인을 승인으로 처리하지 않음. 기존 운영 변경·거절·재검토의 상세 정책은 해당 결정 후 검증 기준에 반영한다.

## 다음 검토 범위와 복귀 조건

개설 심사의 주요 경계·서류 기본/예외 경로·책임 분리·재검토·버전·서류 보호 원칙은 확정했다. 그러나 전체 설계 완료나 출시 준비 완료는 아니다. 공통 기준 문구/채택 책임은 COS-CHURCH-028/029/030, 개인/교회 확인은 COS-CHURCH-031, 이용 중 실질 변화 재검토는 COS-CHURCH-032로 확정했다. 지정/회수 책임은 COS-CHURCH-033, 서비스 제한 책임/단계 원칙은 COS-CHURCH-034/035, 철회/보완 무응답/일반 재검토 종결은 COS-CHURCH-036~039로 추가 확정했다. 실제 담당자 자격·선임·긴급 사고·예외 상세·구체 제한 조합 등은 아래 후속 OPEN 항목으로 남긴다. 구체 서식/기관 확인·API 상태 코드·삭제 작업·실제 담당자와 제공자 검증은 미실행 후속 항목으로 구분한다. 이 검토의 합의 범위와 미결을 정리한 뒤 COS-JOIN-035로 돌아가며 확정된 교인 가입 정책을 재질문하지 않는다.


여섯 기준 문구는 COS-CHURCH-029/030에서 사용자 검토 초안으로 합의했다. 실제 신학 검토·정책 채택/배포는 미완료다. 신청 목회자 개인의 기준 동의와 신청 교회가 같은 기준을 고백한다는 대표·위임 권한에 따른 확인을 별도 항목으로 받는다. 개인 동의만으로 교회의 고백을 검증 완료로 보지 않고 지정 신학 검토자가 교회 공식 신앙고백·정관·소속 교단 자료 등 확인 가능한 근거를 검토한다. 교회 자료가 없거나 선언 주체·권한이 불명확하면 추가 확인 대기로 두고 진술·체크만으로 승인하지 않는다. 교인 개인의 동의나 기도·일기 기록은 요구하지 않는다. 근거: [COS-CHURCH-031](../../decisions/DESIGN_DECISIONS.md#cos-church-031). 실제 증빙·질의 절차는 후속 검토하며 COS-JOIN-035 보류를 유지한다.


## 승인 전 신청자 철회

승인 전 신청자는 앱에서 관리자 승인 없이 개설 신청을 철회할 수 있다. 서버가 현재 상태를 검증해 이후 심사 확정을 차단하고 최소 철회 이력을 남긴다. 별도 승인 보관 예외가 없으면 철회 후 7일(168시간) 이내 원문 운영본을 삭제하고 백업은 운영본 삭제 후 최대 30일 잔존 정책을 적용한다. 승인과 철회 경합은 최초 유효 확정만 인정하고 최신 상태를 안내한다. 이미 승인된 건에 이 철회를 소급 적용해 승인·교인·교회 데이터를 삭제하지 않는다. 근거: [COS-CHURCH-036](../../decisions/DESIGN_DECISIONS.md#cos-church-036). 승인 후 미수락·이미 개설된 교회의 종료·공동 신청자 처리는 별도 미결이다. 최소 철회 결과 이력은 COS-CHURCH-020의 종결 건 정책과 연결한다.


## 보완 무응답 미완료 종료

보완 항목·응답 기한·미응답 시 종료와 자료 삭제 안내가 정상 통지된 시점부터 30일(720시간) 동안 응답이 없으면 거절이 아닌 미완료 종료로 처리한다. 종료 전 서버가 현재 응답·진행 절차·승인된 연장 여부를 확인한다. 다시 신청할 수 있으며 운영팀·외부 기관의 확인 지연을 신청자 무응답으로 처리하지 않는다. 보관 예외가 없으면 종료 후 7일 이내 원문 운영본을 삭제하고 백업은 운영본 삭제 후 최대 30일 잔존 정책을 적용한다. 근거: [COS-CHURCH-037](../../decisions/DESIGN_DECISIONS.md#cos-church-037). 통지 실패·계정 접근 장애·연장 승인 권한은 후속 검토한다. 단순 앱 열람을 보완 완료로 보거나 미완료를 신학 부적합으로 기록하지 않는다. 이전 신청 이력을 덮어쓰지 않으며 새 신청의 적용 기준은 접수 시 버전 정책을 따른다.


## 일반 이의신청 횟수와 예외 접수

동일 개설 결정에 대한 일반 이의신청은 정상 통지 후 30일 기한 내 1회 접수한다. 재검토 중 추가 자료는 같은 건의 보완으로 받고 재검토 결과로 해당 일반 절차를 종결한다. 종결 후 새로운 중대한 근거·절차상 오류 주장은 별도 예외 접수로 사람이 검토하며 같은 내용 반복은 기존 건과 연결해 안내한다. 접수만으로 기존 결과를 자동 변경하지 않는다. 근거: [COS-CHURCH-038](../../decisions/DESIGN_DECISIONS.md#cos-church-038). 새 근거/절차 오류 예외의 접수 책임·인정 기준·원문 삭제 후 재제출과 기한 도과 접수는 후속 검토한다. 최초 결정과 재검토 결과 이력은 덮어쓰지 않는다.


## 일반 재검토 종결 후 원문 처리

거절 유지 재검토 결과·사유·새 근거/절차 오류의 예외 경로가 정상 통지되고 진행 중 별도 검토·승인 보관 예외가 없으면 통지 후 7일(168시간) 이내 원문 운영본을 삭제한다. 일반 이의신청 30일을 반복 시작하지 않는다. 삭제 시 현재 상태를 서버가 검증하고 최소 결과·삭제 이력을 남기며 백업은 운영본 삭제 후 최대 30일 잔존 정책을 적용한다. 재검토에서 승인으로 전환되면 승인 정상 통지부터 30일 보관·이후 7일 내 운영본 삭제 정책을 적용한다. 근거: [COS-CHURCH-039](../../decisions/DESIGN_DECISIONS.md#cos-church-039). 보류 유지·보완 요구·새 예외 검토 중 보관 및 예외 종료 후 삭제 실행 시한은 별도 미결이다.

## 현재 합의와 남은 OPEN

COS-CHURCH-001~040에서 이번 핵심 정책 묶음을 합의했다. 여섯 신학 문구는 사용자 검토 초안 합의이며 실제 책임자의 신학 검토·정책 채택·배포는 미완료다. 전체 상세 설계나 운영 출시 준비가 완료된 것은 아니다. 교인 가입의 확정 결정은 유지한다. [COS-JOIN-035](../../decisions/DESIGN_DECISIONS.md#cos-join-035)는 이미 AGREED이므로 다시 질문하지 않는다. 별도 가입 결과 정정 COS-JOIN-040만 OPEN으로 구분한다.

후속 OPEN 항목(확정으로 처리하지 않음):

- 실제 심사자/인사/신학/정책 책임자 자격·선임·대행·이해충돌, 신학 문구의 실제 해석/근거 검토와 운영 채택.
- 후보 기관들의 공식 명칭·발급 서류·실제 소속 확인, 유형별 최소 증빙·유효성·가림 필수 필드·위임 범위·통지 상세.
- 미제출 초안·보류/보완 유지·계정 장애·기한 연장 권한·예외 접수 책임·예외 보관 종료 후 실행 시한·재검토 인력 대기 상한.
- 구체 기능 제한 조합·기간·해제·제한 결정 이의신청 상세와 긴급 보안 대응, 이미 개설된 교회 종료/분쟁 세부.
- API/DB 상태·버전/멱등·동시 처리·현재 권한·열람 경로 회수·삭제/백업 기술·실제 담당자/제공자 계약 및 실행 증거.

모든 구현·실기기·제공자 연동·삭제/복원 실행 검증은 NOT_RUN이다. 실제 확인 없이 PASS·정책 배포·원격 동기화 완료로 표시하지 않는다.

과거 인터뷰의 COS-JOIN-035 보류와 기본 세 서류 합의는 결정 기록에 보존한다. 현재 적용 정책은 후속 AGREED 결정과 COS-CHURCH-040의 기본 두 서류를 따른다. 위 후속 OPEN과 미실행 상태는 유지한다.
