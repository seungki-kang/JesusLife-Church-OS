## 공통 수락 조건

1. 제공자 담당자/정본·API 버전·capability별 요청/응답과 오류 코드가 식별된다.
2. 본인·교회·역할·제품 이용권·공유 권한을 각각 검사한다. 하나의 계정이 모든 권한을 뜻하지 않는다.
3. 변경 명령은 버전/멱등 키·중복·충돌을 정의한다. 조회 캐시는 제공자가 허용한 TTL·무효화를 따른다.
4. 철회 후 새 접근 거부와 캐시/미사용 grant 폐기를 검증한다. 요청 당시 권한과 응답 표시 당시 컨텍스트가 다르면 표시하지 않는다.
5. 외부 장애·미설정·미제공·자료 부족·접근 거부를 구분하고 핵심 교회 업무는 계속 작동한다.
6. 양쪽 계약 테스트와 실제 sandbox 실행 증거가 있어야 연결 완료로 표시한다. 목업 PASS는 제공자 연동 PASS가 아니다.

## 후속 DB 변경 전 확인

기존 API/DB 계보와 적용 이력, 역할 모델, 신규 상태 전이, 보유/삭제 책임, 개인정보 최소 필드, 실제 제공자 ID/버전 대응을 먼저 확정한다. 그 뒤 OpenAPI와 후속 migration을 함께 검토한다. 기존 v2.6 원본을 고쳐 새 설계와 동일한 척하지 않는다.


## 교회 개설 심사 후속 계약 범위

C02의 교인 가입·역할과 구분해 플랫폼 개설 심사 객체·권한·결과 계약을 설계한다. 교회 실재성·목회자 자격·대표 권한·서비스 이용 허용 기준의 사람 심사, 독립/신생/해외교회 별도 확인 경로, 승인 전 개설·초대 차단, 최초 관리자 수락 시 현재 승인 유효성 검증, AI·CHGO 이단 자동 판정 금지를 포함한다. 플랫폼 공통 신학 기준의 명시 채택·버전 관리·사람 심사 및 외부 판단의 검토 자료 활용 원칙은 COS-CHURCH-002로 확정했다. 사실 확인·지정 신학 검토·별도 개설 심사 책임자 최종 결정의 역할 분리, 신학 검토자와 최종 승인자 다른 사람, 자기 개설 승인 금지는 COS-CHURCH-003으로 확정했다. 서버는 해당 건의 역할 분리·현재 심사 권한·검토 결과 유효성을 검증해야 한다. 구체 API·상태·실제 심사자 선임/자격·기준 버전 형식·교리 조항·재검토·개인정보 필드는 미확정이다. [개설 심사 설계](CHURCH_ESTABLISHMENT_REVIEW.md) 및 COS-CHURCH-001을 따른다. 구현·실행 검증 NOT_RUN.


COS-CHURCH-005에 따라 개설 심사 계약의 기본 입력을 소속증명서·고유번호증 두 서류로 정하고 재직·자격·대표/위임 권한 중 미확인 항목에만 최소 보완 자료를 요청한다(COS-CHURCH-040이 종전 세 서류 요구 범위를 대체). 소속/등록/재직의 검증 목적을 분리하고 허용 교단 기준·발급 기관·실제 소속을 사람이 확인한다. 필요 시 공식 연락 보완, 독립/신생/해외 대체 경로, 지정 심사자 현재 권한에 따른 서류 열람, 개인정보 가림·보완·로그 비노출, 보관·삭제·백업/재검토 이력의 계약이 필요하다. 서류 완비만으로 승인하지 않는다. 구체 자료 필드·파일 처리·보유기간·삭제 증거는 미확정이며 구현·실행 검증 NOT_RUN이다.

연락 사용 철회 후 운영 사본 삭제(COS-JOIN-039 AGREED): 교회 연락 사용 철회는 즉시 효력을 적용하고 해당 교회 운영 연락 목적 사본은 철회 후 7일(168시간) 이내 운영 저장소에서 삭제한다. 삭제 직전 현재 선택·별도 승인 보관 예외를 서버가 재검증하고 연락처 원문 없는 삭제 여부·시각을 기록한다. 개인 계정 연락처·다른 교회의 독립 선택·심사 결과/별도 심사 기록을 포괄 삭제하지 않는다. 백업·복원 삭제와 이미 반출한 자료의 처리는 별도 계약으로 정한다. 예외 승인 권한·재선택/새 제출·백업 상한은 후속 미결이다. 실제 삭제·실패 재시도 증거 검증 NOT_RUN.

## C01/C02 현재 정책 계약과 후속 schema

[가입 승인·탈퇴/정지 현재 설계 계약](ACCOUNT_MEMBERSHIP_SERVICE_SCOPE_CONTRACT.md)을 C01/C02 업무 기준으로 적용한다. 여섯 제품 공통 SSO·대상 API 토큰/현재 권한·교회/서비스/공통 계정 종료·공유·삭제/백업·기한/운영 책임을 그 표에서 추적한다. 반복 인터뷰 본문은 이 계약으로 통합하고 결정 이유/대안은 [결정 기록](../../decisions/DESIGN_DECISIONS.md)에 보존한다.

후보 YAML의 초대 수락 즉시 활성화는 현재 수동 승인과 충돌한다. 후보/적용 마이그레이션/v2.6은 보존하고 후속 schema에서 초대 접수·담당자 승인·소속·역할 수락을 분리한다. 현재 정책 변경이 실제 endpoint/HTTP/schema 배포를 뜻하지 않는다.

후속 계약은 현재 문서의 구현 전 과제표를 기준으로 실제 제공자·클라이언트/복귀·토큰 발급/회수·최소 상태/식별 매핑·멱등/경합·권한/최신성/지연 증거·삭제/백업 지원을 확인해 작성한다. 새 제공자/endpoint/보관 근거를 가정하지 않는다. COS-SSO-001~048은 AGREED / DESIGN이며 COS-JOIN-040~059는 AGREED / DESIGN이다. 관리자 전용 정정·오승인 소속 종료·오거절 재신청·재검토/복구·기한·최소 이력/보관 정책은 [현재 계약](ACCOUNT_MEMBERSHIP_SERVICE_SCOPE_CONTRACT.md#가입-결과-정정-권한)을 따른다. 마지막 관리자 보호의 정정 적용·세부 역할 회수/경합·운영 계약은 OPEN이며 실제 실행·삭제·복원·SSO 검증은 NOT_RUN이다. 실제 위험 식별 근거·최소 보안 참조 보유/삭제·오탐/독립 재검토·보류 검토 시한은 후속 계약 과제로 확인한다. 구현·연동·실행 검증 NOT_RUN.

## C01 사실 조사 인계

[제공자·제품별 로그인 인벤토리](AUTH_PROVIDER_AND_PRODUCT_INVENTORY.md)를 구현 전 근거로 추가했다. ChurchOS JWT 검증과 실제 발급자를 구분하고 로컬 기록의 본인 명시 연결/소유자 매핑을 선행 과제로 둔다. JLPrayer OIDC URL은 placeholder이며 JLBible·JLAcademy/운영 인증은 미확인이다. 아직 공급자·새 endpoint·식별자 치환·마이그레이션을 확정하지 않았다. 조사 표의 필수 기능을 실제 제공자 근거로 대조한 뒤 C01과 C02의 작은 가입 흐름 계약을 구체화한다. 실행 검증 NOT_RUN.
