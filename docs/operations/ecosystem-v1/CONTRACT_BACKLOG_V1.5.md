## 공통 수락 조건

1. 제공자 담당자/정본·API 버전·capability별 요청/응답과 오류 코드가 식별된다.
2. 본인·교회·역할·제품 이용권·공유 권한을 각각 검사한다. 하나의 계정이 모든 권한을 뜻하지 않는다.
3. 변경 명령은 버전/멱등 키·중복·충돌을 정의한다. 조회 캐시는 제공자가 허용한 TTL·무효화를 따른다.
4. 철회 후 새 접근 거부와 캐시/미사용 grant 폐기를 검증한다. 요청 당시 권한과 응답 표시 당시 컨텍스트가 다르면 표시하지 않는다.
5. 외부 장애·미설정·미제공·자료 부족·접근 거부를 구분하고 핵심 교회 업무는 계속 작동한다.
6. 양쪽 계약 테스트와 실제 sandbox 실행 증거가 있어야 연결 완료로 표시한다. 목업 PASS는 제공자 연동 PASS가 아니다.

## 후속 DB 변경 전 확인

기존 API/DB 계보와 적용 이력, 역할 모델, 신규 상태 전이, 보유/삭제 책임, 개인정보 최소 필드, 실제 제공자 ID/버전 대응을 먼저 확정한다. 그 뒤 OpenAPI와 후속 migration을 함께 검토한다. 기존 v2.6 원본을 고쳐 새 설계와 동일한 척하지 않는다.
