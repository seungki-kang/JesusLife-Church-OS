# ChurchOS 상세 개발 설계 v1.5

2026-10-24. ID COS-DETAIL-001. 운영 합의 v1.4를 실제 개발 단위로 구체화한 설계 문서다. 에뮬레이터 실행과 신규 기능 코딩은 이번 단계에서 하지 않는다.

## 1. 기준과 상태

기준 저장소 브랜치: feature/churchos-app-0.1, 커밋 b37c6c8. 사용자가 GitHub에 올린 최신 파일에서 작업을 시작했다. v2.6은 실제 백엔드 구현·검증 기준점이고 운영 v1.4/상세 v1.5는 후속 요구사항이다. 문서가 추가되었다고 v2.6 OpenAPI·DB·외부 제품에 신규 기능이 생기지 않는다.

확인된 검증은 v2.6 서버 테스트 80개, 사용자 제공 PostgreSQL/API 검사 63개 PASS, 사용자가 보낸 Flutter 위젯 테스트 3개 PASS 출력이다. Flutter 세 테스트는 기도 화면의 데모 표시, 시연 역할별 관리자 진입, 교회 전환의 데모 상태 초기화다. 실제 모바일 실행·인증·기도/성경/찬송/설교 연결·신규 기능 검증은 미완료다. 사용자의 테스트 출력은 대화 근거이며 실행 원본 로그가 저장소에 제출된 것은 아니다.

## 2. 출시 범위와 단계

첫 출시는 '교회 기본형'을 목표로 한다. ChurchOS 앱 하나로 교인과 운영자가 기본 업무를 처리한다. 관리자 웹·PWA·교회 홈페이지는 필수 경로가 아니다. 아래 준비 단계는 개발 순서를 뜻하며, 미완성 전문 기능을 숨기고도 '전체 기본형 완성'이라고 부르는 기준은 아니다.

| 단계 | 제공 가치 | 단계 종료 조건 |
|---|---|---|
| D0 설계 확정 | 범위·화면·권한·정본·외부 계약 정리 | 미결 사항·가정·현재 구현과의 차이 기록 |
| D1 운영 흐름 개발 | 인증→교회 가입→공지/일정→관리자 게시 | 실제 API·역할·교회 경계와 앱 오류 처리 검증 |
| D2 기본형 파일럿 준비 | 화이트라벨·기도·성경/찬송·설교/수동 나눔지·공동체·출석·봉사·후속 업무 | 파일럿에 포함할 모든 기능 실제 검증, 콘텐츠 권리/제공 범위 고지 |
| D3 선택형 확장 | Academy·너랑나랑·생명일기 교육 경로, CHGO 설교 초안 | 제공자별 계약과 별도 검증. Academy 미선택 교회에 교육 의무 없음 |
| D4 별도 구축 | 직접 영상 호스팅·교회 전용 앱 | 비용·계정·지원·인계·공통 업데이트 계약과 실행 검증 |

회계·헌금 결제·시설 예약·온라인 쇼핑·독자적 영상 서버·개인 영성 순위는 첫 기본형에 넣지 않는 제안이다. 목사님의 기본 기능 요구를 축소 확정하는 뜻이 아니라 파일럿 범위를 검토하기 위한 구분이다. 각 교회 도입 시 필수 요구를 확인하고 범위를 바꿀 때 데이터·비용·출시 영향을 함께 기록한다.

## 3. 한 앱의 역할·화면 구조

하단 메뉴는 홈·말씀·기도·교회생활·내정보를 기준안으로 한다. 교회 관리자 도구는 내정보의 '교회 관리'와 콘텐츠별 '관리'로 접근한다. 모든 변경 동작은 서버 권한 검사를 거친다. 운영 앱에는 데모 역할 선택을 넣지 않는다. 현재 시연 앱의 역할/교회/Academy 스위치는 테스트 빌드 전용으로 분리해야 한다.

| 화면군 | 필수 화면 | 핵심 동작 | 데이터 책임 |
|---|---|---|---|
| 시작 | 로그인·교회 선택·가입 대기·접근 철회 | 인증·가입·활성 교회 선택 | 인증 제공자 + ChurchOS 소속 |
| 홈 | 교회 브랜드·공지·일정·이번 주 설교·선택 연결 | 목록→상세→원래 위치 복귀 | 교회 정본과 허용된 제공자 결과 |
| 말씀 | 성경·찬송·설교 목록/상세·요약·나눔지 | 앱 내 열람·영상/음성·통독 이동 | JLBible 콘텐츠 / ChurchOS 설교 |
| 기도 | 나의 수첩·교회 공동기도·기도 요청·기도방 | 조회·작성·공유 선택·응답 | JLPrayer |
| 교회생활 | 내 공동체·행사·출석·봉사·선택 교육 | 소속·참여·신청/취소·실천 이동 | ChurchOS / 각 전문 제품 |
| 내정보 | 기본 계정·소속·알림·연결·철회 | 계정/제품/교회 행동 구분 | 각 정본 소유자 |
| 교회 관리 | 브랜드·가입·교인/역할·공지/일정·설교·기도 검토·연결·사용량 | 단계별 편집·미리보기·승인/게시 | ChurchOS + 제공자 권한 |

모든 API 화면에는 LOADING / EMPTY / READY / FAILED / UNAUTHORIZED / FORBIDDEN / STALE 상태를 명시한다. 미설정·권리 미확보·제공자 장애는 빈 목록과 구분한다. 실패를 0건/미활동/미성숙으로 바꾸지 않는다. 온라인 연결이 필요한 쓰기는 성공 응답 전에 완료 표시하지 않는다.

v2.6의 실제 쓰기는 TENANT_ADMIN만 가능하고, 교인 목록은 PASTOR/TENANT_ADMIN이 조회한다. 리더·콘텐츠 편집자·설교 승인자 등 세부 권한은 새 계약과 서버 변경이 필요하다. 기존 UI에서 버튼만 추가해 권한이 구현된 것으로 처리하지 않는다. 자기 관리자 권한의 일방 확대·잠긴 계정 복구는 별도 제어와 검증이 필요하다. 다른 유효 관리자가 없는 상태에서는 마지막 관리자의 역할 해제·소속 정지·교회 탈퇴를 확정할 수 없다. 별도 관리자 부여 절차로 후임이 유효 관리자가 된 뒤 처리하며 동시 변경에도 서버가 검증한다. 계정 보안 잠금·계정 삭제·운영 복구 정책은 별도 검토한다. 근거: [COS-JOIN-011](../../decisions/DESIGN_DECISIONS.md#cos-join-011). 교회 개설 이후 추가 관리자는 해당 교회의 현재 유효 관리자가 같은 교회의 유효 소속 교인 중에서 별도 절차로 지정하고 지정 이력을 남긴다. 가입 승인 담당자·목회자·리더는 해당 직함이나 가입 심사 권한만으로 관리자를 지정할 수 없다. 서비스 운영 담당자가 교회 개설 신청자의 실제 교회 운영 권한을 확인한 뒤 최초 관리자 지정을 진행한다. 확인 전에는 임시 설정만 허용하고 정식 교회 명의의 공개 초대·가입 심사 등 관리자 업무는 허용하지 않는다. 이 확인만으로 다른 교회나 전문 제품 권한을 부여하지 않는다. 근거: [COS-JOIN-026](../../decisions/DESIGN_DECISIONS.md#cos-join-026). 서비스 운영 담당자는 신청자가 입력한 연락처만 신뢰하지 않고 독립적으로 확인한 교회 공식 연락 경로로 대표자 또는 권한 있는 책임자에게 신청자의 관리 위임 여부를 확인한다. 공식 경로가 없거나 확인이 충돌하면 자동 승인하지 않고 추가 확인 대상으로 남긴다. 모든 신청자에게 신분증·증빙 원본 업로드를 기본 요구하지 않는다. 근거: [COS-JOIN-028](../../decisions/DESIGN_DECISIONS.md#cos-join-028). 공식 연락 경로가 없는 교회도 일괄 거절하지 않고 서비스 운영 담당자의 개별 추가 확인을 허용한다. 신청자에게 필요한 최소 위임 근거를 안내하고 자기 신고 외에 교회 실재 및 대표자·권한 있는 책임자의 위임을 뒷받침할 근거를 검토한다. 근거가 부족하거나 충돌하면 확인 대기를 유지한다. 증빙 유형·수집·보유 범위는 별도 확정 전 임의로 확대하지 않는다. 근거: [COS-JOIN-029](../../decisions/DESIGN_DECISIONS.md#cos-join-029). 교회 개설 확인 중 대표권·운영권에 대한 상충 주장이 확인되면 어느 한쪽에 최초 관리자 권한을 부여하지 않고 신규 개설 확인·최초 관리자 활성화를 보류한다. 이 절차만으로 기존 교회 데이터를 병합하거나 관리자를 교체하거나 기존 운영을 자동 중단하지 않는다. 분쟁 해소 확인 기준과 재개 절차는 후속 검토한다. 근거: [COS-JOIN-030](../../decisions/DESIGN_DECISIONS.md#cos-join-030). 확인할 공식 연락 경로의 세부 기준·대체 확인·최소 증거 보관은 후속 검토한다. 최초 관리자는 서비스 운영 담당자의 교회 운영 권한 확인·지정 후 대상 본인이 앱에서 명시적으로 수락해야 활성화된다. 서버가 확인·지정의 현재 유효성과 인증된 대상 본인을 검증하고 해당 교회 최초 유효 소속·관리자 권한·처리 이력을 함께 일관되게 반영한다. 기존 교회 관리자의 가입 승인을 요구하지 않는 최초 개설 전용 절차이며 일반 가입 승인이나 추가 관리자 지정에는 적용하지 않는다. 수락 전 공개 초대·가입 심사 등 관리자 업무는 불가하다. 근거: [COS-JOIN-027](../../decisions/DESIGN_DECISIONS.md#cos-join-027). 최초 관리자 지정도 서버 지정 시각부터 7일(168시간) 동안만 수락할 수 있다. 기한 도달 시 수락을 차단하고 만료 이력을 보존한다. 만료 후 서비스 운영 담당자가 기존 운영 권한 확인의 현재 유효성을 재검토한 뒤 새로 지정한다. 알림 재전송으로 기한을 연장하지 않으며 수락 전 관리자 업무 차단은 유지한다. 기존 확인 결과를 무조건 폐기하거나 증빙을 일괄 재제출하도록 요구하지 않는다. 근거: [COS-JOIN-032](../../decisions/DESIGN_DECISIONS.md#cos-join-032). 근거: [COS-JOIN-012](../../decisions/DESIGN_DECISIONS.md#cos-join-012). 추가 관리자는 지정 대상이 앱에서 명시적으로 수락해야 권한이 활성화된다. 수락 전에는 관리 권한이 없고 마지막 관리자 보호에서 후임 유효 관리자로 계산하지 않는다. 수락 확정 시 지정의 유효성·지정자의 현재 관리자 권한·대상의 현재 유효 소속을 서버에서 다시 검증한다. 근거: [COS-JOIN-013](../../decisions/DESIGN_DECISIONS.md#cos-join-013). 수락 전 추가 관리자 지정은 해당 교회의 현재 유효 관리자 누구나 취소할 수 있고 지정 대상 본인은 거절할 수 있다. 취소·거절 이력은 보존하고 해당 지정으로 수락할 수 없다. 수락과 취소·거절이 경합하면 먼저 유효하게 확정된 처리만 인정하고 최신 상태를 안내한다. 이미 수락해 활성화된 관리자 권한은 별도 역할 해제 절차로 처리한다. 근거: [COS-JOIN-014](../../decisions/DESIGN_DECISIONS.md#cos-join-014). 추가 관리자 지정은 서버 지정 시각부터 7일(168시간) 동안 수락할 수 있고 기한 도달 시 수락을 차단한다. 만료 이력은 보존하고 해당 교회의 현재 유효 관리자가 새로 지정해야 한다. 만료 지정은 후임 유효 관리자로 계산하지 않으며 알림 재전송으로 기한을 연장하지 않는다. 최초 관리자 지정 수락 기한은 COS-JOIN-032를 따르며 교회 운영 권한 확인 자체의 유효기간은 별도 미결이다. 근거: [COS-JOIN-031](../../decisions/DESIGN_DECISIONS.md#cos-join-031). 해당 교회의 현재 유효 관리자는 본인 또는 다른 관리자의 관리자 역할을 별도 절차로 해제할 수 있다. 서버는 확정 시 현재 권한과 다른 유효 관리자가 남는지 검증한다. 역할 해제 이력을 남기고 이후 관리자 업무를 차단한다. 역할 해제만으로 교회 소속을 정지·탈퇴시키지 않는다. 근거: [COS-JOIN-015](../../decisions/DESIGN_DECISIONS.md#cos-join-015). 소속 정지 해제·탈퇴 후 재가입만으로 이전 관리자 권한을 자동 복원하지 않는다. 해당 교회의 현재 유효 관리자가 다시 지정하고 본인이 앱에서 수락해야 활성화된다. 소속 상실 및 이전 지정·해제 이력은 보존한다. 근거: [COS-JOIN-016](../../decisions/DESIGN_DECISIONS.md#cos-join-016). 해당 교회 관리자가 소속 정지를 해제하면 기존 소속을 유효 상태로 회복하고 일반 교인 권한을 별도 가입 요청·재승인 없이 다시 사용할 수 있게 한다. 관리자·가입 승인 담당자 권한은 자동 복원하지 않고 기존 재지정 원칙을 적용한다. 다른 추가 역할과 전문 제품 권한의 복원은 이 결정에 포함하지 않는다. 근거: [COS-JOIN-017](../../decisions/DESIGN_DECISIONS.md#cos-join-017). 탈퇴한 본인은 새 가입 요청으로 같은 교회에 재가입을 신청할 수 있다. 과거 소속·탈퇴·심사 이력과 정본 ID를 보존하며 담당자 승인 전에는 교인 권한을 부여하지 않는다. 승인 시 일반 교인 권한만 부여하고 관리자·가입 승인 담당자 권한은 자동 복원하지 않는다. 소속 레코드의 재사용·추가 방식은 후속 계약으로 정한다. 근거: [COS-JOIN-018](../../decisions/DESIGN_DECISIONS.md#cos-join-018). 유효 소속 교인은 본인이 앱에서 확인하면 관리자 승인 없이 교회 탈퇴를 확정한다. 해당 교회 권한을 차단하고 이력을 보존하며 전문 제품의 개인 계정·기록은 삭제하지 않는다. 마지막 유효 관리자는 COS-JOIN-011의 후임 확보 조건을 충족해야 한다. 정지 중 탈퇴와 재가입 제한은 COS-JOIN-020을 따른다. 근거: [COS-JOIN-019](../../decisions/DESIGN_DECISIONS.md#cos-join-019). 정지 중에도 본인 확인 후 관리자 승인 없이 교회 탈퇴를 허용한다. 소속 종료와 별개로 해당 교회의 미해제 정지에 따른 재가입 제한은 유지한다. 해당 교회 관리자가 제한을 해제한 뒤 새 가입 요청·승인을 거쳐야 하며 탈퇴한 소속이나 특수 권한을 자동 복원하지 않는다. 근거: [COS-JOIN-020](../../decisions/DESIGN_DECISIONS.md#cos-join-020).

## 5. 대표 업무의 데이터·상태·계약

### 5.1 가입과 교회 전환

현재 개설 심사는 COS-CHURCH-005의 기본 서류 확인을 우선 적용한다. 플랫폼이 검토·채택하고 버전 관리하는 이용 허용 교단 목록을 운영한다. 등재 교회도 발급 기관·실제 소속·목회자 재직/자격·대표 권한과 공통 이용 기준을 사람이 확인한다. 미등재 교회도 추가 확인·예외 심사를 신청할 수 있으며 미등재만을 이유로 즉시 거절하지 않는다. 독립/신생/해외 별도 경로에도 확인 면제·자동 승인을 적용하지 않는다. 예외 접수는 승인 보장이 아니고 개별 승인이 교단 목록의 자동 추가를 뜻하지 않는다. 근거: COS-CHURCH-006. 허용 교단 목록은 플랫폼이 지정한 신학 검토 책임자가 근거를 검토해 추가·변경·제외안을 제안하고 별도의 서비스 정책 책임자가 근거·영향·적용 시점·목록 버전을 확인해 최종 채택한다. 두 책임자는 다른 사람으로 두며 개별 개설 심사자는 목록을 임의 변경할 수 없다. 목록 변경과 기존 이용 교회의 권한 변경은 구분한다. 근거: COS-CHURCH-007. 교단·노회 소속증명서를 발급받을 수 없는 독립교회는 교회 설립·운영 근거(정관 또는 이에 준하는 문서)와 신청 목회자의 안수·자격 확인 근거로 대체 제출한다. 교회 고유번호증과 재직·자격·대표 권한 확인은 유지하되 재직증명서 등 추가 자료는 미확인 항목에만 요청한다(COS-CHURCH-040). 발급 기관·실제 관계·자격 인정 기준을 사람이 확인하고 문서 제출만으로 승인하지 않는다. 특정 기관·문서의 법적 효력이나 목회자 자격을 이번 정책만으로 인정하지 않는다. 근거: COS-CHURCH-008. KAICAM이 발급한 해당 교회의 현재 소속을 확인할 수 있는 자료가 있으면 교회 소속증명서의 대응 근거로 심사한다. 목회자 개인 안수·회원 자격만으로 교회 소속을 갈음하지 않는다. 고유번호증·재직·목회자 자격·대표 권한은 각각 확인하고 기관 소속 근거가 부족하면 독립교회 대체 자료로 보완한다. 실제 발급 문서 종류·양식·발급 가능성과 개별 교회 소속은 추가 확인해야 한다. 근거: COS-CHURCH-023. 확인된 교회 대표자 본인뿐 아니라 현재 대표자로부터 명시적인 개설·관리 위임을 받은 목회자도 개설을 신청할 수 있다. 직접 대표자는 인증된 신청자 본인과 자료의 현재 대표 관계를 대조하고 위임 신청은 위임자의 현재 권한과 위임 근거를 확인한다. 재직증명서·담임목사 직함·이름 일치만으로 대표 권한이나 본인 확인을 자동 인정하거나 계정을 병합하지 않는다. 자료가 충돌하면 보완·분쟁 대기 원칙을 적용한다. 근거: COS-CHURCH-024. 공통 신학 기준 초안은 성경의 신앙 기준으로서 권위, 삼위일체, 예수 그리스도의 참 하나님 되심과 참 인간 되심, 십자가와 부활, 그리스도를 통한 은혜의 구원 다섯 항목을 출발점으로 삼는다. 세례 방식·교회 정치·은사 이해·예전의 교단별 차이 자체는 일률적 거절 사유로 삼지 않는다. CT-01~06 문구는 COS-CHURCH-029/030의 사용자 검토 초안으로 합의했으며 해석 범위·판단 근거·상충 처리·실제 운영 채택은 후속 검토한다. 근거: COS-CHURCH-025. 성령의 사역을 여섯 번째 항목으로 추가한다. 문구: 우리는 성령께서 우리 안에 거하시며, 진리를 깨닫게 하시고, 거룩한 삶과 복음의 증언을 위해 우리를 인도하시고 능력을 주심을 믿습니다. 특정 은사의 형태나 특정 체험을 모든 신청자의 필수 조건으로 삼지 않는다. CT-06의 검토 초안 합의이며 CT-01~05 문구의 일괄 승인이나 실제 운영 채택을 뜻하지 않는다. 근거: COS-CHURCH-030. 개설 신청 목회자에게 최종 채택한 공통 기준 원문·적용 버전을 안내하고 별도 명시 동의를 받는다. 동의 버전·시각·인증된 신청자 참조를 최소 기록하되 체크만으로 승인하지 않는다. 신학 검토자가 제출 자료·확인 근거와 기준 부합 여부를 사람 검토한다. 미동의는 신청 미완료·안내로 처리하고 그 사실만으로 이단·부적합 판정을 생성하지 않는다. 일반 교인의 가입 동의로 확대하지 않는다. 근거: COS-CHURCH-026. 신청 목회자 개인의 기준 동의와 신청 교회가 같은 기준을 고백한다는 대표·위임 권한에 따른 확인을 별도 항목으로 받는다. 개인 동의만으로 교회의 고백을 검증 완료로 보지 않고 지정 신학 검토자가 교회 공식 신앙고백·정관·소속 교단 자료 등 확인 가능한 근거를 검토한다. 교회 자료가 없거나 선언 주체·권한이 불명확하면 추가 확인 대기로 두고 진술·체크만으로 승인하지 않는다. 교인 개인의 동의나 기도·일기 기록은 요구하지 않는다. 근거: COS-CHURCH-031. 이용 중 교회의 소속 교단·대표·신청 목회자 변경이나 서류 허위 의심 등 승인 근거의 실질적 변화는 사람이 재검토한다. 기준·목록 변경만으로 자동 이용 중단하지 않고 변경 내용·적용 범위·의견/보완 기회를 안내하는 별도 절차로 다룬다. 단순 신고·AI 결과만으로 정지·자료 공개·관리자 교체하지 않는다. 실제 서비스 제한은 사유·범위·권한·이의신청을 별도 확정한 후 적용한다. 근거: COS-CHURCH-032. 플랫폼의 별도 심사 인사·권한 관리 책임자가 사실 확인 담당자·최종 심사 책임자를 지정·해제하고 신학 검토자는 신학 책임자의 자격 검토·추천을 받아 지정한다. 신청자·대상 교회 관리자는 심사자를 지정하거나 자기 건을 승인할 수 없다. 지정권만으로 원문 열람·자기 권한 확대를 허용하지 않고 지정·해제 이력과 현재 배정·권한 검증을 남긴다. 근거: COS-CHURCH-033. 이용 중 서비스 제한은 사실 확인·신학 검토 및 교회의 의견·보완 자료를 바탕으로 개설 심사 책임자가 필요성과 최소 범위를 제안하고 다른 사람인 서비스 정책 책임자가 최종 결정한다. 사유·범위·적용 시점·재검토/이의신청 경로를 안내하고 결정 이력을 남긴다. 단순 신고·AI 결과로 자동 제한하지 않으며 제한을 원문 공개·관리자 교체·개인 제품 기록 삭제 권한으로 해석하지 않는다. 근거: COS-CHURCH-034. 서비스 제한은 검증된 사유에 필요한 기능만 단계적으로 적용한다. 초대·신규 가입 승인·새 게시 등 확산/변경 기능과 기존 자료 열람·일상 업무 제한을 구분한다. 재검토 개시만으로 제한하지 않고 사람의 결정이 필요하며 더 넓은 제한은 필요성·영향을 별도로 기록·승인한다. 삭제·외부 공개·관리자 자동 교체·개인 제품 계정/기록 변경은 포함하지 않는다. 기능별 조합과 최소 이의신청 접근 경로는 후속 계약으로 명시한다. 근거: COS-CHURCH-035. 심사 원문은 현재 배정·권한을 서버가 검증하는 지정 심사 화면에서만 열람하고 다운로드·외부 공유·이메일 첨부·오프라인 저장은 기본 제공하지 않는다. 배정·권한 해제 후 새 열람을 거부하고 열린 화면도 다음 상태 검증 시 닫으며 임시 표시 데이터를 제거한다. 기존 열람 경로의 회수·잔여 유효시간은 후속 계약으로 검증한다. 실제 화면 촬영·외부 복제를 기술적으로 완전히 회수한다고 보장하지 않는다. 근거: COS-CHURCH-027. 공통 신학 기준은 지정 신학 검토 책임자가 구체 문구·해석 범위·판단 근거를 제안하고 다른 사람인 서비스 정책 책임자가 적용 범위·시점·버전을 확인해 최종 채택한다. 개별 심사자는 기준을 임의 추가·변경할 수 없다. 실제 문구는 별도 초안 검토·확정과 채택 이력을 거치며 책임 구조 확정만으로 배포하지 않는다. 근거: COS-CHURCH-028. 신생교회가 기본 서류를 아직 발급받지 못했더라도 미발급 서류별 확인 목적을 충족하는 대체 근거를 사람이 검증할 수 있으면 예외 심사로 개설 승인을 검토한다. 교단 소속 신생교회는 설립·파송 확인 등으로 실제 관계를 확인하고 독립 신생교회는 설립·운영 근거와 목회자 안수·자격 근거를 검토한다. 등록 정보·재직·대표 권한도 별도로 확인하며 부족하면 보완 대기한다. 구체 인정 자료는 미결이며 없는 고유번호를 만들어 입력하지 않는다. 근거: COS-CHURCH-009. 해외교회는 국내 서류 명칭을 일률 요구하지 않고 소속·등록·목회자 재직/자격·대표 권한의 확인 목적을 충족하는 현지 대응 자료를 지정 심사자가 검토한다. 원문을 제출받고 발급 기관·실제 관계를 확인하며 필요 시 독립 확인한 공식 연락 경로로 보완한다. 심사자가 언어를 검토하기 어려우면 필요한 번역을 요청하되 번역문만으로 진위를 확정하지 않는다. 모든 건에 공증·인증을 요구하지 않고 필요한 경우 추가 인증을 요청한다. 확인이 어려우면 추가 확인 대기로 남긴다. 국가별 인정 자료·추가 인증 요건은 후속 확정한다. 근거: COS-CHURCH-010. 신청자는 적용 기준·결정 사유를 안내받고 이의신청 또는 보완 근거를 제출할 수 있다. 해당 건의 최초 신학 검토자·최종 결정자는 재검토의 신학 판단과 최종 결정에서 제외하고 다른 신학 검토자와 다른 최종 책임자가 재검토한다. 재검토 신학 검토자와 최종 결정자도 서로 다른 사람이다. 인력이 없으면 동일인이 대신 확정하지 않고 재검토 대기를 안내한다. 최초 담당자는 기존 자료·경과 설명만 제공할 수 있다. 근거: COS-CHURCH-004. 개설 심사는 접수 시 신청자에게 안내한 공통 신학 기준·허용 교단 목록 버전을 고정하고 최초 결정과 그 결정의 이의신청 재검토에 적용한다. 신청자가 새 기준 심사를 원하면 변경 영향을 안내한 뒤 명시적으로 요청할 수 있게 한다. 묵시적 버전 전환·자동 거절·기존 운영 교회 권한 자동 변경은 하지 않는다. 허위 자료·대표권 분쟁 등 사실관계 재확인은 버전 고정과 별개로 유지한다. 근거: COS-CHURCH-011. 제출 서류 원문과 최소 심사 결과 이력을 분리해 보관한다. 원문은 심사·이의신청에 필요한 기간만 보관하고 정해진 종료 시점에 삭제한다. 결과 이력에는 적용 기준 버전·확인 항목별 결과·심사자/결정자 참조·시각·결정 상태 등 최소 정보만 남기며 원문 이미지나 불필요한 개인정보를 복제하지 않는다. 각각의 보유기간·종료 기준·삭제 예외·백업 처리·접근 권한은 후속 확정한다. 근거: COS-CHURCH-012. 개설 거절·보류의 이의신청은 적용 기준·사유·신청 경로가 포함된 결과가 신청자 앱에서 열람 가능하도록 정상 통지된 시점부터 30일(720시간) 이내 접수한다. 통지 실패 시 기산하지 않으며 복구 후 정상 통지 시점을 기록한다. 기한 내 접수한 재검토는 기간이 지나도 계속 진행한다. 보완 요청에 대한 답변은 이의신청과 구분한다. 근거: COS-CHURCH-013. 개설 거절의 정상 통지 후 30일 이의신청 기간이 끝나고 접수된 재검토·진행 중 보완·별도 승인된 보관 예외가 없으면 기간 종료 후 7일(168시간) 이내 운영 저장소의 서류 원문을 삭제한다. 서버는 삭제 실행 시 현재 상태와 진행 중 절차를 재검증한다. 삭제 여부·시각은 최소 이력으로 남기고 원문을 결과 이력에 복제하지 않는다. 백업 만료·복원 시 재삭제는 별도 정책이며 운영본 삭제를 전체 삭제 완료로 표기하지 않는다. 근거: COS-CHURCH-014. 개설 승인 결과가 신청자 앱에서 열람 가능하도록 정상 통지된 시점을 승인 건 서류 원문 보유기간의 기산점으로 둔다. 최초 관리자 수락·활성화 지연이나 지정 만료·재지정만으로 같은 자료의 보유기간을 자동 연장하지 않는다. 실제 재검토·새 사실 확인에 필요한 예외는 별도 승인·종료 기준으로 검토한다. 승인 건은 COS-CHURCH-016의 기간을 따른다. 근거: COS-CHURCH-015. 승인 건 서류 원문은 정상 승인 통지부터 30일(720시간) 보관하고 종료 후 7일(168시간) 이내 운영 저장소에서 삭제한다. 삭제 직전에 진행 중 재검토·확인 절차·별도 승인된 보관 예외가 없는지 서버가 재검증한다. 최소 결과와 삭제 여부·시각은 별도 보관하고 원문을 복제하지 않는다. 백업 만료·복원 재삭제와 결과 이력 보유기간은 별도 확정한다. 근거: COS-CHURCH-016. 예외 보관은 해당 건 지정 심사자가 확인 목적·대상 자료·최소 범위·종료 시각을 명시해 요청하고 다른 사람인 플랫폼 서비스 정책 책임자가 검토·승인한다. 승인·해제 이력을 남기며 무기한·자동 연장을 금지한다. 목적 종료 또는 승인 기한 도달 시 해제하고 일반 삭제 절차로 복귀한다. 연장은 근거와 새 종료 시각으로 재승인받으며 심사자 재지정·인력 부족만으로 자동 연장하지 않는다. 근거: COS-CHURCH-017. 백업은 일상 심사에 사용하지 않고 승인된 복구 담당자만 복구 목적으로 접근한다. 운영본 삭제 상태를 원문 없는 최소 기록으로 유지하고 복원 시 서비스 공개 전에 최신 삭제 상태를 재적용해 삭제 원문을 다시 제거한다. 백업본은 확정한 순환 보유 상한에서 만료시키고 운영본 삭제·백업 잔존·백업 만료를 구분한다. 백업 최대 잔존은 COS-CHURCH-019, 복구 담당 권한은 후속 확정을 따른다. 근거: COS-CHURCH-018. 운영본 삭제 시점부터 최대 30일(720시간) 이내 해당 원문을 포함하는 모든 백업·복제 백업의 잔존을 종료한다. 새 백업 생성·복제·복원으로 상한을 재설정하지 않는다. 복원 후 공개 전 최신 삭제 상태 재적용을 유지하고 실제 만료 확인 전 전체 삭제 완료로 표기하지 않는다. 실제 기술·제공자의 지원 여부는 후속 검증한다. 근거: COS-CHURCH-019. 유효 개설 승인의 최소 근거는 해당 교회 서비스 이용 중 유지하고 이용 종료 후 1년 보관한 뒤 삭제한다. 거절·신청 철회 등 미개설 종결 건은 최종 처리 후 1년 보관한 뒤 삭제한다. 진행 중 재검토는 종결로 보지 않고 과거 기준·결정 이력을 덮어쓰지 않으며 원문 이미지는 포함하지 않는다. 구체 종결 시각·삭제 실행 기한·분쟁 예외·백업 처리는 후속 확정한다. 근거: COS-CHURCH-020. 교단·노회 발급 교회 소속증명서(소속)와 교회 고유번호증(등록 정보)을 기본으로 받고 재직·자격·대표/위임 권한 중 미확인 항목에만 필요한 추가 자료를 요청한다(COS-CHURCH-040). 운영팀이 이용 허용 교단 기준·발급 기관·실제 소속을 검증하고 필요 시 가입 결정은 유지한다. 상세: [개설 심사](CHURCH_ESTABLISHMENT_REVIEW.md).

교인 가입과 교회 개설 심사는 별개다. 플랫폼 운영팀이 교회 실재성·목회자 자격·대표 권한·서비스 이용 허용 기준을 확인한 뒤 정식 개설·교인 초대를 허용한다. 목회자 계정만으로 관리자 권한을 부여하지 않으며 최초 관리자 본인 수락 원칙은 유지한다. 독립/신생/해외교회 별도 확인 경로와 AI·CHGO 이단 자동 판정 금지를 포함한 [개설 심사 설계](CHURCH_ESTABLISHMENT_REVIEW.md)를 따른다. 공통 신학 기준은 플랫폼이 명시적으로 채택·버전 관리하고 사람이 심사하며 교단 소속·외부 목록만으로 자동 허용·거절하지 않는다(COS-CHURCH-002). 플랫폼 운영 담당자가 교회 실재성·목회자 자격 자료·대표 권한을 확인하고, 플랫폼이 지정한 신학 검토자가 공통 기준에 따른 검토 의견을 기록한다. 별도로 지정한 플랫폼 개설 심사 책임자가 두 검토 결과와 현재 유효성을 확인해 최종 승인·거절·추가 확인을 결정한다. 신학 검토자와 최종 승인자는 서로 다른 사람으로 두며 신청자나 대상 교회 관리자는 자기 개설 심사를 승인할 수 없다. 근거: COS-CHURCH-003. 여섯 신학 문구의 사용자 검토 초안과 재검토 정책은 후속 합의로 정했으며 실제 신학 검토/운영 채택·담당자 자격/선임은 후속 과제다. COS-JOIN-035는 후속 합의로 AGREED이며 가입 결과 정정 COS-JOIN-040~059는 AGREED / DESIGN이며 마지막 관리자 보호의 정정 적용·세부 계약은 OPEN으로 구분한다.

인증 계정의 issuer/subject와 교회 membership ID를 구분한다. 초기 가입 요청은 교회에서 확인할 이름만 필수 입력으로 받고 연락처는 선택 입력으로 둔다. 생년월일·주소·가족 정보·신앙 이력·자유 서술 사유는 초기 신청 항목에서 제외한다. 인증 계정 식별과 대상 교회는 서버가 확인하며 입력한 이름·연락처를 본인 인증이나 계정 자동 병합 근거로 사용하지 않는다. 근거: [COS-JOIN-023](../../decisions/DESIGN_DECISIONS.md#cos-join-023). 가입 승인 담당자는 해당 교회의 대기 요청에 대해 제출 이름·선택 연락처·신청 시각·현재 신청 상태만 열람한다. 인증 제공자 식별자·토큰·다른 교회 정보·전문 제품 개인 기록은 노출하지 않는다. 담당자 권한만으로 전체 교인 명단이나 과거 종료 요청 전체를 조회할 수 없다. 종료 요청의 최소 결과 안내는 COS-JOIN-025를 따르며 별도 과거 이력 열람 권한은 후속 계약에서 구체화한다. 근거: [COS-JOIN-024](../../decisions/DESIGN_DECISIONS.md#cos-join-024). 이미 열어 둔 가입 요청이 종료되면 현재도 해당 교회의 유효 심사 권한이 있는 사람에게 이미 처리됨과 해당 요청의 최신 결과(승인·거절·취소), 처리 시각만 안내한다. 신청자 이름·연락처는 다시 반환하지 않으며 처리자 신원·사유·다른 이력도 노출하지 않는다. 심사 권한·유효 소속을 상실한 경우에는 결과도 반환하지 않고 접근을 거부한다. 근거: [COS-JOIN-025](../../decisions/DESIGN_DECISIONS.md#cos-join-025). 가입 거절 시 미리 정한 사유 항목 하나를 선택하고 신청자 본인에게 해당 사유의 표준 안내와 재신청 경로를 제공한다. 자유 서술 심사 메모는 수집하지 않는다. 사유는 심사 이력의 업무 데이터로 관리하되 일반 로그·알림 미리보기에 상세 사유나 이름·연락처를 넣지 않는다. 다른 담당자에게 제공하는 종료 결과에는 사유를 추가하지 않는다. 초기 사유 항목과 문구는 COS-JOIN-034를 따른다. 근거: [COS-JOIN-033](../../decisions/DESIGN_DECISIONS.md#cos-join-033). 초기 거절 사유는 교인 확인 불가·대상 교회 착오 두 가지로 시작한다. 교인 확인 불가는 “입력하신 정보만으로 교인 여부를 확인하지 못했습니다. 교회에 확인 후 다시 신청해 주세요.”, 대상 교회 착오는 “신청하신 교회를 다시 확인해 주세요.”로 안내한다. 기타·자유 입력은 두지 않고 개인 신앙·성숙도·사생활 평가는 사유로 기록하지 않는다. 정지·재가입 제한·중복 제출·기술 오류는 기존 상태·오류 처리로 구분한다. 근거: [COS-JOIN-034](../../decisions/DESIGN_DECISIONS.md#cos-join-034). 가입 요청의 업무상 전이는 대기→승인/거절/본인 취소로 확정했다(COS-JOIN-001/004/007). PENDING→APPROVED/REJECTED/CANCELLED의 구체 상태 코드·계약 매핑은 구현 전 제안이며 기존 membership 상태를 그대로 대체하지 않는다. 승인 시 소속을 멱등 생성한다. 탈퇴/정지 시 새 요청의 권한을 차단하고 제품별 연결 근거를 철회한다. 한 계정이 여러 교회의 유효 소속을 동시에 가질 수 있으며 각 교회에서 별도 가입 승인을 받는다. 앱에서는 선택한 활성 교회 하나의 권한·데이터로 업무를 수행한다. 역할·정지·재가입 제한은 해당 교회에만 적용하며 한 교회 관리자는 다른 교회의 소속·역할·정지 정보를 관리 권한만으로 조회할 수 없다. 근거: [COS-JOIN-021](../../decisions/DESIGN_DECISIONS.md#cos-join-021). 이미 유효 소속인 교회에 다시 가입을 신청하면 새 요청·소속을 생성하지 않고 이미 가입된 상태와 해당 교회 홈으로 이동하는 경로를 안내한다. 기존 소속·역할은 변경하지 않으며 초대 링크·다른 기기를 통한 제출에도 동일하게 적용한다. 근거: [COS-JOIN-022](../../decisions/DESIGN_DECISIONS.md#cos-join-022). 모든 가입 요청은 초대 링크 여부와 관계없이 담당자 승인이 필요하다. 승인 전 교인 권한을 부여하지 않는다. 가입 대기자는 교회가 공개한 소개·예배 시간·공개 설교만 볼 수 있으며 교인 명단·내부 자료·공동체 기도에는 접근할 수 없다. 승인 시 해당 교회의 일반 교인 권한만 부여하며 관리자 등 추가 역할 부여는 별도 절차로 분리한다. 근거: [COS-JOIN-001](../../decisions/DESIGN_DECISIONS.md#cos-join-001). 해당 교회 관리자가 가입 승인 담당자를 지정·해제하며 직접 가입 심사도 할 수 있다. 가입 승인 담당자의 위임 범위는 가입 요청 조회·승인·거절뿐이며 다른 담당자 지정·해제나 추가 역할 부여 권한은 얻지 않는다. 이 권한은 해당 교회 안에서만 유효하다. 지정·해제와 승인·거절 이력을 남긴다. 담당자 권한 해제 시 서버에서 권한을 재검증하여 이후 심사를 차단하며 진행 중 요청도 재검증한다. 근거: [COS-JOIN-002](../../decisions/DESIGN_DECISIONS.md#cos-join-002). 가입 승인 담당자는 해당 교회에서 가입 승인된 유효 소속 교인만 지정할 수 있다. 대기·거절·탈퇴·정지 상태이거나 다른 교회에만 소속된 사람은 지정할 수 없다. 탈퇴·정지 등으로 유효 소속을 잃으면 서버가 즉시 가입 요청 조회·승인·거절 권한을 차단하며 진행 중 요청도 재검증한다. 재가입·정지 해제 후에도 담당자 권한을 자동 복원하지 않고 관리자가 다시 지정해야 한다. 외부 사무 담당자 위임은 현재 범위에서 제외한다. 근거: [COS-JOIN-003](../../decisions/DESIGN_DECISIONS.md#cos-join-003). 서버에서 먼저 유효하게 확정된 심사 결과 하나만 인정한다. 확정 시점에 심사자의 현재 권한과 요청의 대기 상태를 다시 검증한다. 뒤늦은 승인·거절은 기존 결과를 덮어쓰지 않고 이미 처리되었다는 안내와 최신 결과를 표시한다. 동일한 처리의 통신 재시도는 기존 결과를 반환하며 교회 소속과 심사 이력을 중복 생성하지 않는다. 심사 결과·소속 변경·심사 이력은 하나의 트랜잭션으로 일관되게 반영한다. 확정 결과 정정은 별도 절차이며 이번 결정으로 정정 권한을 부여하지 않는다. 근거: [COS-JOIN-004](../../decisions/DESIGN_DECISIONS.md#cos-join-004). 가입이 거절된 본인은 새 가입 요청으로 재신청할 수 있다. 기존 거절 결과·이력은 보존하며 새 요청도 담당자 승인을 거친다. 재신청은 기존 결과의 정정이나 자동 승인이 아니다. 근거: [COS-JOIN-005](../../decisions/DESIGN_DECISIONS.md#cos-join-005). 동일 계정·교회에 대기 중인 가입 요청은 하나만 유지한다. 중복 제출에는 기존 요청과 최신 상태를 안내하며 초대 링크나 제출 기기가 달라도 새 대기 요청을 생성하지 않는다. 거절 후 본인의 명시적인 새 재신청은 COS-JOIN-005에 따라 구분한다. 근거: [COS-JOIN-006](../../decisions/DESIGN_DECISIONS.md#cos-join-006). 본인은 대기 중인 가입 요청을 직접 취소할 수 있다. 취소 이력은 보존하며 취소된 요청은 심사할 수 없다. 취소와 심사가 경합하면 서버에서 먼저 유효하게 확정된 처리만 인정하고 후속 요청에는 최신 상태를 안내한다. 이미 승인된 소속은 신청 취소로 종료하지 않고 별도 탈퇴 절차로 구분한다. 근거: [COS-JOIN-007](../../decisions/DESIGN_DECISIONS.md#cos-join-007). 본인은 가입 요청 취소 후 새 요청으로 다시 신청할 수 있다. 기존 취소 요청·이력은 보존하고 새 요청도 담당자 심사를 거친다. 이전 요청을 되살리거나 자동 승인하지 않으며 동일 계정·교회의 대기 요청 하나 유지 원칙을 적용한다. 근거: [COS-JOIN-008](../../decisions/DESIGN_DECISIONS.md#cos-join-008). 해당 교회 소속이 정지된 동안에는 같은 교회의 새 가입 요청을 생성하거나 가입 승인으로 정지를 우회할 수 없다. 정지 해제는 가입 심사와 별도 절차로 구분하며 가입 승인 담당자 권한으로 정지 해제 권한을 얻지 않는다. 근거: [COS-JOIN-009](../../decisions/DESIGN_DECISIONS.md#cos-join-009). 해당 교회 관리자만 교인 소속의 정지·해제를 처리하고 정지·해제 이력을 남긴다. 가입 승인 담당자·목회자·리더는 해당 직함이나 가입 심사 권한만으로 소속 정지·해제를 처리할 수 없다. 근거: [COS-JOIN-010](../../decisions/DESIGN_DECISIONS.md#cos-join-010). 마지막 관리자 보호는 COS-JOIN-011로 확정했다. 일반 교인 권한 회복은 COS-JOIN-017로 확정했다. 정지 사유 공개 범위는 별도 미결이다. 이번 정책 확정이 API·앱 구현 완료를 뜻하지 않는다. 교회 전환 시 이전 교회 요청 취소·캐시 제거·역할 재조회·딥링크 재검증을 수행한다. 이름·전화번호만으로 계정을 병합하지 않는다.

### 5.2 공지와 일정

원본: ChurchOS. 현재 서버가 지원하는 공지/행사 생성·상세·수정·게시·취소를 재사용한다. 초안 목록과 관리자 조회 범위는 아직 보완이 필요하다. 현재 일반 목록은 게시 콘텐츠 중심이므로 현재 API만으로 '관리자 초안함' 완성을 선언하지 않는다. 수정은 ETag/If-Match, 쓰기는 멱등 키를 사용한다. 412 충돌 시 최신 버전을 다시 읽고 사용자 편집 내용을 보존해 재적용 여부를 선택한다. 충돌 시 자동 덮어쓰지 않는다.

게시·취소 상태와 물리 삭제를 구분한다. 현재 취소는 종결 상태로 다루므로 '숨김→다시 게시' 요구가 있으면 새 전이 정책을 설계한다. 앱에서 임의로 취소를 삭제·보관과 같은 버튼으로 표시하지 않는다. 구체적인 종결·복제·재등록 동작을 사용자에게 설명한다.

### 5.3 기도

원본: JLPrayer. ChurchOS가 별도 개인 기도 테이블을 만들지 않는다. 개인 화면은 자기 수첩만, 공동기도는 제공자가 확인한 범위만 읽는다. 개인 수첩을 교회에 공유하려면 '공동기도 요청 제출'을 별도 동작으로 분리한다. 공개 요청 상태 SUBMITTED→APPROVED/REJECTED/WITHDRAWN은 제안이며 JLPrayer 실제 상태 모델과 대조해야 한다. 사용자 개인 기록을 교회에서 삭제하거나 관리자 승인만으로 공개할 수 없게 한다. 화면 원문·키보드 입력·실패 요청 본문·알림 미리보기를 운영 로그에 남기지 않는다.

대상 API capability는 personal.read/write, church.read/submit, moderation.review, room.join/leave다. provider audience 토큰과 본인/교회 참조·공유 정책을 JLPrayer가 검사한다. ChurchOS 토큰을 그대로 모든 제공자에 재사용하지 않는다. 화면이 직접 제공자 API에 접근할지 얇은 gateway를 사용할지는 인증 구조에서 확정하되, 어느 경우도 업무/원문 저장을 ChurchOS에 복제하지 않는다.

### 5.4 성경·찬송·통독

원본: JLBible. ChurchOS 뷰어가 판본/본문/찬송/허용 자산을 API로 받는다. 허용된 표시·검색·악보·음원·오프라인 권한을 나눈다. 판본·콘텐츠 버전·회수/만료 정책을 캐시에 적용한다. 단순 성경 열람·마지막 위치를 통독 완료로 만들지 않는다. 통독 진도 갱신은 JLBible 업무 흐름에서만 확정한다. 라이선스 미확보는 서비스 오류나 0건과 구분한다.

### 5.5 설교·요약·나눔지

원본: 교회별 ChurchOS 콘텐츠. YouTube 연결이 기본이고 음성·원고·승인 요약/나눔지를 별도 제공한다. 직접 영상 호스팅은 기본형 밖이다. 설교 metadata와 asset ref, 소스 버전, 처리 권한, 생성 작업, 요약/나눔지 버전, 승인 기록을 분리한다. 실제 DDL은 생성 전이다.

링크만으로는 초안 생성하지 않는다. CHGO는 개념/근거를 연결하고, 전사·자연어 생성 어댑터는 별도다. 교회가 허용한 원고·검토 전사만 입력한다. 생성 초안은 리뷰 전 비공개이며 원고가 바뀌면 STALE을 표시한다. 검토자가 수정·승인하고 게시자가 게시한다. 한 사람이 두 권한을 가질 수 있으나 생성 완료가 자동 승인을 만들지 않는다. 작업 재시도·취소·소스 버전·교회 경계를 검증한다. CHGO 실패 시 수동 요약·기존 승인본을 계속 제공한다.

### 5.6 Academy와 실천

교회 선택/제품 이용권, 개인 수강, ChurchOS 행사 참가, 생명일기/너랑나랑 개인 계정을 각각 구분한다. 연결 참조 후보는 tenantRef, courseRef, cohortRef, lessonRef, churchEventRef, activityRef다. 제공자 소유 ID를 ChurchOS DB 외래키로 강제하거나 이름으로 매칭하지 않는다.

Academy의 교육 안내→너랑나랑 활동→생명일기 실천/나눔으로 이동한다. ChurchOS는 생명일기 작성 여부·회차·원문을 받지 않는다. 코치 권한·공유는 생명일기에서 따로 확인한다. 수강 종료/교회 탈퇴/제품 이용권 해지는 개인 기록 삭제를 뜻하지 않는다.

## 6. 기존 API와 신규 요구의 차이

| 영역 | 확인한 실제 구현 | 다음 설계/개발 |
|---|---|---|
| 인증 | 설정된 OIDC JWT 검증 어댑터 | 실제 제공자·앱 로그인·복구·세션·제품별 토큰 |
| 교회 | 승인 소속의 tenant 조회 | 개설·브랜드·가입 요청·승인·전환 목록 |
| 교인 | 목록·생성 | 역할/소속 정정·승인·정지·범위별 조회 |
| 공지/행사 | 생성·목록·상세·수정·게시·취소 | 관리자 초안함·위임 권한·앱 저장/충돌 UI |
| 출석/공동체/봉사/돌봄 | 설계/DB 기반, 주요 앱 API 미구현 | 상태 전이·행사/담당자 범위·정정·조회 |
| 기도/성경/찬송 | 시연 화면과 소비자 요구 | 제공자 계약·권한·콘텐츠/공유 범위·앱 API 연결 |
| 설교/CHGO 나눔지 | 운영 설계·시연 설명 | 새 API·DDL·비동기 작업·승인·파일/콘텐츠 정책 |
| 관리자 | 시연 화면·TENANT_ADMIN 서버 쓰기 | 실제 역할 조회·세부 위임·모바일 전체 흐름 |

신규 API는 다음 버전에서 OpenAPI·권한·DB·테스트를 함께 추가한다. v2.6의 spec에 경로가 있어도 실제 라우트·업무 구현이 없으면 완료가 아니다. 후속 마이그레이션은 별도 추가하며 기존 V001~V015를 수정하지 않는다. 다른 Git DB 계보에는 적용하지 않는다.

## 8. 정밀화 단계의 산출물과 다음 순서

현재 산출물: 이 문서, FEATURE_MATRIX_V1.5.csv, CONTRACT_BACKLOG_V1.5.md. 기능표는 화면·정본·권한·현재 구현·다음 단계·검증 기준을 연결한다. 계약 백로그는 제공자별 입력/출력·불허 데이터·장애/철회 조건을 정리한다. 모두 문서 검토 전인 설계이며 실제 API 계약 체결을 뜻하지 않는다.

다음 순서는 (1) 교회 기본형 범위 검토 (2) 실제 제공자 정본/소스 대조 (3) 역할/상태/입출력 확정 (4) 화면별 상세 동선·오류 화면 (5) OpenAPI·신규 DDL 검토 (6) 구현 재개다. 에뮬레이터 실행은 구현 검증을 재개할 때 수행한다. 이번 Git 커밋은 설계 브랜치에만 보존하고 자동 main 병합을 하지 않는다.

검토가 필요한 항목은 미결로 유지하며 사용자 의사결정으로 자동 간주하지 않는다. 기능을 추가할 때 정본 소유·권한·상태·화면·실행 증거를 함께 갱신한다.


개설 신청 철회 후속 합의(COS-CHURCH-036): 승인 전 신청자는 앱에서 관리자 승인 없이 개설 신청을 철회할 수 있다. 서버가 현재 상태를 검증해 이후 심사 확정을 차단하고 최소 철회 이력을 남긴다. 별도 승인 보관 예외가 없으면 철회 후 7일(168시간) 이내 원문 운영본을 삭제하고 백업은 운영본 삭제 후 최대 30일 잔존 정책을 적용한다. 승인과 철회 경합은 최초 유효 확정만 인정하고 최신 상태를 안내한다. 이미 승인된 건에 이 철회를 소급 적용해 승인·교인·교회 데이터를 삭제하지 않는다. 상세는 [개설 심사 설계](CHURCH_ESTABLISHMENT_REVIEW.md)를 따른다. 구현·삭제 실행 검증 NOT_RUN.


보완 미응답 처리(COS-CHURCH-037): 보완 항목·응답 기한·미응답 시 종료와 자료 삭제 안내가 정상 통지된 시점부터 30일(720시간) 동안 응답이 없으면 거절이 아닌 미완료 종료로 처리한다. 종료 전 서버가 현재 응답·진행 절차·승인된 연장 여부를 확인한다. 다시 신청할 수 있으며 운영팀·외부 기관의 확인 지연을 신청자 무응답으로 처리하지 않는다. 보관 예외가 없으면 종료 후 7일 이내 원문 운영본을 삭제하고 백업은 운영본 삭제 후 최대 30일 잔존 정책을 적용한다. 상세는 [개설 심사 설계](CHURCH_ESTABLISHMENT_REVIEW.md). 구현·삭제 실행 검증 NOT_RUN.


개설 이의신청 횟수(COS-CHURCH-038): 동일 개설 결정에 대한 일반 이의신청은 정상 통지 후 30일 기한 내 1회 접수한다. 재검토 중 추가 자료는 같은 건의 보완으로 받고 재검토 결과로 해당 일반 절차를 종결한다. 종결 후 새로운 중대한 근거·절차상 오류 주장은 별도 예외 접수로 사람이 검토하며 같은 내용 반복은 기존 건과 연결해 안내한다. 접수만으로 기존 결과를 자동 변경하지 않는다. 상세는 [개설 심사 설계](CHURCH_ESTABLISHMENT_REVIEW.md). 구현·실행 검증 NOT_RUN.


개설 재검토 종결 자료(COS-CHURCH-039): 거절 유지 재검토 결과·사유·새 근거/절차 오류의 예외 경로가 정상 통지되고 진행 중 별도 검토·승인 보관 예외가 없으면 통지 후 7일(168시간) 이내 원문 운영본을 삭제한다. 일반 이의신청 30일을 반복 시작하지 않는다. 삭제 시 현재 상태를 서버가 검증하고 최소 결과·삭제 이력을 남기며 백업은 운영본 삭제 후 최대 30일 잔존 정책을 적용한다. 재검토에서 승인으로 전환되면 승인 정상 통지부터 30일 보관·이후 7일 내 운영본 삭제 정책을 적용한다. 상세는 [개설 심사 설계](CHURCH_ESTABLISHMENT_REVIEW.md). 구현·삭제 실행 검증 NOT_RUN.


교인 가입 대기 정보 수정(COS-JOIN-035 AGREED): 가입 대기 중 본인은 이름·선택 연락처를 수정할 수 있고 기존 요청 하나를 유지한다. 수정 시 요청 버전을 갱신하며 담당자는 최신 정보를 다시 확인해야 한다. 수정 전 버전으로 보낸 승인·거절은 확정하지 않고 최신 정보를 안내한다. 종료된 요청은 이 수정으로 확정 결과나 과거 신청 정보를 변경할 수 없다. 본인/대기 상태와 서버 요청 버전을 확정 시 검증하며 일반 계정 프로필 변경과 해당 요청 수정은 구분한다. 구현·실행 검증 NOT_RUN.


승인 교인 연락처 열람(COS-JOIN-036 AGREED): 승인된 교인의 연락처는 해당 교회 관리자와 명시적으로 연락 업무를 위임받은 담당자만 필요한 범위에서 열람한다. 담당자는 배정된 공동체·업무 대상 범위로 제한하며 목회자·리더 직함만으로 전체 연락처를 열람하지 못한다. 가입 승인 담당자는 기존 대기 요청 열람 범위를 유지하고 승인만으로 전체 교인 연락처 권한을 얻지 않는다. 일반 교인에게 연락처를 자동 공개하지 않는다. 신청 연락처의 승인 후 보유/사용 전환·위임 지정/해제·감사·구체 필드는 후속 확정한다. 서버는 현재 교회·업무 위임·배정 대상·필드 권한을 검증해야 하며 메뉴 표시만으로 권한을 구현했다고 보지 않는다. 구현·실행 검증 NOT_RUN.


신청 연락처 승인 후 사용(COS-JOIN-037 AGREED): 가입 신청 연락처의 심사 연락 목적과 승인 후 교회 운영 연락 목적을 구분해 안내하고 승인 후 사용은 본인의 별도 선택을 받는다. 선택하지 않아도 가입·승인을 막지 않고 운영 연락처로 자동 복사하지 않는다. 선택한 해당 교회에서만 COS-JOIN-036의 역할·업무 범위로 사용하며 다른 교회로 자동 공유하지 않는다. 심사 기록 보유·삭제는 별도 정책으로 정한다. 선택 주체·교회·목적·현재 선택 상태를 서버가 확인하고 메뉴만 숨겨 구현 완료로 보지 않는다. 변경/철회·구체 기간·연락처 종류는 후속 미결이다. 구현·실행 검증 NOT_RUN.


운영 연락 사용 철회(COS-JOIN-038 AGREED): 본인은 앱에서 해당 교회의 연락처 사용 선택을 관리자 확인 없이 철회할 수 있고 서버가 이후 관리자·담당자 열람 및 새 연락 발송을 차단한다. 철회만으로 소속·가입 승인·기본 교회 기능을 잃지 않으며 개인 계정과 다른 교회의 독립 선택은 변경하지 않는다. 해당 교회 운영 연락처 사본은 별도 확정할 기한에 따라 삭제하고 심사 결과·연락처 원문 없는 최소 철회 이력은 구분한다. 이미 발송한 연락·대기 발송/진행 요청·외부 주소록/반출본·삭제 기한은 후속 계약으로 구분한다. 실제 연락처/요청 본문을 철회 감사 기록에 복제하지 않는다. 구현·실행 검증 NOT_RUN.


연락 사용 철회 후 운영 사본 삭제(COS-JOIN-039 AGREED): 교회 연락 사용 철회는 즉시 효력을 적용하고 해당 교회 운영 연락 목적 사본은 철회 후 7일(168시간) 이내 운영 저장소에서 삭제한다. 삭제 직전 현재 선택·별도 승인 보관 예외를 서버가 재검증하고 연락처 원문 없는 삭제 여부·시각을 기록한다. 개인 계정 연락처·다른 교회의 독립 선택·심사 결과/별도 심사 기록을 포괄 삭제하지 않는다. 백업·복원 삭제와 이미 반출한 자료의 처리는 별도 계약으로 정한다. 예외 승인 권한·재선택/새 제출·백업 상한은 후속 미결이다. 실제 삭제·실패 재시도 증거 검증 NOT_RUN.

## 10. 공통 인증·종료 정책 적용

여섯 제품 공통 계정·SSO와 교회/서비스/공통 계정의 권한·종료 범위를 구분한다. [현재 설계 계약](ACCOUNT_MEMBERSHIP_SERVICE_SCOPE_CONTRACT.md)의 범위표·차단/작업 기준·삭제/보관 기한·책임표를 C01/C02의 상세 설계 기준으로 적용한다. 구체 UI/API/DB·제공자 지원은 구현 전 과제다. 계정/교회 관계 종료와 기록의 물리 삭제를 구별하며 교회 관리자에게 개인 공통 계정·타 제품 원문 권한을 부여하지 않는다.

[기존 구현 대조](COMMON_AUTH_SSO_REVIEW.md)에 따라 v2.6 JWT/소속 검증과 실제 6제품 SSO를 구분한다. COS-SSO-001~048은 AGREED / DESIGN이며 COS-JOIN-040~059는 AGREED / DESIGN이다. 관리자 전용 정정·오승인 소속 종료·오거절 재신청·재검토/복구·기한·최소 이력/보관 정책은 [현재 계약](ACCOUNT_MEMBERSHIP_SERVICE_SCOPE_CONTRACT.md#가입-결과-정정-권한)을 따른다. 마지막 관리자 보호의 정정 적용·세부 역할 회수/경합·운영 계약은 OPEN이며 실제 실행·삭제·복원·SSO 검증은 NOT_RUN이다. 실행 검증 NOT_RUN.
