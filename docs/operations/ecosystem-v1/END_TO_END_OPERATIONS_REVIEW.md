## 한 교회의 정상 운영 이야기

가상의 은혜교회가 개설을 신청하고 성도 한 명이 가입하여 제품을 이용한 뒤 교회를 떠나는 경우다. 특정 실재 교회·목회자의 심사 결과를 뜻하지 않는다.

## 발견 사항과 우선순위

문서 검토에서 기존 정책끼리 양립할 수 없는 확정 규칙은 발견하지 않았다. 이는 구현 안전성 보장이 아니다. 아래 표는 후속 COS-JOIN-040~059 합의 이후에도 남은 미결을 구분한다. 설계 합의를 실제 운영 채택이나 검증 완료로 확장하지 않는다.

| 우선순위 | 발견 사항 | 다음 작은 작업 | 상태 |
|---|---|---|---|
| P1 | COS-JOIN-040~059 합의, 마지막 관리자 보호의 정정 적용·세부 계약 미결 | 마지막 관리자·역할 회수·경합·운영 계약 구체화 | 정책 AGREED / 상세 OPEN |
| P1 | 계정 탈퇴 후 교회 관리 공백의 상세 복구 절차 미완성 | 검증 주체·대표 권한·신규 관리자 수락·분쟁 처리 설계 | 기존 후속 과제 |
| P1 | 공통 인증 제공자·식별/토큰·로컬 기록 연결 미검증 | 제공자 선정 전 요구 계약 정리, 제품 정본 대조 | 미확인/구현 전 |
| P1 | 신학 문구와 교단 후보는 아직 운영 채택 전 | 실제 책임자·운영 채택 절차·심사 인력 확인 | 기존 후속 과제 |
| P2 | 담당자 해제·교회 전환·계정 종료의 진행 작업 차단 경로 미구현 | 상태/버전/확정 시점·부분 실패 응답 계약 정리 | 구현 전 |
| P2 | 정책마다 기한은 있으나 제공자 기능·인력 검증 전 | 60초 차단·7일 삭제·백업 최대30일 등 기존 합의의 실행 가능성 검증 | NOT_RUN |

기존 승인된 업무 정책을 변경하지 않고 계약 작성으로 풀 수 있는 항목과 사용자 선택이 필요한 정책을 분리한다. 미결이 있다는 이유로 이미 합의한 SSO·서류 두 종·수동 교인 승인을 다시 질문하지 않는다.

## 실제 구현과의 차이

v2.6에는 JWT 검증·DB 소속/역할 검증·교인 생성·공지/행사 일부 API가 있지만, 교인 생성은 가입 요청/승인 절차의 구현 증거가 아니다. 앱은 시연 기반이며 실제 공통 로그인과 여섯 제품 SSO 연결·교회 개설/서류 심사·역할 위임·통합 종료/삭제는 이 검토에서 실행하지 않았다. 기존 CI 통과를 이 표의 기능 통과로 승계하지 않는다.
