# ChurchOS 전체 운영 기준과 구현 인계 v1.3

2026-10-24. 사용자 합의 방향을 개발 항목으로 구체화한 문서. 상태: 운영 기준 반영, 기능 구현 전. v2.6은 검증된 구현 기준점으로 보존한다. 최신 운영 시나리오와 이 문서가 후속 변경 방향을 설명하며 과거 API·DB가 자동 변경된 것은 아니다.

[앱 전용 운영 기준 v1.4](APP_ONLY_OPERATIONS.md)를 함께 적용한다. 별도 웹·관리자 웹 없이 교인·목회자·관리자가 앱에서 핵심 업무를 완료한다. DEV02에 모바일 관리자·장문 편집·파일 선택을 포함하고, DEV10에서 웹 대시보드 없는 Android/iOS 전체 흐름을 검증한다.

## 1. 이번 합의의 적용

| 영역 | 적용 방향 | 정본/실행 책임 |
|---|---|---|
| 기본 앱 | 교회별 화이트라벨, 교인·공지·일정·공동체·출석·봉사·후속 업무 | ChurchOS |
| 기도 | ChurchOS 안에서 나의 기도수첩·교회 공동기도 사용 | JLPrayer API·데이터·공유 규칙, ChurchOS 화면 |
| 성경·찬송 | ChurchOS 안에서 열람 | JLBible 콘텐츠·판본·권리, ChurchOS 뷰어 |
| 통독 | 전문 제품에서 계획·진도·활동 | JLBible |
| 설교 | 기본 YouTube 연결, 별도 음성·원고·승인 요약·나눔지 | ChurchOS 교회 콘텐츠 |
| 직접 영상 업로드 | 기본형에 포함하지 않고 별도 상담·구축 서비스 | 계약된 영상 호스팅·운영, 교회별 책임 |
| 교육 | 교회가 선택해 도입 | Academy 과정·개설반·수강·수료 |
| 교육 실천 | Academy 참여 교회의 너랑나랑·생명일기 직접 연결, 수료 후 지속 | 각 전문 제품의 세션·기록·공유·코칭 |
| 엔진 | 모든 제품의 개념·관계·허용 근거·해석, 설교 초안 지원 | CHGO 독립 엔진, 전사/생성 어댑터 구분 |

제품 독립성은 사용자에게 모든 기능마다 별도 앱으로 이동하도록 요구하는 뜻이 아니다. 앱 내 화면이 JLPrayer/JLBible API를 사용할 수 있다. 전문 서비스의 핵심 업무 규칙·DB를 ChurchOS에 복제하지 않는다.

## 2. 앱 내 기도 계약 보완

v2.6의 공개 캠페인/최소 상태/앱 열기 계약은 앱 내 기도수첩 편집에 충분하지 않다. 후속 계약에 다음 capability를 분리한다. 실제 제공자 경로는 협의 전이며 아래 기능명이 현재 API가 아니다.

| capability | 화면 | 처리와 권한 |
|---|---|---|
| prayer.personal.read/write | 나의 기도 | 본인 기록 조회·작성·수정·응답·삭제는 JLPrayer가 판정 |
| prayer.church.read | 교회 공동기도 | 교회/기도방 공개범위와 참여 자격을 JLPrayer가 검증 |
| prayer.church.submit | 교회 기도 요청 | 개인 작성과 교회 공개 게시를 구분, 필요한 검토 적용 |
| prayer.room.join/leave | 참여 기도방 | ChurchOS 소속 참조와 JLPrayer 참여·권한을 분리 |

교회 소속·리더 역할 변경은 계약된 이벤트로 전달하고 JLPrayer가 접근 근거를 재검증한다. 개인 기도수첩은 교회 운영자에게 노출하지 않는다. 화면에서 권한에 맞는 원문을 전달받을 수 있지만 교회 운영 DB·공지·통계·이벤트·로그에 복제하지 않는다. Flutter 상태와 화면 종료 시 잔여 콘텐츠, 계정/교회 전환, 기기 캐시를 함께 관리한다. 오프라인 원문 보관은 기본 제공으로 약속하지 않고 제품 보안 정책 확정 후 구현한다. 글 제목·알림 미리보기도 민감할 수 있으므로 동일하게 다룬다.

ChurchOS의 기도회 행사·출석과 JLPrayer의 기도 참여는 별개다. 교회 공개 게시를 승인할 수 있는 운영자라도 개인 기록 열람권을 갖지 않는다. 기도 화면의 임시 장애로 교회 공지·일정 기능이 중단되지 않는다.

## 3. 영상 서비스와 독립 앱

| 서비스 | 기본 제공/상담 범위 | 비용·책임 원칙 |
|---|---|---|
| 기본형 | ChurchOS 화이트라벨·교회 기본 운영·YouTube 설교 연결 | 영상 파일 자체를 복사/호스팅하지 않음 |
| 영상 확장형 | 기존 ChurchOS와 교회 전용 영상 서비스 연결 | 저장·변환·전송·백업과 유지보수 범위 별도 계약 |
| 독립 구축형 | 교회 전용 앱·영상 서비스·추가 기능·운영 지원 | 가능한 교회 명의 계정, 구축비/사용량/지원비/인계 구분 |

직접 영상을 올리고 싶은 교회는 별도 상담으로 접수한다. 전용 앱 필요성을 확인해 영상 확장 또는 독립 구축으로 안내한다. 독립 앱도 영상 호스팅 비용을 없애지 않는다. 교회별 소스 복제와 개별 수정 누적을 피하고 공통 ChurchOS 기반·버전·설정·검증된 확장으로 유지한다. 저장 한도 도달 시 임의 자동 삭제하지 않는다. 관리 화면은 저장량·전송량·보유정책·정리 대상을 구분한다. 구체 한도와 요금은 미정이다.

## 6. 앞으로 함께 결정할 사항과 제안

1. '교회 기본 기능'에 회계·헌금·시설예약까지 바로 포함할지 확대하지 말고 첫 파일럿의 필수 업무를 확인한다. 현재 합의된 기본 범위는 교회·교인·공지·일정·공동체·출석·봉사·후속 업무다.
2. 기도제목을 교회 공동체에 게시할 때 즉시 공개/관리자 검토 정책이 필요하다. 교회별 설정으로 제공하되 개인 수첩과 공개 요청을 분리하는 안을 권한다.
3. 성경·찬송을 기본 메뉴로 넣는 것과 모든 번역본/가사/악보/음원을 제공하는 것은 다르다. 확보한 판본부터 제공한다.
4. 공통 로그인은 제품별 접근권·공유 선택을 생략하지 않는 방식으로 만든다. 처음 연결한 뒤 반복 입력을 줄인다.
5. 개인 기록에 관한 기능은 '누구에게 보이는가'를 화면에서 설명한다. 교회가 앱 비용을 지불해도 개인 원문 열람권은 생기지 않는다.
6. 영상 독립 구축은 기본 앱 출시를 지연시키지 않는 별도 견적·인수·지원 범위로 관리한다.

## 7. 변경 상태

이번 단계에서는 운영 문서·경계표·화면 목록·개발 백로그를 정리했다. Flutter 코드·서버 API·DDL·실제 연동은 새로 구현하지 않았다. v2.6 파일 해시와 기존 마이그레이션은 보존했다. 후속 API·DB는 새 버전으로 함께 변경하고 기존 63개 PASS를 승계하지 않는다. GitHub 원격 main 반영 전이며 로컬 커밋/번들로 전달한다.
