# ChurchOS 중심 생태계 운영 시나리오 v1.4

작성일: 2026-10-24 (한국 시간). 문서 ID: COS-ECO-OPS-001.

## 적용 상태와 권위

사용자의 전체 운영 기획·경계 정리 요청에 따라 작성한 개발 기준 제안이다. ChurchOS, 너랑나랑, 생명일기, JLPrayer, JLBible, JLAcademy, CHGO를 대상으로 한다. JLAcademy의 사용자 표시명은 JesusLife Academy로 대응한다. ChurchOS 최종 브랜드명은 미정이다. 지저스라이프 원은 내부 생태계 명칭으로만 사용한다.

2026-10-24 추가 지시를 반영했다. ChurchOS는 화이트라벨과 교회 기본 기능 및 제품 연결을 담당한다. Academy는 교회별 선택 서비스이며, 참여 교회의 교육 흐름에서 너랑나랑과 생명일기를 직접 연결한다. 특히 생명일기는 교육 이후 실천·나눔·코칭과 연결한다. CHGO는 모든 제품과 관계되는 독립 엔진으로 정의한다. 이 운영 방향은 사용자 지시이며, 아래 구체적인 연동 필드·권한·화면은 아직 구현 전이다.

이미 확정된 독립 개발·API 연결·ChurchOS 중심 앱 원칙은 유지한다. 이 문서에서 새로 제시하는 공유 범위·진도 제한·출시 순서·상품 운영은 운영 기획 제안이며 제공자 승인이나 구현 완료를 뜻하지 않는다. 다른 여섯 제품의 최신 코드와 정책은 아직 대조하지 않았다. 제품 간 계약 상태는 소비자 요구사항이며 실제 연동 검증은 미실행이다.

v2.6 패키지는 검증된 구현 스냅샷으로 그대로 보존한다. 이 문서는 그 후속 운영 설계다. 내용이 다른 항목은 아래 처분표를 통해 후속 계약·화면·스키마에 반영한다. 과거 마이그레이션을 수정하거나 기존 DB에 신규 계보를 섞지 않는다. 원본·감사·Git 이력·과거 검증 증거는 삭제하지 않는다.

확인 근거: v2.6 제품 정의, 통합 경계 계약, integrations.yaml, 화면 27개, OpenAPI, V001~V015, 서버 컨트롤러와 외부 상태 이벤트 스키마. 사용자 제공 실제 PostgreSQL 16.15/API 검사 63개 PASS 및 GitHub Actions 초록색 성공 화면은 v2.6에 대한 근거다. 이번 문서의 신규 운영 시나리오는 실제 실행 검증되지 않았다.

최신 합의와 다음 개발 기준은 [구현 인계 v1.3](IMPLEMENTATION_HANDOFF.md)을 따른다. ChurchOS 안의 기도수첩·교회 공동기도는 JLPrayer API가 정본을 관리하고 ChurchOS가 화면을 제공한다. 직접 영상 업로드 요청은 별도 영상 확장/독립 앱 구축 상담으로 분리한다.

성경·찬송·설교·말씀 나눔지의 최신 경계는 [말씀 운영 설계 v1.2](WORD_AND_SERMONS.md)를 따른다. ChurchOS 내 성경·찬송 열람과 교회 설교 콘텐츠의 CHGO 처리를 추가한다. 개인 기록 금지 규칙은 유지한다.

[앱 전용 운영 기준 v1.4](APP_ONLY_OPERATIONS.md): 교인·목회자·관리자 모두 앱에서 기본 교회 업무를 완료한다. 별도 ChurchOS 웹/PWA/관리자 웹을 만들거나 필수 경로로 두지 않는다. 서버/API는 필요하며 외부 인증·YouTube 관리 등 외부 서비스 작업은 구분한다.

## 1. 운영 목적

교회는 화이트라벨 ChurchOS에서 공지·일정·교인·소그룹·출석·후속 업무를 운영한다. 교회 기본 운영만 도입할 수 있으며 Academy 이용을 필수 조건으로 삼지 않는다. Academy를 선택한 교회에는 과정·개설반·모임과 너랑나랑·생명일기 활동이 연결되는 교육 운영 경로를 제공한다. 개인은 필요에 따라 전문 제품을 사용한다. ChurchOS 도입이 전문 제품 전체 가입이나 정보 공유 의무를 만들지 않는다. 전문 제품은 ChurchOS 없이도 자체 계정과 핵심 기능을 운영한다. 사용자 화면은 한국어를 기본으로 하며 국가·언어 확장은 제품별로 관리한다.

ChurchOS는 Flutter 앱 하나 안에서 역할별 화면을 제공한다. 관리자 웹을 초기 범위에 추가하지 않는다. 다른 제품으로의 앱 이동·설치 필요·복귀는 명확하게 안내한다. 모바일 환경별 안전한 앱 열기 방식은 실기기 검증 후 확정한다. 전문 제품의 핵심 기능을 ChurchOS에 복제하는 방식을 편의상 선택하지 않는다.

성공 기준은 교회 개설, 가입, 첫 공지 확인, 행사 참여, 담당자 업무 완료가 실제로 쉬워지는 것이다. 일기·기도·통독 횟수나 수료율을 개인의 영적 가치·성숙·사역 적합성 점수로 홍보하지 않는다.

## 5. 운영 시나리오

각 시나리오의 합격 조건은 앞으로 수행할 검증 기준이며 현재 PASS 기록이 아니다.

### S01. 교회 개설과 도입

현재 개설 심사는 COS-CHURCH-005의 기본 서류 확인을 우선 적용한다. 플랫폼이 검토·채택하고 버전 관리하는 이용 허용 교단 목록을 운영한다. 등재 교회도 발급 기관·실제 소속·목회자 재직/자격·대표 권한과 공통 이용 기준을 사람이 확인한다. 미등재 교회도 추가 확인·예외 심사를 신청할 수 있으며 미등재만을 이유로 즉시 거절하지 않는다. 독립/신생/해외 별도 경로에도 확인 면제·자동 승인을 적용하지 않는다. 예외 접수는 승인 보장이 아니고 개별 승인이 교단 목록의 자동 추가를 뜻하지 않는다. 근거: COS-CHURCH-006. 허용 교단 목록은 플랫폼이 지정한 신학 검토 책임자가 근거를 검토해 추가·변경·제외안을 제안하고 별도의 서비스 정책 책임자가 근거·영향·적용 시점·목록 버전을 확인해 최종 채택한다. 두 책임자는 다른 사람으로 두며 개별 개설 심사자는 목록을 임의 변경할 수 없다. 목록 변경과 기존 이용 교회의 권한 변경은 구분한다. 근거: COS-CHURCH-007. 교단·노회 소속증명서를 발급받을 수 없는 독립교회는 교회 설립·운영 근거(정관 또는 이에 준하는 문서)와 신청 목회자의 안수·자격 확인 근거로 대체 제출한다. 교회 고유번호증과 재직·자격·대표 권한 확인은 유지하되 재직증명서 등 추가 자료는 미확인 항목에만 요청한다(COS-CHURCH-040). 발급 기관·실제 관계·자격 인정 기준을 사람이 확인하고 문서 제출만으로 승인하지 않는다. 특정 기관·문서의 법적 효력이나 목회자 자격을 이번 정책만으로 인정하지 않는다. 근거: COS-CHURCH-008. 예외·백업 처리·접근 권한은 후속 확정한다. 근거: COS-CHURCH-012. 개설 거절·보류의 이의신청은 적용 기준·사유·신청 경로가 포함된 결과가 신청자 앱에서 열람 가능하도록 정상 통지된 시점부터 30일(720시간) 이내 접수한다. 통지 실패 시 기산하지 않으며 복구 후 정상 통지 시점을 기록한다. 기한 내 접수한 재검토는 기간이 지나도 계속 진행한다. 보완 요청에 대한 답변은 이의신청과 구분한다. 근거: COS-CHURCH-013. 개설 거절의 정상 통지 후 30일 이의신청 기간이 끝나고 접수된 재검토·진행 중 보완·별도 승인된 보관 예외가 없으면 기간 종료 후 7일(168시간) 이내 운영 저장소의 서류 원문을 삭제한다. 서버는 삭제 실행 시 현재 상태와 진행 중 절차를 재검증한다. 삭제 여부·시각은 최소 이력으로 남기고 원문을 결과 이력에 복제하지 않는다. 백업 만료·복원 시 재삭제는 별도 정책이며 운영본 삭제를 전체 삭제 완료로 표기하지 않는다. 근거: COS-CHURCH-014. 개설 승인 결과가 신청자 앱에서 열람 가능하도록 정상 통지된 시점을 승인 건 서류 원문 보유기간의 기산점으로 둔다. 최초 관리자 수락·활성화 지연이나 지정 만료·재지정만으로 같은 자료의 보유기간을 자동 연장하지 않는다. 실제 재검토·새 사실 확인에 필요한 예외는 별도 승인·종료 기준으로 검토한다. 승인 건은 COS-CHURCH-016의 기간을 따른다. 근거: COS-CHURCH-015. 승인 건 서류 원문은 정상 승인 통지부터 30일(720시간) 보관하고 종료 후 7일(168시간) 이내 운영 저장소에서 삭제한다. 삭제 직전에 진행 중 재검토·확인 절차·별도 승인된 보관 예외가 없는지 서버가 재검증한다. 최소 결과와 삭제 여부·시각은 별도 보관하고 원문을 복제하지 않는다. 백업 만료·복원 재삭제와 결과 이력 보유기간은 별도 확정한다. 근거: COS-CHURCH-016. 예외 보관은 해당 건 지정 심사자가 확인 목적·대상 자료·최소 범위·종료 시각을 명시해 요청하고 다른 사람인 플랫폼 서비스 정책 책임자가 검토·승인한다. 승인·해제 이력을 남기며 무기한·자동 연장을 금지한다. 목적 종료 또는 승인 기한 도달 시 해제하고 일반 삭제 절차로 복귀한다. 연장은 근거와 새 종료 시각으로 재승인받으며 심사자 재지정·인력 부족만으로 자동 연장하지 않는다. 근거: COS-CHURCH-017. 백업은 일상 심사에 사용하지 않고 승인된 복구 담당자만 복구 목적으로 접근한다. 운영본 삭제 상태를 원문 없는 최소 기록으로 유지하고 복원 시 서비스 공개 전에 최신 삭제 상태를 재적용해 삭제 원문을 다시 제거한다. 백업본은 확정한 순환 보유 상한에서 만료시키고 운영본 삭제·백업 잔존·백업 만료를 구분한다. 백업 최대 잔존은 COS-CHURCH-019, 복구 담당 권한은 후속 확정을 따른다. 근거: COS-CHURCH-018. 운영본 삭제 시점부터 최대 30일(720시간) 이내 해당 원문을 포함하는 모든 백업·복제 백업의 잔존을 종료한다. 새 백업 생성·복제·복원으로 상한을 재설정하지 않는다. 복원 후 공개 전 최신 삭제 상태 재적용을 유지하고 실제 만료 확인 전 전체 삭제 완료로 표기하지 않는다. 실제 기술·제공자의 지원 여부는 후속 검증한다. 근거: COS-CHURCH-019. 유효 개설 승인의 최소 근거는 해당 교회 서비스 이용 중 유지하고 이용 종료 후 1년 보관한 뒤 삭제한다. 거절·신청 철회 등 미개설 종결 건은 최종 처리 후 1년 보관한 뒤 삭제한다. 진행 중 재검토는 종결로 보지 않고 과거 기준·결정 이력을 덮어쓰지 않으며 원문 이미지는 포함하지 않는다. 구체 종결 시각·삭제 실행 기한·분쟁 예외·백업 처리는 후속 확정한다. 근거: COS-CHURCH-020. 교단·노회 발급 교회 소속증명서(소속)와 교회 고유번호증(등록 정보)을 기본으로 받고 재직·자격·대표/위임 권한 중 미확인 항목에만 필요한 추가 자료를 요청한다(COS-CHURCH-040). 운영팀이 이용 허용 교단 기준·발급 기관·실제 소속을 검증하고 필요 시 독립 확인한 교단·노회 공식 연락처로 보완한다. 서류 완비 자동 승인 금지, 독립/신생/해외 별도 심사, 지정 심사자만 서류 열람, 불필요 개인정보 가림 허용을 적용한다. 보관·삭제 기한은 개설 심사 설계의 후속 합의(COS-CHURCH-012~020/036~039)를 따른다. 과거 연락 확인 중심 기본 절차의 해당 범위는 이 결정으로 대체하며 기존 교인 가입 결정은 유지한다. 상세: [개설 심사](CHURCH_ESTABLISHMENT_REVIEW.md).

교인 가입 승인과 별도로 플랫폼 운영팀의 교회 개설 심사를 거친다. 교회 실재성·목회자 자격·대표 권한·서비스 이용 허용 기준을 확인한 후 정식 개설과 교인 초대를 허용하며 목회자 계정 가입만으로 관리자 권한을 부여하지 않는다. 독립교회·신생교회·해외교회에는 별도 확인 경로를 둔다. AI·CHGO의 이단 자동 판정은 금지한다. 공통 신학 기준은 플랫폼이 명시적으로 채택·버전 관리하고 사람이 심사하며 교단 소속·외부 목록만으로 자동 허용·거절하지 않는다(COS-CHURCH-002). 구체 교리 조항은 아직 미결이다. 플랫폼 운영 담당자가 교회 실재성·목회자 자격 자료·대표 권한을 확인하고, 플랫폼이 지정한 신학 검토자가 공통 기준에 따른 검토 의견을 기록한다. 별도로 지정한 플랫폼 개설 심사 책임자가 두 검토 결과와 현재 유효성을 확인해 최종 승인·거절·추가 확인을 결정한다. 신학 검토자와 최종 승인자는 서로 다른 사람으로 두며 신청자나 대상 교회 관리자는 자기 개설 심사를 승인할 수 없다. 근거: COS-CHURCH-003. 기존 운영 권한 확인·최초 관리자 수락은 이 심사와 연결하며 일반 교인 승인 결정은 유지한다. [개설 심사 설계](CHURCH_ESTABLISHMENT_REVIEW.md)와 COS-CHURCH-001을 따른다.

주체: 교회 도입 담당자. 시작: ChurchOS 도입을 선택한다. 책임: ChurchOS.

1. 계정 인증 후 교회 개설을 요청한다. 교회 식별 정보와 관리 책임자를 등록한다.
2. 서비스 운영 담당자가 교회 개설 신청자의 실제 교회 운영 권한을 확인한 뒤 최초 관리자 지정을 진행한다. 확인 전에는 임시 설정만 허용하고 정식 교회 명의의 공개 초대·가입 심사 등 관리자 업무는 허용하지 않는다. 이 확인만으로 다른 교회나 전문 제품 권한을 부여하지 않는다. 동일 이름의 기존 교회가 있으면 자동 병합하지 않고 소유·운영 권한 확인 절차로 보낸다. 공식 연락 경로의 세부 기준·대체 확인 최소 근거·중복 교회 처리의 구체 기준은 후속 검토한다. 근거: [COS-JOIN-026](../../decisions/DESIGN_DECISIONS.md#cos-join-026). 서비스 운영 담당자는 신청자가 입력한 연락처만 신뢰하지 않고 독립적으로 확인한 교회 공식 연락 경로로 대표자 또는 권한 있는 책임자에게 신청자의 관리 위임 여부를 확인한다. 공식 경로가 없거나 확인이 충돌하면 자동 승인하지 않고 추가 확인 대상으로 남긴다. 모든 신청자에게 신분증·증빙 원본 업로드를 기본 요구하지 않는다. 근거: [COS-JOIN-028](../../decisions/DESIGN_DECISIONS.md#cos-join-028). 공식 연락 경로가 없는 교회도 일괄 거절하지 않고 서비스 운영 담당자의 개별 추가 확인을 허용한다. 신청자에게 필요한 최소 위임 근거를 안내하고 자기 신고 외에 교회 실재 및 대표자·권한 있는 책임자의 위임을 뒷받침할 근거를 검토한다. 근거가 부족하거나 충돌하면 확인 대기를 유지한다. 증빙 유형·수집·보유 범위는 별도 확정 전 임의로 확대하지 않는다. 근거: [COS-JOIN-029](../../decisions/DESIGN_DECISIONS.md#cos-join-029). 교회 개설 확인 중 대표권·운영권에 대한 상충 주장이 확인되면 어느 한쪽에 최초 관리자 권한을 부여하지 않고 신규 개설 확인·최초 관리자 활성화를 보류한다. 이 절차만으로 기존 교회 데이터를 병합하거나 관리자를 교체하거나 기존 운영을 자동 중단하지 않는다. 분쟁 해소 확인 기준과 재개 절차는 후속 검토한다. 근거: [COS-JOIN-030](../../decisions/DESIGN_DECISIONS.md#cos-join-030).
3. 교회명·로고·색·표시명을 설정하고 기본 홈을 미리 본다. 공용 앱/개별 교회 앱은 서로 다른 배포 방식으로 안내한다.
4. 최초 관리자는 서비스 운영 담당자의 교회 운영 권한 확인·지정 후 대상 본인이 앱에서 명시적으로 수락해야 활성화된다. 서버가 확인·지정의 현재 유효성과 인증된 대상 본인을 검증하고 해당 교회 최초 유효 소속·관리자 권한·처리 이력을 함께 일관되게 반영한다. 기존 교회 관리자의 가입 승인을 요구하지 않는 최초 개설 전용 절차이며 일반 가입 승인이나 추가 관리자 지정에는 적용하지 않는다. 수락 전 공개 초대·가입 심사 등 관리자 업무는 불가하다. 근거: [COS-JOIN-027](../../decisions/DESIGN_DECISIONS.md#cos-join-027). 최초 관리자 지정도 서버 지정 시각부터 7일(168시간) 동안만 수락할 수 있다. 기한 도달 시 수락을 차단하고 만료 이력을 보존한다. 만료 후 서비스 운영 담당자가 기존 운영 권한 확인의 현재 유효성을 재검토한 뒤 새로 지정한다. 알림 재전송으로 기한을 연장하지 않으며 수락 전 관리자 업무 차단은 유지한다. 기존 확인 결과를 무조건 폐기하거나 증빙을 일괄 재제출하도록 요구하지 않는다. 근거: [COS-JOIN-032](../../decisions/DESIGN_DECISIONS.md#cos-join-032). 활성화 후 공지·일정·교인 가입 기능부터 운영한다.
5. 전문 제품은 미연결이 기본이다. Academy는 교회가 별도로 선택한다. 미선택 교회의 기본 홈에는 수강·과제·일기 미작성 표시를 만들지 않는다. 교회 연결 설정과 개인의 제품 사용·공유 선택을 별도로 받는다.

실패/대안: 교회 확인 대기 중에는 임시 설정만 허용하고 정식 교회 명의의 공개 초대 발송을 제한한다. 로고 실패는 기본 이미지로 대체한다. 외부 제품 장애는 개설을 막지 않는다.

합격 조건: 최초 지정은 서버 기준 168시간 기한 도달 시 수락이 차단되고 이력이 유지된다. 알림 재전송은 연장하지 않으며 만료 후 운영 담당자의 유효성 재검토·재지정이 필요하다. 만료만으로 증빙 일괄 재제출을 요구하지 않는다. 개설 확인 중 대표권·운영권 주장이 충돌하면 최초 관리자 활성화가 차단되며 기존 교회 데이터 병합·관리자 교체·운영 중단은 자동 발생하지 않는다. 공식 연락 경로가 없다고 일괄 거절하지 않고 추가 확인을 안내한다. 자기 신고 외 교회 실재·위임 근거를 검토하고 근거 부족·충돌 시 대기를 유지하며 미확정 증빙 수집을 임의 확대하지 않는다. 신청자 입력 연락처만으로 운영 권한 확인을 완료하지 않고 독립적으로 확인한 공식 연락 경로로 위임 여부를 확인한다. 공식 경로 부재·확인 충돌 시 추가 확인 대기로 남기며 자동 승인하지 않는다. 모든 신청자에게 신분증·증빙 원본 업로드를 요구하지 않는다. 최초 관리자 지정만으로 권한을 활성화하지 않는다. 본인 수락 시 서버가 확인·지정의 현재 유효성과 인증된 대상 본인을 검증하고 최초 소속·관리 권한·처리 이력을 함께 일관되게 반영한다. 기존 관리자의 가입 승인을 요구하지 않으며 수락 전 관리자 업무는 차단한다. 운영 담당자의 실제 교회 운영 권한 확인 전에는 임시 설정만 허용되고 공개 초대·가입 심사 등 관리자 업무가 차단된다. 확인만으로 타 교회나 전문 제품 권한이 부여되지 않는다. 전문 제품을 모두 끈 상태로 교회 개설→첫 공지 게시가 가능하다. 스플래시·로그인·메뉴에 내부 생태계 명칭이 나오지 않는다. 개별 교회 앱 배포를 즉시 완료로 표시하지 않는다.

### S02. 교회 가입과 첫 화면

주체: 새 교인. 시작: 교회 초대 링크 또는 교회 검색. 책임: ChurchOS.

1. ChurchOS를 열고 계정을 인증한다. 교회 가입 요청과 전문 앱 동의를 한 화면의 필수 동의로 묶지 않는다. 초기 가입 요청은 교회에서 확인할 이름만 필수 입력으로 받고 연락처는 선택 입력으로 둔다. 생년월일·주소·가족 정보·신앙 이력·자유 서술 사유는 초기 신청 항목에서 제외한다. 인증 계정 식별과 대상 교회는 서버가 확인하며 입력한 이름·연락처를 본인 인증이나 계정 자동 병합 근거로 사용하지 않는다. 근거: [COS-JOIN-023](../../decisions/DESIGN_DECISIONS.md#cos-join-023). 가입 승인 담당자는 해당 교회의 대기 요청에 대해 제출 이름·선택 연락처·신청 시각·현재 신청 상태만 열람한다. 인증 제공자 식별자·토큰·다른 교회 정보·전문 제품 개인 기록은 노출하지 않는다. 담당자 권한만으로 전체 교인 명단이나 과거 종료 요청 전체를 조회할 수 없다. 종료 요청의 최소 결과 안내는 COS-JOIN-025를 따르며 별도 과거 이력 열람 권한은 후속 계약에서 구체화한다. 근거: [COS-JOIN-024](../../decisions/DESIGN_DECISIONS.md#cos-join-024). 이미 열어 둔 가입 요청이 종료되면 현재도 해당 교회의 유효 심사 권한이 있는 사람에게 이미 처리됨과 해당 요청의 최신 결과(승인·거절·취소), 처리 시각만 안내한다. 신청자 이름·연락처는 다시 반환하지 않으며 처리자 신원·사유·다른 이력도 노출하지 않는다. 심사 권한·유효 소속을 상실한 경우에는 결과도 반환하지 않고 접근을 거부한다. 근거: [COS-JOIN-025](../../decisions/DESIGN_DECISIONS.md#cos-join-025). 가입 거절 시 미리 정한 사유 항목 하나를 선택하고 신청자 본인에게 해당 사유의 표준 안내와 재신청 경로를 제공한다. 자유 서술 심사 메모는 수집하지 않는다. 사유는 심사 이력의 업무 데이터로 관리하되 일반 로그·알림 미리보기에 상세 사유나 이름·연락처를 넣지 않는다. 다른 담당자에게 제공하는 종료 결과에는 사유를 추가하지 않는다. 초기 사유 항목과 문구는 COS-JOIN-034를 따른다. 근거: [COS-JOIN-033](../../decisions/DESIGN_DECISIONS.md#cos-join-033). 초기 거절 사유는 교인 확인 불가·대상 교회 착오 두 가지로 시작한다. 교인 확인 불가는 “입력하신 정보만으로 교인 여부를 확인하지 못했습니다. 교회에 확인 후 다시 신청해 주세요.”, 대상 교회 착오는 “신청하신 교회를 다시 확인해 주세요.”로 안내한다. 기타·자유 입력은 두지 않고 개인 신앙·성숙도·사생활 평가는 사유로 기록하지 않는다. 정지·재가입 제한·중복 제출·기술 오류는 기존 상태·오류 처리로 구분한다. 근거: [COS-JOIN-034](../../decisions/DESIGN_DECISIONS.md#cos-join-034).
2. 초대의 교회·만료·재사용 정책을 확인하고 가입 요청을 만든다. 동일 계정·교회에 대기 중인 가입 요청은 하나만 유지한다. 중복 제출에는 기존 요청과 최신 상태를 안내하며 초대 링크나 제출 기기가 달라도 새 대기 요청을 생성하지 않는다. 거절 후 본인의 명시적인 새 재신청은 COS-JOIN-005에 따라 구분한다. 근거: [COS-JOIN-006](../../decisions/DESIGN_DECISIONS.md#cos-join-006).
3. 모든 가입 요청은 초대 링크 여부와 관계없이 담당자 승인이 필요하다. 승인 전 교인 권한을 부여하지 않는다. 가입 대기자는 교회가 공개한 소개·예배 시간·공개 설교만 볼 수 있으며 교인 명단·내부 자료·공동체 기도에는 접근할 수 없다. 승인 시 해당 교회의 일반 교인 권한만 부여하며 관리자 등 추가 역할 부여는 별도 절차로 분리한다. 근거: [COS-JOIN-001](../../decisions/DESIGN_DECISIONS.md#cos-join-001). 해당 교회 관리자가 가입 승인 담당자를 지정·해제하며 직접 가입 심사도 할 수 있다. 가입 승인 담당자의 위임 범위는 가입 요청 조회·승인·거절뿐이며 다른 담당자 지정·해제나 추가 역할 부여 권한은 얻지 않는다. 이 권한은 해당 교회 안에서만 유효하다. 지정·해제와 승인·거절 이력을 남긴다. 담당자 권한 해제 시 서버에서 권한을 재검증하여 이후 심사를 차단하며 진행 중 요청도 재검증한다. 근거: [COS-JOIN-002](../../decisions/DESIGN_DECISIONS.md#cos-join-002). 가입 승인 담당자는 해당 교회에서 가입 승인된 유효 소속 교인만 지정할 수 있다. 대기·거절·탈퇴·정지 상태이거나 다른 교회에만 소속된 사람은 지정할 수 없다. 탈퇴·정지 등으로 유효 소속을 잃으면 서버가 즉시 가입 요청 조회·승인·거절 권한을 차단하며 진행 중 요청도 재검증한다. 재가입·정지 해제 후에도 담당자 권한을 자동 복원하지 않고 관리자가 다시 지정해야 한다. 외부 사무 담당자 위임은 현재 범위에서 제외한다. 근거: [COS-JOIN-003](../../decisions/DESIGN_DECISIONS.md#cos-join-003). 서버에서 먼저 유효하게 확정된 심사 결과 하나만 인정한다. 확정 시점에 심사자의 현재 권한과 요청의 대기 상태를 다시 검증한다. 뒤늦은 승인·거절은 기존 결과를 덮어쓰지 않고 이미 처리되었다는 안내와 최신 결과를 표시한다. 동일한 처리의 통신 재시도는 기존 결과를 반환하며 교회 소속과 심사 이력을 중복 생성하지 않는다. 심사 결과·소속 변경·심사 이력은 하나의 트랜잭션으로 일관되게 반영한다. 확정 결과 정정은 별도 절차이며 이번 결정으로 정정 권한을 부여하지 않는다. 근거: [COS-JOIN-004](../../decisions/DESIGN_DECISIONS.md#cos-join-004).
4. 승인되면 해당 교회 홈에서 공지·일정·가입 가능한 공동체를 확인한다.
5. 가입이 거절된 본인은 새 가입 요청으로 재신청할 수 있다. 기존 거절 결과·이력은 보존하며 새 요청도 담당자 승인을 거친다. 재신청은 기존 결과의 정정이나 자동 승인이 아니다. 근거: [COS-JOIN-005](../../decisions/DESIGN_DECISIONS.md#cos-join-005).
6. 본인은 대기 중인 가입 요청을 직접 취소할 수 있다. 취소 이력은 보존하며 취소된 요청은 심사할 수 없다. 취소와 심사가 경합하면 서버에서 먼저 유효하게 확정된 처리만 인정하고 후속 요청에는 최신 상태를 안내한다. 이미 승인된 소속은 신청 취소로 종료하지 않고 별도 탈퇴 절차로 구분한다. 근거: [COS-JOIN-007](../../decisions/DESIGN_DECISIONS.md#cos-join-007).
7. 본인은 가입 요청 취소 후 새 요청으로 다시 신청할 수 있다. 기존 취소 요청·이력은 보존하고 새 요청도 담당자 심사를 거친다. 이전 요청을 되살리거나 자동 승인하지 않으며 동일 계정·교회의 대기 요청 하나 유지 원칙을 적용한다. 근거: [COS-JOIN-008](../../decisions/DESIGN_DECISIONS.md#cos-join-008).
8. 해당 교회 소속이 정지된 동안에는 같은 교회의 새 가입 요청을 생성하거나 가입 승인으로 정지를 우회할 수 없다. 정지 해제는 가입 심사와 별도 절차로 구분하며 가입 승인 담당자 권한으로 정지 해제 권한을 얻지 않는다. 근거: [COS-JOIN-009](../../decisions/DESIGN_DECISIONS.md#cos-join-009).
9. 해당 교회 관리자만 교인 소속의 정지·해제를 처리하고 정지·해제 이력을 남긴다. 가입 승인 담당자·목회자·리더는 해당 직함이나 가입 심사 권한만으로 소속 정지·해제를 처리할 수 없다. 근거: [COS-JOIN-010](../../decisions/DESIGN_DECISIONS.md#cos-join-010).
10. 선택한 전문 제품만 본인에게 연결 안내한다. 기존 개인 계정은 인증된 연결 절차로 확인한다. 이름·전화번호 일치만으로 계정을 합치지 않는다.

합격 조건: 가입 거절에는 사유 항목 하나를 선택하고 신청자 본인에게 표준 안내·재신청 경로를 제공한다. 자유 서술 심사 메모를 수집하지 않고 일반 로그·알림 미리보기에 상세 사유·이름·연락처를 넣지 않는다. 다른 담당자의 종료 결과 응답에는 사유가 없다. 열린 요청이 종료되면 현재 심사 권한 유지 시 이미 처리됨·최신 결과·처리 시각만 반환하고 이름·연락처·처리자·사유·다른 이력은 반환하지 않는다. 권한·유효 소속을 잃으면 결과도 거부한다. 가입 승인 담당자의 대기 요청 조회 응답은 이름·선택 연락처·신청 시각·현재 상태로 제한한다. 인증 제공자 식별자·토큰·다른 교회 정보·전문 제품 개인 기록을 노출하지 않고 전체 교인 명단·과거 종료 요청 전체의 조회는 담당자 권한만으로 허용하지 않는다. 연락처 미입력 상태에서도 이름만으로 가입 요청을 제출할 수 있다. 초기 신청에 생년월일·주소·가족 정보·신앙 이력·자유 서술 사유를 요구하지 않는다. 이름·연락처가 같아도 본인 인증이나 계정 병합으로 처리하지 않는다. 이미 유효 소속인 교회에 링크·기기를 바꾸어 신청해도 새 요청·소속을 만들지 않고 기존 역할을 유지하며 가입 상태와 홈 이동을 안내한다. 여러 교회 소속은 각 교회 별도 승인을 거치고 한 교회 관리자에게 다른 교회의 소속·역할·정지 정보가 노출되지 않는다. 한 교회의 정지·재가입 제한이 다른 교회 권한에 적용되지 않는다. 정지 중 본인 탈퇴도 허용하지만 재가입 제한은 유지하고 새 요청·승인으로 우회할 수 없다. 해당 교회 관리자가 제한을 해제해도 탈퇴한 소속·특수 권한은 자동 복원되지 않고 새 가입 심사를 거친다. 유효 소속 본인은 앱 확인 후 관리자 승인 없이 탈퇴할 수 있다. 타인의 탈퇴 요청은 거부하고 마지막 관리자 보호를 적용한다. 탈퇴 시 해당 교회 권한과 진행 중 요청을 재검증해 차단하며 이력을 보존하고 전문 제품의 개인 계정·기록은 삭제하지 않는다. 탈퇴한 본인의 새 재가입 요청이 가능하고 과거 소속·탈퇴·심사 이력과 정본 ID는 유지된다. 재가입 승인 전에는 교인 권한이 없고 승인 시 일반 교인 권한만 부여한다. 관리자가 정지를 해제하면 기존 소속과 일반 교인 권한이 새 가입 요청·재승인 없이 회복된다. 가입 승인 담당자 권한은 자동 복원하지 않는다. 정지 해제·재가입 후에도 이전 관리자 권한이 자동 복원되지 않고 현재 유효 관리자 재지정·본인 수락 전에는 관리자 업무가 차단된다. 이전 소속 상실·지정·해제 이력은 유지된다. 현재 유효 관리자의 본인·타 관리자 역할 해제 시 현재 권한·교회 경계·마지막 관리자 조건을 서버가 확정 시 검증하고 이력을 남긴다. 이후 관리자 업무를 차단하되 소속 정지·탈퇴는 발생하지 않는다. 동시 해제로 유효 관리자가 없어지지 않는다. 지정자가 아닌 해당 교회 유효 관리자도 수락 전 지정을 취소할 수 있고 대상 본인은 거절할 수 있다. 취소·거절 이력을 보존하고 해당 지정으로 수락을 거부한다. 타 교회 관리자·비관리자의 취소와 타인의 거절은 거부한다. 수락과 취소·거절 경합은 최초 유효 확정만 인정하고 최신 상태를 안내한다. 추가 관리자 지정만으로 관리 권한이 활성화되지 않고 수락 전에는 후임 유효 관리자로 계산하지 않는다. 수락 확정 시 지정 유효성·지정자 현재 권한·대상 현재 유효 소속을 서버에서 재검증한다. 추가 관리자 지정은 현재 유효 관리자만 가능하며 대상은 같은 교회의 유효 소속 교인으로 제한하고 지정 이력을 남긴다. 가입 심사 권한·목회자·리더 직함만으로 지정하거나 대기·거절·탈퇴·정지·다른 교회에만 소속된 사람을 지정하는 요청은 거부한다. 마지막 관리자의 역할 해제·소속 정지·교회 탈퇴는 다른 유효 관리자 없이는 거부하고 동시 변경으로도 유효 관리자 수가 0이 되지 않는다. 해당 교회 관리자만 소속 정지·해제가 가능하고 이력이 남는다. 가입 심사 권한이나 목회자·리더 직함만으로는 정지·해제할 수 없고 타 교회 관리자의 처리도 거부한다. 정지 중 같은 교회의 새 요청 생성을 차단하고 초대 링크·재신청·기존 요청 승인으로 정지를 우회할 수 없다. 가입 승인 담당자 권한만으로 정지 해제를 할 수 없다. 취소 후 새 재신청을 허용하되 취소 요청·이력은 유지하고 새 요청은 승인 전 권한 없이 재심사를 거친다. 취소된 요청이 되살아나지 않으며 재신청 동시 제출에도 대기 요청은 하나다. 본인의 대기 요청 취소와 이력 보존을 확인하고 타인의 취소는 거부한다. 취소된 요청의 심사는 차단한다. 취소/심사 경합은 최초 유효 확정만 인정하고 최신 상태를 안내한다. 승인된 소속은 신청 취소로 종료되지 않는다. 동일 계정·교회의 동시 제출과 다른 링크·기기의 중복 제출에도 대기 요청 하나만 유지하고 기존 요청·최신 상태를 안내한다. 거절 후 본인의 새 재신청이 가능하고 이전 거절 결과·이력은 유지된다. 새 요청도 승인 전 교인 권한이 없고 담당자 심사를 거친다. 동시 승인·거절은 먼저 유효하게 확정된 결과만 남긴다. 확정 시 권한·대기 상태를 재검증하고 후속 상충 처리에는 이미 처리됨과 최신 결과를 표시한다. 같은 처리 재시도는 기존 결과를 반환하고 소속·심사 이력을 중복 생성하지 않는다. 결과·소속 변경·이력 저장 중 하나라도 실패하면 부분 반영되지 않는다. 일반 심사 권한만으로 확정 결과를 정정할 수 없다. COS-JOIN-040에 따라 현재 유효 교회 관리자만 별도 정정 절차를 실행하고 원결정·정정 이력을 보존한다. COS-JOIN-040~059는 AGREED / DESIGN이다. 관리자 전용 정정·오승인 소속 종료·오거절 재신청·재검토/복구·기한·최소 이력/보관 정책은 [현재 계약](ACCOUNT_MEMBERSHIP_SERVICE_SCOPE_CONTRACT.md#가입-결과-정정-권한)을 따른다. 마지막 관리자 보호의 정정 적용·세부 역할 회수/경합·운영 계약은 OPEN이며 실제 실행·삭제·복원·SSO 검증은 NOT_RUN이다. 대기·거절·탈퇴·정지 및 다른 교회만 소속된 사람의 담당자 지정을 거부한다. 유효 소속 상실 시 서버가 심사 권한을 즉시 차단하고 재가입·정지 해제 후에도 관리자 재지정 전에는 차단을 유지한다. 관리자는 직접 가입 심사 및 담당자 지정·해제를 수행할 수 있다. 담당자는 가입 요청 조회·승인·거절만 가능하고 다른 담당자 관리·추가 역할 부여·다른 교회 심사는 차단된다. 지정·해제 및 승인·거절 이력을 확인한다. 권한 해제 후 열린 심사 화면에서 요청해도 서버가 거부하고 진행 중 요청도 재검증한다. 초대 가입도 승인 전 교인 권한이 없고 대기자는 공개 소개·예배 시간·공개 설교만 열람한다. 승인으로 추가 역할을 얻지 않는다. 가입 링크 재전송·중복 제출로 소속이 중복 생성되지 않는다. 거절·만료 상태에서 비공개 자료가 노출되지 않는다. 전문 제품 가입을 거절해도 기본 교회 생활을 사용할 수 있다.

### S03. 일상 공지·일정·출석

주체: 관리자와 교인. 책임: ChurchOS.

1. 관리자가 공지·행사를 초안으로 작성하고 검토 후 게시한다.
2. 교인은 공개범위 안의 게시된 자료만 본다. 행사 참가 신청과 현장 출석은 별개 상태로 다룬다.
3. 행사 운영자가 QR·리더 확인 등 허용 방식으로 출석을 기록한다.
4. 정정 권한·사유·이력을 별도로 관리한다. 대량 등록은 미리보기와 오류 목록을 제공한다.
5. 후속 연락이 필요한 경우 제한된 업무 코드를 가진 돌봄 업무로 배정한다.

합격 조건: 동시 수정 충돌과 중복 제출을 처리한다. 타 교회 명단·출석은 보이지 않는다. 출석 이벤트를 성장 판정으로 변환하지 않는다. 출석·신청·정정 UI는 구현 후 실제 검증한다.

### S04. 새가족 연락·돌봄·봉사

주체: 담당 목회자/리더. 책임: ChurchOS.

1. 권한 범위 안에서 환영 연락·방문·실질 지원 업무를 생성한다.
2. 담당자·기한·업무 코드·상태를 저장하고 담당자가 완료 또는 재배정한다.
3. 상담·기도 원문은 입력받지 않는다. 현장에 필요한 자유 서술 요구는 별도 제품·정책 검토로 보낸다.
4. 봉사는 자원 의사·기술·경험·가능 시간·공동체 필요 등 허용된 근거로 제안한다.
5. 당사자가 수락·거절한다. 거절이 전문 제품 사용·공유 권한에 영향을 주지 않는다.

합격 조건: 일기 작성량·기도 횟수·CHGO 개인 결과를 조회하거나 봉사 배치의 근거로 사용하지 않는다. 담당자 해제 후 업무 접근이 종료된다.

### S05. 너랑나랑 혼자하기·함께하기

주체: 개인 사용자. 시작: ChurchOS 연결 카드 또는 너랑나랑 직접 실행. 정본: 너랑나랑.

1. ChurchOS에서 선택한 경우 본인 요청으로 단회 앱 열기를 수행한다. 직접 실행이면 ChurchOS 소속을 요구하지 않는다.
2. 혼자하기/함께하기, 상대 이름과 실제 참여 계정의 구분, 상대 초대와 수락은 너랑나랑이 처리한다.
3. 문답·은혜 기록·서명·임시저장·복원·이력 관리를 너랑나랑에서 수행한다.
4. 사용자 요청이 있으면 ChurchOS로 복귀한다. 본인용 이어하기 참조만 제한적으로 갱신한다.
5. 교회 모임으로 운영해도 모임 참석과 관계 세션 완료를 분리한다.

실패/대안: 상대 초대 거절·만료·탈퇴는 너랑나랑이 처리한다. 교회 밖 상대도 별도 참여 정책을 따른다. 제품 미설치 시 설치/나중에 선택을 제공하고 ChurchOS로 돌아갈 수 있게 한다.

합격 조건: 목장 가입으로 세션이 자동 생성되지 않는다. 교회 리더가 개인 답변·서명·은혜 기록·진도표를 볼 수 없다. 교회 탈퇴가 개인 세션·기록 소유권을 변경하지 않는다.

### S06. 생명일기 작성·공유·코칭

주체: 개인 작성자. 정본: 생명일기.

1. ChurchOS는 '생명일기 열기'를 제공하되 작성 여부에 따른 뱃지·미작성 경고·연속 작성일을 표시하지 않는다.
2. 7문항·회차·임시저장·완료·복원은 생명일기가 처리한다. 이번 운영 기획으로 기존 문항을 변경하지 않는다.
3. 공유·코칭을 선택하면 생명일기에서 대상·범위·기간·철회 방식을 확인한다. 실제 제품 지원 범위를 대조하기 전 자동 공유를 만들지 않는다.
4. 교회가 모임을 운영하면 ChurchOS에는 일정과 참석만 기록한다.
5. 복귀 시 작성 성공 여부·회차·내용을 ChurchOS에 전송하지 않는다. 앱 이동 결과와 콘텐츠 활동 결과를 구분한다.

합격 조건: ChurchOS 상태 캐시·알림·통계·이벤트에 작성 여부가 남지 않는다. 보안 목적 앱 연결 로그도 활동 진도 추론에 사용하지 않으며 필요 최소 보유기간을 따로 정한다. 목회자 역할만으로 공유 대상이 되지 않는다.

### S07. 교회 기도회와 JLPrayer 캠페인

주체: 교회 행사 담당자·JLPrayer 캠페인 운영자·개인. 정본: 행사=ChurchOS, 기도 활동=JLPrayer.

1. ChurchOS에 기도회 시간·장소·공지·참석을 관리한다.
2. JLPrayer에서 공개 캠페인 또는 권한이 제한된 기도방을 개설한다.
3. ChurchOS에는 게시가 허용된 캠페인 소개·기간·참조만 연결한다. 외부 원문 자동 수집을 하지 않는다.
4. 참여·기도제목·공유·응답 기록·개인 알림의 정본은 JLPrayer가 처리한다. ChurchOS 내 기도 화면에서 API로 작성·열람·응답을 제공한다. 개인 수첩과 교회 공개 요청은 구분한다.
5. 기도회에 출석해도 캠페인 참여·기도 완료가 자동 생성되지 않는다.

합격 조건: 교회 중보팀 역할이 기도방 접근권을 자동 부여하지 않는다. 비공개 기도제목·간증은 ChurchOS 공지나 감사 로그로 복사되지 않는다. 기도방 탈퇴와 교회 팀 탈퇴를 구분한다.

### S08. 공동체 성경통독

주체: 통독 운영자·개인. 정본: 통독=JLBible, 모임=ChurchOS.

1. JLBible에서 계획·본문 범위·진도 정책을 설정한다.
2. ChurchOS에는 통독 모임 일정과 계획 참조를 연결한다.
3. 개인은 JLBible에서 읽기와 완료 처리를 수행한다. ChurchOS 본인 카드에는 허용된 오늘 읽기 참조·이어하기만 표시한다.
4. 본문이 다른 화면에 필요하면 라이선스가 허용한 제공 방식을 사용한다. 전문 제품 토큰을 URL에 실어 전달하지 않는다.
5. 공동체 진행률은 별도 집계·열람 계약이 없으면 관리자에게 제공하지 않는다.

합격 조건: ChurchOS에 별도 진도 원장이 생기지 않는다. 오프라인 읽기는 JLBible이 동기화 충돌을 처리한다. ChurchOS 행사 출석이 읽기 완료로 바뀌지 않는다.

### S09. JesusLife Academy 교육 운영

주체: Academy를 선택한 교회의 교육 담당자·강사·수강자. 정본: 교육 운영·학습=JLAcademy, 교회 현장 운영=ChurchOS.

선행조건: 교회가 Academy 도입을 선택하고 교육 운영자를 정한다. ChurchOS만 도입한 교회에는 이 경로를 요구하지 않는다. 개인의 수강·전문 제품 연결은 별도로 확인한다.

1. Academy에서 과정·차시·강사·수강 조건을 정한다. ChurchOS에서 교회의 교육 행사와 담당자를 정한다.
2. 행사 ID와 강좌/개설반/차시 참조를 API로 연결한다. 단순 제목 일치로 연결하지 않는다.
3. 행사 신청과 수강 등록은 각각 확정한다. Academy 등록 실패 시 '행사 신청 완료 / 수강 등록 미완료'로 구분해 재시도 안내한다.
4. 교실·현장 출석은 ChurchOS, 과제·평가·진도는 Academy에서 관리한다.
5. 출석을 수료 요건으로 사용할 경우 Academy가 허용된 운영 사실을 받고 자체 정책으로 수료를 판정한다. 수정된 출석의 정정 이벤트도 처리한다.
6. 강사는 Academy 권한으로 배정된 강좌만 조회한다. ChurchOS 관리자 역할을 자동 강사 권한으로 쓰지 않는다.

합격 조건: 같은 요청 재시도로 중복 수강·결제가 생기지 않는다. ChurchOS가 수료증을 독자 발급하지 않는다. 관리자용 수강 명단·수료 조회는 별도 목적·권한 계약 전까지 제공하지 않는다. 개인에게는 본인 상태를 제공할 수 있다.

### S10. 지저스라이프 16회 통합 프로그램

주체: Academy 참여 교회의 교육 책임자와 참여자. 교회 일정·출석 운영: ChurchOS. 교육 프로그램 총괄·과정·학습 정본: Academy. 너랑나랑과 생명일기 활동 정본: 각 제품.

1. Academy 과정과 ChurchOS의 16회 모임 일정을 연결한다. 차시와 현장 모임은 변경 가능한 참조로 매핑한다.
2. Academy는 차시별 너랑나랑 연결과 생명일기 실천·나눔 경로를 교육 계획에 직접 배치한다. 기도·성경 활동도 필요한 경우 연결한다. 각 활동의 이용·공유 범위를 별도로 안내하며 Academy 안에 문답·일기 편집기를 복제하지 않는다.
3. ChurchOS는 모임과 담당자 업무를 관리하고, 각 전문 제품은 자기 활동을 관리한다.
4. 프로그램 참가 신청만으로 개인 기록이 리더에게 공유되지 않는다. 필수 교육 요건이 있다면 등록 전에 Academy가 명시하고, 원문 제출 의무와 혼동하지 않는다.
5. 종료 시 ChurchOS는 모임 운영 결과, Academy는 수료 결과를 각각 확정한다. CHGO는 별도 허용 근거와 계약이 있을 때만 해석한다.

합격 조건: '출석 완료 / 학습 완료 / 개인 기록 / 성장 해석'이 서로 다른 상태로 유지된다. 전문 제품 하나가 미준비이면 해당 선택 활동을 비활성화해도 교회 모임 운영은 계속된다.

### S11. 공동체 운영 현황과 CHGO 엔진

주체: 권한 있는 목회자. 운영 통계 정본: ChurchOS. 성장 해석 정본: CHGO.

1. ChurchOS는 출석·행사·후속 업무 현황을 운영 지표로 집계한다.
2. CHGO는 ChurchOS만의 통계 부가 기능이 아니라 모든 제품과 연결되는 독립 엔진이다. 제품마다 개념 매핑·규칙·해석·집계 중 필요한 기능을 계약한다. ChurchOS의 공동체 집계 화면은 이 엔진 활용 중 하나다. ChurchOS가 전문 제품 원문을 모아 CHGO에 중계하지 않는다.
3. CHGO는 제공자별 적법한 권한·제품 정책·목적별 허용 범위에 따라 받은 근거만 해석한다. 입력 제공 범위는 별도 계약 전까지 없음으로 취급한다.
4. ChurchOS에는 허용된 공동체 집계만 전달한다. 집단·기간·표본·coverage·갱신 시각·억제 여부를 함께 표시한다.
5. 10명 미만 또는 차분·반복 질의로 개인 추정 가능성이 있는 결과는 억제한다. 이 기준은 최소 설계 조건이며 익명성 보장이 아니다.

합격 조건: 개인별 드릴다운·순위·성숙 점수·사역 자동 추천이 없다. 미연결·자료 부족·갱신 지연을 0점으로 표현하지 않는다. CHGO 장애 시 ChurchOS 운영 지표는 계속 작동한다.

### S12. 알림과 연결 실패

주체: 각 제품 운영자·사용자. 책임: 원래 사건의 소유 제품.

1. 교회 공지·행사 변경·담당 업무는 ChurchOS, 세션 초대는 너랑나랑, 일기 알림은 생명일기, 기도 알림은 JLPrayer, 읽기 알림은 JLBible, 학습·과제 알림은 Academy가 소유한다.
2. 전달 시스템을 공용화하더라도 알림 정본·수신 설정·발송 권한은 제품별로 분리한다.
3. 발송 중복 키는 source product + event ID + recipient + channel로 정하고 재시도를 중복 발송으로 만들지 않는다. 개인정보 원문은 잠금화면 알림에 넣지 않는다.
4. 교회가 강좌 일정을 바꾸면 일정 알림은 ChurchOS가 맡고, Academy는 강의 자료·과제 변경이 있을 때 자기 알림을 보낸다.
5. 외부 호출 실패는 timeout·재시도·명시적 지연 상태로 처리한다. 본인 카드에 갱신 시각을 표시하고 만료된 상태를 최신 완료처럼 표시하지 않는다.

합격 조건: 한 사건에 두 제품이 같은 알림을 보내지 않는다. 제품 연결 실패가 교인 등록·공지 저장 트랜잭션을 롤백하지 않는다. 계약과 발송 구현 전까지 '설계'로 표시한다.

### S13. 공유 철회·연결 해제

주체: 개인 사용자. 동의 정본: 각 전문 제품.

1. ChurchOS는 연결 현황과 제품별 동의 관리 진입점을 제공한다. 제품의 동의 원장을 복제하지 않는다.
2. 사용자가 상태 공유를 철회하면 해당 제공자가 정책을 갱신하고 ChurchOS는 후속 조회·상태 갱신을 중단한다.
3. 캐시·미사용 handoff를 무효화하고 이미 발급된 권한의 잔여 유효시간·차단 방식을 계약에 명시한다.
4. 공유 철회·제품 연결 해제·교회 탈퇴·제품 계정 삭제를 서로 다른 행동으로 설명한다.
5. 제품의 개인 원문 삭제는 해당 제품에서 처리한다. ChurchOS 연결 해제가 타 제품 원문 삭제를 명령하지 않는다.

합격 조건: 철회 후 새 handoff가 거부되고 앱 재시작·캐시 복원으로 상태가 다시 보이지 않는다. 이전에 전달된 기록과 백업·감사 보유 처리의 한계를 제품별로 설명한다.

### S14. 여러 교회 소속·교회 이동·역할 해제

주체: 개인·교회 관리자. 책임: ChurchOS 소속, 전문 제품의 개인 계정은 각 제품.

1. 한 계정이 여러 교회의 유효 소속을 동시에 가질 수 있으며 각 교회에서 별도 가입 승인을 받는다. 앱에서는 선택한 활성 교회 하나의 권한·데이터로 업무를 수행한다. 역할·정지·재가입 제한은 해당 교회에만 적용하며 한 교회 관리자는 다른 교회의 소속·역할·정지 정보를 관리 권한만으로 조회할 수 없다. 근거: [COS-JOIN-021](../../decisions/DESIGN_DECISIONS.md#cos-join-021). 이미 유효 소속인 교회에 다시 가입을 신청하면 새 요청·소속을 생성하지 않고 이미 가입된 상태와 해당 교회 홈으로 이동하는 경로를 안내한다. 기존 소속·역할은 변경하지 않으며 초대 링크·다른 기기를 통한 제출에도 동일하게 적용한다. 근거: [COS-JOIN-022](../../decisions/DESIGN_DECISIONS.md#cos-join-022). 사용자가 교회를 전환하면 활성 tenant를 바꾸고 교회별 역할·캐시·연결을 다시 검증한다.
2. 다른 유효 관리자가 없는 상태에서는 마지막 관리자의 역할 해제·소속 정지·교회 탈퇴를 확정할 수 없다. 별도 관리자 부여 절차로 후임이 유효 관리자가 된 뒤 처리하며 동시 변경에도 서버가 검증한다. 계정 보안 잠금·계정 삭제·운영 복구 정책은 별도 검토한다. 근거: [COS-JOIN-011](../../decisions/DESIGN_DECISIONS.md#cos-join-011). 교회 개설 이후 추가 관리자는 해당 교회의 현재 유효 관리자가 같은 교회의 유효 소속 교인 중에서 별도 절차로 지정하고 지정 이력을 남긴다. 가입 승인 담당자·목회자·리더는 해당 직함이나 가입 심사 권한만으로 관리자를 지정할 수 없다. 최초 관리자 확인은 별도 미결이다. 근거: [COS-JOIN-012](../../decisions/DESIGN_DECISIONS.md#cos-join-012). 추가 관리자는 지정 대상이 앱에서 명시적으로 수락해야 권한이 활성화된다. 수락 전에는 관리 권한이 없고 마지막 관리자 보호에서 후임 유효 관리자로 계산하지 않는다. 수락 확정 시 지정의 유효성·지정자의 현재 관리자 권한·대상의 현재 유효 소속을 서버에서 다시 검증한다. 근거: [COS-JOIN-013](../../decisions/DESIGN_DECISIONS.md#cos-join-013). 수락 전 추가 관리자 지정은 해당 교회의 현재 유효 관리자 누구나 취소할 수 있고 지정 대상 본인은 거절할 수 있다. 취소·거절 이력은 보존하고 해당 지정으로 수락할 수 없다. 수락과 취소·거절이 경합하면 먼저 유효하게 확정된 처리만 인정하고 최신 상태를 안내한다. 이미 수락해 활성화된 관리자 권한은 별도 역할 해제 절차로 처리한다. 근거: [COS-JOIN-014](../../decisions/DESIGN_DECISIONS.md#cos-join-014). 추가 관리자 지정은 서버 지정 시각부터 7일(168시간) 동안 수락할 수 있고 기한 도달 시 수락을 차단한다. 만료 이력은 보존하고 해당 교회의 현재 유효 관리자가 새로 지정해야 한다. 만료 지정은 후임 유효 관리자로 계산하지 않으며 알림 재전송으로 기한을 연장하지 않는다. 최초 관리자 지정 수락 기한은 COS-JOIN-032를 따르며 교회 운영 권한 확인 자체의 유효기간은 별도 미결이다. 근거: [COS-JOIN-031](../../decisions/DESIGN_DECISIONS.md#cos-join-031). 해당 교회의 현재 유효 관리자는 본인 또는 다른 관리자의 관리자 역할을 별도 절차로 해제할 수 있다. 서버는 확정 시 현재 권한과 다른 유효 관리자가 남는지 검증한다. 역할 해제 이력을 남기고 이후 관리자 업무를 차단한다. 역할 해제만으로 교회 소속을 정지·탈퇴시키지 않는다. 근거: [COS-JOIN-015](../../decisions/DESIGN_DECISIONS.md#cos-join-015). 소속 정지 해제·탈퇴 후 재가입만으로 이전 관리자 권한을 자동 복원하지 않는다. 해당 교회의 현재 유효 관리자가 다시 지정하고 본인이 앱에서 수락해야 활성화된다. 소속 상실 및 이전 지정·해제 이력은 보존한다. 근거: [COS-JOIN-016](../../decisions/DESIGN_DECISIONS.md#cos-join-016). 해당 교회 관리자가 소속 정지를 해제하면 기존 소속을 유효 상태로 회복하고 일반 교인 권한을 별도 가입 요청·재승인 없이 다시 사용할 수 있게 한다. 관리자·가입 승인 담당자 권한은 자동 복원하지 않고 기존 재지정 원칙을 적용한다. 다른 추가 역할과 전문 제품 권한의 복원은 이 결정에 포함하지 않는다. 근거: [COS-JOIN-017](../../decisions/DESIGN_DECISIONS.md#cos-join-017). 탈퇴한 본인은 새 가입 요청으로 같은 교회에 재가입을 신청할 수 있다. 과거 소속·탈퇴·심사 이력과 정본 ID를 보존하며 담당자 승인 전에는 교인 권한을 부여하지 않는다. 승인 시 일반 교인 권한만 부여하고 관리자·가입 승인 담당자 권한은 자동 복원하지 않는다. 소속 레코드의 재사용·추가 방식은 후속 계약으로 정한다. 근거: [COS-JOIN-018](../../decisions/DESIGN_DECISIONS.md#cos-join-018). 유효 소속 교인은 본인이 앱에서 확인하면 관리자 승인 없이 교회 탈퇴를 확정한다. 해당 교회 권한을 차단하고 이력을 보존하며 전문 제품의 개인 계정·기록은 삭제하지 않는다. 마지막 유효 관리자는 COS-JOIN-011의 후임 확보 조건을 충족해야 한다. 정지 중 탈퇴와 재가입 제한은 COS-JOIN-020을 따른다. 근거: [COS-JOIN-019](../../decisions/DESIGN_DECISIONS.md#cos-join-019). 정지 중에도 본인 확인 후 관리자 승인 없이 교회 탈퇴를 허용한다. 소속 종료와 별개로 해당 교회의 미해제 정지에 따른 재가입 제한은 유지한다. 해당 교회 관리자가 제한을 해제한 뒤 새 가입 요청·승인을 거쳐야 하며 탈퇴한 소속이나 특수 권한을 자동 복원하지 않는다. 근거: [COS-JOIN-020](../../decisions/DESIGN_DECISIONS.md#cos-join-020). 허용된 교회 탈퇴 또는 역할 해제 시 해당 교회의 권한을 중단하고 진행 중 요청도 재검증한다.
3. 전문 제품에서 교회 역할을 근거로 부여한 권한은 별도 연결 이벤트로 철회한다. 제품의 개인 사용 권한과 구분한다.
4. 새 교회에 과거 개인 기록·공유·통독·수강 정보를 자동 이관하지 않는다. 교회가 지불한 이용권 만료도 개인 기록의 교회 귀속을 뜻하지 않는다.
5. 교회 운영 기록의 보유·정정과 전문 제품 개인 기록의 보유·삭제는 각각 처리한다.

합격 조건: 이전 교회의 토큰·요청·캐시로 새 교회 데이터를 볼 수 없다. 동일인이 여러 교회에 있다는 이유로 개인정보가 교차 노출되지 않는다.

### S15. 교회 계약·이용권·해지

주체: 교회 계약 담당자·개인·상품 운영자. 상태: 운영 설계 제안, 가격·판매 방식 미확정.

1. ChurchOS 계약과 전문 제품 이용권을 구분해 안내한다. 묶음 상품을 판매해도 각 제품의 이용권 정본·지원 책임을 명시한다.
2. 교회가 구매한 좌석 배정과 개인 계정·기록을 분리한다. 교회 관리자는 이용권 배정에 필요한 정보만 본다.
3. 결제·환불·해지는 하나의 거래 책임 주체를 정한다. 여러 제품이 같은 주문을 각각 청구하지 않는다.
4. 이용권 만료 시 사용 제한·내보내기·보유·삭제 선택을 각 제품 정책으로 설명한다. 자동 원문 삭제를 기본으로 가정하지 않는다.

합격 조건: 계약 해지가 개인 원문을 교회에 넘기지 않는다. 중복 청구·중복 환불을 막는다. 상용화 전 국가별 판매·보유·동의 요구를 별도 확인한다.

### S16. 문의·장애·백업·종료

주체: 사용자·교회 운영자·제품별 지원자.

1. ChurchOS는 교회 운영과 앱 연결 문의를 접수하고, 전문 활동 문의는 담당 제품으로 안내한다.
2. 공유하는 진단 정보는 제품·오류 코드·시간·연결 추적 ID 등 최소 정보다. 원문·토큰을 붙여 보내지 않는다.
3. 각 제품은 자신의 DB·암호화·백업·복구·장애 공지를 책임진다. 공통 장애라도 데이터 정본을 하나로 합치지 않는다.
4. 복구 후 연결 권한·삭제/철회 상태·이벤트 중복을 재검증한다. 복원으로 철회된 권한이 되살아나면 안 된다.
5. 제품 종료 시 사용자 고지·내보내기·보유 종료·연결 해제는 담당 제품이 실행하고 ChurchOS는 연결을 제거한다.

합격 조건: 지원자가 개인 원문을 요구하지 않고도 기본 진단이 가능하다. 백업 복구와 제품 간 철회 재동기화를 실제 실행한 증거가 있어야 운영 완료로 판단한다.

### S17. Academy 참여 교회의 생명일기 실천·나눔 지속

주체: Academy 참여 교회의 교육 책임자·코치·작성자. 교육 계획: Academy. 개인 기록·공유·코칭: 생명일기. 교회 일정: ChurchOS.

1. 교회가 Academy를 선택하면 담당자가 과정·개설반·강사·참여자를 Academy에서 구성한다. ChurchOS 교인 명단 전체를 자동 수강 등록하지 않는다.
2. 교육 과정에서 너랑나랑 활동을 연결하고 생명일기 실천 시작 시점·안내·나눔 모임을 계획한다. 기존 16회 교육 후 주 1회 생명일기 실천·코칭 및 100회 1단계 운영 취지를 참고하되, 회차·진행 계산 정본은 생명일기에 둔다. 세부 프로그램 규칙은 교재와 기존 제품 정본 대조 후 확정한다.
3. Academy는 활동 목적·사용 안내·제품 연결을 제공한다. 생명일기 작성 화면·문항·회차 계산·원문 보관을 소유하지 않는다. 참여자는 생명일기에서 본인 계정으로 작성한다.
4. 공유·코칭을 원하면 생명일기에서 코치/나눔 상대·범위·기간을 정한다. Academy의 강사 배정이 생명일기 공유 권한을 자동 생성하지 않는다.
5. 나눔 모임 일정·장소·참석은 ChurchOS에서 관리하고 Academy에서는 교육 운영에 필요한 모임 참조만 사용한다. 생명일기 작성 여부·원문·회차는 ChurchOS에 보내지 않는다.
6. Academy에도 개별 작성 상태를 기본 전송하지 않는다. 수료 요건과 연동하려면 작성자가 선택한 확인 방식·최소 확인값·열람자·철회·보유기간을 별도 계약한다. 원문 제출이나 개인 영적 평가는 기본 요건으로 만들지 않는다.
7. 교육 수료 후에도 개인은 생명일기를 계속 사용하고 교회는 나눔 모임을 계속 운영할 수 있다. Academy 수강 종료와 생명일기 계정·기록·공유 기간을 각각 처리한다. 코치 권한도 본래 부여 근거와 기간을 재검증한다.

합격 조건: Academy 참여 교회에서 교육→실천 안내→생명일기→나눔 모임이 이어진다. 같은 계정 연결 요청을 반복해도 기록·수강이 중복되지 않는다. 교육 종료·이용권 해지로 일기가 자동 삭제되지 않는다. 직접적 교육 관계를 근거로 개인 원문이 중앙 수집되지 않는다.

### S18. 모든 제품의 CHGO 엔진 활용

주체: 각 제품 서비스와 CHGO 엔진 운영자. 개념·해석 정본: CHGO. 제품 업무 정본: 각 제품.

1. ChurchOS·너랑나랑·생명일기·JLPrayer·JLBible·Academy가 자신의 기능과 CHGO 개념·관계 ID의 대응을 명시한다. Academy를 사용하지 않는 교회·개인 제품에도 개념 관계가 성립한다.
2. 각 제품은 개념 조회, 허용된 근거 교환, 규칙/해석 결과, 공동체 집계 중 실제 필요한 capability만 선택한다. 개념 참조만 사용하는 제품에 개인 활동 전송을 요구하지 않는다.
3. 입력 필드·목적·권한·결과 열람자·보유·철회·버전을 제품별 계약으로 정한다. 모든 제품이 관련된다는 이유로 모든 데이터를 보내지 않는다. 원문·개인 식별 근거의 허용 여부는 별도 정본 정책과 계약 없이는 없음으로 취급한다.
4. 요청은 해당 제품에서 CHGO API로 직접 전달한다. ChurchOS가 여섯 제품의 필수 중계 서버나 원문 통합 저장소가 되지 않는다. CHGO의 접근 키와 업무 DB 권한도 분리한다.
5. 결과는 요청 제품과 승인된 대상에게만 반환한다. 너랑나랑/생명일기 관련 결과를 ChurchOS나 Academy에 자동 전달하지 않는다. 기존 승인된 정적 교환 계약이 있으면 그 범위를 우선 대조하고 확장하지 않는다.
6. 엔진 규칙·개념 버전·근거 범위·불확실성을 기록한다. 활동 횟수·수료를 성숙으로 자동 등치하지 않는다. 장애 시 해당 제품의 저장·읽기·교회 업무를 계속하고 해석 기능만 지연/불가로 표시한다.

합격 조건: 여섯 제품 모두 개념 매핑표를 갖는다. 실제 실행 연결은 제품별 증거로 판단한다. 허용되지 않은 필드를 거부하고, 결과의 제품 간 누출을 막는다. 엔진 장애·철회·규칙 버전 변경을 시험한다.

### S19. 교회 앱에서 성경과 찬송 사용

ChurchOS 말씀 메뉴에서 성경과 찬송을 열람한다. JLBible이 판본·콘텐츠·권리와 제공 범위를 관리하고, ChurchOS는 API 기반 뷰어를 제공한다. 통독계획·진도는 JLBible에서 처리한다. 열람을 통독 완료로 기록하지 않는다. 상세 절차와 실패·권리·캐시 검증은 [말씀 설계 S19](WORD_AND_SERMONS.md)를 따른다.

### S20. 담임목사 설교 등록과 제공

교회별 권한 있는 편집자·승인자가 설교 링크·원고·음성을 준비된 형식으로 등록하고 검토·게시한다. 링크만으로 내용을 추측해 요약하지 않는다. 음성 전사는 별도 작업으로 검토한다. 설교 정본과 공개범위는 ChurchOS가 소유한다. 상세 절차와 검증은 [말씀 설계 S20](WORD_AND_SERMONS.md)를 따른다.

### S21. CHGO 연계 설교 요약·말씀 나눔지

허용된 설교 원고/검토 전사 버전에 CHGO의 개념·근거 연결을 적용한다. 전사와 생성 어댑터를 별도로 두고 근거 있는 초안을 만든 후 목회자가 수정·승인해 게시한다. 개인 일기·기도·나눔 답변은 입력하지 않는다. 소스 변경·엔진 장애·재시도·승인 전 비노출 검증은 [말씀 설계 S21](WORD_AND_SERMONS.md)를 따른다.

### S22. 직접 영상 업로드 교회의 별도 구축

기본형은 YouTube 연결을 제공한다. 교회가 직접 업로드를 요청하면 영상 보유량·예상 시청·공개범위·브랜드·운영 담당자를 확인한다. 기존 ChurchOS에 전용 영상 서비스를 연결할지 독립 앱을 구축할지 판단한다. 교회 명의 계정·저장/전송 비용·유지보수·데이터 인계·공통 소스 업데이트 책임을 계약한다. 독립 앱이 영상 비용을 없애거나 기본형 교회에 비용을 전가하지 않는다. 상세는 [구현 인계](IMPLEMENTATION_HANDOFF.md)를 따른다. 완료 조건은 실제 업로드/재생/접근권·비용 사용량·장애/인계 검증이다.

### S23. 앱만으로 교회 운영

관리자가 휴대폰 앱에서 교회 개설·브랜드·가입 승인·공지/일정·설교/나눔지·출석·역할 철회까지 완료한다. 교인도 앱에서 열람·기도·말씀·연결을 사용한다. 별도 자체 웹 관리자로 보내지 않는다. 업로드 단절·앱 종료 후 작업 복귀와 Android/iOS 실기기 검증을 수행한다. 상세 합격 조건과 외부 인증 예외는 [앱 전용 운영 기준](APP_ONLY_OPERATIONS.md)을 따른다. 현재 미구현·미실행이다.

## 6. 공통 연결 계약

| 항목 | 필수 규칙 |
|---|---|
| 계정 | issuer+subject 기반 연결, 이름·연락처로 자동 병합 금지, 제품별 audience |
| 소속 | ChurchOS tenant/membership과 제품별 계정/그룹 참조를 구분 |
| 참조 | product+resource kind+opaque ID+version으로 의미 지정, 타 DB 외래키·직접 SQL 금지 |
| Handoff | 단회·최대 10분·사용자/교회/제공자/기능 결속·등록된 복귀 주소·원토큰 로그 금지 |
| 상태 | 제공자×기능별 enum·본인 조회·만료·마지막 갱신·철회 처리. 범용 자유 문자열로 원문 우회 금지 |
| 운영 사실 | 출석 정정·행사 취소 등 원천 정본의 이벤트와 버전 전달, 수신 제품이 자신의 상태를 판정 |
| 이벤트 | schema version·event ID·시간·source·목적·중복 처리·서명·재전송 검증 |
| 장애 | timeout·재시도·격리·마지막 갱신 표시, 핵심 업무와 외부 호출 분리 |
| 로그 | 최소 행위 메타데이터, 개인 원문·비밀·원토큰·답안 금지 |
| 보유 | 상태 캐시·연결 보안 로그·이벤트·감사·백업의 기간과 삭제 책임을 구분해 계약 확정 |

수신이 허용된다는 것은 영구 보관이나 관리자 열람까지 허용한다는 뜻이 아니다. 초기 연동은 너랑나랑/JLPrayer/JLBible/Academy의 본인용 기능만 대상으로 하고, 생명일기/CHGO의 개인 상태는 받지 않는다. 관리자용 전문 활동 집계는 별도 계약 없이는 제공하지 않는다.

## 7. 지식·교육·성장 경계

성경 본문·번역본·인물/장소/연대는 JLBible, 교육과정·차시·학습목표는 Academy, 성장 개념·관계·해석은 CHGO가 소유하는 기준을 제안한다. 같은 '하나님 나라' 용어를 사용해도 본문 참조·교육 설명·성장 개념은 다른 레이어다. 제품별 ID를 유지하고 검토된 대응 관계와 버전을 연결한다. 기존 신학 정본 ID와 저작권 기준을 이 문서로 변경하지 않는다. Theology 등 외부 정본의 정의 권위는 별도 원본 규칙을 따른다.

개설 재검토 종결 자료(COS-CHURCH-039): 거절 유지 재검토 결과·사유·새 근거/절차 오류의 예외 경로가 정상 통지되고 진행 중 별도 검토·승인 보관 예외가 없으면 통지 후 7일(168시간) 이내 원문 운영본을 삭제한다. 일반 이의신청 30일을 반복 시작하지 않는다. 삭제 시 현재 상태를 서버가 검증하고 최소 결과·삭제 이력을 남기며 백업은 운영본 삭제 후 최대 30일 잔존 정책을 적용한다. 재검토에서 승인으로 전환되면 승인 정상 통지부터 30일 보관·이후 7일 내 운영본 삭제 정책을 적용한다. 상세는 [개설 심사 설계](CHURCH_ESTABLISHMENT_REVIEW.md). 구현·삭제 실행 검증 NOT_RUN.


교인 가입 대기 정보 수정(COS-JOIN-035 AGREED): 가입 대기 중 본인은 이름·선택 연락처를 수정할 수 있고 기존 요청 하나를 유지한다. 수정 시 요청 버전을 갱신하며 담당자는 최신 정보를 다시 확인해야 한다. 수정 전 버전으로 보낸 승인·거절은 확정하지 않고 최신 정보를 안내한다. 종료된 요청은 이 수정으로 확정 결과나 과거 신청 정보를 변경할 수 없다. 본인/대기 상태와 서버 요청 버전을 확정 시 검증하며 일반 계정 프로필 변경과 해당 요청 수정은 구분한다. 구현·실행 검증 NOT_RUN.


승인 교인 연락처 열람(COS-JOIN-036 AGREED): 승인된 교인의 연락처는 해당 교회 관리자와 명시적으로 연락 업무를 위임받은 담당자만 필요한 범위에서 열람한다. 담당자는 배정된 공동체·업무 대상 범위로 제한하며 목회자·리더 직함만으로 전체 연락처를 열람하지 못한다. 가입 승인 담당자는 기존 대기 요청 열람 범위를 유지하고 승인만으로 전체 교인 연락처 권한을 얻지 않는다. 일반 교인에게 연락처를 자동 공개하지 않는다. 신청 연락처의 승인 후 보유/사용 전환·위임 지정/해제·감사·구체 필드는 후속 확정한다. 서버는 현재 교회·업무 위임·배정 대상·필드 권한을 검증해야 하며 메뉴 표시만으로 권한을 구현했다고 보지 않는다. 구현·실행 검증 NOT_RUN.


신청 연락처 승인 후 사용(COS-JOIN-037 AGREED): 가입 신청 연락처의 심사 연락 목적과 승인 후 교회 운영 연락 목적을 구분해 안내하고 승인 후 사용은 본인의 별도 선택을 받는다. 선택하지 않아도 가입·승인을 막지 않고 운영 연락처로 자동 복사하지 않는다. 선택한 해당 교회에서만 COS-JOIN-036의 역할·업무 범위로 사용하며 다른 교회로 자동 공유하지 않는다. 심사 기록 보유·삭제는 별도 정책으로 정한다. 선택 주체·교회·목적·현재 선택 상태를 서버가 확인하고 메뉴만 숨겨 구현 완료로 보지 않는다. 변경/철회·구체 기간·연락처 종류는 후속 미결이다. 구현·실행 검증 NOT_RUN.


운영 연락 사용 철회(COS-JOIN-038 AGREED): 본인은 앱에서 해당 교회의 연락처 사용 선택을 관리자 확인 없이 철회할 수 있고 서버가 이후 관리자·담당자 열람 및 새 연락 발송을 차단한다. 철회만으로 소속·가입 승인·기본 교회 기능을 잃지 않으며 개인 계정과 다른 교회의 독립 선택은 변경하지 않는다. 해당 교회 운영 연락처 사본은 별도 확정할 기한에 따라 삭제하고 심사 결과·연락처 원문 없는 최소 철회 이력은 구분한다. 이미 발송한 연락·대기 발송/진행 요청·외부 주소록/반출본·삭제 기한은 후속 계약으로 구분한다. 실제 연락처/요청 본문을 철회 감사 기록에 복제하지 않는다. 구현·실행 검증 NOT_RUN.


연락 사용 철회 후 운영 사본 삭제(COS-JOIN-039 AGREED): 교회 연락 사용 철회는 즉시 효력을 적용하고 해당 교회 운영 연락 목적 사본은 철회 후 7일(168시간) 이내 운영 저장소에서 삭제한다. 삭제 직전 현재 선택·별도 승인 보관 예외를 서버가 재검증하고 연락처 원문 없는 삭제 여부·시각을 기록한다. 개인 계정 연락처·다른 교회의 독립 선택·심사 결과/별도 심사 기록을 포괄 삭제하지 않는다. 백업·복원 삭제와 이미 반출한 자료의 처리는 별도 계약으로 정한다. 예외 승인 권한·재선택/새 제출·백업 상한은 후속 미결이다. 실제 삭제·실패 재시도 증거 검증 NOT_RUN.

## 공통 인증·종료 시나리오의 현재 정책

B11 로그인과 S02 가입·S14 소속/계정 종료·S15 이용권·S16 장애/복구는 [현재 설계 계약](ACCOUNT_MEMBERSHIP_SERVICE_SCOPE_CONTRACT.md)을 함께 적용한다. 초대도 담당자 승인 전 교인 권한이 없고 교회 탈퇴/정지는 개인의 다른 서비스 탈퇴/삭제로 확대하지 않는다. 공통 탈퇴는 본인 확정에 따라 각 서비스 종료/삭제·모든 교회 관계 종료를 요청하고 마지막 관리자 공백은 별도 복구한다.

정지/탈퇴·복구·공유 재개·재이용·부분 실패·제한 상태 조회의 기한/책임은 계약표를 따른다. 이전 삭제 건과 새 이용 기록을 구분하며 제품별 원문은 이동시키지 않는다. COS-SSO-048도 설계 합의했으며 구현/실기기/제공자 연동 검증은 NOT_RUN.
