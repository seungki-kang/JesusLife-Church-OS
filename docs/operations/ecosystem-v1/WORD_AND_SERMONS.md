# ChurchOS 말씀·찬송·설교·나눔지 운영 설계 v1.2

2026-10-24. 문서 ID COS-WORD-001. 상태: 사용자 요청에 따른 후속 설계, 구현·실행 검증 전.

## 1. 확인 결과

| 대상 | v2.6에서 확인한 것 | 부족한 것 |
|---|---|---|
| 성경 | JLBible 오늘 읽기·이어가기·앱 열기 카드 | ChurchOS 내 성경 본문 열람·검색·독서 설정·본문 API 연결 |
| 찬송 | 확인 범위에서 전용 명세·API·서버 구현 없음 | 찬송 목록·번호/제목 검색·가사/악보/음원 권한별 열람 |
| 설교 | 사용자경험 문서의 '설교·예배 링크' 항목 | 독립 설교 자료 관리·음성·전사·버전·게시 권한 |
| 말씀 나눔지 | 확인 범위에서 전용 구현 없음 | 설교 기반 초안·출처·검토·게시·정정 흐름 |
| CHGO | 공동체 집계와 전 제품 엔진 관계 설계 | 설교/본문/교육 개념 연결·근거 반환·검토 가능한 나눔지 생성 계약 |

확인 범위는 현재 확보한 ChurchOS v2.6 제품·UX·API·서버 및 후속 운영 문서다. 모든 과거 문서나 JLBible/CHGO 최신 저장소를 전수 확인한 결과는 아니다. 기존 63개 API·DB PASS는 이 신규 기능의 PASS가 아니다.

## 2. 확정하는 방향

사용자는 자기 교회 앱에서 성경과 찬송을 사용한다. 통독계획·진도·통독 모임의 전문 기능은 JLBible에서 사용한다. 담임목사 설교는 ChurchOS에서 링크·텍스트·음성 등 준비된 방식으로 제공하고, 설교 요약과 말씀 나눔지는 CHGO 엔진의 개념·근거 연결을 거쳐 목회자의 검토 후 제공한다. Academy 선택 여부와 무관한 교회 기본 말씀 기능으로 설계한다.

ChurchOS에 말씀 홈·성경/찬송 뷰어·설교·나눔지 화면을 제공하지만, 성경·찬송 콘텐츠 정본과 열람 권한은 JLBible 콘텐츠 서비스가 담당하는 안을 채택한다. 찬송 카탈로그는 그 안의 분리된 콘텐츠 영역으로 확장하며 새 독립 제품을 임의로 추가하지 않는다. 실제 제공자 구현과 권리 범위는 후속 확인한다. 설교와 교회가 승인한 요약·나눔지는 ChurchOS의 교회 콘텐츠다. CHGO는 처리 엔진이며 설교 게시 권한을 소유하지 않는다.

## 5. S19. 성경·찬송 사용

1. 성도가 자기 교회 앱의 성경 또는 찬송을 선택한다.
2. ChurchOS가 JLBible 콘텐츠 API에서 판본·권리·허용 기능을 확인한다. 교회 멤버 권한과 콘텐츠 이용권을 서로 대체하지 않는다.
3. 사용자가 책/장/절 또는 찬송 번호/제목을 선택한다. 판본별 번호 체계와 곡·가사·편곡·녹음 식별자를 구분한다.
4. 허용된 본문·가사·악보·음원을 앱 내 표시한다. 표시·검색·다운로드·오프라인·재생 권한을 각각 판정한다.
5. 사용자가 통독을 선택한 경우에만 JLBible 통독 흐름으로 이동한다. 원래 ChurchOS 위치로 복귀한다.

예외: 권리 미확보 자료는 준비 중/제공 불가로 표시하고 임의 웹 수집·타 사이트 음원 재생으로 대체하지 않는다. 단절 시 허용된 캐시만 사용하고 자료가 없으면 안내한다. 캐시는 판본·콘텐츠 버전·권리 만료·회수 정책을 따르며 권리 소멸 후 접근을 처리하는 기준이 필요하다.

합격 조건: 실제 기기에서 앱 전환 없이 성경·찬송 기본 열람, 판본 전환, 글자 크기, 재생 실패 처리를 확인한다. 본문 열람만으로 통독 완료 이벤트가 발생하지 않는다. 권리 범위 밖 다운로드·재생을 거부한다.

## 6. S20. 설교 등록과 게시

주체: 교회별 권한을 가진 설교 자료 편집자·승인자. 목회자 직함만으로 모든 편집/게시 권한을 자동 부여하지 않는다.

1. 제목·설교자·예배일·본문 참조·공개범위를 등록한다. 링크만 등록하거나 텍스트/음성 파일을 추가할 수 있다. 모든 자료 형식을 필수로 요구하지 않는다.
2. 교회가 업로드·공개·전사·AI 처리에 사용할 수 있는 자료인지 확인하고 권리/허용 범위 상태를 기록한다. 외부 링크 열람과 원본 다운로드·전사·재배포 권한을 구분한다.
3. 링크 전용은 '링크 설교'로 제공한다. 링크 제목·URL만으로 설교 내용을 추측해 요약하지 않는다. 외부 사이트가 전사를 제공하지 않으면 목회자가 원고/자막/요약을 제출할 수 있다.
4. 음성은 검증된 파일을 교회별 비공개 저장소에 보관하고 전사 작업을 비동기로 요청한다. 전사 결과의 본문·인명·오인식 구간을 편집자가 확인한다. 검토 전 전사를 목사님의 확정 발언처럼 게시하지 않는다.
5. 승인자가 공개범위와 버전을 확인해 게시한다. 설교 자체 게시와 AI 나눔지 게시 승인을 분리할 수 있다.

예외: 파일 형식·크기·길이 제한, 검사, 서명된 접근 URL과 만료, 교회 간 접근 격리를 적용한다. 외부 주소는 등록/호출 대상을 검증하고 임의 주소의 서버측 다운로드를 막는다. 삭제·접근 철회 시 파일·전사·파생 초안의 접근도 처리한다.

합격 조건: 타 교회 자료 접근 거부, 업로드 실패 복구, 링크 전용 게시, 수동 요약 제공, 전사 없는 경우의 명시적 표시가 가능하다.

## 7. S21. CHGO 기반 설교 요약·말씀 나눔지

### 입력과 엔진 분리

입력은 교회가 처리를 허용한 특정 설교 버전의 원고 또는 검토된 전사, 본문 참조, 허용된 성경 인용, 대상/언어/모임 시간 등 작성 설정이다. 개인 일기·기도·관계 답변·나눔 응답은 입력하지 않는다. 성경 전체나 권리 미확보 본문을 생성 모델에 일괄 전송하지 않는다.

CHGO는 온톨로지·근거·개념 연결 엔진이다. 음성 전사와 자연어 생성은 별도 어댑터의 역할이며 CHGO가 이미 이를 구현했다고 가정하지 않는다. 선택된 생성 모델·자료 전달·보관·국외 처리 조건은 실제 제공자 선정 단계에서 확인한다. 엔진/생성기 미준비 시 목회자 수동 요약·나눔지 업로드를 제공한다.

### 처리 순서

1. 편집자가 '설교 요약·나눔지 초안 만들기'를 요청한다. 교회·설교·소스 버전·요청자·목적·설정 버전으로 작업을 식별한다.
2. Worker가 입력 권한과 최신 소스 버전을 확인한다. 네트워크/처리 작업은 게시 저장 트랜잭션과 분리한다.
3. CHGO가 본문 참조·성장/관계 개념·근거 위치를 연결한다. 기존 신학 정본과 예수생명·하나님 나라 관점의 검토된 규칙을 참조한다. 설교자의 주장과 엔진의 해석을 구분한다.
4. 전사/생성 어댑터가 근거 있는 요약과 나눔 질문의 초안을 작성한다. 설교에 없는 발언·본문·간증을 만들어 넣지 않는다. 엔진의 추가 적용 제안은 '추가 제안'으로 분리한다.
5. 검증기가 인용 범위·출처 연결·판본·필수 항목·금지된 개인 정보·근거 없는 단정을 확인한다. 자동 검사가 신학적 진실이나 정확성을 보증하지는 않는다.
6. 목회자/승인자가 원본과 초안을 비교해 수정·승인한다. 필요 시 생성 결과를 버리고 수동 작성한다. 승인 없이 교인 알림이나 게시를 하지 않는다.
7. ChurchOS가 승인본과 승인자·소스/출력/엔진 버전을 보관하고 교회별 공개범위로 제공한다. 요약·질문별 원문 문단/시간 구간 또는 성경 참조를 내부 검토에서 확인할 수 있게 한다.
8. 설교 원문이 수정되면 이전 소스 기반 결과를 오래된 버전으로 표시한다. 자동 덮어쓰기·자동 재게시하지 않고 재검토 후 새 버전을 게시한다.

### 작업/게시 상태

자료: DRAFT→REVIEW→PUBLISHED→WITHDRAWN. 생성 작업: QUEUED→RUNNING→SUCCEEDED/FAILED/CANCELLED. 생성 초안: DRAFT→REVIEW→APPROVED→PUBLISHED→WITHDRAWN. 소스 변경으로 생긴 STALE 표시는 작업 상태와 별개다. 재시도는 같은 작업/버전의 중복 초안을 만들지 않는다. 엔진 장애가 이미 승인된 설교·나눔지 열람을 막지 않는다.

### 나눔지 기본 구성

1. 설교 제목·설교자·예배일·성경 본문 참조.
2. 승인된 핵심 요약과 핵심 메시지.
3. 본문 관찰 질문과 설교 이해 질문.
4. 삶의 적용·관계·공동체 나눔 질문. 개인 죄·상처 공개를 강요하지 않는다.
5. 함께 기도할 주제. 개인 기도수첩 원문을 자동 채우지 않는다.
6. 원본 설교 연결·문서 버전·교회 검토 표시. AI 초안 사용 여부를 승인자의 실제 발언과 혼동하지 않게 안내한다.

합격 조건: 링크만 있고 내용이 없으면 생성 거부, 권한/근거 부족 시 미확정 처리, 수정된 원문과 이전 초안의 불일치 검출, 승인 전 비노출, 교회 간 결과 격리, 재시도 중복 방지, 엔진 장애 시 수동 작성과 기존 승인본 열람을 확인한다.

## 8. 나눔과 개인 기록의 경계

말씀 나눔지는 교회가 제공하는 공통 자료다. 초기에는 개인 답변 제출·영성 평가를 기본 기능에 넣지 않는다. 나눔 모임의 일정·출석은 ChurchOS, 개인 기도 기록은 JLPrayer, 생명일기 기록은 생명일기에 둔다. 나눔지의 '기도하기'는 JLPrayer로 연결할 수 있지만 ChurchOS가 공개된 나눔 주제를 개인 기도에 자동 저장하지 않는다. Academy는 교회가 별도로 선택했을 때 교육 자료를 참조할 수 있으며 주일 설교와 나눔지 제공의 필수 조건이 아니다.

교회가 허용한 설교 원고·전사·승인 요약을 CHGO 작업에 보내는 것은 개인 기도/일기 원문을 수집하는 것과 다른 처리다. 기존 개인 원문 금지 정책을 완화하지 않고 '교회 제공 설교 콘텐츠' capability를 별도 정의한다. 설교에 개인 간증·제3자 정보가 포함되면 편집자가 처리 범위를 확인하고 필요 구간을 제외한다.

## 9. 후속 API·저장 구조 제안

경로는 설계 초안이며 현재 라우트가 아니다. 기존 v2.6 OpenAPI나 DB에 구현된 것으로 표시하지 않는다.

| 제공자 | 계약 대상 |
|---|---|
| JLBible | /content/bible/editions, /passages, /search, /content/hymns/editions, /hymns, /assets/authorize |
| ChurchOS | /sermons, /sermons/{id}, /sermons/{id}/assets, /sermons/{id}/generation-jobs, /discussion-guides, /discussion-guides/{id}/approve, /publish, /withdraw |
| CHGO | 설교 소스 버전별 개념 매핑·근거 연결·초안 지원 작업 API와 결과 조회 |

교회 데이터 후보: sermon, sermon_asset, sermon_source_version, content_processing_permission, generation_job, sermon_summary_version, discussion_guide_version, content_approval. 모든 교회 소유 자료는 tenant 경계·행위 감사·버전·조건부 수정·멱등성을 적용한다. 대용량 파일은 DB 행에 원문 바이너리를 넣지 않고 접근 통제된 asset ref로 관리한다. 전문 콘텐츠 본문은 JLBible 정본에서 제공하고 임시 캐시 정책을 별도 확정한다.

새 V016 이후 마이그레이션이 필요할 수 있지만 이번에는 생성하거나 적용하지 않는다. CHGO/본문 제공 API 계약이 확정되지 않은 상태에서 DB부터 확정하면 재작업 위험이 있기 때문이다. 신규 DB DDL·OpenAPI·화면 구현은 이 설계를 기준으로 다음 작업에서 함께 검증한다.

## 10. 구현 순서

| 순서 | 결과 | 검증 |
|---|---|---|
| W1 | ChurchOS 말씀 메뉴·교회 설교 링크/원고·수동 요약·나눔지 게시 | 역할·교회 격리·게시/철회·앱 동선 |
| W2 | JLBible 성경/찬송 콘텐츠 계약과 ChurchOS 뷰어 | 권리 확인·판본·검색·재생·캐시·통독 분리 |
| W3 | 설교 음성 파일·검토 가능한 전사 | 접근 격리·실패/재시도·전사 수정 |
| W4 | CHGO 개념/근거와 생성 어댑터를 통한 초안 | 근거·소스 버전·신학 검토·승인 전 비노출 |
| W5 | 목장 나눔 운영·통독/기도 연결·교회 파일럿 | 교인 실기기 사용·철회·장애·업무 시간 |

권리 확보가 늦는 콘텐츠를 임의 대체하지 않는다. 각 단계의 미완료 기능은 미제공/준비 중으로 표시한다. CHGO 기반 자동 초안은 W4 완료 후에만 제공하며 W1의 수동 자료도 유효한 운영 경로다.

## 11. 이번 변경과 남은 상태

이번에 수행한 것은 기존 설계 확인과 후속 문서 반영이다. 성경/찬송 뷰어·설교 API·전사·생성·CHGO 실행 연결·콘텐츠 권리 확보는 NOT_IMPLEMENTED 또는 NOT_RUN이다. v2.6 소스·DDL·매니페스트는 유지했다. GitHub main은 아직 갱신하지 않았다. JLPrayer의 앱 내 기도 기능은 직전 논의의 권고안이며, 이번 성경/설교 설계로 승인·구현 완료된 것으로 처리하지 않는다.


## 12. 일반 교회 앱 조사에 따른 영상 제공 방식 보완

조사일 2026-10-24. 대표 서비스의 공식 문서에 따른 비교이며 한국 교회 전체의 이용 비율을 조사한 것은 아니다.

| 서비스 | 공식적으로 확인한 방식 | 참고 |
|---|---|---|
| Tithely Church Apps | YouTube/Vimeo 채널·재생목록 피드 연결, 임베딩 허용 필요 | https://support.tithe.ly/hc/en-us/articles/34987827048343-How-to-Add-Videos-to-Your-Church-App |
| Planning Center / Church Center | YouTube/Vimeo 영상 연결과 호스팅된 설교 음성 제공 | https://www.planningcenter.com/publishing |
| Subsplash | 미디어 파일 직접 업로드와 처리, 미디어 라이브러리 활용 | https://support.subsplash.com/en/articles/8872273-uploading-media |
| YouTube | 공식 플레이어의 앱 내 임베딩, 자막 다운로드는 별도 인증·권한 필요 | https://developers.google.com/youtube/player_parameters ; https://developers.google.com/youtube/data/reference/rest/v3/captions/download |

ChurchOS 기본안은 'YouTube 영상 연결 + 앱 내 공식 플레이어 + 별도 음성/원고 + 승인된 요약·나눔지'다. 교회 YouTube 채널이 필수는 아니다. 채널이 있으면 개별 영상 URL부터 연결하고, 이후 설교 전용 재생목록 가져오기를 제공한다. 채널 전체 영상을 무조건 게시하지 않고 자동 수집 후보→교회 검토→게시로 처리한다. 영상 ID로 중복 수집을 막고 날짜·설교자·본문·시리즈를 교회가 확인한다. 게시/수정/삭제는 원본 플랫폼 상태와 앱 게시 상태를 구분한다.

직접 영상 업로드도 확장 경로로 설계하되 초기 기본 구현 범위와 구분한다. 직접 호스팅은 저장소·대용량 업로드 재개·인코딩·해상도 변환·스트리밍·CDN·트래픽·비공개 접근 제어가 준비된 경우에 제공한다. 사용자에게 준비되지 않은 업로드 버튼을 노출하지 않는다. 교회가 채널을 운영하지 않으면 음성/원고만으로 설교를 게시하거나 향후 직접 영상 호스팅을 선택할 수 있다.

영상 재생 소스와 AI 처리 소스를 분리한다. YouTube 연결만으로 원본 영상 다운로드·음성 추출·자막 확보가 가능하다고 표시하지 않는다. CHGO 초안에는 교회가 제공한 원고/음성 또는 권한이 확인된 자막을 사용한다. 자료가 없으면 영상만 게시하고 초안 생성은 대기한다.

앱 내 공식 플레이어는 YouTube 표시·동작을 유지한다. 임베딩 차단·삭제·비공개 전환·연령/지역 제한 등 재생 실패 시 안내와 원본 열기를 제공한다. ChurchOS 교인 전용 화면에 연결해도 공개/일부공개 YouTube 원본이 교회 회원 전용으로 보호되는 것은 아니다. 제한 자료는 접근 제어가 가능한 호스팅 방식과 별도 검증이 필요하다. 배경 음성·다운로드·광고/추천 완전 제거를 연결 방식의 기본 기능으로 약속하지 않는다.

초기 구현 순서는 개별 YouTube 연결→앱 내 재생·실패 처리→음성/원고·검토 게시→재생목록 수집→CHGO 초안 지원→직접 영상 호스팅 선택 확장이다. 이번 조사·문서 변경은 기능 구현 또는 실행 검증이 아니다.
