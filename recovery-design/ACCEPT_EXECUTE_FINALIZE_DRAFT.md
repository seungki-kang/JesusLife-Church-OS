# 실제 접수→실행→최종 확정 상태 계약

2026-10-28 / TECHNICAL_DRAFT / PARTIAL_RECOVERY / 업무 구현·실행 NOT_RUN

## 범위와 근거

[REC 결정 색인](RECOVERY_DECISIONS.md)의 REC-025~032, [기존 구현 대조](IDEMPOTENCY_BASELINE_ALIGNMENT.md), [기기/서버 ID 연결](SUBMISSION_RECEIPT_BINDING_DRAFT.md)을 이어 일반 교회 업무 쓰기의 처리 결과를 설계한다. 기존 자원별 API·Idempotency-Key·경로별 영수증이 기준이다. 가입 심사·다른 제품 개인 원문·CHGO 작업의 공통 실행기로 확대하지 않는다.

아래 상태명·분리 트랜잭션·호환 이행은 구체화를 위한 후보이며 이번 “다음 단계”를 정책 승인으로 기록하지 않는다. 새 DB 테이블·API·실행 대기열을 구현하지 않는다.

## 세 층의 상태 구분

| 층 | 후보 상태 | 의미 |
|---|---|---|
| 기기 | LOCAL_ONLY / SUBMITTED_UNKNOWN | 최소 참조만 생성 또는 송신 후 서버 응답을 못 받음. 서버 접수/실패 증거 아님 |
| 서버 공개 | PROCESSING / REVIEW_REQUIRED | 최초 접수 증거 있음, 최종 업무 결과 미확정. 두 상태 모두 최초 접수+168h의 같은 기한 |
| 서버 공개 | COMMITTED / REJECTED | 업무 반영 또는 미반영을 근거로 실제 최종 확정한 결과. 그 실제 확정+168h |
| 내부 실행 제어 | 미착수·실행권 보유·확정·조사 | 실행 주체/세대/잠금과 내구 증거를 관리하는 내부 후보. 공개 다섯 항목에 추가하지 않음 |

RESULT_UNKNOWN은 앱의 불확실성이다. PROCESSING은 장기 서버 작업 대기열을 약속하는 상태가 아니다. “기록을 찾지 못함”은 서버 REJECTED가 아니다. HTTP 입력/인증 실패를 모두 영속 REJECTED로 저장하지 않는다.

## 전이표 — 기술 초안

| 사건 | 선행 조건과 서버 처리 | 결과·기록 | 사용자 안내 |
|---|---|---|---|
| 로컬 생성 후 송신 안 됨 | 서버 실제 접수 증거 없음 | 로컬만 존재 | 서버 접수/완료로 표시하지 않음 |
| 입력·인증·소속 검증 실패 | 최소 필드 검증, 비인가 요청 존재 차단 | 실제 접수 전 오류. 무조건 서버 요청 기록 생성 금지 | 일반 입력/접근 안내 |
| 최초 유효 접수 | 계정/교회/경로/키/검증된 입력의 결합을 내구 확정 | confirmation_ref와 accepted_at 후보, PROCESSING | 접수 확인, 업무 성공 아님 |
| 같은 범위·같은 입력 재도착 | 기존 내구 요청과 대조 | 새 실행 소유자 생성하지 않음 | 현재 자격과 기한 내 최소 조회 |
| 같은 범위·다른 입력 | 기존 결합 불일치 | 기존 결과를 수정하지 않고 충돌 | 같은 식별자로 내용 변경 불가 |
| 실행 착수 | 하나의 실행권, 현재 권한/기간/대상/업무 버전 검증 | 실행 제어 참조. 앱에 권한으로 노출 안 함 | 미확정 안내 |
| 업무 반영 확정 | 업무 변경·감사·기존 성공 영수증·최종 결과의 일관된 커밋 | COMMITTED, 실제 최종 확정 근거 | 완료. 원문은 현재 별도 권한으로만 |
| 업무 미반영 확정 | 모든 해당 실행이 미착수/롤백임을 확인하고 실행권 차단 | REJECTED, 최소 결과 근거 | 미반영 확정. 수정/재제출은 별도 명시 동작 |
| 커밋 여부 불명 | 연결 단절·DB 장애 등으로 결과 증명 불가 | REVIEW_REQUIRED, 최초 접수 기한 유지 | 결과 확인, 자동 재실행 금지 |
| 조사로 실제 결과 확인 | 단 하나의 최종 전이, 실제 확정 증거 | COMMITTED 또는 REJECTED | 실제 확정+168h 내 최소 조회 |
| 일반 조회 만료 | 최초 접수/실제 최종 확정+168h 도달 | 공개 투영 차단, 내부 업무 상태 변경 없음 | 만료를 업무 실패로 단정하지 않음 |

미확정 조회가 만료된 뒤 실제 최종 결과가 확정되면 최종 구간을 제공한다는 기존 합의를 유지한다. 단순 재조회·조사 담당자 변경·알림·백업 복원이 새 확정 시각을 만들지 않는다. 최종 결과는 후속 업무 수정으로 덮어쓰지 않으며 정정은 별도 의도/현재 권한으로 처리한다.

## 내구 접수와 업무 커밋을 연결하는 후보 구조

후보 A는 별도 최소 접수 확정(TxA) 뒤 기존 업무 트랜잭션을 확장한 실행(TxB)을 수행하는 방식이다. 원문을 접수 기록/복구 대기열에 복제하지 않고 참조·보호된 동일성 검증·상태만 남긴다. 자동 재실행용 원문 대기열을 새로 만들지 않는다.

TxA가 성공하고 TxB 전에 프로세스가 죽으면 접수 기록만 남는다. 복구는 실행권을 안전하게 차단/인계하고 미착수 또는 롤백을 증명한 후 미반영 결과를 확정하는 방향이다. 타임아웃·임대 만료·로그 부재만으로 미착수/롤백을 증명하지 않는다. 옛 실행자가 여전히 살아 있거나 커밋 가능하면 미확정을 유지한다. 입력이 사라졌다고 원문을 새로 수집해 자동 실행하지 않는다.

TxB의 커밋에는 업무 변경·최소 감사·기존 영수증·최종 결과·필요한 발행 대기 참조를 같은 확정 단위로 묶는 것을 권장한다. 그 중 하나의 기록 실패는 업무 성공만 남기는 방식으로 우회하지 않는다. 실제 저장소 분리가 필요하면 이 원자성을 대체할 명시적 계약을 별도 설계해야 한다.

접수와 업무를 한 트랜잭션으로 유지하는 후보 B는 성공 전 롤백 시 접수 증거도 사라져 미확정/거절 조회를 충족하기 어렵다. 따라서 A를 우선 검토하되 선정 완료로 표시하지 않는다. 두 후보를 동시에 두 실행 체계로 구현하지 않는다. 실제 트랜잭션 경계·잠금·세대 차단·접수 기록 수명은 미결이다.

## 실제 시각의 증거

accepted_at은 서버 도착 로그/기기 전송 시각이 아니라 유효 접수의 내구 확정 사건에 연결한다. confirmed_at도 DB now()/업무 created_at/트랜잭션 시작 시각과 자동 동일시하지 않는다. 정확한 사건 시각과 저장 원자성을 함께 보장할 DB/서버 시계 계약이 필요하다. 확정 뒤 관측 시각이 실제 커밋 시각과 다르면 그 차이를 숨기거나 과거 시각을 추정해 저장하지 않는다.

실제 커밋 사건과 조회 기산 시각을 어떻게 증명·영속화할지는 중요한 기술 미결이다. 근거를 확인할 수 없는 요청에 최종 시각을 만들어 성공을 표시하지 않는다. 기존 168시간 정책을 다른 시계로 바꾸는 합의도 아니다.

## 해제·만료·외부 상태

REC-025에 따라 같은 업무 권한 범위에서 해제 선확정은 미확정 쓰기를 막고, 쓰기 선확정은 결과를 유지한다. 최초 접수가 해제보다 빨랐다는 이유로 실행을 허용하지 않는다. 잠금 대기 뒤에도 현재 소속·권한·기간·대상을 다시 판정한다.

자연 만료는 DB 트랜잭션 시작 now()만으로 판정하지 않는다. 마지막 권한 판정과 커밋 사이 시간 경계를 어떻게 강제할지도 OPEN이다. 외부 공통 계정 정지와 로컬 DB를 원자적으로 묶었다고 가정하지 않으며, 최신성/확인 불가 차단은 별도 인증 계약을 따른다.

| 기존 동작 | 후속 확장에 따른 차이 | 이행 조건 |
|---|---|---|

| 기존 POST 재생은 현재 쓰기 권한 검사 | 업무 역할 종료 후 본인 최소 조회 | 별도 읽기 권한, 기존 쓰기를 조회 대용으로 재전송하지 않음 |
| 24h 성공 응답 재생, 만료 행 409 | 168h 최소 상태 조회 | 원문 재생 기한을 조용히 늘리지 않음 |
| 자원별 route_key+키 | 불투명 확인 ID 연결 | 기존 키 범위를 전역으로 바꾸지 않음 |
| row_version 변경 시 REPLAY_SUPERSEDED | 과거 성공 여부 최소 조회 가능 후보 | 현재 원문/행 버전을 과거 결과로 복제하지 않음 |

확장 계약을 기존 무변경 API에 적용 완료한 것으로 선언하지 않는다. 이전 클라이언트와 신규 클라이언트의 실패/재시도 의미를 확인하기 전 새 접수 의미를 운영 활성화하지 않는다. 새 계약 버전·지원 감지 방식은 OPEN이다.

## 알림과 조사

커밋 전 외부 알림/이벤트 발행 금지, 전달 시점 현재 접근과 알림 조건 확인. 알림 실패는 업무 실패/새 실행이 아니다. 같은 성공 알림을 재발행하는 경우의 전달 중복 방지는 쓰기 중복 방지와 별도다. 새 알림 정책은 여전히 DRAFT다.

24시간 수동 이관의 출처는 REC-017 대화 복원 요약이다. 해결 보장·조사 기록 보유기간·권한 완화가 아니다. 담당/대행·연락 수단·정체 판정·장기 미종결 처리 기준은 미결이며 승인되지 않은 수치를 추가하지 않는다.
