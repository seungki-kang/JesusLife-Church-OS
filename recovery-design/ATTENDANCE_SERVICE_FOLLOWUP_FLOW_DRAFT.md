# 출석·봉사·후속 업무 — 대상·정정·권한 계약

2026-10-28 / 기존 정책 연결 + 상세 TECHNICAL_DRAFT / PARTIAL_RECOVERY / 구현·실행 NOT_RUN

## 범위와 원칙

[구현/합의 대조](ATTENDANCE_SERVICE_FOLLOWUP_BASELINE.md), [REC 결정](RECOVERY_DECISIONS.md), [연락처 사용/소속 계약](../docs/operations/ecosystem-v1/ACCOUNT_MEMBERSHIP_SERVICE_SCOPE_CONTRACT.md), [홈·일정 계약](HOME_NOTICE_EVENT_FLOW_DRAFT.md)을 이어 교회 운영 사실만 설계한다. ChurchOS 출석은 Academy 수료·JLBible 통독·JLPrayer 기도 참여·생명일기 작성 여부/회차가 아니다. 개인 영성 기록/상담 원문을 ChurchOS에 모아 담당자나 CHGO에 전달하지 않는다.

아래 화면·capability·상태 전이·대상 자격 세부·수명은 후보이며 새 정책 확정이 아니다. 기존 합의와 구체 기술 선택을 구분한다. 앱만으로 처리하되 서버·현재 권한 확인은 필요하다.

## 대상·담당·권한을 별개로 검증

| 축 | 서버 검증 후보 | 금지 |
|---|---|---|
| 대상 | 선택 교회·행사/공동체·유효 대상 참조·처리 시점의 자격 | 이름/연락처 일치로 교인 병합·타 교회 참조 사용 |
| 담당자 | 현재 계정/소속·정확한 업무 위임·대상 범위·시작/종료 | 리더/목회자 직함·봉사 참여만으로 전체 명단/연락처 열람 |
| 행위 | 조회·기록·정정·배정·상태 변경·연락 각각의 권한 | 조회 허용을 수정·정정·연락·재위임으로 확대 |
| 시점 | 현재 처리 권한과 과거 실제 업무 사건을 구분 | 대상 탈퇴로 과거 원본 포괄 삭제 또는 현재 미소속자를 신규 유효 교인으로 취급 |
| 데이터 필드 | 식별에 필요한 최소 표시·허용 운영 코드 | 기도/상담/일기·신앙 평가·전체 요청을 메모/로그/알림에 복사 |

대상이 다른 공동체로 이동하거나 탈퇴한 경우 과거 사건의 유효성·정정 자격은 별도 역사 근거로 확인한다. 현재 소속 회복/재가입과 과거 교인 ID의 관계를 이름으로 합치지 않는다. 과거 담당자가 당시 맡았다는 이유만으로 현재 열람/정정을 허용하지 않는다. 역사적 대상 자격/보유·표시의 세부는 OPEN이다.

## 출석 정상 흐름과 최소 상태

허용 행사 선택→현재 담당 범위의 대상 확인→허용 방식의 출석 기록→서버 확정→허용 목록/본인 결과 확인 흐름을 후보로 둔다. 일반 교인에게 다른 교인의 출석 명단을 기본 제공하지 않는다. 본인 SELF/QR 방식의 개별 허용 정책·QR 발급/만료/양도 방지·현장 확인은 OPEN이며 코드 존재만으로 활성화하지 않는다.

참가 신청, 참석 대상, 출석 사실, 미기록, 정정으로 무효화된 기록은 별개다. 현재 attendance는 출석 행 중심이므로 목록에 없다는 이유로 ‘결석’ 또는 신앙 태만을 확정하지 않는다. 실제 사건 시각 occurred_at과 서버 기록/수정 시각을 구분하고 현장 시각을 조작해 정정 권한을 연장하지 않는다.

중복 제출은 동일 행사·교인 조합과 현재 명령 동일성을 함께 대조한다. unique 제약 충돌을 무조건 성공으로 삼거나 다른 사건 시각/방식의 기록을 조용히 덮어쓰지 않는다. 같은 사람에 대해 서로 다른 처리 내용이 경합하면 기존 사실·버전을 확인한다. 대량 가져오기를 지원할 경우 미리보기·행별 권한/오류·중복 판별·부분 성공 범위를 계약해야 하며 현재 기능으로 약속하지 않는다. 파일/위치/생체정보를 출석 증명 기본 수집물로 추가하지 않는다.

방문자·외부인처럼 유효 교인 참조가 없는 대상은 현 membership FK에 맞추기 위해 가짜 교인/자동 가입으로 생성하지 않는다. 별도 방문자 정책 없이는 개인 기록 수집을 임의 확장하지 않고 운영 안내로 전환한다.

## 출석 정정과 행사 종료 후 처리

REC-011에 따라 정정 사유는 입력 오류·누락·중복 처리·기타 중 하나를 담당자가 직접 선택한다. 기본 선택·자유 서술·증빙 첨부·음성 설명은 초기 범위에서 제외하고 ‘기타’도 설명을 강제하지 않는다. 사유/업무 이력과 일반 로그·푸시를 분리한다.

이미 기록한 사실을 수정·추가·무효화하는 작업은 신규 출석과 구별한다. 과거 결과·정정의 최소 연결을 남기는 후보를 사용하고 조용한 물리 삭제/사람 자동 병합을 피한다. 정정 이력의 정확한 필드·버전·보유·최소 대상 표시·출석 무효화 스키마는 OPEN이다. 현재 attendance에 row_version이 없으므로 ETag가 있다고 가정하지 않는다.

행사 종료 후에는 관리자가 현재 권한으로 처리하거나 대상·행위·기간을 최소화해 새로 지정하고 본인이 수락한다(REC-010/019). 수락 가능한 제안 기간168h와 실제 정정 권한은 별개이며, 실제 정정 권한은 유효 수락 활성부터 최대168h와 더 이른 지정 마감으로 제한한다. 이미 지난 절대 마감은 활성화하지 않는다. 이전 권한 자동 연장·반복 재지정으로 제한 우회는 허용된 것으로 간주하지 않으며 반복 지정 상한은 OPEN이다.

행사 취소·완료·게시 철회가 과거 출석 사실의 일괄 취소/삭제가 되지 않는다. 신규 기록 허용 여부와 역사적 정정 허용 여부를 상태별로 정해야 하며 기존 행사 cancel API로 출석 처리까지 완료했다고 표시하지 않는다. 같은 권한 범위의 해제·만료·정정 확정 경합은 REC-025를 따른다.

## 봉사 제안·수락과 운영 권한 분리

봉사 대상 공동체/업무·기대 기간·역할 안내→본인 수락/거절→현재 조건 확인 후 활성→종료 흐름은 S04 방향을 따른다. 자원 의사·기술·경험·가능 시간·공동체 필요 같은 최소 코드 근거를 사용하며 기도 횟수·일기 작성량·CHGO 개인 결과·영적 등급으로 배치하지 않는다. GIFT/LEADER_DISCERNMENT라는 기존 코드를 신앙 평가 자유 서술의 근거로 쓰지 않는다.

봉사 참여를 수락했다고 출석 정정·교인 연락·가입 승인·관리자·개인 제품 열람 권한이 생기지 않는다. 운영 권한이 필요하면 일반 업무 위임 또는 특별 권한의 해당 절차를 따로 진행한다. 일반 업무 권한의 최대1년/정확한 종료/수락 규칙을 모든 봉사 참여 일정에 자동 복제하지 않는다. 기존 ministry_assignment는 날짜 필드와 nullable ends_on을 가지므로 역할 권한 모델과의 매핑·참여 종료 필요성·동시성은 후속 미결이다.

거절·만료·불참/종료를 전체 제품 사용 제한·공개 낙인·평판 점수로 바꾸지 않는다. ACTIVE 이후 종료와 미수락 제안의 거절/취소를 구분한다. 대체 봉사자를 정하는 절차가 다른 사람의 수락이나 기존 담당 해제를 자동 완료하지 않는다. 활동 시점 중복·가능 시간의 최소 범위·공개 배치표·본인 종료/변경·알림의 상세는 DRAFT/OPEN이다.

## 후속 업무: 최소 코드와 명시적 배정

허용된 운영 필요를 사람이 확인→대상/목적/업무 코드·담당·기한 지정→허용 담당자가 진행/완료/취소하는 흐름을 후보로 둔다. 환영 연락·방문·실질 지원 등 S04 범위이며 부재 출석만으로 자동 돌봄/영성 문제 판정을 만들지 않는다. 자동 업무 생성/추천 규칙은 미승인이다.

V012의 operational_note NULL 강제를 유지한다. 현재 허용 operational_code는 WELCOME_CALL·CONTACT_ATTEMPTED·VISIT_SCHEDULED·REFERRED·NO_RESPONSE·OTHER_NO_TEXT다. 범주·우선순위·purpose_code·기한·상태는 운영 정보이며 개인 사정·상담·의료·가정 문제를 담는 자유 입력으로 바꾸지 않는다. OTHER/OTHER_NO_TEXT에도 ‘기타 설명’·첨부·음성·기도 원문을 붙이지 않는다.

후보 상태는 OPEN→ASSIGNED→IN_PROGRESS→DONE/CANCELLED이며 상세 허용 전이는 아직 API 계약이 아니다. 연락 시도/응답 없음은 업무 코드이고 완료/포기·소속 종료와 같지 않다. 기한 경과가 자동 완료·개인 위험/우선순위 자동 상향·공개 알림 확대를 만들지 않는다. 긴급 우선순위나 SAFETY_HANDOFF 코드만으로 긴급 대응 서비스/외부기관 자동 전송이 구현됐다고 안내하지 않는다.

업무 대상과 배정 담당자는 구별한다. 새 담당 배정·배정 변경·담당자의 인계 요청을 구분하고, 정확한 변경 주체/수락·인수 요건은 후속 확정한다. S04의 ‘재배정’은 업무 건의 담당 연결 변경이며 본인의 시스템 권한을 다른 사람에게 재위임하는 허가가 아니다. REC-003의 일반 권한 인계는 관리자 후임 지정·본인 수락 원칙을 유지한다. 이전 담당 접근은 현재 유효 배정/권한을 확인하며 인계가 기한을 자동 연장하지 않는다.

## 연락처·대상자 공개 경계

COS-JOIN-036~039에 따라 연락처 조회는 현재 관리자 또는 명시 연락 업무 위임·배정 대상 범위 안에서만 가능하고 승인 후 운영 사용은 본인 별도 선택을 요구한다. 후속 업무 assignee라고 모든 연락처를 자동 제공하지 않는다. 연락 사용 철회는 이후 열람/새 발송을 차단하고 해당 교회 운영 사본을168h 내 삭제하되, 업무 존재·교회 소속·개인 계정·다른 교회 정보를 포괄 삭제하지 않는다.

원문 없는 업무 상태를 남길 수 있는 범위와 연락 불가 시 대안은 목적별로 정한다. 선택 미제공자를 거절/결석/돌봄 거부로 낙인찍지 않는다. 대상 본인이 자기 후속 업무의 무엇을 볼지, 담당자 간 열람/관리자 열람·요약은 명시적 정책이 필요하며 전체 명단/개인 세부를 기본 공개하지 않는다.

## 저장·통계·외부 연동과 수명

출석/봉사/후속 업무는 ChurchOS 정본 운영 사실로 남긴다. Academy 수강·통독·기도방·일기/너랑나랑 공유를 자동 변경하지 않는다. Academy에 행사 출석 참조를 보낼 경우 목적/필드/수신자/동의/철회 계약이 필요하며 출석을 수료로 자동 등치하지 않는다. CHGO 입력은 계약 전 없음, 기존 허용 집계 기준·소집단/차분 억제를 완화하지 않는다.

보유/삭제는 출석 원본·정정 이력·봉사 제안/의사·배정 이력·후속 최소 업무·연락 사본·감사·기기 참조·백업을 구분한다. 일반 요청 조회168h·특정 정정/종료 최소 이력1년·서류 백업30일을 모든 운영 기록에 확대하지 않는다. 법정 기간이나 새 숫자를 이번 문서로 정하지 않는다.

오프라인 관리자 실행 대기열·민감 명단 영구 캐시를 추가하지 않는다. 412/중복/응답 불명·권한 해제·다른 계정/교회 전환·복원은 r29 요청 계약과 각 업무 고유 조건을 함께 대조한다. 출석 QR/대량 등록/노트 자유 입력 등 미구현 버튼을 실제 제공처럼 표시하지 않는다.
