## 읽는 기준

이 표는 화면→행위→권한→정본 데이터→실패 처리→수용 조건을 같은 행에 연결한 인계 문서다. 권한 이름/신규 API·저장 구조·화면 배치는 아직 후보이며, 기존 합의와 기술 미결을 구분한다. 새 정책·역할·기간을 승인하거나 코드 작업을 시작한 것이 아니다.

[CSV 원본](BASIC_MVP_HANDOFF.csv)은 이 문서 표의 전체 열을 제공한다. 두 표는 같은 행 데이터에서 생성한 표현이다. 상세 source와 baseline은 CSV 및 각 근거 문서에서 확인한다. [r35 미결18개](IMPLEMENTATION_BLOCKERS.csv)의 ID는 의존 항목이며 해소된 것으로 보지 않는다. 표시한 B항목만 충족하면 완성이라는 전수 판정도 아니다.

## 범위

교인·목회자·관리자는 같은 앱에서 기본 업무를 처리한다. 서버/인증/백업은 필요하며 별도 관리자 웹을 필수로 하지 않는다. 플랫폼 심사·서명·스토어·복구 업무는 목적별 별도 주체다. ChurchOS가 개인 영성 기록의 원본이나 전문제품의 권한 원장이 되지 않는다.

MVP의 중심은 인증/교회 문맥→가입/권한→홈/공지/일정→공동체/출석/봉사/후속 업무다. 설교 수동경로·기도/말씀·Academy 연결·브랜드·복원도 인계 경계에 포함하되 제공자/권리/운영 게이트를 별도 표시했다. 회계·헌금·시설예약·직접영상호스팅·자동영성평가·민감 관리자 오프라인 쓰기 대기열은 이번 범위에 추가하지 않는다.

## 구현 순서 후보와 경계

1. 인증·ChurchOS 이용·교회 선택·서버 현재권한 계약을 먼저 고정한다. 최초 개설과 일반 교인 승인은 순환 없이 분리한다.
2. 가입/역할 및 보호 홈의 상태를 목업으로 연결하고, 실제 식별·상태·미결 정책이 정해진 뒤 API/DB 계약과 함께 구현한다. 가입 대기 공개 화면에 기존 인증 내부 API를 전용하지 않는다.
3. 공지/일정은 기존 API와 새 수정본/게시본·위임권한의 차이를 메운다. 기존 PATCH가 게시행을 즉시 바꾸는 것을 초안 저장으로 연결하지 않는다. 기존 ETag/If-Match/24시간 성공 재생을 보존하고 버전 개정을 설계한다.
4. 공동체·출석·봉사·후속 업무는 DB가 있다는 이유로 CRUD를 바로 노출하지 않는다. 행위별/대상별/필드별 ACL·상태·역사 대상·정정·보유를 먼저 계약한다. 공동체 가입/이동/리더·명단·종료는 r37 상세 초안과 연결하며 정책 승인/API 구현은 미완료다.
5. 설교 수동경로와 제공자 기능을 별도 의존 게이트로 연결한다. CHGO 자동초안/Academy 지연이 교회 공지·일정의 장애가 되지 않게 한다. 기도/성경의 기존 기본 기능 방향은 유지하며 실제 API·콘텐츠 권리 미확보를 준비 완료로 표시하지 않는다.
6. 브랜드·서명/배포·삭제/백업/격리 복원·운영 담당과 실제 통합 검증은 공개 전에 각각 충족한다. 현재 파일럿·에뮬레이터·본격 코드는 계속 보류한다.

## 모든 행에 적용할 공통 수용 조건

- 서버가 현재 계정/서비스 상태·선택 교회·소속·행위/대상/기간/필드를 확인한다. 앱 메뉴 숨김은 보안 검사가 아니다.
- 다른 교회·다른 계정·권한 없는 원문의 제목/미리보기/개수/첨부/이벤트/로그도 노출하지 않는다. 개인 영성 원문/토큰/비밀을 일반 운영 로그에 넣지 않는다.
- 계정/교회 전환과 해제 이후 늦은 응답을 새 문맥에 붙이지 않는다. 온라인 확인 불가와 빈 목록/성공을 구분한다. 관리자 쓰기를 오프라인 자동 재실행하지 않는다.
- 쓰기 성공은 서버의 유효 확정 증거로 판단한다. 타임아웃을 실패/성공으로 단정하지 않고 결과 확인 후 명시 동작한다. 동시성·멱등성 규칙은 각 업무 계약을 따른다.
- 일반업무 본인 최소조회168시간/다섯 필드는 가입 심사·공통 종료·제공자 API에 자동 적용하지 않는다. 특별 조회의 본인확인/공개범위를 별도로 검증한다.
- 운영본/첨부/검색/캐시/외부처리자/백업·최소 이력은 각각 수명/완료 증거가 필요하다. 탈퇴/철회/공개 종료를 전부 물리 삭제와 같게 처리하지 않는다.
- 목업 성공·기존 canonical PASS·CSV 수용 문구는 실제 새 기능의 PASS가 아니다. 이번 행의 execution_status는 모두 NOT_RUN이다.
