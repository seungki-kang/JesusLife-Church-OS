# 교회 소개 게시 권한·공개 종료·검색과 캐시 — MVP33 상세 계약

2026-11-10 / TECHNICAL_DRAFT / 기준: main 904f71b + 현 작업 브랜치의 COS-CHURCH-041 / 실행 NOT_RUN

[화이트라벨 설계](WHITE_LABEL_SETTINGS_DISTRIBUTION_DRAFT.md#교회-소개-항목의-설정과-게시-계약-초안)의 후속이다. 합의된 제품 방향은 [COS-CHURCH-041](../docs/decisions/DESIGN_DECISIONS.md#cos-church-041)이다. 교회는 목회철학·사명·비전을 각각 추가하거나 셋 다 생략할 수 있다. 아래 권한 매핑·경로·캐시·이력은 구현과 운영 검토에 사용할 후보이며 이번에 승인된 새 정책은 아니다. 인물 소개·사진의 본인 동의와 철회는 [별도 인계 판정](LEADER_INTRO_INTEGRATED_REVIEW_4_HANDOFF_VERDICT.md)을 따른다. 기존 공지·행사·외부 서비스는 이번 계약으로 변경하지 않는다.

## 앱에서 하는 작업과 권한

앱의 ‘교회 관리 → 우리 교회 소개’에서 **항목 고르기 → 작성 → 공개 대상과 배치 → 대상별 미리보기 → 변경 확인 → 게시** 순서로 진행한다. 미선택 항목은 본문 입력을 요구하지 않는다. ‘이번 게시에서 내리기’는 변경 요약에서 별도로 표시한다. 글을 내리는 결정은 홈 카드만 빼는 동작이나 물리 삭제와 다르다.

| 주체 | 허용 범위 후보 | 차단할 행위 |
|---|---|---|
| 담임목사 | 교회 도입과 목회 방향 결정. 이미 해당 작업 권한이 있다면 앱에서 직접 실행 | 직함·비용 결제·교회 소개 작성자라는 이유로 편집·게시 권한 자동 획득 |
| 해당 교회의 유효 관리자 | 첫 구현의 기본 편집·게시 주체 후보. 두 권한을 분리 판정하고 자격 있는 동일인이 둘 다 맡을 수 있음 | 다른 교회 작업·플랫폼 운영권·과거 권한으로 쓰기 |
| 편집만 위임받은 담당자 | 같은 교회에서 초안 조회·저장·방문자/교인 미리보기. 기존 업무 위임의 유효성·범위 검사 | 게시·게시 종료·다른 사람에게 권한 재위임·교인 신분을 바꾸는 미리보기 |
| 게시를 위임받은 담당자 | 별도 위임이 채택되는 경우, 같은 교회의 검토 대상 초안 읽기·미리보기·게시 또는 내리기 | 편집 권한 없이 본문 수정·대상 임의 확대·위임 부여 |
| 방문자·가입 대기자 / 유효 교인 | 방문자와 가입 대기자는 공개 게시본만, 유효 교인은 해당 교회 교인 대상까지 | 초안/미리보기·접근 불가 항목의 제목·본문·개수 조회 |

초기 권장안은 **유효 관리자 게시 + 범위를 정한 편집 위임**이다. 별도 게시 위임은 후속 범위로 두는 것을 권장한다. 담임목사 전용 승인 화면, 두 사람의 강제 승인, 자동 게시·예약 게시를 첫 범위에 넣지 않는다. 관리자 및 업무 위임의 구체 적용은 [기존 권한 계약](ONBOARDING_APP_STATE_CONTRACT_DRAFT.md#특별-권한과-일반-업무-위임을-구분)을 기준으로 매핑을 확정한다. 권한을 부여하는 새 역할/기간은 이번에 만들지 않는다.

쓰기 확정 직전에 서버가 계정·선택 교회·소속·현재 업무 권한을 다시 검사한다. 동일 교회의 역할 해제와 게시가 경합하면 최종 순서를 판정할 수 있어야 한다. 해제가 먼저 유효하게 확정되면 게시를 거부한다. 게시가 먼저 유효하게 확정된 경우 권한 해제만으로 게시본을 소급 삭제하지 않는다. 권한 상태를 검증할 수 없으면 게시를 확정하지 않는다. 교회 전환·로그아웃·권한 상실 후 도착한 늦은 미리보기는 화면에 붙이지 않는다.

## 상태·정본·API 후보

| 분리할 상태 | 의미 및 정본 |
|---|---|
| 초안 구성 | 교회별 선택 항목, 본문, 대상, 배치와 초안 버전. 미선택 항목의 새 레코드를 생성할 필요 없음 |
| 게시본 | 해당 교회의 단일 현재 게시 버전과 게시된 항목 참조. 선택된 초안을 저장했다고 게시본이 바뀌지 않음 |
| 공개·배치 | 대상은 공개 또는 현재 유효 교인 후보. 홈에 배치하지 않아도 소개나 기존 링크에서 열 수 있는지 게시 범위로 판단 |
| 종료·재추가 | 게시 대상에서 제거하면 이전 본문이 현재 게시본을 통해 열리지 않음. 재추가는 새 초안/새 게시이며 운영 기록 삭제는 별도 |
| 파생 사본 | 검색 인덱스·화면 메모리·전달 캐시. 현재 게시본과 대상 권한을 대신하지 않음 |

ChurchOS 서버가 게시본을 소유한다. 도메인/교회명 변경으로 소속·교회 ID를 바꾸지 않는다. 예전 링크에는 교회와 항목의 안정된 참조만 두고 버전별 원문에 직접 접근하게 하지 않는다. 현재 게시 대상이 아니거나 권한이 없는 직접 링크에는 동일한 일반 안내를 사용한다. 네트워크/서버 상태 미확인과 게시 종료는 앱 안내에서 구분한다.

| 작업 이름 후보 | 입력과 사전 조건 | 응답·실패 경계 |
|---|---|---|
| 관리 초안 읽기·저장 | 현재 교회·편집권·기준 초안 버전·변경 항목 | 새 초안 버전 또는 충돌. 미선택 항목은 본문 없이 저장 가능. 공개 조회 변경 없음 |
| 대상별 미리보기 | 현재 관리 권한·교회·초안 버전·대상 | 운영 공개본이 아닌 미리보기. 다른 교회나 버전과 혼합하지 않음 |
| 게시·게시 대상 제외 | 현재 교회·게시 권한·미리 본 초안 버전·기준 게시 버전·중복 방지 키 | 같은 트랜잭션에서 게시 참조와 최소 이력·후속 작업 근거를 반영하는 후보. 충돌·권한 실패 시 부분 게시 없음 |
| 게시 결과 확인 | 현재 교회·권한 및 해당 시도의 참조 | 기존 확정 결과를 확인. 응답 유실을 실패로 단정하거나 새 게시를 자동 실행하지 않음 |
| 홈·소개·검색·직접 링크 읽기 | 교회 참조·현재 대상 판정·현재 게시 참조 | 허용 필드만 반환. 초안·숨겨진 항목·교인 전용 내용을 공개 응답에 합치지 않음 |

실제 경로·스키마·오류 코드·보유 기간은 미결이다. [일반 중복 방지 기준](COMMAND_IDEMPOTENCY_STATUS_CONTRACT_DRAFT_2026-10-27.md)의 자원별 경로·If-Match·Idempotency-Key를 우선 대조한다. 기존 성공 재생 24시간을 새 게시 결과 보유 기간으로 확정하지 않는다. 개인 소개 철회의 168시간 조회 계약도 이 기능에 옮기지 않는다. 서버가 미리보기 버전과 현재 게시 버전 두 조건을 비교하는 방법, 최종 권한 경합의 판정 방법, 중복 키 만료 후 불명 결과 확인 방식은 구현 전 확정한다.

## 게시를 내린 뒤의 조회·검색·캐시

**권장 흐름:** 게시 참조 교체가 확정되는 시점부터 새로운 서버 읽기는 현재 게시본으로 판정한다. 검색 인덱스 삭제나 앱 캐시 무효화가 끝날 때까지 이전 글이 계속 열리는 구조는 피한다. 이미 기기에 표시된 화면과 ChurchOS 밖으로 전달된 사본은 서버의 새 읽기와 따로 다룬다.

| 표면 | 새 읽기 차단과 정리 후보 | 실패·지연 시 |
|---|---|---|
| 홈·소개·직접 링크 | 현재 게시본과 대상이 일치할 때만 본문·제목을 제공 | 이전 호환 브랜드 구성이 있어도 소개 본문은 대체 노출하지 않음 |
| ChurchOS 검색 | 첫 범위는 별도 검색 인덱스를 새로 만들지 않음. 기존 검색 경로가 있다면 현재 게시본 확인 후 제목·본문 조각·개수를 생성 | 이전 인덱스가 남아도 사용자가 볼 결과에는 포함하지 않음. 파생 사본 제거 완료는 별도 확인 |
| 앱 화면과 미리보기 | 교회·계정·권한 변경 시 관리 미리보기 제거. 소개 화면 재진입·앱 복귀 시 다시 확인. 늦은 응답은 교회·대상·버전을 비교 | 이미 열린 화면의 제거 시간은 별도 수용 기준 필요. 첫 범위는 오프라인 본문·미리보기 미제공 권장 |
| CDN·공유 전달 캐시 | 소개 본문과 미리보기는 공유 캐시를 사용하지 않는 방향. 배포 전 실제 응답·중간 계층 정책 확인 | 캐시 무효화 지연에도 현재 접근 검사를 건너뛰는 경로가 없어야 함 |
| 외부 검색·메신저·스크린샷 | ChurchOS의 원본 링크는 현재 상태로 응답. 외부 공개 검색 제공은 첫 범위에서 제외 권장 | 이미 외부에 저장된 미리보기·사본의 회수나 즉시 삭제는 보장할 수 없음 |

[REC-006의 공개 캐시](RECOVERY_DECISIONS.md)와 공개 예배 안내 등 기존 제한 캐시는 이 설계로 수정하지 않는다. 목회철학·사명·비전의 새 본문을 기존 캐시에 넣을지, 온라인 확인만 허용할지는 적용 범위를 명시해 결정한다. 캐시 상한의 달력 7일/168시간 여부는 기존대로 미결이다. SSO의 60초 기준을 게시 철회에 그대로 적용하지 않는다.

## 기록·장애·복구

| 상태나 사건 | 필요한 운영 처리 |
|---|---|
| 게시 전 충돌·권한 실패 | 저장하지 않은 변경과 서버 게시 상태를 분리해 안내. 최신 권한으로 볼 수 없는 초안·본문을 오류에 넣지 않음 |
| 게시 응답 유실 | 게시 결과를 확인하고, 확정 증거가 없으면 완료로 표시하지 않음. 새 버전 자동 발행 금지 |
| 본문 접근 종료와 파생 사본 정리 | 사용자 조회 차단과 검색·캐시 정리 완료를 별도로 기록. 정리 재시도는 동일 교회·게시 버전에 대해 반복 가능해야 하며 새 게시본을 제거하지 않음 |
| 최소 감사 이력 | 교회, 작업자 참조, 행위, 이전/이후 버전, 서버 확정 시각, 결과 등 최소 필드 후보. 일반 로그·이벤트·푸시에 본문이나 보호 정보 금지 |
| 원본·과거 버전·감사·백업 | 현재 게시본, 편집 초안, 과거 버전, 최소 감사, 파생 사본, 백업을 기록 종류별로 다룸. 게시 종료만으로 보유 기간이 일괄 시작·연장되거나 물리 삭제되지는 않음 |
| 복구 | 설정 복구는 현재 권한과 최신 게시 종료·삭제·공개 대상 제한을 다시 적용한 뒤 공개한다. 오래된 설정·복원본이 내려간 항목을 자동으로 재게시하지 않음 |

보유/폐기 기한은 기록별 목적·기산점·열람 주체·삭제 증거를 정한 뒤 확정한다. 기존 개인 데이터나 다른 업무에 합의한 기한을 새 교회 소개 기록에 일괄 적용하지 않는다.

## 개발 순서와 통과 조건

1. **설계 결정:** 초기 게시 주체·편집 위임 매핑, 공개/교인 대상, 본문 온라인 확인 범위를 결정한다. B02(권한), B03(확정과 결과 확인), B06/B09(본문 및 기기 처리), B17(설정 호환)과 연결하되 차단이 해소됐다고 보지 않는다.
2. **계약과 화면 인계:** 앱 화면 문구와 검토·실패 흐름, 초안/게시 버전, 서버 작업별 입출력 및 정본 참조를 연결한다. v2.6 스냅샷과 구버전 앱이 새 필드를 잘못 해석하지 않는 전환 방식을 확인한다.
3. **구현 승인 이후 검증:** W29~W31, W33~W52를 API/앱에서 각각 실행한다. 권한 경합·검색 지연·응답 유실·백업 복원을 포함한다. 검증 전에는 실제 교회 공개를 준비 완료로 표시하지 않는다.
