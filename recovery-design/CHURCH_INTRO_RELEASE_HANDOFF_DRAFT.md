# 교회 소개 출시 1차 인계 — 정책 선택·화면·API·기록 수명

2026-11-10 / DESIGN_REVIEW + TECHNICAL_DRAFT / 기준 904f71b + COS-CHURCH-041 작업 브랜치 / 실행 NOT_RUN

[교회 소개 게시 상세 계약](CHURCH_INTRO_PUBLICATION_CONTRACT_DRAFT.md)을 개발 전에 검토할 수준으로 구체화한다. 합의된 범위는 [COS-CHURCH-041](../docs/decisions/DESIGN_DECISIONS.md#cos-church-041)의 독립적인 추가·생략과 담임목사 도입 결정이다. 아래 권한 매핑, 경로, 처리 방식과 보유 기한은 운영 승인 또는 구현 완료가 아니다. 인물 소개·사진 철회, 공지·행사, 프로그램 신청, 전문 제품 연동에는 적용하지 않는다.

## 1차 범위와 정책 선택

| 검토 항목 | 기존 근거와 경계 | 1차 권장안과 남은 결정 |
|---|---|---|
| 편집·게시 주체 | [REC-001~004](RECOVERY_DECISIONS.md)의 일반 위임 원칙을 검토한다. REC-002의 편집/게시 분리는 공지·행사 범위다. 교회 개설·최초 관리자 지정과 담임목사 직함은 별개다. | 유효 관리자가 게시한다. 유효 관리자가 초안을 편집하거나 수락한 일반 업무 담당자에게 **소개 편집만** 위임한다. 같은 유효 관리자가 편집과 게시를 할 수 있다. 소개의 별도 게시 위임과 의무 이중 승인은 1차에서 제외하는 후보. 기존 위임에 추가할 행위 범위·수락/종료 적용을 명시적으로 결정한다. |
| 온라인 확인과 읽기 | [REC-005/006](../RECOVERY_README_2026-10-26.md#5-오프라인)은 이전에 확인한 공개 교회 소개·예배 일정에 제한 캐시를 허용한다. 7일은 마지막 서버 유효 확인 기준이고 단위는 미결이다. | **새 선택형 목회철학·사명·비전 본문**은 서버 확인이 가능한 경우에만 표시하는 후보. 브랜드 호환본·기존 공개 예배 안내와 저장 단위를 분리한다. 세 항목을 REC-005/006의 기존 캐시 허용 범위에서 제외할지 명시적으로 결정한다. 채택 전에는 새 본문 오프라인 노출·배포를 확정하지 않는다. |
| 기록 보유 | [기록 교차 검토](CROSS_DOMAIN_RETENTION_REVIEW.md)의 공개 차단·운영본 삭제·백업 만료·최소 이력 분리를 사용한다. 다른 업무에서 정한 수치는 목적이 다르다. | 첫 범위는 과거 본문 보관함과 과거 설정 원클릭 복원을 제공하지 않는다. 운영·백업에 남는 기록의 실제 삭제 기한과 증거까지 정한 후 실데이터를 받는다. 아래 표의 기산점은 검토 후보이며 임의 기본 기간을 적용하지 않는다. |

텍스트로 작성하는 세 항목만 다룬다. 항목을 선택했더라도 미완성 내용은 초안에만 남는다. 예약 게시·외부 검색 노출·첨부 이미지·과거 본문 버전 열람 UI는 첫 범위에서 제외하는 후보로 둔다.

## 앱 화면과 동작

| 화면 또는 전환 | 표시와 사용자 동작 | 실패·권한 처리 |
|---|---|---|
| 교회 관리 → 우리 교회 소개 | ‘목회철학 추가’, ‘사명 추가’, ‘비전 추가’. 처음에는 선택하지 않아도 다음 단계로 이동 가능. 이미 게시한 항목은 ‘게시 중’, 수정 중이면 ‘게시본과 다른 초안 있음’ | 권한이 없는 계정에는 관리 진입을 제공하지 않고 서버도 직접 요청을 거절. 교회 전환 시 이전 편집 문맥을 사용하지 않음 |
| 편집 | 본문·보여줄 대상·홈 배치. ‘초안 저장’은 성도 화면을 바꾸지 않음. ‘이 항목 내리기’는 다음 게시 변경에 포함 | 공백 본문은 초안에서 가능. 게시 시 추가·유지할 항목에만 본문 검사를 적용. 만료 권한으로 오프라인 쓰기 예약 금지 |
| 미리보기 | ‘방문자 화면’·‘교인 화면’에서 각 대상의 실제 표시와 홈 배치를 비교. 초안임을 분명히 표시 | 미리보기에는 관리 권한 필요. 교인 대상 화면을 미리 봐도 실제 교인 권한이 생기지 않음. 관리 문맥 해제 시 미리보기 폐기 |
| 게시 전 확인 | ‘추가 / 수정 / 홈에서만 빼기 / 게시 종료’와 공개 대상 변경을 분리 표시. 운영 기록 삭제와 분리 | 변경 요약을 본 버전이 바뀌면 다시 미리보기. 게시 권한을 잃으면 게시 차단 및 이전 게시본 유지 |
| 게시 결과 | ‘게시 완료’, ‘변경사항을 다시 확인해 주세요’, ‘처리 결과를 확인하고 있어요’를 구분 | 결과 확인 불가 시 완료·실패로 단정하지 않음. 조회 권한이 사라지면 최소 안내만 표시. 신규 게시 자동 실행 금지 |
| 방문자·교인 홈/소개/직접 링크 | 현재 게시 대상 중 열람이 가능한 항목만 표시. 모두 없으면 소개 섹션을 생략하되 다른 교회 기능은 유지 | 연결 실패와 게시 대상 아님을 구분. 접근 불가·미게시의 내부 사유나 존재를 노출하지 않음 |

**예시:** 공개된 사명을 홈에서만 빼면 ‘우리 교회’와 허용된 링크에서 계속 읽을 수 있다. 같은 사명을 ‘교인만’으로 변경해 게시하면 방문자와 가입 대기자의 이전 링크에는 본문이 나오지 않는다. 사명 자체를 내리면 교인도 이전 링크에서 읽을 수 없다. 항목을 다시 넣는 경우 새 검토와 명시적인 게시가 필요하다.

## 서버 입출력과 확정 순서 후보

경로 표기는 자원 경계를 검토하기 위한 예시다. 기존 [중복 방지 계약 대조](COMMAND_IDEMPOTENCY_STATUS_CONTRACT_DRAFT_2026-10-27.md)와 [화이트라벨 구현 대조](WHITE_LABEL_BASELINE_ALIGNMENT.md)를 우선한다. 아래 API 경로와 스키마는 미구현·미승인 상태다.

| 경로 후보 | 주요 입력 | 출력·경계 |
|---|---|---|
| GET /manage/church-intro/draft | 현재 교회 관리 문맥 | 권한 범위의 초안, 초안 버전, 기준 게시 버전. 버전 참조는 교회 범위에서만 유효 |
| PUT /manage/church-intro/draft | 초안 조건부 버전, 선택한 항목의 본문·대상·배치, 게시 종료로 표시한 항목 | 새 초안 버전. 미선택 항목의 빈 본문이나 공개 여부를 강제하지 않음 |
| POST /manage/church-intro/preview | 대상, 초안·기준 게시 버전 | 대상별 렌더링 결과와 검토 기준. 관리 응답에만 전달. 실제 게시/권한 변경 없음 |
| POST /manage/church-intro/publications | 초안·기준 게시 버전, 조건부 쓰기 조건, Idempotency-Key | 확정된 게시 버전·최소 결과 참조. 클라이언트가 보낸 본문·대상으로 서버 초안을 우회하지 않음 |
| GET /manage/church-intro/publication-result | 원 요청을 식별할 최소 참조 후보 | 같은 교회에서 현재 결과 확인 자격이 있을 때 최소 결과만. 원문 없음. 응답 유실 시 찾을 수 있는 참조와 조회 기한은 확정 필요 |
| GET /church-intro 및 항목 상세 | 서버에서 확인한 교회·대상 문맥 | 현재 게시본과 대상에 일치하는 항목만. 교인 여부를 클라이언트의 대상 문자열로 결정하지 않음 |

게시에서는 **권한 재검사 → 중복 요청 판별 → 미확정 새 요청의 초안·게시 버전 대조 → 현재 게시본 교체와 결과 증거 저장** 순서가 후보이다. 이미 확정된 동일 요청은 현재 접근 자격 확인 후 기존 결과를 재사용한다. 게시 성공으로 버전이 바뀌었다는 이유로 같은 요청의 결과를 충돌로 바꾸지 않는다. 같은 키로 요청 내용이 바뀌면 새 게시로 처리하지 않는다. 결과는 원문 없이 반환하며 키 만료를 게시 실패의 증거로 해석하지 않는다. 조건부 요청·오류 코드·권한/게시 경합·멱등 결과 저장 방식은 구현 전 확정한다.

게시 참조·최소 감사·후속 작업 근거는 같은 확정 단위로 처리하는 후보를 유지한다. 검색 정리가 늦어져도 공개 읽기는 현재 게시본을 직접 확인한다. 새 게시가 확정된 뒤 예전 정리 작업이 재실행되면 예전 버전의 파생 사본만 정리한다.

## 구현 게이트

- **정책 검토:** 1차 게시 주체와 편집 위임 적용 범위, 새 선택형 본문의 온라인 확인 정책, 기록별 보유 목적·책임자·기간을 확정한다. 접근 차단과 물리 삭제의 시점을 분리한다.
- **기술 검토:** v2.6 기존 API·스키마와 충돌하지 않는 경로 및 버전 조건, 응답 유실 결과 확인, 현재 권한 경합, 구버전 앱 호환, 실제 캐시 전달 설정을 검증할 명세로 만든다.
- **실데이터 전:** 만료·정리·격리 복구 절차를 확인한다. 공개본을 보호하기 위해 파생 사본 정리에 의존하지 않는다. 유효한 게시나 새 버전을 예전 복구·정리 작업으로 되돌리지 않는다.
- [검증 시나리오 W53~W62](WHITE_LABEL_ACCEPTANCE.csv)는 이 인계의 신규 조건이다. [개발 인계표 MVP33](BASIC_MVP_DEVELOPMENT_HANDOFF.md#통합-인계표)와 함께 읽는다. 승인 기록·실행 증거가 생기기 전에는 B02/B03/B06/B09/B17을 완료 처리하지 않는다.
