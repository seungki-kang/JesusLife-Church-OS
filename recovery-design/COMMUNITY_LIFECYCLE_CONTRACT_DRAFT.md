## 적용 근거와 제안 범위

[기준선](COMMUNITY_BASELINE_ALIGNMENT.md), [가입/역할 계약](ONBOARDING_APP_STATE_CONTRACT_DRAFT.md), [업무 계약](ATTENDANCE_SERVICE_FOLLOWUP_FLOW_DRAFT.md), [콘텐츠 계약](HOME_NOTICE_EVENT_FLOW_DRAFT.md), [기록 수명](CROSS_DOMAIN_RETENTION_REVIEW.md)을 이어 작성한다. 교회 가입 수동 승인과 일반 업무 위임 합의는 유지한다. 그러나 **공동체 가입 방식·배정 수락·이동 확정 방식·일반 구성원 명단 범위는 이번에 새로 제안하는 정책**이며 AGREED가 아니다. r37 작성 당시 새 합의는 없었다. r38에서 참여 대상 자격만 [REC-033](RECOVERY_DECISIONS.md#rec-033-공동체-참여-대상)으로 확정했다. r39에서 본인 신청 수동 승인과 그 승인 주체만 [REC-034](RECOVERY_DECISIONS.md#rec-034-공동체-본인-신청-수동-승인)로 추가 확정했다. r40에서 배정 제안의 본인 수락 후 활성화만 [REC-035](RECOVERY_DECISIONS.md#rec-035-공동체-배정-제안-본인-수락)로 추가 확정했다. r41에서 배정 제안 수락기한은 [REC-036](RECOVERY_DECISIONS.md#rec-036-공동체-배정-제안-수락-기한)으로 확정했다. r42에서 제안 생성 주체는 [REC-037](RECOVERY_DECISIONS.md#rec-037-공동체-배정-제안-생성-권한)으로 확정했다. r43에서 심사/배정 담당 지정·해제 주체는 [REC-038](RECOVERY_DECISIONS.md#rec-038-공동체-담당자-지정해제-주체)으로 확정했다. r44에서 담당자의 해당교회 가입승인 유효소속 자격은 [REC-039](RECOVERY_DECISIONS.md#rec-039-공동체-담당자-대상-자격)로 확정했다. r45에서 담당권한 본인수락 후 활성화는 [REC-040](RECOVERY_DECISIONS.md#rec-040-공동체-담당-권한-본인-수락-후-활성화)로 확정했다. r46에서 담당 지정 수락기한은 [REC-041](RECOVERY_DECISIONS.md#rec-041-공동체-담당-지정-수락-기한)으로 확정했다. r47에서 심사/배정 담당 임기·연장 기간기준은 [REC-042](RECOVERY_DECISIONS.md#rec-042-공동체-담당-임기연장-기간-기준)로 확정했다. r48에서 담당 소속상실 즉시차단·회복후 관리자재지정/본인수락은 [REC-043](RECOVERY_DECISIONS.md#rec-043-공동체-담당-소속상실권한회복)으로 확정했다. r49에서 권한상실 제안자의 미수락 배정 제안은 [REC-044](RECOVERY_DECISIONS.md#rec-044-권한상실-제안자의-미수락-배정-제안)로 보류/현재관리자 재확인·원168시간 불변을 확정했다. r50에서 재확인 중 대상교인/공동체 변경은 [REC-045](RECOVERY_DECISIONS.md#rec-045-재확인-시-대상공동체-변경-제안)로 기존취소이력/새제안·본인수락을 확정했다. 해당 공동체 참여필수 여부·재확인 다른결과/취소권한·경합 등은 미확정이다.

확정된 자격은 해당 교회의 가입 승인된 유효 소속 교인만 신규 참여 대상으로 삼는 것이다(REC-033). 본인 신청은 REC-034의 관리자/명시 참여심사 담당자 승인 후 참여로 확정했다. 배정 제안의 본인 수락 후 활성화는 REC-035로 확정했다. 나머지 권장안은 ① 이동은 대상 공동체 참여가 확정되기 전 기존 참여를 자동 종료하지 않기 ② 일반 구성원에게 전체 명단·연락처를 자동 공개하지 않기다. 교회별 자동승인/자유가입/의무배정은 별도 승인 전 제공하지 않는 후보안이다. 아래 구체화는 REC-033 자격·REC-034 본인 신청 수동 승인·REC-035 배정 본인 수락을 제외하고 제안 범위로 읽는다.

## 1. 독립 상태와 권한 축

| 축 | 의미 | 자동으로 따라오지 않는 것 |
|---|---|---|
| 교회 소속 | 교회 전체의 대기/유효/정지/탈퇴 | 공동체 자동 가입·리더·제품 공유 |
| 공동체 수명 | 운영중/모집중지/보관 후보 상태 | 구성원 삭제·역사 출석 수정·다른 제품 종료 |
| 참여 의사/심사 | 본인 신청·배정 제안·취소·수락/거절 | 아직 활성 참여 아님 |
| 실제 참여 | 현재 유효한 해당 공동체 관계 | 교회 관리자·연락·명단·게시/출석 권한 |
| 리더 직함 | 대상 공동체의 책임/표시 | 일반 업무 관리권한 전체 |
| 업무 위임 | 행위·대상·시작/종료·본인수락에 따른 권한 | 재위임·하위공동체·다른교회 권한 |
| 공유/콘텐츠 권리 | 연락 사용·기도방·교육·개인 공유 | 공동체 소속만으로 전체 공개 |

공동체 참여 관계와 현재 접근 제한을 분리한다. 교회 정지로 접근이 막혔다고 과거 참여 사실을 삭제하지 않는다. 정지 해제/재가입 때 공동체 참여를 자동 회복할지 재확인할지는 OPEN이며, 추가 위임·개인 공유 자동복원은 허용하지 않는다. 현 ACTIVE/INACTIVE enum만으로 위 상태를 표현했다고 간주하지 않는다.

## 2. 목록·소개·대상 선택

유효 교인이 본인이 볼 수 있는 공동체 소개와 내 참여 상태를 확인한다. 비소속/대기자의 공동체 검색·공개 소개 여부는 별도 공개 정책이 없으면 교회 공개 소개 범위로 제한한다. 존재하지 않는 공동체와 권한 없는 공동체를 구분하는 응답으로 비공개 조직을 추정하게 하지 않는다.

[REC-046](RECOVERY_DECISIONS.md#rec-046-복수-공동체-참여와-권한-독립)에 따라 같은 교회에서 복수 공동체 동시참여를 허용한다. 공동체별 승인/역할/권한은 독립이다. 주공동체를 하나만 둘지·동일 종류별 제한/상한은 OPEN이다. 현재 unique(교회,공동체,교인)는 같은 공동체 중복 방지이지 전체 공동체 하나 제한이 아니다. 이름/가족/전화번호로 사람을 합치거나 자동 소속시키지 않는다. 미성년자/방문자/외부봉사자·보호자 경로는 별도 설계 전 활성 교인처럼 등록하지 않는다.

## 3. 가입·배정 정상 동선 — 권장안

### 본인 신청

소개/참여 조건 확인→본인 신청→권한 담당자 검토→현재 자격·요청 버전 재확인→참여 확정/거절→본인 최소 결과. 교회 가입 심사 권한만으로 공동체 참여를 심사하지 않는다. 본인 신청 승인 권한은 REC-034에 따라 해당 교회 현재 유효 관리자 또는 해당 공동체 명시적 참여심사 권한을 받은 유효 담당자로 한정한다. 배정 제안·강제 종료 등 다른 관리행위를 이 심사 권한에 자동 포함하지 않는다. 리더 직함만으로 처리 권한을 만들지 않는다.

같은 교회/본인/공동체에 상충 대기 건을 하나로 제한하는 후보를 두고, 이미 참여 중이면 새 참여 대신 현재 상태를 안내한다. 구체 중복키·신청과 배정 제안의 경합 처리·신청 수정 가능 필드는 OPEN이다. 종료 결과를 재신청으로 덮어쓰지 않는다. 심사 자유 사유/신앙평가/개인 원문은 수집하지 않으며 필요한 거절 코드·본인 안내 범위는 별도 확정한다. 교회 가입의 사유2종을 공동체 거절에 그대로 복사하지 않는다.

### 관리자/담당자의 배정 제안

REC-037에 따른 해당교회 관리자 또는 해당공동체 명시 배정 유효담당자가 같은교회 유효 대상·공동체·영향을 지정→본인이 제안을 확인/수락 또는 거절→서버가 최신 조건을 재확인해 참여 확정한다. 미수락 제안은 명단/콘텐츠 열람권을 만들지 않는다. 배정 제안에 본인 수락을 요구하는 것은 REC-035 합의다. 일반 업무 위임 규칙을 자동 이식한 것이 아니라, REC-036의 별도 합의로 서버 유효 제안 생성부터168시간 수락기한을 적용한다. 기한 도달 시 차단하고 필요하면 현재 자격 확인 후 새 제안한다. 알림 재전송으로 연장하지 않는다.

본인 신청은 이미 그 공동체 참여 의사를 표시한 것이므로 승인 후 재수락을 요구하지 않는 안을 제안한다. 신청 이후 내용/대상·교회 조건이 본질적으로 달라지면 옛 신청을 동의로 재활용하지 않는다. 해당 변경/재확인 세부는 OPEN이다.

### 취소·거절·확정 경합

미확정 신청/제안 취소와 이미 유효 참여 탈퇴를 구분한다. 승인/수락·취소가 경합하면 유효 조건을 재검증한 먼저 확정 결과 하나를 유지하는 기술 후보다. 중복 재시도는 참여/이력을 늘리지 않는다. 응답 유실은 결과 확인 우선이며 새 키로 자동 가입하지 않는다. 신청/제안·참여/이력의 일관 확정과 버전 계약이 필요하다.

## 4. 공동체 이동 — 확정 정책과 기술 초안

이동은 “새 공동체 추가 가입”과 다르다. REC-048에 따라 본인이 기존A→대상B·새 참여와 기존 참여 종료 영향을 함께 확인하고 명시적으로 동의한다. 역할/연락 범위 안내의 구체 필드와 동의 증빙은 별도 초안이다. 교인 ID를 교회 간 옮기거나 기존 출석/역사를 B로 다시 쓰지 않는다. 다른 교회로 이동은 기존 교회 탈퇴/새 교회 가입의 별도 절차다.

REC-047 확정 정책: 대상B 참여가 유효하게 확정될 때 A 종료+B 참여 확정을 함께 처리한다. 이동 의사·승인 주체/조건의 상세와 이동 이력의 기술적 일관 확정 방법은 별도 초안이다. 그 전에는 A를 자동 탈퇴시키거나 B명단을 미리 열어주지 않는다. 거절/취소/만료/통신 실패만으로 기존A를 잃지 않는다. 이미 확정된 이동은 단순 신청 취소로 소급 복구하지 않고 별도 새 이동/정정으로 처리한다.

이 정책은 같은 ChurchOS 교회 안의 이동에 대한 설계 합의다. 실제 원자적 구현은 TECHNICAL_DRAFT/NOT_RUN이며 정책 합의를 실행 검증으로 읽지 않는다. REC-049에 따라 A측 별도 승인은 요구하지 않는다. 본인 명시 동의와 B 유효승인은 필요하며 A측에는 권한 범위 내 결과 안내·별도 업무 인계를 연결한다. B 승인자는 REC-050에 따라 현재 해당 교회 관리자 또는 B 명시 참여심사 유효담당자로 한정한다. 리더 직함만으로는 불가하다. 주공동체 제한/동시 이동 정책은 OPEN이다. 기존 권한을 지나치게 유지하지 않도록 최종 확정 전 현재 계정/소속·A관계·B상태·요청버전·제한을 재검증한다. 충돌 시 최신 결과를 안내하고 자동 중간상태 보정을 하지 않는다.

이동은 A의 리더 직함·명단/연락·공지/출석/후속업무 위임을 B에 복사하지 않는다. A 범위 근거 상실 시 새 접근을 차단하고 진행업무/후임은 별도 처리한다. B에서 필요한 새 위임은 관리자 지정·본인 수락으로 시작한다. 행사후 역사 정정은 현재 별도 정정 권한으로 판단한다.

## 5. 리더·보조리더 지정과 인계

현재 관리자가 같은교회 유효소속·해당 공동체 현재 참여 자격을 확인해 리더 직함을 지정하고 본인 확인/수락을 받는 안을 제안한다. LEADER/ASSISTANT 문자열만으로 권한을 활성화하지 않는다. 실제로 필요한 명단조회/연락/참여심사/콘텐츠/출석/후속업무는 각각 목적·대상·기간·행위를 지정한다. 일반 업무 위임으로 분류된 부분에만 REC의 수락·기간·범위축소·해제 원칙을 적용한다. 리더 직함과 참여 기간 자체는 일반업무 최대1년으로 확정하지 않는다.

리더는 다른 리더/관리자를 임의 임명하거나 직접 권한을 재위임하지 않는다. 인계는 관리자 지정→후임 본인 수락→확정 후 현재 접근 재검증의 일반 업무 합의를 따른다. 기존 리더 해제는 후임 수락과 별개로 필요 시 집행하고, 공백은 권한 있는 관리자에게 최소 업무로 전달하는 후보다. 후임 미정 이유로 탈퇴/공통계정 종료 후 접근을 유지하지 않는다. 교회 마지막 관리자 보호를 “마지막 공동체 리더는 탈퇴 불가”로 확대하지 않는다.

리더 수·공동리더·직함 표시 범위·리더 임기/수락기한·직함과 위임 활성화의 원자성은 OPEN이다. 새로운 리더 자격 심사를 영적 점수·일기 작성량·기도 참여로 자동화하지 않는다.

## 6. 명단과 필드별 공개 — 보수적 권장안

| 주체 | 기본 표시 후보 | 별도 근거 없으면 숨김 |
|---|---|---|
| 비소속/가입대기 | 교회가 허용한 공개 소개 | 구성원 이름/관계·명단수·리더 개인정보 |
| 일반 공동체 참여자 | 본인 참여/요청 상태·허용 소개 | 타인 전체명단·연락처·출석·탈퇴/정지 사유 |
| 해당 범위 명단 담당 | 현재 위임 범위의 식별에 필요한 표시이름·참여 역할/상태 최소필드 | 생년월일/주소/가족·전체교회/하위조직 명단·인증 subject |
| 명시 연락 담당 | 현재 대상 범위·본인 별도 연락 선택이 유효한 최소 연락 필드 | 심사 제출 연락처 자동복사·철회 연락처·타 제품 개인기록 |
| 관리자 | 현재 교회 운영 목적·필드에 필요한 범위 | 비용지급/직함을 근거로 개인수첩/일기/관계 원문 |

REC-060에 따라 일반 참여자의 기본은 본인상태·허용소개·공개동의 리더소개이며 전체명단/연락처 자동공개는 없다. 동료 간 선택 공개 여부·필드는 OPEN이다. 이 표의 업무담당 최소필드는 별도 초안이다. 기존 상세 설계의 맡은 공동체 최소 범위도 현재 권한/배정과 필요한 필드로 구현한다. 이름·프로필사진·리더명도 무조건 공개된 값이 아니다.

검색·자동완성·이름 중복 안내·페이지 총수/배지·알림 수신목록·내보내기·최근본·공유 링크·다운로드까지 동일 범위/필드를 적용한다. 권한 없는 구성원을 제외한 뒤 목록/개수를 계산한다. 통계는 개인 추정/반복 질의 위험을 대조하고 소수 구성원을 0으로 바꿔 표시하지 않는다. 기본 파일 내보내기/연락처 일괄다운로드는 제공하지 않는 후보이며 필요하면 별도 목적·권한·기간·사본 관리 계약을 둔다.

부모 공동체 리더라고 자식명단·형제명단이 자동 열리지 않는다. parent 변경도 데이터 이동/권한 확장으로 간주해 명시 범위를 검토한다. 순환A→B→A·동시 부모변경·타교회 부모를 서버에서 차단하는 후속 계약이 필요하다. 공동체 계층만으로 다른 제품 기도방/수강/개인공유를 확장하지 않는다.

## 7. 참여 탈퇴·교회 소속 상실·조직 종료

본인 공동체 탈퇴는 교회 탈퇴/다른 공동체 종료가 아니다. 본인 명시 확인으로 현재 참여를 종료하고 해당 공동체 근거의 새 접근·미사용초대·구 문맥 응답을 차단하는 안을 제안한다. 진행 배정/후속업무가 있으면 권한 있는 관리자에게 이관 필요를 안내하되 종료 개인의 권한을 유지하는 해결법을 쓰지 않는다. 본인 탈퇴의 별도 담당 승인 불필요는 REC-057로 확정했다. 강제 참여 종료 주체·표준 사유/통지는 OPEN이다. 일반 교회 담당/가입심사 권한만으로 공동체 강제종료를 만들지 않는다.

교회 소속 정지/탈퇴·공통 보안정지/공통탈퇴는 각 원문 범위로 차단한다. 이미 유효한 역사 참여/출석을 소급 말소하지 않는다. 공동체 재가입/복구는 현재 자격·본인 의사를 새로 확인하고 옛 역할/위임/개인 공유를 자동 되살리지 않는다. 가입 정정으로 교회 소속이 회복되더라도 공동체 참여/리더/위임 재활성 세부는 별도 OPEN이다.

공동체 보관/종료는 물리삭제와 다르다. 관리자 또는 명시 조직관리 권한자가 영향(참여·신청·리더/위임·일정·봉사·업무)을 확인하고 새 가입/배정·새 관리쓰기를 차단하는 후보를 둔다. 종료와 가입/이동이 경합하면 최신 상태·버전을 대조해 원자적으로 확정해야 한다. 과거 콘텐츠의 열람 대상·담당은 별도 정하며 종료됐다고 전체 교회에 공개하지 않는다. ARCHIVED만으로 자식 공동체/개설반·기도방을 종료하지 않는다. 자식 존재 시 종료/재부모 지정 방식·재개 정책은 OPEN이다.

보관본 재개는 별도 명시 관리 동작과 현재 권한 검증으로 처리하는 후보다. 보관 전 리더/위임/초대/원문 공유를 자동 복구하지 않는다. 보관 이후 들어온 옛 요청을 재실행하지 않는다.

## 8. 데이터·이력·실패 계약

후보 기록은 공동체 정의·참여 요청/배정제안·실제 참여 구간·이동 참조·직함·독립 위임 참조·최소 변경 이력이다. 실제 테이블/칼럼/API 경로는 확정하지 않는다. 기존 community_member의 조합 unique를 과거 구간 삭제·단일 행 반복덮어쓰기로 해결하지 않고, 안정적 참여 식별과 역사/재가입 세대를 계약한다. 교회/계정/조직/요청·참여/위임 버전은 용도를 구분한다.

오프라인 관리자 대기열은 추가하지 않는다. 통신 유실은 결과 불명→확인 우선이며 중복 이동·새 참여를 자동 실행하지 않는다. 실제 기존 영수증24시간/일반조회168시간을 신규 공동체 업무에 자동 승계하지 않는다. 명단 원문/연락처·초대토큰·개인 기록을 로그/알림/일반이력에 넣지 않는다.

참여/직함/요청/거절/이동·감사/캐시/백업의 수명은 OPEN이고 특정 이력1년·원문백업30일을 확대하지 않는다. 복원 전에 최신 삭제·정지·소속·참여·위임·최종실행 근거를 적용하며 원래 사건시각을 유지한다. ChurchOS 공동체 이력으로 JLPrayer 참여/Academy 수료/생명일기 상태를 추정하거나 삭제하지 않는다.

## r38 부분 합의의 적용

REC-033은 신규 참여 대상 자격을 확정한다. 본인 신청/관리자 배정/이동의 실제 확정 시 현재 유효 소속을 검증해야 하며, 신청 당시 자격만으로 이후 정지/탈퇴를 우회하지 않는다. 검증의 구체 트랜잭션/버전·권한 최신성은 DRAFT다. 방문자 경로 미구현을 교인 자동 생성으로 대신하지 않는다. 과거 이력과 현재 권한은 분리한다. 이 결정만으로 공동체 참여를 자동 승인하거나 정지해제 후 기존 참여/역할을 자동 복구하지 않는다.

## r39 신청 승인 방식 확정

[REC-034](RECOVERY_DECISIONS.md#rec-034-공동체-본인-신청-수동-승인)를 적용한다. 본인 신청은 담당 승인 전 실제 참여로 취급하지 않는다. 리더 직함과 교회 가입심사 권한만으로 처리하지 않는다. 승인자의 현재 교회/공동체/행위별 권한과 신청자 REC-033 자격을 검증한다. 자체신청 자기심사·담당자 지정/임기·수락기한·거절코드·동시확정 기술은 미결이며 자동 확정하지 않는다. 이전 본문의 권장안/당시 미결 표시는 이 항목만 해당 합의로 구체화됐다.

## r40 배정 제안 본인 수락 확정

[REC-035](RECOVERY_DECISIONS.md#rec-035-공동체-배정-제안-본인-수락)를 적용한다. 제안→미수락 대기→대상 본인 명시 수락→현재 조건 검증 후 참여 활성화 흐름이다. 미수락 상태를 참여 명단/보호자료 열람권으로 쓰지 않는다. 담당 대리 수락/알림 열람/무응답 자동활성은 허용하지 않는다. 수락 기한과 제안 생성/취소 권한·중복/경합·반복 제안/거절·만료·물리보유는 미결이다. 과거 본문의 이 항목 미결/권장 표시는 이 합의로 구체화됐다. 기술 상태명/원자성은 아직 DRAFT다.

## r41 배정 제안 기한 합의

[REC-036](RECOVERY_DECISIONS.md#rec-036-공동체-배정-제안-수락-기한): 유효 제안 생성+168시간, 기한 도달 수락 차단, 재전송/열람으로 연장 없음. 만료 후 필요한 새 제안은 현재자격 재확인 후 구별해서 처리한다. 앞선 문단의 배정수락기한 OPEN은 당시 상태이며 이 합의로 해소됐다. 반복 제안 제한·거절 이후 정책·생성/최종수락 사건 증거·경계 경합은 미결이다. 구현 후보로 서버기준 now<기한일 때만 유효, now>=기한은 차단하는 조건을 대조하되 트랜잭션/최종확정 시각 증명은 DRAFT로 남긴다. 기기시각/푸시 도착시각으로 수락을 허용하지 않는다. 실제 참여기간/물리보유·조회기간에 이168시간을 확대하지 않는다.

## r42 제안 생성 주체 확정

[REC-037](RECOVERY_DECISIONS.md#rec-037-공동체-배정-제안-생성-권한): 해당교회 현재유효 관리자 또는 해당공동체 명시 배정권한 유효담당만 생성한다. 참여신청 심사권한과 별개이며 리더직함만으로 허용하지 않는다. 담당권한 검증과 REC-033 대상자격·REC-035 본인수락·REC-036 제안기한을 각각 확인한다. 담당 지정/자격/기간·취소/회수·제안자 권한상실 후 기존 미수락제안 효력은 OPEN이다. “배정권한 미결”로 적힌 이전 문단은 이 생성주체 항목에 한해 구체화됐으며 제안 생성권을 모든 공동체 관리행위로 확대하지 않는다.

## r43 심사·배정 담당자 지정/해제 확정

[REC-038](RECOVERY_DECISIONS.md#rec-038-공동체-담당자-지정해제-주체): 해당 교회의 현재 유효 관리자만 공동체 심사/배정 담당자를 지정·해제한다. 권한별 공동체/행위 범위를 구별하고 심사 담당이 배정 담당을 자동 겸하지 않는다. 담당자 직접 후임 지정·재위임은 불가하며 관리자 지정 경로를 따른다. 리더직함/교회가입심사/공동체심사·배정 권한만으로 이 관리권한을 얻지 않는다. 앞선 담당 지정주체 미결은 이 합의로 해소한다. 담당 자격/본인수락/기간·현재권한 상실/진행업무/제안효력·복구는 미결이며 이번 합의에 일괄 포함하지 않는다. 해제/업무확정 경합의 실제 기술은 기존 최신권한 원칙과 함께 후속 검증한다.

## r44 담당자 교회 자격 확정

[REC-039](RECOVERY_DECISIONS.md#rec-039-공동체-담당자-대상-자격): 심사/배정 담당자는 해당교회 가입승인 유효소속 교인만 지정 가능하다. 외부인/대기/거절/정지/탈퇴/타교회만 소속은 제외. REC-038 관리자 지정과 REC-034/037 행위별 권한을 함께 확인한다. 유효소속만으로 권한을 주거나 타교회 권한을 복사하지 않는다. 앞선 담당자격 미결은 교회 소속 요건만 이 합의로 구체화됐다. 해당 공동체 참여도 필요한지·담당 본인수락/임기·소속상실 후 지정기록/진행업무·회복 재지정 상세는 미결이다.

## r45 담당업무 본인 수락 확정

[REC-040](RECOVERY_DECISIONS.md#rec-040-공동체-담당-권한-본인-수락-후-활성화): 관리자 지정→대상본인 공동체/업무범위 확인→명시수락→현재 유효 지정/자격·범위 재검증 후 권한 활성화. 미수락 담당에게 신청자 목록/심사·배정 권한을 열어주지 않는다. 일반 공동체 참여·리더직함·통지열람을 업무 수락으로 쓰지 않는다. 앞선 담당 수락 여부 미결은 이 합의로 구체화됐으며 수락기한/임기·미수락 취소/거절·변경/경합·회복 등은 여전히 미결이다. 공동체 배정참여제안168시간을 이 지정에 자동 이식하지 않는다.

## r46 담당 지정 수락기한 확정

[REC-041](RECOVERY_DECISIONS.md#rec-041-공동체-담당-지정-수락-기한): 서버 유효 지정부터168시간, 기한 도달 수락 차단. 통지재전송/열람·재방문으로 연장하지 않는다. 만료 후 필요하면 관리자가 현재 대상자격/범위를 확인해 새 지정하며 옛지정 시각을 바꾸지 않는다. 일반 공동체 배정참여제안(REC-036)과 담당지정(REC-041)은 별개 사건이다. 실제 담당 임기/연장·범위변경/경합·보유는 미결. 이전 문단의 담당수락기한 OPEN은 이 합의로 해소됐다. 구현 후보로 서버 기준 now<기한만 수락 가능, now>=기한은 차단하는 조건을 검증하되 최종확정 경계/시각증명은 DRAFT다.

## r47 담당 임기·연장 기준 확정

[REC-042](RECOVERY_DECISIONS.md#rec-042-공동체-담당-임기연장-기간-기준): 업무종료 사전지정, 지정/각연장당 최대 교회달력1년, 연장본인수락·자동연장금지. 일반업무 [1년 계산](ONE_YEAR_LIMIT_PROPOSAL_2026-10-26.md)을 연결하며 미승인 시간대 예외기술은 그대로 DRAFT다. 늦은 수락으로 사전종료를 이동하지 않고 공백권한을 소급하지 않는다. 참여기간/리더직함임기·기록보유는 변경하지 않는다. 이전 담당임기 OPEN은 이 기간기준에 한해 구체화됐다. 연장제안 수락기한의 적용·해제/종료와 진행업무/기존미수락제안 효력·범위변경/경합은 별도미결이다.

## r48 담당자 소속상실과 권한회복 확정

[REC-043](RECOVERY_DECISIONS.md#rec-043-공동체-담당-소속상실권한회복): 해당교회 유효소속 상실 시 심사/배정 권한 즉시차단. 소속회복만으로 자동복원하지 않고 관리자재지정+본인수락·현재자격/범위/기한/기간검증을 거친다. 옛수락을 재사용하지 않는다. 과거 유효확정/이력은 소급취소/삭제하지 않는다. 타교회·개인제품 권한에 확대하지 않는다. 진행요청은 최신권한/실제확정 근거로 대조하며 기술경합/늦은응답·캐시차단 검증은 NOT_RUN. 소속상실 전에 생성한 미수락 배정제안 처리와 공동체참여/리더직함 자체 회복은 별도미결이다. 앞선 담당회복 미결은 이 범위에서 구체화됐다.

## r49 제안자 권한상실과 미수락 제안 확정

[REC-044](RECOVERY_DECISIONS.md#rec-044-권한상실-제안자의-미수락-배정-제안)를 적용한다. 이전 미수락제안 효력 OPEN은 아래 범위에서 해소됐다. 상태명/물리저장 방식은 기술 DRAFT다.

| 사건/조건 | 처리 | 유지할 경계 |
|---|---|---|
| 제안자의 해당 배정권한 상실·아직 미수락 | 수락보류, 현재 관리자 재확인 필요 | 옛토큰/열린 화면으로 수락 확정 금지 |
| 현재관리자 재확인 전 | 수락/참여 활성화 불가 | 보류를 자동취소/새제안으로 변환하지 않음 |
| 현재관리자가 유효성 재확인 | 현재조건/기한을 확인해 처리 | 관리자 확인은 대상본인 수락 대체 아님 |
| 원제안 생성+168시간 도달 | 수락차단 | 보류/인계/재확인으로 기한정지·연장·초기화 없음 |
| 만료 뒤 새 제안 필요 | 현재자격 확인·권한있는 생성주체의 새제안 | 옛제안 덮어쓰기/자동수락 없음 |
| 이미 유효 수락·참여확정 | 과거확정 유지, 현재 권한 별도검증 | 제안자 상실만으로 참여 소급취소 없음 |

권한상실 감지/수락/관리자확인 경합은 최종현재조건과 실제확정 근거를 대조해야 한다. 실제 서버보류·진행중요청·늦은응답 차단이 구현됐다고 주장하지 않는다. 권한회복/담당재지정만으로 보류를 자동해제하지 않는다. 원기한은 보류중에도 계속 진행한다. 재확인 결과필드/취소/통지·제안내용 변경·다른관리자 동시확인·관리공백·보유/복원은 OPEN이다. 특히 내용변경을 옛본인동의로 수락시키거나 원기한을 리셋하는 규칙을 이번 합의로 만들지 않는다.

## r50 재확인 중 대상·공동체 변경 확정

[REC-045](RECOVERY_DECISIONS.md#rec-045-재확인-시-대상공동체-변경-제안): 보류제안 재확인에서 대상교인/공동체가 바뀌면 기존 제안을 취소이력으로 보존하고 새제안·새대상 본인 확인/수락으로 처리한다. 같은ID에 대상/공동체를 덮어쓰지 않는다. 옛생성시각·결과/이력은 보존한다.

| 상황 | 적용 기준 |
|---|---|
| 내용불변 단순 관리자재확인 | 원제안/원168h 유지, 담당자권한회복/재확인으로 자동수락 없음 |
| 대상교인/공동체 실제변경 | 기존 미수락제안 취소이력·새제안 분리, 새대상 본인수락 |
| 실제 새제안 생성 | 현재 생성권한/대상자격·공동체 검증, 새유효생성+168h |
| 이미 참여확정/종결과 경합 | 최신상태/실제확정 대조; 미수락취소로 확정참여 소급취소 금지 |
| 취소성공·새생성실패 등 | 성공을 꾸미거나 무조건 재생성하지 않음; 원자성/복구/중복방지 상세 DRAFT |

취소·새제안 최소 연결참조는 후보이며 정확한 필드·사유·알림·보유는 미결이다. 일반 생성담당에게 모든 취소권한/강제종료권한을 자동 부여하지 않는다. 의미 없는 형식수정으로 원기한을 늘리는 정책은 채택하지 않았다. 기존제안을 취소해도 활성참여/과거출석·개인제품 데이터가 삭제되지 않는다. 이전 재확인 내용변경 OPEN은 이 대상교인/공동체 범위에서 구체화됐다.

## r51 복수참여와 권한격리 확정

[REC-046](RECOVERY_DECISIONS.md#rec-046-복수-공동체-참여와-권한-독립): 목장·찬양팀·봉사팀 등 여러 공동체 동시참여를 허용한다. 각 참여의 자격/승인·본인수락·역할/위임은 독립이다. 하나의 공동체 리더/담당권한을 다른 공동체에 복제하지 않는다. B추가참여는 A탈퇴/이동 확정이 아니며 A활동/역사참여를 B로 다시 쓰지 않는다. 공동체별 종료는 다른참여를 자동종료하지 않고, 교회소속/계정 상실은 기존범위로 재검증한다.

내 공동체 화면은 본인이 실제 참여한 허용 관계를 표시하는 후보이며 타공동체 명단/관리권한을 열어주는 경로가 아니다. 한 사람이 여러 관계에 들어가므로 공동체별 인원합계와 교회 전체 실인원은 다를 수 있다. 이를 같은 통계로 표시하거나 개수/필터를 통해 비공개 참여를 노출하지 않는다. 정확한 집계/노출/시간기준은 DRAFT이며 새 열람권을 만들지 않는다.

주공동체 정책·종류별 제한/최대개수·수용인원·동시신청/겹친일정/명단/이동은 별도미결. 기존 community_member unique(교회,공동체,교인)는 같은공동체 중복방지이고 전체교인 단일공동체 제약이 아니다. 과거 복수참여 OPEN은 이 범위에서 해소됐다. 기존 “복수·주공동체 규칙, 본인신청 승인주체...” 요약이 두 항목을 섞어 읽힐 수 있어 이번에 분리했다.

## r52 공동체 이동 확정 범위

[REC-047](RECOVERY_DECISIONS.md#rec-047-공동체-이동-확정): 새 공동체 참여가 유효하게 확정될 때 기존 참여 종료를 함께 처리한다. 그 전이나 거절·취소 시에는 기존 참여를 유지한다. 추가참여는 REC-046에 따라 기존 참여를 유지한다. 교회자격 상실 등의 차단 규칙은 별도 적용한다. 권한 주체/본인 A종료 확인·만료·보유·동시성·실제 원자성은 이번 답변으로 확정하지 않았다. 앞부분 r37 당시의 정책 제안 설명은 역사적 상태이며 현재 합의는 REC033~047의 각 한정 범위를 따른다. CM07·CA09/57/58·MVP16에 연결하며 실행은 NOT_RUN이다.

## r53 이동 본인 종료 확인

[REC-048](RECOVERY_DECISIONS.md#rec-048-공동체-이동-본인-종료-확인): 공동체 이동 시 본인이 새 공동체 참여와 기존 공동체 참여 종료의 영향을 함께 확인하고 명시적으로 동의한다. B 참여 수락만으로 A 종료 동의를 추정하지 않는다. 본인 확인만으로 심사/권한/자격 검증을 생략하지 않는다. 추가참여와 이동을 구분하며 REC-047 확정 전/거절/취소는 기존 참여 유지다. 과거 r52의 “본인 A종료 확인 미결”은 이 범위에서 해소됐다. 승인 주체·A측 승인·동의 변경/철회·증빙/보유·실제 원자성은 미결/초안으로 유지한다.

## r54 기존 측 추가 승인 없이 이동

[REC-049](RECOVERY_DECISIONS.md#rec-049-이동의-기존-공동체-추가-승인-불필요): 본인의 명시적 이동 동의와 새 공동체의 유효한 승인이 있으면 기존 공동체 담당자의 추가 승인 없이 이동한다. 기존 담당자에게 결과를 알리고 진행 업무 인계는 별도로 처리한다. 안내 열람·인계 완료를 숨은 추가 승인/이동 대기조건으로 삼지 않는다. 인계 때문에 종료자의 접근을 유지하지 않는다. 결과 안내의 최소정보/현재 수신권한·실패처리·인계 상세는 초안이다. 앞선 r52/r53의 A측 승인 OPEN은 이 범위에서 해소됐다. B 승인주체의 정확한 범위·취소/기한/경합·보유·실제 원자성은 미결/초안이다.

## r55 새 공동체 이동 승인자 확정

[REC-050](RECOVERY_DECISIONS.md#rec-050-새-공동체-이동-승인자): 새 공동체 이동 승인은 현재 해당 교회 관리자 또는 해당 공동체의 명시적 참여심사 유효 담당자만 처리한다. 리더 직함만으로 승인권을 얻지 않는다. REC-034 심사권한의 공동체 범위를 이동 B측에도 적용한다. A 담당/리더·교회가입심사·배정권만으로 B 승인을 허용하지 않는다. 기존 담당 지정·수락·기간·해제 규칙과 REC-047~049를 유지한다. 과거 B승인자 범위 OPEN은 이 범위에서 해소됐다. 자신의 이동 셀프심사·대체담당/접수/거절/취소·기한/경합·통지/보유·실제 원자성은 미결/초안이다.

## r56 이동 셀프승인 금지

[REC-051](RECOVERY_DECISIONS.md#rec-051-공동체-이동-셀프승인-금지): 자신의 공동체 이동 요청은 스스로 승인하지 못한다. 본인 외 다른 유효 승인자가 심사한다. 다른 승인자가 없을 때의 예외 절차는 OPEN이다. 대상 본인이 교회 관리자/B심사담당이어도 동일하다. 역할 전환만으로 우회하지 못한다. 본인 동의는 심사승인과 구분해 유지한다. REC-047에 따라 미확정 중 A참여는 유지하되 별도 자격차단을 무시하지 않는다. 과거 셀프심사 OPEN은 자기 이동 승인 금지 범위에서 해소됐다. 대체담당 지정·승인자 부재·거절/취소·기한/증빙·동일인 식별/원자성은 미결/초안이다.

## r57 다른 이동 승인자 부재 처리

[REC-052](RECOVERY_DECISIONS.md#rec-052-다른-이동-승인자-부재-처리): 본인 외 유효한 이동 승인자가 없으면 자동 승인하지 않는다. 관리자가 기존 자격·본인 수락 절차에 따라 다른 심사 담당자를 지정하고 권한이 유효해진 뒤 처리하며, 그전에는 이동 미확정·기존 참여 유지다. 담당 지정 제안만으로 심사권이 생기지 않는다. 기존 REC038~043의 자격/수락/기한/기간/차단을 적용한다. 담당 수락은 이동 승인 자체가 아니며 이동 요청 수명과 담당 수락168시간을 혼동하지 않는다. 별도 교회자격 차단은 그대로 적용한다. 앞선 승인자 부재 OPEN은 이 경로에서 해소됐으며 관리자도 없거나 지정대상도 없음·이동 취소/대기기한/증빙·실제 원자성 등은 미결/초안이다.

## r58 미확정 이동 요청 본인 취소

[REC-053](RECOVERY_DECISIONS.md#rec-053-공동체-이동-요청-본인-취소): 이동이 확정되기 전에는 본인이 요청을 취소할 수 있다. 이미 확정된 이동은 요청 취소로 되돌리지 않는다. 미확정 취소 시 REC-047의 A참여 유지, 별도 자격차단 적용을 유지한다. 버튼 클릭/응답 유실은 취소 완료 증거가 아니며 실제 결과 확인·중복처리는 기술초안이다. 과거 본인취소 OPEN은 이 범위에서 해소됐다. 취소/승인 동시경합 우선순위·담당취소권·기한·자격상실 중 취소·사유/통지/보유·실제 원자성은 미결/초안이다.

## r59 승인·취소 경합 설계

[이동 경합 상세 초안](COMMUNITY_MOVE_RACE_DRAFT.md)에 상태별 결과·현재 권한·롤백/응답유실/통지실패·중복방지 기준선 연결을 구체화했다. 먼저 유효하게 최종확정된 결과 하나 유지 정책은 PROPOSED이며 새 AGREED 결정은 없다. 구체 원자성/키/응답/수명·실제 병렬검증은 DRAFT/NOT_RUN.

## r60 이동 승인·취소 경합 정책 확정

[REC-054](RECOVERY_DECISIONS.md#rec-054-이동-승인취소-경합-최종확정-기준): 이동 승인·취소가 경합하면 서버가 현재 권한·상태를 검증하여 먼저 유효하게 최종 확정한 결과 하나만 인정한다. 기기 클릭·서버 도착 순서를 뜻하지 않는다. 취소먼저면 A유지/B이번이동 미활성, 이동먼저면 요청취소로 소급복구하지 않는다. r59의 경합 정책 PROPOSED는 이 범위에서 해소됐다. 구체 트랜잭션/권한철회 경합·키/응답/수명·다중이동은 DRAFT/OPEN, 실제 실행 NOT_RUN이다.

## r61 같은 기존 참여의 미확정 이동 하나

[REC-055](RECOVERY_DECISIONS.md#rec-055-같은-기존-참여의-미확정-이동-하나): 같은 기존 공동체 참여를 종료하는 미확정 이동 요청은 하나만 유지한다. 목적지를 바꾸려면 기존 요청을 취소한 뒤 새로 신청한다. 추가참여는 별도로 구분한다. 취소가 유효확정되기 전 새 목적지 신청을 자동 생성하지 않는다. 이미 이동확정이면 현재관계를 확인하며 옛 동의/참여를 재활용하지 않는다. 과거 다중이동 OPEN은 같은 출발참여의 중복대기 금지 범위에서 해소됐다. 미확정 상태집합/다른출발참여/이미B참여·추가참여경합·참여세대/DB 제약·기한/보유는 미결/초안이다.

## r62 목적지에 이미 참여 중인 경우

[REC-056](RECOVERY_DECISIONS.md#rec-056-목적지-공동체-이미-참여-중인-경우): 목적지 공동체에 이미 참여 중이면 새 이동 신청을 만들지 않고 기존 공동체 참여 종료 절차로 안내하며, 목적지 참여는 유지한다. A종료 안내만으로 종료를 실행하지 않는다. B참여 중복생성/역할복사/역사덮어쓰기 금지, 별도 정지/권한해제 적용은 유지한다. 과거 이미B참여 OPEN은 신청 시 이 조건을 확인한 경로에서 해소됐다. 신청 후 B가 별도로 활성화되는 경합·기존 대기요청 종결/전환·본인종료 승인/권한·보유는 미결/초안이다.

## r63 본인 공동체 탈퇴 확정

[REC-057](RECOVERY_DECISIONS.md#rec-057-본인-공동체-탈퇴-별도-승인-불필요): 본인이 종료 영향을 확인하면 해당 공동체는 담당자 별도 승인 없이 탈퇴할 수 있다. 교회 소속과 다른 공동체 참여는 유지하며 담당자 결과 안내·진행 업무 인계는 별도로 처리한다. 본인 명시확인과 현재대상 관계를 검증한다. 안내/인계/후임 미완료로 탈퇴를 묶거나 종료자 접근을 유지하지 않는다. 과거 탈퇴승인 OPEN은 이 범위에서 해소됐다. 리더/독립위임·미확정 이동/배정 연계·경합·강제종료/복구·통지 최소필드/보유는 미결/초안이다. REC-056 이미목적지참여 경로와 연결하며 종료안내만으로 실행하지 않는다.

## r64 리더 탈퇴·후임 공백 분리

[REC-058](RECOVERY_DECISIONS.md#rec-058-리더-본인탈퇴와-후임-공백-분리): 공동체 리더도 후임이 없어도 본인 탈퇴할 수 있다. 후임 지정을 기다리며 탈퇴를 막지 않고 리더 공백을 관리자에게 안내해 별도로 지정한다. REC-057 본인 종료영향 확인을 유지한다. 후임 미정/미수락·마지막 공동체 리더라는 이유로 본인 탈퇴를 대기시키지 않는다. 종료자 옛 접근 유지·구성원 자동승격·관리자 자동겸임·직접 재위임 근거가 아니다. 교회 마지막 관리자 보호는 변경하지 않는다. 공백통지/담당업무·리더 직함/독립위임 세부전이·임기/기한·보유는 미결/초안이다.

## r65 공동체 재가입·권한 자동복원 금지

[REC-059](RECOVERY_DECISIONS.md#rec-059-공동체-재가입과-과거-권한-자동복원-금지): 공동체 탈퇴 후 재가입은 현재 자격과 해당 경로의 승인·수락 절차를 새로 확인한다. 과거 리더 직함·업무권한은 자동 복원하지 않는다. 본인신청 승인과 배정 본인수락 등 각 경로의 현행절차를 구분한다. 과거 참여/출석/직함 이력을 덮어쓰지 않고 재가입만으로 과거자료 열람·개인공유·다른제품 권한을 되살리지 않는다. 참여세대/동시성·종료사유별 제한/대기기간·정지해제/정정회복·역사자료 열람/보유는 미결/초안이다.

## r66 일반 참여자 기본 공개 범위 확정

[REC-060](RECOVERY_DECISIONS.md#rec-060-일반-공동체-참여자의-기본-공개-범위): 일반 공동체 참여자의 기본 열람 범위는 본인 상태·허용된 공동체 소개·공개에 동의한 리더 소개다. 다른 구성원 전체 명단과 연락처는 자동 공개하지 않는다. 리더소개 동의와 직함/권한수락·연락처 공개를 구분한다. 인터넷/다른교회/다른공동체 공개 승인 아님. 리더소개 정확한필드/대상·동의철회·명단담당 최소필드/통계/내보내기·캐시/보유는 미결/초안이다. 과거 일반명단 기본범위 OPEN은 이 범위에서 해소됐다.

## r67 리더 소개 기본 수신범위

[REC-061](RECOVERY_DECISIONS.md#rec-061-리더-소개-기본-공개-대상): 공개에 동의한 리더 소개의 기본 공개 대상은 해당 공동체의 현재 유효 참여자로 한정한다. 교회 전체·인터넷 공개는 별도 동의 범위로 구분한다. 일반열람은 현재 교회/해당공동체 유효관계와 소개동의를 함께 검증한다. 다른공동체/과거참여/대기/미수락·부모조직 소속으로 확대하지 않는다. 관리자 목적별 검토권한은 별도다. 확대공개 기능·필드/철회·캐시/기기저장·현재상태 검증시점/보유는 미결/초안이다. 과거 소개 수신범위 OPEN은 이 한정 범위에서 해소됐다.

## r68 리더 소개 표시 항목 확정

[REC-062](RECOVERY_DECISIONS.md#rec-062-리더-소개-표시-항목과-연락-동의-분리): 공개 동의한 리더 소개는 표시 이름·공동체 직함을 기본으로 하고 사진·짧은 소개는 본인이 선택한다. 전화번호·이메일은 별도 연락 동의로 분리한다. 이름/직함 기본은 소개공개 동의가 전제다. 사진/소개 미선택으로 참여/직함을 제한하지 않고 계정프로필/심사연락처 자동전재 금지. 연락동의가 모든참여자에게 번호 공개를 허용하는 것은 아니다. 필드편집/동의철회·사진/소개 검토/규격·캐시/증빙/보유는 미결/초안이다. 과거 소개필드 OPEN은 이 구성만 해소됐다.

## r69 리더 소개 공개 동의 본인 철회

[REC-063](RECOVERY_DECISIONS.md#rec-063-리더-소개-공개-동의-본인-철회): 리더가 앱에서 소개 공개 동의를 직접 철회하면 관리자 승인 없이 해당 소개 공개를 중단한다. 철회만으로 리더 직함·업무권한을 해제하지 않는다. 해당 동의/대상을 검증하고 별도 연락/확대공개 동의와 구분한다. 공개중단은 원본물리삭제나 외부사본 회수 완료를 뜻하지 않는다. 철회 우회 재게시 금지 방향·캐시/오프라인 전파시간·다중동의 UX/재동의·직함종료 연계/보유는 미결/초안이다. 과거 철회 OPEN은 본인직접철회/승인불필요/직함분리 범위에서 해소됐다.

## r70 직함 종료·재지정 소개 공개

[REC-064](RECOVERY_DECISIONS.md#rec-064-리더-직함-종료와-소개-재공개-확인): 리더 직함이 종료되면 과거 공개 동의가 남아 있어도 현재 리더 소개에서 내린다. 재지정되더라도 본인이 공개를 다시 확인한 뒤 게시한다. 다른공동체 소개/과거이력/독립업무권한과 구분한다. 직함 재지정/업무수락으로 공개 재확인을 대체하지 않는다. 재확인 전 기본항목도 자동게시하지 않는다. 기존 직함종료 연계 OPEN은 이 정책만 해소됐다. 정확한 참조/버전·캐시/동시재게시·재확인기한/보유는 미결/초안이다.

## r71 소개 편집권 구분

[REC-065](RECOVERY_DECISIONS.md#rec-065-리더-소개-편집권-구분): 사진·짧은 소개는 본인이 편집하고 관리자는 수정 제안만 할 수 있다. 공동체 직함은 실제 지정 기록을 따른다. 관리자 제안은 원문덮어쓰기/자동적용 아님. 직함 지정/업무권한과 개인소개를 분리한다. 기존 공개동의/철회·직함종료 재확인을 유지하며 저장후 자동게시·표시이름 편집·제안기한/수락·위반콘텐츠 비공개권/보유는 미결이다.

## r72 저장·미리보기·공개 반영

[REC-066](RECOVERY_DECISIONS.md#rec-066-리더-소개-저장과-공개-반영-분리): 소개 편집은 저장만으로 공개하지 않는다. 본인이 미리보기를 확인한 뒤 공개 반영을 눌러 게시하며, 비공개·철회 상태에서 편집만으로 자동 공개되지 않는다. 현재직함/동의/대상·허용항목을 검증한다. 미게시 초안은 일반참여자에게 노출하지 않는 기술계약이 필요하며 버전/스냅샷은 초안이다. 철회후 재동의·이전공개본 유지/숨김·경합/실패/보유는 미결. 저장후 자동게시 OPEN은 본 정책 범위에서 해소됐다.

## r73 편집 중 기존 공개본 유지

[REC-067](RECOVERY_DECISIONS.md#rec-067-소개-편집-중-기존-공개본-유지와-중단): 공개 중인 소개를 수정하는 동안 새 내용을 공개 반영하기 전까지 기존 공개본을 유지한다. 동의 철회나 리더 직함 종료가 발생하면 기존 공개본도 중단한다. 미게시 초안의 필드/사진이 기존본에 섞이지 않도록 버전/참조 계약이 필요하다. 기존공개 유지 중에도 현재 동의/직함/수신범위를 검증한다. 비공개/철회/직함종료 상태에서 과거본을 부활시키지 않는다. 이전공개본 유지정책 OPEN은 이 범위에서 해소됐으며 동시편집/구버전/철회경합·미디어/캐시/보유는 미결/초안이다.

## r74 미리보기 이후 변경

[REC-068](RECOVERY_DECISIONS.md#rec-068-미리보기-이후-변경과-최신-재확인): 리더 소개 미리보기 이후 내용·공개 대상·직함이 바뀌면 이전 미리보기로 게시하지 않고 본인이 최신 내용을 다시 확인한다. 변경 시 최신본을 자동 게시하거나 오래된 내용으로 덮어쓰지 않는다. 최신 재확인 후 명시적 공개 반영이 필요하며 철회/직함종료를 우회하지 않는다. 기존 유효 공개본은 REC-067 적용. 구버전 게시 거절 정책은 이 범위에서 합의됐고 버전/대상 변경 감지 단위·원자성·유효시간·게시/철회 경합·보유는 기술 초안/미결이다. 관리자 제안 도착만으로 본인 소개가 변경되는 것은 아니다.

## r75 공개 반영과 철회 경합

[REC-069](RECOVERY_DECISIONS.md#rec-069-공개-반영과-동의-철회-경합): 리더 소개 공개 반영 시 서버에서 현재 공개 동의를 확인하며, 철회 확정 후에는 대기 중이던 게시 요청으로 다시 공개되지 않는다. 게시가 먼저 유효 확정됐어도 후속 철회 시 기존본을 중단한다. 철회 전 요청/재시도가 재동의나 새 공개 의사를 대신하지 않는다. 구 영수증을 현재 공개상태/권한 증거로 취급하지 않는다. 게시 최종쓰기와 동의검사 일관성·오래된 작업 차단은 기술 후보이며 정확한 트랜잭션/버전/지연 상한/캐시/재동의/보유는 미결·NOT_RUN이다. 이전 경합 OPEN은 이 정책 범위에서만 해소됐다.

## r76 게시 응답 유실

[REC-070](RECOVERY_DECISIONS.md#rec-070-게시-응답-유실과-결과-우선-확인): 리더 소개 게시 후 통신이 끊기면 성공·실패를 단정하거나 다시 게시하지 않고 기존 요청 결과와 현재 공개 상태를 먼저 조회한다. 과거 게시 성공과 현재 공개 상태를 구분하고 결과 미확인 동안 자동 새 게시를 하지 않는다. 조회 실패/404/기록없음/만료는 미처리 증명이 아니다. 현재 권한과 계정/교회 경계를 유지한다. v2.6의 24시간 영수증을 새 소개 조회 API나 168시간 보유 구현으로 간주하지 않는다. 끝내 미확인인 경우의 수동 확인/재게시·조회 API/기간/기기 참조는 미결·기술초안이다.

## r77 철회 후 다시 공개

[REC-071](RECOVERY_DECISIONS.md#rec-071-철회-후-새-동의와-명시적-공개-반영): 소개 공개 철회 후 다시 공개하려면 본인이 최신 내용·공개 대상을 확인하고 새로 동의한 뒤 명시적으로 공개 반영한다. 이전 게시 요청은 자동 재개하지 않는다. 새 동의만으로 게시하지 않고 현재 직함/동의/내용·대상을 검증한다. 관리자 제안·재로그인·편집 저장은 새 동의가 아니다. 이전 요청과 새 공개 의도 구분은 기술 계약이 필요하며 화면 수/버튼 구성·중간 실패·보유/삭제는 미결이다. 삭제된 사진/초안 복원이나 전체교회/인터넷 공개를 추가 승인하지 않는다. 기존 재동의 OPEN은 이 정책 범위에서만 해소됐다.

## r78 재동의 단일 화면

[REC-072](RECOVERY_DECISIONS.md#rec-072-재동의와-공개-반영의-단일-화면): 철회 후 다시 공개하는 화면은 최신 소개·공개 대상을 한 화면에서 보여주고 동의 확인란과 ‘동의하고 공개 반영’ 버튼을 제공한다. 확인란 선택/화면 열기만으로 동의·게시 성공을 표시하지 않는다. REC-071의 의미 구분과 REC-068~070의 최신 재확인/철회 차단/결과조회는 유지한다. 한 화면이 동의/게시 원자성을 보장하지 않으며 부분실패 계약은 미결이다. 미리 선택하지 않은 확인란·선택전 실행차단·중복클릭 방지·변경후 확인초기화는 UX_DRAFT이며 동의 문구/접근성/API/보유는 별도 검토한다.

## r79 동의 저장 후 게시 실패

[REC-073](RECOVERY_DECISIONS.md#rec-073-동의-저장-후-게시-실패의-본인-재시도): 동의는 저장됐지만 게시 실패가 확정되고 내용·대상·직함·동의가 그대로 유효하면 재동의를 반복하지 않고 본인이 ‘공개 반영 다시 시도’를 선택한다. 결과 미확인 시에는 먼저 조회한다. 타임아웃/404/기록없음/만료는 확정실패 증거가 아니다. 현재권한/버전 검증은 유지하며 동의철회/내용·대상 변경을 재시도로 우회하지 않는다. 같은의도 식별자·실패 영수증 최종성·실행 키/실패원인별 재시도는 기술초안이다. 이전 부분실패 OPEN은 이 UX 정책 범위에서만 해소됐고 원자성/필드/API/기간은 미결이다.

## r80 선택 항목과 게시 흐름 대조

[선택 항목 대조](LEADER_INTRO_OPTIONAL_FIELDS_ALIGNMENT.md): 사진·짧은 소개 없이도 동의한 표시 이름·현재 공동체 직함으로 소개를 공개할 수 있다는 REC-062를 기존 게시·철회·재시도 흐름에 연결했다. 새 정책 합의는 추가하지 않았다. 사진/소개 미선택을 오류로 막거나 프로필/연락처를 자동 채우지 않는다. 기본필드도 공개동의와 현재직함/대상 검증이 필요하다. 생략/명시적 비우기/업로드실패 구분·필드별 철회/보유/캐시는 기술초안/OPEN이다.

## r81 사진만 즉시 비공개

[REC-074](RECOVERY_DECISIONS.md#rec-074-소개-유지와-사진만-즉시-비공개): 본인이 리더 소개 전체를 철회하지 않고 사진만 즉시 비공개로 전환할 수 있으며, 나머지 소개는 유효한 공개 조건 안에서 유지한다. 원본 파일 삭제·보유는 별도로 다룬다. 관리자승인/전체재게시 없이 처리하며 전체동의철회/직함종료이면 나머지소개도 중단한다. 편집중 기존공개본 유지로 사진 비공개를 우회하지 않는다. 과거사진 포함 게시/재시도 차단·사진재공개/캐시/미디어/원본삭제·보유는 기술초안/OPEN이다. r80의 필드별 철회 OPEN은 사진만 비공개 정책 범위에서만 해소됐다.

## r82 사진 재공개

[REC-075](RECOVERY_DECISIONS.md#rec-075-사진-재공개의-본인-확인과-명시적-반영): 비공개로 내린 소개 사진은 본인이 사진·공개 대상을 다시 확인하고 ‘사진 공개 반영’을 선택해야 다시 공개하며, 예전 요청으로 자동 복원하지 않는다. 사진 선택/업로드/저장만으로 공개하지 않는다. 전체소개 철회/직함종료를 사진버튼으로 우회하지 않고 실제사진/대상 변경시 최신재확인한다. 준비중 사진비공개·나머지유효소개 유지. 사진 동의문구/세대·조회/실패/캐시/파일보유는 기술초안/OPEN이다. REC-074의 사진 재공개 OPEN은 이 정책 범위에서만 해소됐다.

## r83 소개 전체 상태 대조

## r85 확정 실패 재시도 동일성
