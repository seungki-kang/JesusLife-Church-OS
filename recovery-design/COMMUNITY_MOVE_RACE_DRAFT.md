# 공동체 이동 승인·취소 경합 상세 초안

2026-10-29 / r60 / REC-054 AGREED_SCOPED + TECHNICAL_DRAFT / PARTIAL_RECOVERY / 실행 NOT_RUN

## 권위와 범위

r58을 이어 작성한다. 사용자의 “다음 단계 진행”은 상세 설계 작업 요청으로 반영했다. r59에서는 경합 정책을 미승인 제안으로 기록했고, r60에서 직접 질문에 대한 사용자 “네”로 REC-054의 한정 정책을 확정했다. [REC-047~053](RECOVERY_DECISIONS.md#rec-047-공동체-이동-확정)의 이동·본인동의·승인권·셀프승인금지·부재·본인취소 합의를 유지한다. 현재 정책 근거는 [REC-054](RECOVERY_DECISIONS.md#rec-054-이동-승인취소-경합-최종확정-기준)이며 구체 기술 선택은 미확정이다.

## 확정 정책 — REC-054 한정 범위

동일 이동 요청에 대한 승인/이동 확정과 본인 취소가 경합하면 서버가 현재 자격·권한·상태를 검증하여 먼저 유효하게 최종 확정한 결과 하나만 인정한다. 기기 클릭 시각, 네트워크 도착 순서, 심사화면 진입, 작업 접수나 잠금 획득만으로 승자를 정하지 않는다. 실패/롤백된 시도는 확정 결과가 아니다.

| 결과 | A 참여 | B 참여 | 뒤늦은 상충 처리 |
|---|---|---|---|
| 취소가 먼저 유효 확정 | 기존 유지, 별도 자격차단 적용 | 이번 이동으로 활성화하지 않음 | 승인으로 취소 결과 덮어쓰기 금지 |
| 이동이 먼저 유효 확정 | B확정과 함께 종료 | 유효 참여 확정 | 요청취소로 소급 복구 금지 |
| 어느 쪽도 확정 못함 | 미확정만으로 선종료 금지 | 이번 이동으로 미리 활성화 금지 | 최신 상태 확인 후 허용 동작만 명시 재시도 |
| 응답이 유실됨 | 추정 변경 금지 | 추정 변경 금지 | 결과 불명 표시·허용된 결과 확인 우선 |

이 표는 기존 B참여가 이미 있거나 별도의 추가참여가 확정된 경우를 임의 취소하는 규칙이 아니다. 해당 중복 관계의 이동 정책은 OPEN이다.

## 화면·권한 계약 후보

- 본인에게 A종료+B참여 영향과 현재 상태를 표시한다. 취소 버튼을 눌렀다는 이유만으로 성공 화면을 먼저 확정하지 않는다.
- 승인자는 REC-050의 현재 해당교회 관리자/대상B 명시 참여심사 유효담당이며 REC-051 자기승인 금지를 적용한다. 승인 전에 보였던 화면/토큰의 역할만으로 현재 승인하지 않는다.
- 권한 없는 사람에게 상충 결과를 안내한다는 이유로 이동 대상·다른 공동체 존재/명단/개인정보를 공개하지 않는다. 결과 안내도 현재 본인/업무 범위 검증을 통과해야 한다.
- 뒤늦은 요청에는 현재 접근권한으로 볼 수 있는 최종 상태를 안내한다. HTTP 코드/공개 필드/조회 수명은 아직 고정하지 않는다.

## 데이터·실패 설계 후보

하나의 이동 식별과 현재 버전/상태를 기준으로 상충 전이를 직렬화하는 계약이 필요하다. 승인 처리에는 현재 계정/교회 자격·A유효관계·B상태·본인 동의 대상/버전·승인자 범위를 대조한다. 취소에는 요청 본인·현재 취소 가능한 상태를 대조한다. 정지/탈퇴 중 취소할 수 있는 특수 경로는 별도 OPEN이다.

업무 변경(A종료+B확정), 요청 최종결과 및 최소 이력이 서로 다른 성공처럼 남지 않게 하는 구체 트랜잭션/버전/잠금/조건부 갱신은 TECHNICAL_DRAFT다. 기존 community_member에 전용 버전/이력/API가 구현됐다고 보지 않는다. 동시 권한 철회·다중 요청 A→B/A→C·담당부재 지정 흐름의 경합은 추가 계약이 필요하다.

기존 v2.6의 Idempotency-Key/자원별 영수증을 무시해 두 번째 중복방지 체계를 만들지 않는다. 해당 구현의24시간 재생과 일반조회168시간을 신규 이동에 자동 승계하지 않는다. 키/주체/교회/경로/요청 지문·조회 기록 연결은 기존 기준선과 대조해 후속 계약한다. 통신유실에 새 키를 발급해 자동 이동하거나 취소를 반복 실행하지 않는다.

DB확정 전에 발송한 통지를 최종 성공 증거로 쓰지 않는다. 최종 확정과 통지 전달을 연결하는 outbox 등은 기술 후보이며 통지 실패로 확정 이동을 반대로 실행하지 않는다. A담당자 안내·인계 완료는 REC-049에 따라 이동 대기 승인 조건이 아니다. 로그/알림에 개인 원문·토큰·전체 명단을 넣지 않는다.

## r61 동일 출발참여 다중 요청 경계

## r62 이미 목적지 참여 중인 경로
