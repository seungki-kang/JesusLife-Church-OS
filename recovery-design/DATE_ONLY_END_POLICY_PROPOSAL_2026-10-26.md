## 문제

관리자가 종료일을 10월 31일로 입력했을 때 그날 시작과 동시에 종료되는지, 그날까지 사용할 수 있는지 명확해야 한다.

## 확정 설계

- 날짜만 지정한 업무는 확인된 교회 시간대에서 지정한 종료일 전체를 포함한다.
- 서버 판정 구간은 시작 시각 이상, 종료 경계 미만으로 한다. 종료 경계는 다음 날짜 시작 시각이다. 23:59:59처럼 정밀도에 의존하는 값을 저장하지 않는다.
- 예: 교회 시간대가 Asia/Seoul이고 종료일이 2026-10-31이면 2026-11-01 00:00 Asia/Seoul부터 권한이 없다. 표시 문구는 ‘2026년 10월 31일까지 · 교회 기준’으로 하고 상세 확인에 정확한 종료 경계를 보여준다.
- 날짜 마감은 달력 기준이다. 앞서 합의한 상대 기간 ‘7일 = 168시간’을 날짜 마감으로 바꾸지 않는다.
- 행사 정정 권한 등 복수 제한이 있으면 168시간 상한, 지정한 짧은 기간, 절대 마감 중 가장 먼저 도달하는 경계에서 종료한다. 날짜 입력으로 상한을 늘리지 않는다.
- 기간 확인 화면에서 최대 허용 기간을 초과하면 자동으로 줄여 저장하지 않고 수정을 요청한다. 1년의 달력·윤년 계산은 r5의 REC-023으로 갱신됐다.
- 시간대가 없거나 다음 날짜 시작이 중복·존재하지 않는 경우 조용히 추정하거나 이동하지 않는다. [DRAFT] 날짜만 지정한 확정을 차단하고 정확한 유효 종료 시각을 확인받는 방안은 미승인 세부안이다.
- 한 번 확정한 실제 종료 시각은 교회 시간대 설정 변경으로 이동하지 않는다. 실제 기간 변경은 기존 제안 교체·연장·축소 절차를 따른다.
- 종료 시각과 같은 순간에는 만료로 판정한다. 앱의 버튼 상태와 별개로 서버가 실행 시 현재 권한을 검증한다.

| 날짜 마감이 최대 기간을 초과 | 자동 연장·조정 없이 입력 수정 요청 |
