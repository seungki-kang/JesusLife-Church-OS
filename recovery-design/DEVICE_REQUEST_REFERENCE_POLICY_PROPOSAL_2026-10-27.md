# 기기 최소 확인 기록과 계정 전환 정리 기준

확정 근거: 사용자가 직전 정리 기준 질문에 “네”로 동의했다. 명시적 로그아웃·다른 계정 전환 시 해당 계정의 기기 확인 기록을 제거하고, 같은 계정의 교회 전환 때는 교회별로 격리해 유지한다. 저장 기술·보유 기간·서버 요청 발견 API·나머지 사건별 제안 전체를 확정하지 않는다.

## 1. 범위

복원 누적 r13의 확정된 결과 확인 우선·자동 재실행 금지를 유지한다. 이번 대상은 ChurchOS 일반 업무 명령을 제출한 뒤 결과를 확인하기 위한 기기 참조다. 인증 토큰 저장·개인 제품 원본·작성 중 초안·서버 업무 데이터·감사·중복 방지 기록은 별도 정책이며 이번 삭제 제안의 대상이 아니다. 부분 복원 상태를 유지한다.

## 2. 최소 기록 후보

| 필드 | 목적 | 제약 |
|---|---|---|
| local_submission_ref / nullable confirmation_ref (DRAFT) | 송신 전 기기 참조와 응답 뒤 서버 확인 ID를 구분 | 기존 request_id 한 값으로 두 시점을 표현하지 않음. 새 공개 항목 아님 |
| account_ref | 본인 기록 격리 | 검증된 계정의 불투명 참조, 이메일로 연결 금지 |
| tenant_ref | 교회별 격리 | 교회 이름·명단 없이 불투명 참조 |
| contract_version | 올바른 조회 계약 선택 | 지원하지 않으면 임의 변환·재실행 금지 |
| submitted_at_local | 기기 기록 수명 관리 후보 | 기기 추정값, 서버 확정 시각·권한 판정 근거로 사용 금지 |

명령 본문·변경 값·사람 이름·원문·화면 캡처·완료 결과 캐시·토큰·비밀을 이 기록에 넣지 않는다. 최소 참조도 계정·교회 활동과 연결될 수 있으므로 공개 정보나 익명 정보로 취급하지 않는다. 원시 요청 식별자를 분석 로그·오류 보고·푸시 알림에 자동 수집하지 않는다.

## 3. 생성과 사용

- 사용자가 연결 상태에서 저장을 제출하는 시점에 기록한다. 네트워크 송신 전 기록과 송신이 원자적일 수 없으므로 ‘기록이 있다=서버 접수됨’으로 판단하지 않는다.
- 앱 재시작은 결과 조회만 이어간다. 기기 기록에 쓰기 본문이 없더라도 별도 화면 초안을 사용해 자동 재전송하지 않는다.
- 조회는 재인증·현재 계정·선택 교회·소속 유효성을 확인한 뒤 수행한다. 식별자만으로 조회 권한을 얻지 못한다.
- 기기 보호가 풀리지 않거나 저장 기술을 지원하지 않으면 평문으로 대체 저장하지 않는다. 사용자에게 결과 확인 경로의 제한을 알리고 안전한 수동 확인으로 연결한다.

## 4. 사건별 정리 제안

| 사건 | 기기 확인 기록 | 서버 업무와 결과 |
|---|---|---|
| 정상 앱 종료·재시작 | 유효 로그인 계정에 속한 최소 참조 유지 가능 | 재접속 후 현재 권한으로 조회, 자동 쓰기 금지 |
| 같은 계정의 교회 전환 | 교회별 격리 보관, 현재 교회 밖 기록은 숨김 | 이미 접수된 요청 취소 아님 |
| 명시적 로그아웃 | 해당 계정의 이 확인 기록을 제거하고 진행 중 조회 응답을 화면에 적용하지 않음 | 서버 업무·감사·중복 방지 기록 삭제 아님 |
| 다른 계정으로 전환 | 이전 계정 기록 제거·화면 초기화 | 새 계정으로 이전 요청 조회 금지 |
| 인증 일시 만료·일시 장애 | 화면·조회 차단, 보호된 참조는 별도 수명 내 유지 후보 | 소속 상실로 단정하지 않음, 재인증 후 다시 검증 |
| 서버가 교회 탈퇴·소속 상실 확정 | 해당 교회 참조 제거·화면 초기화 | 서버 업무 취소·삭제와 별개 |
| 서버가 공통 계정 정지·탈퇴 확정 | 해당 계정 참조 제거·화면 초기화 | 기존 공통 계정·서비스별 처리 정책 적용 |
| 유효 권한으로 최종 결과를 앱이 확인 | 해당 기기의 참조 제거 | 서버 최소 상태 168시간·업무 원본·감사 수명은 별개 |
| [DRAFT] 유효 응답으로 이미 안 서버 조회 만료 시각 도달 | 기기 참조 정리 후보. 일반 404만으로 만료 판정 금지 | 실패 확정·키 재사용 허용 아님 |

로그아웃·계정 전환 중 뒤늦게 도착한 응답은 계정·교회·세션 세대를 다시 비교해 폐기한다. 이전 요청의 ‘완료’ 알림이 새 계정 화면에 나타나지 않게 한다. 조회 취소는 서버의 이미 제출된 쓰기 취소와 다르다. 로컬 삭제 요청 실패 시에도 즉시 접근·표시를 차단하며 삭제 재시도와 오류를 관리한다. 정확한 삭제 완료·암호화 키 폐기 보장은 플랫폼별 검증 전 주장하지 않는다.

## 5. 미확정 요청을 남기고 로그아웃하는 경우

‘아직 결과를 확인하지 못한 요청이 있습니다. 로그아웃해도 이미 보낸 요청은 취소되지 않습니다.’라는 안내를 제안한다. 명시적 로그아웃을 막지는 않는다. 개인정보·원문·타 교회 정보 없이 안내한다. 로그아웃 완료 후 확인 기록을 제거한다. 앱이 자동으로 새 요청을 만들지 않게 한다.

다시 로그인했을 때 이전 결과를 조회할 수 있는 서버의 본인 요청 발견 경로가 필요하다. 본인 발견 범위는 REC-029, 미확정/최종 기한은 REC-030, 다섯 공개 항목은 REC-031로 갱신됐다. 실제 경로·필드명·접근 통제 구현은 DRAFT다. 이메일·표시 이름이나 기기 지문으로 요청을 자동 연결하지 않는다. 발견할 수 없으면 미실행으로 추정하거나 새 업무로 재실행하지 않고 현재 권한으로 실제 업무 자료를 확인하거나 수동 확인한다. 이 제한을 개발 인계에 포함한다.

## 6. 수명과 저장 기술 — OPEN

기기 참조를 무기한 남기지 않는다. 그러나 미확정 요청의 보유 상한을 최종 결과 조회 168시간과 자동으로 같게 정하지 않는다. 서버 일반 발견 기한은 REC-030으로 정해졌다. 기기 참조 수명·실행 기한·중복 방지 수명은 함께 보완해야 한다. 기기 시계 변경·장기 오프라인·복원에도 안전한 정리 방식을 명세하기 전 실제 구현은 보류한다.

기기 보호 저장소·암호화 키·OS 백업 제외·앱 제거·다중 기기·복원·정리 실패 처리의 구체 기술은 미결이다. 백업에서 제거된 이전 참조가 돌아와도 이전 세션이나 토큰을 근거로 실행·공개하지 않는다. 어떤 경우에도 참조 소실·정리로 이미 제출한 쓰기를 자동 재생성하지 않는다.

## 7. 설계 수용 조건 — 실행 결과 아님

- 공유 기기의 로그아웃 후 다른 계정에 이전 요청 존재·상태가 노출되지 않는다.
- 계정 전환 도중 도착한 성공 응답이 새 계정에 표시되지 않는다.
- 교회 전환 후 이전 교회 결과가 현재 교회 화면에 나타나지 않는다.
- 단순 인증 만료를 탈퇴 확정으로 오인해 처리하지 않는다.
- 확인 기록 삭제가 서버 업무 삭제·취소·미실행 판정으로 변하지 않는다.
- 기록 소실·앱 재설치·백업 복원 후 자동 업무 재실행이 없다.
- 유효한 현재 권한 없이 서버 요청 발견·최소 상태 조회를 하지 않는다.

## r26 보완: 만료를 알 수 없는 기기 기록

일반 404는 미존재/타인/타교회/만료를 구분하지 않으므로 기기 만료 증거가 아니다. 서버 만료를 못 받은 참조에도 독립된 로컬 상한이 필요하다. “기기 제출+168시간+시계 오차 여유”는 후보이며 숫자·여유·시계 역행/복원 판정은 OPEN이다. 상한 초과 시 참조만 제거하고 서버 미실행/취소를 추정하지 않는다. 만료 뒤 실제 최종 확정은 현재 권한의 서버 발견 경로로 확인한다.

## 송신 전 참조와 서버 확인 ID — r28 대조

서버 확인 ID를 송신 전에 보유한다고 가정하지 않는다. [연결 계약 초안](SUBMISSION_RECEIPT_BINDING_DRAFT.md)이 기기 제출 참조·기존 경로별 멱등 범위·서버 확인 ID를 구분한다. 추가 최소 범위/필드·읽기 연결·보유기간은 미확정이며 기존 로그아웃/계정/교회 경계 합의는 그대로다.
