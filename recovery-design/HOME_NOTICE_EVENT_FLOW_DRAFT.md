# 교회 홈·공지·일정 — 열람→편집→게시→철회 앱 계약

2026-10-28 / 기존 합의 연결 + 후속 상세 DRAFT / PARTIAL_RECOVERY / 구현·실행 NOT_RUN

## 근거와 범위

[기존 운영/상세 설계](../docs/operations/ecosystem-v1/DETAILED_DESIGN_V1.5.md), REC-002의 편집/게시 분리, REC-025~032의 권한·결과 확인·기록 경계, [가입/역할 앱 계약](ONBOARDING_APP_STATE_CONTRACT_DRAFT.md), [실제 구현 대조](CONTENT_BASELINE_ALIGNMENT.md)를 따른다. 같은 사람이 편집과 게시 권한을 가질 수 있으나 자동 게시를 뜻하지 않는다. 설교의 목회자 검토·JLPrayer 게시 심사는 각각 별도다.

권한 capability 이름·새 수정본/게시본 구조·철회 의미 분리·정렬/날짜 필터는 후속 제안이다. 기존 COS/REC 합의로 새 세부 전체를 승인 처리하지 않는다. 새 경로/DB/Flutter 코드·실제 연동은 만들지 않는다.

## 홈의 사용자별 경계

| 사용자 | 홈에서 제공할 내용 | 제공하지 않는 것 |
|---|---|---|
| 비로그인/가입 대기 | 교회가 공개한 소개·예배 시간·공개 설교, 자기 가입/인증 안내는 본인 확인 후 | 내부 공지/일정·교인 명단·공동기도를 “홈 카드”로 우회 공개 |
| 유효 소속 일반 교인 | 교회 브랜드·현재 허용 공지·허용 일정·설교·허용 제품 연결 | 초안·승인 전 수정본·권한 없는 대상별 콘텐츠 |
| 허용 편집/게시 담당 | 교인 홈 + 현재 지정 범위의 관리 진입 | 직함만으로 전체 관리자·타 교회·다른 제품 개인 기록 접근 |
| 현재 관리자 | 해당 교회 관리 목록/콘텐츠 작업 | 다른 교회·개인 영성 원문·무제한 데이터 내보내기 |

홈은 여러 카드의 허용 결과를 조합하는 화면이다. 공지/일정과 외부 기도/성경/CHGO 장애를 카드별로 격리한다. 실패를 빈 목록/성공으로 꾸미지 않는다. 인증/소속 확인 불가이면 보호 카드의 이전 원문부터 숨기고 접근 확인을 안내한다. 빈 목록·접근 확인·일시 장애·미연결을 구분한다.

카드의 제목·미리보기·배지 개수·정렬·페이지 정보도 대상 권한을 적용한다. 푸시/검색/공유 링크/위젯/최근 본 항목이 상세 API를 우회하지 않는다. 공개 카드와 내부 카드에 다른 캐시/인증 계약을 사용한다. 정확한 카드 수·고정 순서·고정글·읽음 통계/명단은 새로 확정하지 않는다.

## 편집과 게시의 분리 — 권장 구조 DRAFT

게시본은 일반 열람의 정본이고, 편집 중 수정본은 현재 허용 편집자/게시자만 볼 수 있는 별도 후보다. 처음에는 수정본만 있고 게시 확인 후 지정 버전을 게시본으로 만든다. 게시 후 다시 편집하더라도 기존 게시본을 유지하다가 허용 게시자가 최신 수정본을 명시 반영하는 방향을 권장한다. 편집만으로 제목/대상/날짜가 홈과 상세에 반영되지 않는다.

두 버전의 물리 저장 방식·게시 전 검토 의무·이력 보유·새 API는 미확정이다. 편집/게시 분리의 기존 원칙을 만족시키는 후보이며 이미 승인된 필수 독립 심사자 제도가 아니다. 같은 사람이 두 권한을 갖고 명시 게시할 수 있다. 관리자도 게시 영향 확인을 거친다.

현재 v2.6은 게시 행 PATCH가 즉시 바뀌므로 이 후보 구현 전 “편집본 저장” 버튼을 현재 PATCH에 연결해 게시본이 유지된다고 표시하면 안 된다. 현행 관리자 즉시 수정 모드는 사실대로 표시하고, 새 분리 계약의 클라이언트/버전 이행을 검토한다. PATCH status/audience/publishAt 변경으로 게시 권한이나 대상 확대 검증을 우회하지 못하게 해야 한다.

## 상태와 행위의 의미

| 행위 | 후속 의미 후보 | 현재 v2.6 대응/차이 |
|---|---|---|
| 초안 저장 | 미게시 내용 저장 | DRAFT 생성/허용 PATCH 있음 |
| 게시 | 지정 버전을 지정 대상에게 제공, 예약 시각 조건 유지 | PUBLISHED. 미래 publish_at이면 아직 일반 공지 비공개 |
| 게시 후 수정 | 별도 수정본 저장 후 명시 게시 | 현재 동일 행 즉시 PATCH. 새 버전 구조 필요 |
| 공지 게시 철회 | 일반 열람 중단, 업무 원본/최소 이력과 분리 | 현 cancel은 CANCELLED 종결. 다시 공개는 현재 지원하지 않음 |
| 실제 행사 취소 | 행사가 취소됐다는 업무 사실, 이미 연결된 운영 업무 영향 검토 | 현 cancel은 일반 목록에서 제외. 취소 안내 카드는 후속 계약 |
| 일정 게시 철회 | 행사 개최 사실과 별개로 게시 노출만 중단 | 현재 별도 동작 없음. 행사 cancel로 조용히 대체 금지 |
| 게시 기간 만료 | 공지의 일반 열람 조건 종료 | expires_at 필터. 자동 DB EXPIRED 전이 아님 |
| 행사 완료/과거 | 시간이 지남과 운영 완료 판정은 별개 | 일반 목록에 과거 행사 가능. COMPLETED 버튼/자동 전이 미구현 |
| 보관/물리 삭제 | 운영 수명·삭제 근거로 별도 처리 | 현재 라이프사이클 API의 cancel과 같지 않음 |

새 “잠시 숨김→재게시”는 이번 범위에서 승인하지 않는다. CANCELLED 종결 건은 현재 코드대로 직접 수정/재게시하지 않는다. 정정 재등록/복제 후보가 필요하면 별도 새 의도로 연결하되 대상·권한·기존 취소 이력을 다시 확인하고 참가/출석/봉사/개인 제품 자료를 자동 복사·병합하지 않는다.

취소된 행사의 대상자 안내를 위해 최소 취소 표시를 유지할지는 후속 제안이다. 현재 일반 목록은 CANCELLED를 제외하므로 숨겨진 행사 원문을 가져와 취소 카드로 우회 공개하지 않는다. 취소 안내의 허용 필드·대상·기간·알림은 OPEN이다. “목록에서 안 보임=행사가 취소됨”으로 추정하지 않는다.

## 권한 매핑 후보

| 행위 | 서버에서 별도 검증할 권한 | 경계 |
|---|---|---|
| 일반 열람 | 현재 소속·대상·상태·시각 | 교회 관리자라서 개인 제품 원문을 볼 수 없음 |
| 관리 목록/상세 | 현재 콘텐츠 관리 범위 | 초안 제목/수정본·종결 원문은 성도 열람과 분리 |
| 초안 생성/편집 | 해당 공지/일정 편집 capability | 게시·철회 권한 자동 부여 안 됨 |
| 게시/대상 확대/게시 시각 확정 | 해당 게시 capability + 최신 버전 | PATCH 등 모든 진입 경로에 같은 행위 분류 적용 |
| 철회/취소 | 명시된 영향 범위의 capability | 편집자가 무조건 행사 취소할 수 있다고 가정하지 않음. 정확한 위임 정책 OPEN |
| 삭제/보관 | 별도 보유/삭제 근거 | cancel 역할로 실제 원문 삭제하지 않음 |

기존 관리자 권한과 REC-002의 편집/게시 원칙은 유지한다. 새 capability 이름·철회 담당의 지정 방식·권한 기간은 미결이다. 공통 계정·소속·업무 권한 최신성 및 해제 경합은 기존 계약을 적용하되, 실제 직렬화 구현 완료를 주장하지 않는다.

## 예약·대상 변경·시간대

공지는 일반 열람 때 publish_at<=서버 현재, expires_at이 없거나 현재보다 뒤인지 검사한다. 앱 시계나 푸시 시각으로 공개하지 않는다. 예약 시각이 와도 원래 대상·현재 접근을 매번 확인한다. 예약 시각의 게시자 권한을 다시 요구할지/게시 후 위임 해제의 영향은 후속 정책으로 남기며 임의 자동 철회를 만들지 않는다.

대상을 줄인 게시본은 새 열람/카드/페이지/현재 화면에서 최신 범위를 적용하는 설계가 필요하다. 기존 전달 바이트/스크린샷/외부 사본 완전 회수를 보장하지 않는다. 대상 확대는 미래 게시 권한을 검증하고 원래 개인정보 동의 범위를 넓힌 것으로 간주하지 않는다.

일정의 교회 시간대·UTC 시각·현지 보조 표시를 분리한다. 달력의 “시작일 기준”과 “기간과 겹치는 일정”은 다른 조회다. 현재 시작 시각 필터를 기간 교차 조회로 표시하지 않는다. 교차 조회 후보는 명시한 반열린 범위와 시작/종료 비교를 쓰되 종료 없음은 점 일정/지속 여부 규칙을 따로 정한다. 자정·일광절약·여러 날 행사를 테스트할 계약이 필요하며 일반 담당자 날짜 마감 합의를 행사 종료 시각으로 자동 이식하지 않는다.

## 충돌·응답 불명·현재 화면

기존 ETag/If-Match·멱등 키를 유지한다. 428/400/412/409의 기존 의미를 변경하지 않는다. 412는 최신 버전과 내 편집의 차이를 확인하고 사용자가 재적용하도록 한다. 권한 없는 원문을 재조회해 비교하지 않는다. 계정/소속 상실 시 보존 중 입력을 계속 공개하는 권한을 가정하지 않는다. 보호 임시 입력의 보유/정리/OS 백업은 OPEN이며 일반 공개 캐시7일을 적용하지 않는다.

응답 불명은 이미 보낸 저장/게시/cancel의 결과를 먼저 확인한다. 새 키를 발급하거나 새 공지/행사를 자동 만들어 해결하지 않는다. r29 일반 요청 최소 상태 계약은 후속 구현이며 현재 API로 제공된다고 표시하지 않는다. 이미 확정된 게시물/행사 사실은 담당자 권한 해제만으로 소급 삭제하지 않는다.

홈은 교회가 선택한 항목 중 현재 방문자·교인에게 공개된 게시본만 조합한다. 선택하지 않은 항목은 빈 카드로 남기지 않는다. 메뉴 숨김과 게시 철회는 구분한다. 설정 및 미리보기는 [담임목사님 중심의 도입과 선택형 교회 앱](WHITE_LABEL_SETTINGS_DISTRIBUTION_DRAFT.md#담임목사님-중심의-도입과-선택형-교회-앱)을 참조한다.

현재 화면/뒤로가기/최근 목록은 계정·교회·대상·게시 버전을 다시 확인한다. 내부 공지/일정은 초기 공개 소개/예배 일정의 제한 캐시와 다르다. no-store를 무시한 영구 원문 캐시·오프라인 관리자 실행 대기열을 추가하지 않는다.

## 알림·홈 반영과 장애

게시가 커밋된 뒤에만 발행 대기 참조를 생성/확정하는 설계를 검토한다. 실제 발송 전에 현재 대상·철회·시간·선택을 재검증한다. 게시 후 편집본 저장만으로 공지 알림을 보내지 않는다. 예약 공지를 예정 전 알림으로 노출하지 않는다. 구체 알림 동의/중복/취소 안내·발송 시한은 OPEN이며 제목/본문/이름을 잠금 화면에 자동 노출하지 않는다.

외부 제품 오류는 공지/일정 업무 커밋을 성공으로 위장하거나 롤백하는 근거가 아니다. 알림 실패도 게시 실패/자동 재게시가 아니다. 복원은 최신 권한·철회·게시 버전·삭제 상태·발행 확정을 적용하고 공개/발송을 재개한다.
