# 구현 전 미결 사항 분류 — r35

2026-10-29 / PRIORITIZATION_DRAFT / 정책 합의·개발 착수 승인 아님

[기록 교차 검토](CROSS_DOMAIN_RETENTION_REVIEW.md)와 [18개 분류표](IMPLEMENTATION_BLOCKERS.csv)를 함께 읽는다. ID는 진행 관리용이며 COS/REC 확정 결정 ID가 아니다. 모든 항목의 실제 실행 검증은 NOT_RUN이다. 이 표는 모든 미결을 전수 포괄하거나 이미 해결했다고 주장하지 않는다.

| 게이트 | 의미 | 항목 수 |
|---|---|---|
| DESIGN_BEFORE_IMPLEMENTATION | 해당 실제 기능의 데이터/권한/실행 구조를 확정하기 전에 해결 | 5 |
| BEFORE_RUNTIME_DATA | 목업 설계는 가능하되 해당 실제 사용자 자료를 받기 전에 정책/보호를 확정 | 6 |
| OPTIONAL_FEATURE_GATE | 의존 기능을 미제공으로 두고 독립된 다른 범위 설계를 계속할 수 있음 | 4 |
| BEFORE_RELEASE | 담당·배포·실제 통합/복구 검증 등 운영 공개 전 충족 | 3 |

게이트는 의존 기능 단위다. BEFORE_RELEASE라고 해서 그 전에 보안 경계를 무시한 구현이 허용되거나, OPTIONAL이라고 해서 기도/말씀의 기존 제품 방향을 삭제한다는 뜻은 아니다. 실제 서비스 출시를 허용하는 항목도 아니다. 파일럿/에뮬레이터/본격 구현은 계속 보류한다.

## 우선순위와 후속 진행

1. B01~B04/B08: 안정적 식별·현재 권한·최종확정·중복방지·복원 계약을 연결한다. 실제 제공자 미확인이면 제안/미확인 상태를 유지한다.
2. B05~B07/B09~B11: 기록별 정책을 정한다. 새 기간부터 임의 선택하지 않고 목적·종료 사건·최소 필드·열람자·사본·삭제 증거를 먼저 좁힌다.
3. B12~B15: 제공자별 권리/API/데이터·철회 증거를 받는다. 소스가 없으면 구현 완료로 바꾸지 않고 기능 게이트를 유지한다.
4. B16~B18: 실제 담당/배포/실행 증거를 준비한다. 지금은 운영 실행을 재개하지 않는다.

다음 설계 묶음은 **교회 기본 MVP의 화면→행위→권한→정본→실패/수명→수용 조건을 연결한 개발 인계표**다. 후보 경로/필드는 미확정으로 남기고 이미 합의한 정책을 다시 묻지 않는다. 그 후 새 정책 결정이 실제 필요한 경우, 해당 목적/대상 하나를 좁혀 권장안과 질문 하나로 진행한다. 이번 “진행”을 새 기간/공유 범위에 대한 동의로 기록하지 않는다.

검증 상태와 설계 승인 상태는 별개다. 문서·CSV·ZIP 정적 검사가 통과해도 B18은 해소되지 않는다. 소실된 원문과 최신 GitHub는 미확인/부분복원 상태를 유지한다.
