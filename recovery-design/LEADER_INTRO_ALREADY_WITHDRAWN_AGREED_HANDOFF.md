# 이미 철회된 같은 동의 세대 — 합의 인계

## 합의 적용

같은 동의 세대가 이미 철회됐음을 현재 본인 권한으로 검증한 경우 추가 효력 변경 없이 안내한다. 이번 요청이 과거 철회를 실행한 것으로 기록하지 않는다. 이것은 상태 관찰과 요청의 실행 사실을 구분하는 원칙이다.

| 상황 | 적용 |
|---|---|
| 같은 요청의 최종 근거 존재 | 그 요청의 검증된 결과를 현재 권한/유효 조회 창 안에서 확인 |
| 요청 결과 근거 없고 같은 세대의 철회 상태만 검증 | 이미 철회됨을 안내; 과거 요청의 성공으로 소급하지 않음 |
| 이전 세대 철회·새 세대 공개 | 새 세대 효력을 변경하지 않음 |
| 대상/본인 관계 또는 상태 불명 | 이미 철회됨을 추정하지 않음; 기존 제한 확인 경계 유지 |
| 서로 다른 요청의 동시 처리 | 각 요청이 실행했는지와 관찰한 상태를 구별하도록 상세 설계 |

권한 검증·동시성·확정 근거를 실제로 구현한 것은 아니다. 상태를 읽은 직후 변경될 수 있는 경합과 결과 근거를 저장할 경계가 남아 있다. 새 동의 세대의 현재 상태를 과거 세대 안내에 섞지 않는다.

## 새로 확정하지 않은 것

이미 철회됨을 읽기 응답으로만 처리할지, 새 요청의 내구 결과 의미로 저장할지 미결이다. 따라서 재조회 가능성·감사·확인 시각·조회 종료 계산도 함께 결정해야 한다. 추가 효력 변경이 없다는 이유로 필요한 기록을 생략하거나 무기한 저장하지 않는다. 기존 철회 시각을 새 확인 시각으로 변경하지 않으며 REC090 다섯 종류 공개 상한을 유지한다.

## 다음 설계

두 후보를 응답 유실과 반복 요청 관점에서 비교한다. 새 요청의 내구 무변경 결과를 남기는 경우에도 그것은 과거 철회 실행 증명이 아니라 이번 판정의 근거여야 한다. 읽기 안내만 두는 경우에는 나중에 이번 응답을 재현할 수 있는지, 불명 상태가 어떻게 제한되는지를 명시해야 한다. 저장 형식·시각/기간·감사는 선택 전 후속 계약으로 남긴다.
