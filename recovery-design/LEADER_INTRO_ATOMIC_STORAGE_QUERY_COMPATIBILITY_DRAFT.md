# P1/P2 구현 전 명세 — 원자 저장·조회·키 호환

2026-11-01 / r163 / PREIMPLEMENTATION_SPEC_DRAFT / PARTIAL_RECOVERY / 실제 실행 NOT_RUN

[REC096 인계](LEADER_INTRO_P1_P2_DIRECTION_AGREED_HANDOFF.md), [구체 계약 제안](LEADER_INTRO_ATOMIC_STORAGE_QUERY_COMPATIBILITY_DRAFT.md), [r157 코드 대조](LEADER_INTRO_INTEGRATED_REVIEW_1_CODE_MAPPING.md), [r160 남은 다섯 묶음](LEADER_INTRO_INTEGRATED_REVIEW_4_HANDOFF_VERDICT.md)을 따른다. 아래 저장/잠금/호환 방식은 제안이며 실제 API/DDL/코드가 아니다. REC001~096 이외 새 합의를 만들지 않는다.

## 논리 저장 단위와 불변 조건

| 단위 | 최소 역할 | 불변 조건 후보 |
|---|---|---|
| 본인-대상 관계 | 현재 계정과 해당 동의 세대/교회 관계 검증 | 번호/키 소지만으로 권한을 얻지 않음; 소속 종료와 관계 목적 구별 |
| 의도 결속 | 새 명령의 I=K·본인·명령범위·고정 입력·T 연결 | 같은 범위의 키는 한 입력/대상에만 결속; 변경 입력 충돌 |
| 결과 | 서버 R·실행/무변경 의미·확정 근거 | 한 의도의 최종 의미를 재조회로 덮어쓰지 않음 |
| 효력 상태 | 특정 동의 세대의 현재 공개 허용/철회 | 옛 의도로 새 동의 세대 변경 금지 |
| 최소 감사 | 판정 주체/목적·결과 관계 | 원문/토큰 없이 결과와 일관되게 확정 |
| 유한 보호 | 정리된 키·옛 실행/복원에 대한 별도 목적 | 결과 정리/부재를 재실행 허용으로 쓰지 않음 |

이는 여섯 물리 테이블을 요구하는 안이 아니다. 결과와 키 결속을 같은 저장 단위에 둘 수 있으나 수명/접근 목적이 다르면 필드별 정리와 검증 관계를 명세해야 한다. 기존 idempotency_record 재사용 여부는 아래 호환표와 P3/P4의 수명에 따라 결정한다.

## 동기 원자 경계 제안

새 요청은 현재 인증/최소 입력을 확인한 뒤, 의도 결속과 정확한 대상 세대·현재 권한을 동일한 확정 경계에서 검증한다. 상태가 유효하면 철회 효력 변경, 이미 철회된 같은 세대면 효력 변경 없는 판정을 수행한다. 그 판정의 최소 결과·키 결속·필수 감사는 같은 트랜잭션에서 확정하도록 설계한다. 어느 필수 기록만 따로 성공한 상태를 사용자 성공으로 공개하지 않는다.

별도 접수 전용 트랜잭션을 먼저 커밋하거나 이후 워커가 효력을 바꾸는 구조를 몰래 추가하지 않는다. 최종 결과 전용 읽기는 기존 근거를 읽고 새 결속/결과를 생성하지 않는다. 데이터베이스 장애 때 실제 결과와 오류 로그의 확정 여부를 구별한다.

## 충돌·잠금 순서 제안

명령 범위/본인/키에 대한 직렬화와 해당 동의 세대의 상태 경합 보호를 함께 설계한다. 한 후보는 ‘의도 범위 직렬화→기존 결과 대조→대상 세대 판정/잠금→권한 현재성 확인→효력/결과/감사 확정’이다. 기존 코드의 advisory lock+행 잠금을 비교 기준으로 사용하되 세대/권한 자료와의 실제 잠금 순서는 아직 선정하지 않았다.

서로 다른 키로 같은 세대를 처리할 때도 대상 상태 판정이 직렬화되어야 한다. 권한 회수 경로 역시 같은 확정 질서에 참여하거나 명시적으로 보장된 최신성 계약이 필요하다. 명령 안에서만 잠금을 잡고 회수 쪽은 관여하지 않으면 최종 권한 경합이 해결됐다고 주장할 수 없다. DB 제약·격리수준·교착/직렬화 오류 처리·재실행 규칙은 구현 전 채워야 한다.

자동 내부 트랜잭션 재시도를 고려하더라도 원래 의도/입력을 유지하고 COMMIT 불명과 구별한다. 어떤 오류를 안전한 재시도 대상으로 볼지 확정하기 전에는 클라이언트/워커의 숨은 무제한 재실행을 도입하지 않는다.

## 같은 요청의 쓰기 응답과 결과 읽기

| 경우 | 동작 후보 | 금지 |
|---|---|---|
| 기존 결과·동일 입력 확인 | 현재 권한/조회 유효성 확인 후 원래 결과 반환 | 현재 자원이 바뀌었다고 과거 결과를 거절로 덮어쓰기 |
| 같은 키 변경 입력 | 충돌 차단·원래 결속 보존 | 새 R/새 실행으로 자동 처리 |
| R 없이 키/대상 참조만 있음 | 읽기 전용 lookup으로 기존 결속 찾기 | lookup에서 INSERT/업무 실행 |
| 결과는 있지만 권한/창 불명 | 공개 보류·한정 확인 | 일부 결과만 노출해 검증 우회 |
| 결과 부재·정리 또는 키 만료 | 현재 확인 한계 안내 | 미실행 단정·새 키 자동 실행 |
| 참조 전부 소실 | REC086 범위 제한 재발견 | 전체 과거 이력 검색·이름 추정 |

쓰기 재전송에 결과를 반환하는 정책은 현재 유효 조회 조건을 넘지 않는다. 상태 변경 없는 재전송이라도 타인 존재/과거 결과가 노출되지 않아야 한다. 정상 GET/lookup은 업무 결과/접수·최종 시각을 갱신하지 않는다. 운영 접근 로그가 필요하면 별도 목적·수명을 따르며 새 명령 결과와 구별한다.

## 기존 코드와 호환 경계

| 기존 구조 | 새 철회 명령에서의 처리 제안 | 이행 조건 |
|---|---|---|
| Idempotency-Key 헤더 | 새 명령도 같은 헤더 개념을 사용·I=K | 기존 생성/변경 경로와 명령 범위 분리 |
| tenant/actor/route/key 유일성 | 고정 본인·세대·명령 의미를 추가 검증 | 지원 계약 버전/정규화/새 경로 명세 |
| 성공 자원 참조/created_at | 기존 레거시 영수증은 그대로 보존 | 새 최종 근거/시각으로 이름만 바꾸지 않음 |
| 만료 키409·24시간 | 기존 API 계약 유지 | 새 결과/보호 기간과 분리; 전체 expires_at 일괄 수정 금지 |
| REPLAY_SUPERSEDED | 기존 일반 변경 API 의미 유지 | 새 요청 결과 읽기에 현재 자원 재표현을 강제하지 않음 |
| ACTIVE 소속/TENANT_ADMIN 쓰기 | 기존 일반 API 권한 유지 | 본인 목적 경로를 별도 검증; 관리자 우회/전체 소속조건 제거 금지 |
| V001 이후 기존 SQL | 원본 바이트 보존 | 실제 DB 계보 확인 후 추가 이행 설계; 덮어쓰기 금지 |

새 결과를 기존 영수증 테이블에 확장할지 별도 목적 단위로 둘지는 미선정이다. 두 안 모두 한 의도에 둘 이상의 실행기가 생기지 않아야 한다. 이행 중 구버전/신버전 클라이언트·경로·기록 형식이 어떤 요청을 읽거나 거절하는지 명세해야 한다. 실제 운영 배포가 ZIP과 같다는 가정을 하지 않는다.

## 키 정리 후 재생 — P4 차단 유지

결과/키 기록을 지운 뒤 같은 키 또는 새 키의 옛 의도가 다시 오는 경우를 단순 NOT EXISTS INSERT로 해결하지 않는다. 대상 세대가 이미 철회면 새 세대 변경을 막아야 하고, 새 키 반복에 무제한 무변경 기록을 만들지도 않아야 한다. 유한한 보호 참조·세대/계약 버전 퇴역·옛 경로 종료 등 후보의 실제 범위와 신뢰 기준을 선택해야 한다.

백업에서 결과와 보호 참조가 함께 과거로 돌아가면 같은 DB 안의 보호만으로 최신 철회를 입증할 수 없을 수 있다. 실제 복원 경로/최신 상태 재적용·독립 신뢰 기준·보호 사본 자체 정리를 P4에서 검증해야 한다. 영구 tombstone이나 일률90일을 이번 명세로 선택하지 않는다.

## P1/P2 완료에 필요한 산출물과 남은 연결

구현 전에는 실제 저장 배치/제약·모든 변경 경로의 잠금/권한 회수 순서·현재 본인 관계 정본·키/입력 정규화·지원 계약 버전·정식 응답/만료·레거시 읽기/거절 정책을 채워야 한다. 이번 명세로 P1/P2 완료를 선언하지 않는다. 다만 새 독립 미결을 늘리지 않고 P1/P2 안의 기술 작업으로 관리한다.

P3의 A/F 사건·기간·기기/기록 정리, P4의 옛 실행/복원 보호, P5의 실제 권한/운영 근거는 기존 미결 그대로 연결한다. 현재 자료만으로 모든 숫자와 실제 조직을 확정할 수 없다. 다음에는 이 저장 후보들을 한 표로 비교해 **기존 영수증 확장 또는 별도 최소 결과 저장**의 권고안을 구체화한다. 구현·파일럿은 시작하지 않는다.

검증 인계는 동일키/다른키 경합·새 세대·회수 경합·결과/감사 실패·COMMIT 불명·읽기 비실행·레거시 재전송·키 정리/복원이다. 기존 CA144/159~162 상세이며 모두 NOT_RUN. 기존 COS·REC001~096·정본·과거 자료·작업14/CA162/MVP34·다른 MVP33행·18B/DG/FD/RV 보존. PARTIAL_RECOVERY·코드/DB/GitHub 변경 없음.
