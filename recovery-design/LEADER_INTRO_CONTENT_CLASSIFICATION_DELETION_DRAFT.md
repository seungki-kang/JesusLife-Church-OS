# 소개 원문·동의 증빙의 분류와 사건별 삭제 대상 초안

2026-10-30 / r110 / RECORD_CLASSIFICATION_PROPOSAL + TECHNICAL_DRAFT / PARTIAL_RECOVERY / 실행 NOT_RUN

## 목적과 기준

[r109 LR01~12/RP01](LEADER_INTRO_SUPPORT_RECORD_RETENTION_COMPARISON.md), [계정·소속·서비스 계약](../docs/operations/ecosystem-v1/ACCOUNT_MEMBERSHIP_SERVICE_SCOPE_CONTRACT.md), [REC-063/064](RECOVERY_DECISIONS.md#rec-063-리더-소개-공개-동의-본인-철회), [REC-076~081](RECOVERY_DECISIONS.md#rec-076-종료-후-본인-소개-동의-철회)을 연결한다. 여기서 개인/교회/공동 분류는 제품 데이터의 처리 목적·삭제 단위를 정하는 설계 후보다. 저작권/법적 소유권·법정 보유의무를 확정한 문서가 아니다.

권장 D-A는 본인이 작성한 소개 문구·선택 사진과 교회의 실제 직함/지정/참여 이력, 공개 동의/철회 최소 증빙을 서로 다른 목적으로 분리하는 것이다. 개인 자료가 교회 앱에 게시됐다는 이유로 교회 영구 보관 자료가 되지 않으며, 계정에 연결됐다는 이유로 교회 운영 기록 전체가 본인 탈퇴 시 삭제되는 것도 아니다. 분류는 PROPOSED이며 실제 데이터 이동/삭제·새 보유기간 확정은 없다.

## 혼합/공동 기록의 삭제 단위 — 기술 후보

1. 계정 하나가 아니라 제품/교회/소개·콘텐츠버전/미디어참조/동의세대/사본별 대상을 한정한다. 전체테이블 cascade삭제 금지.
2. 공개투영은 현재동의/권한/직함으로 먼저 차단하고 삭제대기 중에도 원문 열람을 허용하지 않는다. 화면숨김만으로 실제삭제완료를 표시하지 않는다.
3. 교회업무가 과거직함 사실을 필요로 하면 해당최소참조/시각·결과를 본인 소개본문/사진과 분리한다. 최소이력이 남는다는 이유로 사진·소개 전문을 보존하지 않는다.
4. 공동문서의 본인인용/첨부를 식별하고 제거/대체/접근제한 후보와 타인기여 보존을 검토한다. 조용히 역사문서 의미를 바꾸거나 임의 익명처리 완료로 선언하지 않는다. 정정/안내·공동문서권한·표현보존 방식은 별도계약이다.
5. 원본/파생/썸네일·검색/캐시/첨부/큐/외부처리자·백업 범위와 실제삭제시각을 추적한다. 보관예외는 근거/승인/최소범위/종료가 별도확정돼야 하며 ‘교회업무’라는 포괄이유로 자동연장하지 않는다.
6. 삭제 후 남는 DC06/07/LR12는 최소목적/수명/접근/복원재적용을 별도로 정한다. 권한회수/삭제 재적용 근거를 지우고 백업에서 원문/옛소개가 다시 나오는 순환을 차단한다.

공동문서·업무이력에 개인정보가 섞인 것을 ‘교회 소유’라고 이름 붙여 원문삭제에서 모두 제외하는 방식도, 본인 계정참조가 있다는 이유로 타인/교회 이력을 모두 지우는 방식도 채택하지 않는다. 실제구조/기여/필드분리 확인 없이 자동분류 배치를 만들지 않는다.

## 보유·접근 인계

DC01/02 개인소개 목적종료 후 실제수명·DC04 업무이력·DC06/07 최소증빙·DC08/09 혼합자료의 보유/예외는 아직 OPEN이다. 기존 종료7일·대상원문백업30일·특정종료최소이력1년의 적용범위를 r109와 같이 유지한다. 소개동의철회 증빙 자체나 모든지원감사에1년/30일을 자동붙이지 않는다.

운영담당은 REC-079~081의 자격/해당건 최소접근만 갖는다. 데이터분류·삭제 검토 문서가 원문/사진을 담당자가 열람할 새근거가 되지 않는다. 자동스캔에 다른제품 개인원문/생명일기작성상태를 입력하지 않는다. 데이터분류가 법적권리 판단을 자동 대체한다고 주장하지 않는다.

## r111 후속 결정 — REC-082

[REC-082 개인 소개자료·교회 운영 이력·최소 증빙의 목적 분리](RECOVERY_DECISIONS.md#rec-082-개인-소개자료교회-운영-이력최소-증빙의-목적-분리): 본인이 작성한 소개 문구·선택 사진은 개인 소개자료, 실제 직함·지정·참여 사실은 교회 운영 기록, 동의·철회 사실은 원문 없는 최소 증빙으로 분리하고 공동 문서는 본인 자료와 타인 기여를 구분하는 기준을 확정했다. 구체 보유기간·명시삭제 권한·공동문서 정정 방식은 미결이다. 위 r110 D-A 질문은 당시 이력이다. 분류원칙만 AGREED_SCOPED이며 구체소유/사본판정·명시삭제/공동문서정정·기간/백업/기술후보는 OPEN이다. 실제분류/삭제 NOT_RUN.
