## 작업 단위와 결과 원장 — 최소 필드 후보

제품/교회/대상/동의세대·목적/필드범위·정책버전/원래기산/마감·사본식별/정리행위/실제결과/시각·필요actor/근거참조를연결한다. 고객이름/명칭·원문/사진·전체payload/토큰을원장에복제하지 않는다. 사본식별정보에접근비밀/서명URL을넣지 않는다. 해시가개인정보를없애거나사본계보완전성을증명한다고가정하지 않는다.

결과후보는 조사미완료/미접수/진행중/일부완료/실패/확인불가/적용대상없음확인/해당범위완료다. API enum이나새DB스키마는미선정이다. 전체완료는정의된범위의모든필수사본과차단/삭제/백업조건이확인돼야한다. 하나라도미확인이면전체PASS가아니다. 지연/부분실패의다음조치·책임자·안내기한은별도운영계약이며마감초기화 금지다.

최소원장자체가새개인관계사본이므로접근/보유/백업/최종삭제가필요하다. 종결증거를남긴다는이유로계정참조를영구보관하지않는다. 실제삭제/백업종료의근거수준·실행자/확인자권한·예외승인자는미결이다.

## 순서와 경합 조건

1. 대상/목적/세대·유효근거/예외와실제사본목록을고정한다. 삭제대상선정시각뒤새동의/새개인자료가생겼다면같은계정이라는이유로포함하지 않는다.
2. 해당공개/조회/담당접근을현재권한으로차단한다. 이미유효철회된대상은정리대기중에도중단을유지한다. 계정전체/다른유효동의까지무관하게차단하지 않는다.
3. 옛작업의세대결속/실행권한을차단한뒤운영본·파생/캐시·지원사본을정리한다. 삭제실패가철회취소/게시재시도사유는아니다. 작업을재실행해새세대자료를지우지않도록최종판정을한다.
4. 백업/복원소스는일반조회와격리하고원래만료/실제폐기근거를추적한다. 통제가능한복원시최신차단/삭제/권한을먼저재적용한다. 복구가능성미확인이면공개보류·운영인계한다.
5. 최후보호참조는목적과필요한범위/유한마감을정한뒤FG조건을검증해정리한다. 기한이도래했지만안전성미검증이면개인자료무기한보관으로자동전환하지않고정해진조정/사고절차로처리해야한다. 그절차와책임은실데이터전미결이다.

일반DB트랜잭션으로외부캐시/기기/처리자/불변백업까지원자확정했다고주장하지않는다. 각단계는실제상태/재시도/부분실패를추적하며업무철회확정결과와구분한다. 삭제완료응답유실은결과조회/사본상태검증으로판정하고새요청으로원래시각을초기화하지 않는다.
