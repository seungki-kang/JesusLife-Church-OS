## 확정 범위

접수·최종 결과는 해당 요청과 연결된 서버의 내구 저장 근거로 판정한다. 서버 도착이나 응답 시각만으로 판정하지 않는다. 접수 사실을 검증한 것과 최종 업무 결과를 검증한 것은 다르다.

| 인계 항목 | 확정된 원칙 | 추가로 필요한 것 |
|---|---|---|
| 접수 | 특정 요청의 내구 근거 필요 | 실제 수용 사건·처리 책임·저장 경계 |
| 최종 결과 | 요청/동의 세대에 결속된 결과 근거 필요 | 업무 반영과 결과 근거의 원자성·거절 결과 범위 |
| 응답 유실 | 응답 부재로 실패를 단정하지 않음 | 최초 응답 전 식별 복구·조회 경로 |
| COMMIT 불명 | 오류/롤백 시도만으로 미실행 판단 금지 | 실제 내구 근거 확인·유한 확인 업무 |
| 시간 | 사건/근거와 구별하여 검증, 임의 생성 금지 | 사건 정의·권위·정밀도·불명 시 조회 기산 |
| 공개/수명 | REC090 공개 상한과 기존 목적 경계 유지 | 결과 기록/멱등 보호/삭제·복원 수명 계약 |

기존 코드의 자원 created_at과24시간 성공 영수증을 새 철회 계약으로 이름만 바꿔 승계하지 않는다. 동기 모델과 별도 내구 수용 모델 중 하나를 선택한 것이 아니다. 아직 최소 근거가 어떤 저장 방식으로 확보될지 확인하지 않았으며 실제 동작 PASS를 선언하지 않는다.
