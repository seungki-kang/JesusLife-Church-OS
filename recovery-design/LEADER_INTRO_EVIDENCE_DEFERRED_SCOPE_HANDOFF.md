# 별도 철회 증빙 확인의 후속 분리 — 적용 인계

2026-10-30 / r122 / AGREED_SCOPED_DESIGN / PARTIAL_RECOVERY / 실행 NOT_RUN

[REC-083](RECOVERY_DECISIONS.md#rec-083-별도-철회-증빙-확인의-후속-기능-분리)의 범위 결정을 [r121 종료 점검표](LEADER_INTRO_REVIEW_CLOSURE_CHECKLIST.md)에 적용한다. 기존 점검표의 C01 OPEN과 질문은 당시 기록이며 이 후속 결정으로 범위 선택만 해소됐다.

| 구분 | 이번 적용 | 남은 일 |
|---|---|---|
| W 본인 철회 | 첫 출시의 기존 권리/범위 유지 | 대상 결속·현재 권한·커밋/멱등·응답 유실 후 최소 결과 확인 명세 |
| Q 일반 결과 확인 | 기존 자격·다섯 공개 항목·168시간 유지 | 실제 보유/조회/삭제·현재 권한 검증 계약 |
| E 별도 증빙 확인 | 첫 출시 필수에서 제외, 후속 후보 보존 | 재개시 별도 자격/필드/목적/기간/API 결정 |
| S 추가 확인 | 기존 별도 지정/건별 배정/최소 접근 원칙 유지 | 접수 자격·실제 운영/기한·필드/수명 미결 |
| 현재 효력/감사/보호 | E 유무와 별개로 필요 | 목적별 최소기록·유한 보유/백업·복원/옛실행 검증 |

이 분리는 화면/API의 제품 범위 선택이다. 증빙을 하나도 남기지 않거나 이미 정해진 삭제 의무를 없애는 저장 정책 변경이 아니다. 개인정보 원문·사진을 감사 목적에 복사하지 않는다. E 후속 설계를 위해 자료를 무기한 미리 모으지 않는다.

## 점검표의 후속 상태

- C01: AGREED_SCOPED로 범위 선택 해소. 실제 구현 완료가 아니다.
- C08: DEFERRED_DESIGN. E 재개 전 해결할 조건은 유지하며 첫 출시 E 전용 기능 게이트와 구분한다.
- C02~07: 기존 OPEN 유지. 특히 W 결과 미확인과 현재 효력/삭제·복원 보호는 E의 후속 분리를 이유로 건너뛰지 않는다.
- 전역18B·DG/FD/RV: 유지. 전체 MVP 준비 또는 개발 허가를 선언하지 않는다.

## 첫 출시 결과 확인의 남은 공백

교회 탈퇴 후 본인은 W를 실행할 수 있지만 Q는 현재 소속을 요구한다. 이 차이를 해결하려고 Q를 광범위하게 개방하지 않는다. W가 실제 확정됐으나 응답을 받지 못한 경우에 해당 본인·특정 의도/동의 세대의 최소 결과만 확인할 수 있는 계약이 필요하다.

별도 W 결과 경로·현재 자격·허용 필드·조회 기간·기기 참조·멱등 영수증 만료/삭제 후 동작은 아직 후보를 고르지 않았다. 기존24시간 영수증이나168시간 조회를 자동 이식하지 않는다. 결과 확인 불가는 새 철회 의도 자동 생성/재게시/대리 철회로 해결하지 않는다. 코드/스키마를 작성하지 않았다.

다음 작업은 **소속 종료 후 본인 철회의 응답 유실 시 최소 결과 확인 계약**이다. 장기 증빙(E)을 되살리지 않고, W에 필요한 한정 결과 확인과 Q의 기존 경계를 비교해 작성한다. 새 정책 선택이 필요하면 한 항목씩 묻는다.
