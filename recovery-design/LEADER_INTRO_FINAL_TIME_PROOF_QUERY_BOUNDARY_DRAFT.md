# 최종 확정 시각 증명과 168시간 조회 경계

2026-11-09 / r168 / CONTRACT_DRAFT_NOT_ADOPTED / PARTIAL_RECOVERY

[REC-098](RECOVERY_DECISIONS.md#rec-098-최종-결과-168시간-조회와-선접수-표시-경계)의 168시간·선접수 표시 합의를 구현 인계 수준으로 구체화한 초안이다. [S2 인계](LEADER_INTRO_S2_STORAGE_DIRECTION_AGREED_HANDOFF.md), [P3 후보](LEADER_INTRO_P3_TIME_RETENTION_CONSOLIDATED_DRAFT.md)와 연결한다. 시계·DB 기능은 실제 환경에서 확인하지 않았다. 아래 경계·실패 계약은 권고이며 추가 합의로 기록하지 않는다.

## 최종 사건과 시각 증명

- **업무 정본:** 같은 철회 요청의 본인·고정 입력·동의 세대·결과·감사가 단일 원자 경계에서 확정된 사건을 F로 본다. 실행·무변경·입증 가능한 최종 거절 모두 해당 요청 자체의 확정 사건을 갖는다. 과거에 다른 요청이 철회한 시각을 가져오지 않는다.
- **시각 증명:** F가 확정됐다는 증거와 F가 언제 발생했는지의 증거를 구분한다. 권고안은 확정 권위가 제공하는 시각을 해당 내구 결과와 검증 가능하게 결속하는 것이다. 필요한 논리 근거는 요청/결과 버전, 원자 확정 증거와의 결속, 시각 출처·정밀도·신뢰 상태다. 실제 필드와 물리 저장 위치는 미결이다.
- **금지:** 기기 전송, API 도착, 트랜잭션 안에서 먼저 찍은 일반 생성 시각, 응답 시각, 재시작 후 발견 시각을 정확한 확정 시각으로 치환하지 않는다. 기존 v2.6 코드의 일반 API 영수증은 자원 생성 시각과 24시간 만료를 쓰므로 새 F 근거로 승계하지 않는다. 출처: canonical v2.6의 services/church-core/src/postgres.ts의 영수증 생성 및 트랜잭션 경로.
- **권고 후보:** 실제 DB/저장 계층에서 권위 있는 확정 시각을 제공하고, 재시작·장애 복구·정상 수명 동안 동일 결과와 안정적으로 결속할 수 있다면 사용한다. 시각이 원자 확정 뒤 별도 투영으로만 확보될 경우, 투영은 같은 정본의 시각만 재구성하는 읽기 근거다. 두 번째 업무 확정, 재실행, 최초 관찰 시각에 의한 보정은 금지한다.
- **채택 차단:** 권위 시각을 제공할 수 없는 환경에서는 배포 전 시간 계약이 미충족이다. 확정 전 기록 시각이나 최초 관찰 시각을 기준으로 삼는 대안은 창이 짧아지거나 길어질 수 있다. 채택하려면 의미와 오차를 공개적으로 정의하고 REC-098 적용 범위를 별도 검토한다. 이를 기본 대체값으로 사용하지 않는다.

## 조회 경계 권고

서버의 신뢰 시각을 now로, 검증된 F의 시각을 f로 둔다. UTC 절대 시각에서 end = f + 604800초로 산정한다. 사용자 시간대는 표시만 바꾼다. 결과 제공 조건은 **현재 본인 인증·대상 결속·읽기 자격 충족 AND f ≤ now < end**다. 정확히 end에는 종료한다. 목록·직접 조회·읽기 전용 결속 조회·제한 재발견이 같은 비교 규칙을 사용한다. 각 응답은 결과 공개를 판정하는 한 시점의 서버 시각을 사용하며, 네트워크 전달 지연은 조회 창을 연장하지 않는다. 정밀도를 낮춘 표시값이나 기기 시각으로 비교하지 않는다.

예: 최종 확정이 11월 9일 17:00 KST이면 11월 16일 17:00 KST 직전까지 조건을 충족할 때 조회 가능하며, 정확히 17:00부터 종료한다. 11월 12일에 처음 발견해도 종료 시점은 동일하다. 과거 응답을 기기나 중간 캐시에서 다시 내보내 서버 검증을 우회하지 않도록 한다. 이미 전달된 사본의 로컬 정리·오프라인 표시는 별도 설계다.

## 근거 공백과 시계 장애

| 상황 | 처리 권고 | 금지 |
|---|---|---|
| COMMIT 응답 유실 | 현재 본인 인증 뒤 같은 결속을 읽어 내구 확정을 확인 | 자동 명령 재실행, 로그만 보고 미실행 판정 |
| 확정 증거는 있으나 f가 미검증 | 결과 조회 기간을 판단할 수 없으므로 일반 조회에서 세부 결과·시각 공개 보류; 제한된 복구/문의로 연결 | 현재 시각으로 다시 기산, 만료·실패로 단정 |
| now 역행·미래 점프·복원 직후 시계 신뢰 불명 | 신뢰하지 못하는 조회 응답을 잠시 차단; 시계 정상화와 최신 권한·삭제 상태 검증 후 동일 f/end로 평가 | 일시적으로 앞선 시계로 영구 만료·삭제, 뒤로 움직인 시계로 확정된 만료 재개 |
| 신뢰 판정의 오차 범위가 경계를 가로지름 | 기간 판정 보류 및 재조회 안내; 실제 허용 오차·관측 근거가 채택 조건 | 기기 시계·임의 허용 시간을 추가해 창 연장 |
| 권한 없음·타인·대상 불일치 | 기존 비공개 응답 경계 적용; 결과 존재 또는 시간 장애를 개인별 단서로 노출하지 않음 | 키/참조 소지만으로 상태나 시각 노출 |
| 검증된 end 도달 | 일반 조회 종료; 삭제·감사·문의·백업·보호의 각 목적 계약 유지 | 업무 효과 취소, 재실행 허용, 보호표식 일괄 삭제 |

시간 근거 복구는 같은 내구 사건의 증거를 확보하는 작업이다. 원래 f를 입증하지 못하면 자동 만료, 결과 재생성, 무기한 조사로 넘기지 않는다. 기존 REC088/089의 제한된 확인·재검토를 연결하되 운영 담당자·기한과 구체 안내는 미결이다. 만료 판정과 백업 복원 뒤 재노출 방지는 실제로 회귀 없이 동작하는지 확인해야 한다.
