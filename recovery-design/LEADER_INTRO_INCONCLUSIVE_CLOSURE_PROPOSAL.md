# 결과 미입증 시 확인 업무 종결 조건 제안

2026-10-31 / r139 / PROPOSED / PARTIAL_RECOVERY / 실행 NOT_RUN

[직전 내부 확인 기준](LEADER_INTRO_INCONCLUSIVE_CLOSURE_PROPOSAL.md)과 [기존 합의](RECOVERY_DECISIONS.md)를 유지한다. 이 문서는 요청 결과를 끝내 입증하지 못할 때 확인 업무만 마치는 조건을 제안한다. 사용자 승인·운영 채택·실제 권한 부여가 아니다.

## 종결 조건 카드

| 조건 | 확인할 근거 | 충족하지 못한 경우 |
|---|---|---|
| IC01 대상 결속 | 본인과 특정 요청·동의 세대의 검증된 관계 | 타인 존재를 공개하지 않고 제한된 추가 확인으로 분기 |
| IC02 조사 범위 | 승인된 자료 범위, 수행한 확인, 접근 불가·소실·불일치 목록 | 조사 완료라고 표시하지 않음 |
| IC03 결과 한계 | 결과를 입증할 근거가 없다는 사실과 그 이유 | 현재 소개 상태·404·로그 부재만으로 성공/실패 추정 금지 |
| IC04 실행 관계 | 실제 진행 중 작업, 지연 전달, 재생 가능 경로의 별도 확인 | 실행 안전성 미확인으로 남김. 확인 건 종결을 작업 취소로 취급하지 않음 |
| IC05 유한 종료 | 실제 책임자, 승인된 확인 상한, 예외 종료와 정리 기준 | 운영 종결 준비 미완료. 무기한 보유나 임의 종료를 대안으로 삼지 않음 |
| IC06 적격 검토 | 현재 지정·건별 권한·충돌 검사와 종결 판단의 최소 이력 | 담당자 부족으로 자기승인·DB 권한 확대하지 않음 |
| IC07 안내·정리 | 현재 허용된 본인 안내 경로와 최소 기록별 보유/삭제/백업 기준 | 안내 권한이나 보유기간을 종결 처리로 자동 연장하지 않음 |

IC04는 모든 자료가 삭제됐다는 증명이 아니다. 실제 실행이 계속될 수 있다면 담당·유한 처리 수명·지연 확정 처리·재실행 방지의 별도 계약이 필요하다. 이를 채우지 않은 상태는 개발 인계의 차단 조건으로 남긴다. 조사 상한을 기다렸다는 사실만으로 실행 경로가 닫혔다고 판단하지 않는다.

## 판정 분기

| 확인된 상황 | 업무 결과 | 확인 업무 처리 후보 |
|---|---|---|
| 정확한 요청의 최종 근거 확보 | 검증된 결과 | 근거 확보 종결; 실제 확정 시각 유지 |
| 실제 실행 진행을 확인 | 아직 최종 아님 | 처리 책임과 유한 다음 확인으로 인계; 확인 불가 종결로 숨기지 않음 |
| 제한된 조사 완료, 결과 미입증, IC01~07 충족 | 불명 유지 | 확인 불가라는 한계를 명시하여 확인 업무만 종결 |
| 실행 상태 또는 필수 권한/기준 미확인 | 불명 유지 | 미충족 조건과 책임을 남김; 종결 승인 금지 |
| 동일 확인 건 중복 접수 | 원래 결과 유지 | 원래 확인 건에 연결; 원래 기산과 업무 요청은 유지 |

현재 동의가 철회 상태인 사실과 이 특정 요청이 철회를 확정했다는 사실은 다르다. 새 요청 제출·대리 철회·동의 복구·직접 DB 보정은 이 절차에서 허용하지 않는다.

## 사용자 안내 후보

현재 권한이 검증되고 별도 지원 안내가 허용된 경우에만 다음 의미를 전달한다.

“정해진 범위에서 확인했지만, 이 요청의 최종 결과를 입증하지 못했습니다. 이번 확인 업무는 종료되며, 이것이 철회 실패나 재실행 허용을 뜻하지는 않습니다.”

화면 문구는 실제 정책 확정 후 다듬는다. 소개 원문·사진·다른 사람의 정보·내부 조사 메모를 첨부하지 않는다. REC-087에 따라 끝난 일반 조회 창을 지원 화면으로 다시 열지 않는다. 통지가 전달되지 않았다는 이유로 일반 조회 기간을 초기화하지 않으며, 통지 시도·실패 기록도 목적별 유한 수명을 정한다. 구체 공개 필드와 안내 기간은 OPEN이다.

## 종결 후 새 근거

새로운 검증 가능 근거가 생기면 원래 요청과 연결한 재검토 후보로 다룬다. 같은 주장 반복만으로 새 조사 시계를 시작하지 않는다. 재검토 승인 주체·인정 사유·최대 범위와 유한 기한은 OPEN이다. 과거 종결 판단을 지우지 않고 새 근거와 정정 관계를 최소 이력으로 연결한다.

뒤늦게 실제 최종 확정이 검증되면 원래 확정 사건과 시각을 쓴다. 발견 시각으로 최종 조회 창을 새로 만들지 않는다. 아직 유효한 최종 조회 창이면 REC-087에 따라 현재 본인 권한을 검증하여 재포함하고, 이미 끝난 창이면 별도 안내/정정 정책이 필요하다. 새 증거 발견은 철회 재실행 권한이 아니다.

## 개발 전 남은 결정

1. 확인 업무만 별도 종결하는 원칙의 사용자 동의.
2. 실제 운영 책임자·자격·독립 검토/겸임 조건과 종결 권한.
3. 확인 접수 사건·상한·안내·예외·재검토의 유한 시간 계약.
4. 실행 경로와 중복 방지 보호의 종료/인계 근거.
5. 조사·안내 기록별 최소 항목과 보유·삭제·백업 계약.

24시간 영수증 수명, 기존 일반 Q의168시간, 특정 탈퇴 전달 실패의24시간을 이번 조사 기한으로 복사하지 않는다. 새 상태명·API·테이블·수명 숫자는 확정하지 않았다. r128 공개 항목 상한도 여전히 미합의다.

## 검증 조건

검증 계획은 결과 불명+모든 조건 충족, 실행 진행 중, 담당 회수, 근거 불일치, 통지 실패, 새 증거, 최종 창 만료 후 발견, 같은 문의 반복, 계정/교회 전환을 포함한다. 각각 업무 결과 조작·실행 취소 오인·기간 초기화·타인 노출·무권한 재실행이 없는지 확인해야 한다. 기존 CA144/159~162의 세부 검증 인계이며 새 시나리오 수나 테스트 성공을 추가하지 않는다. 전부 NOT_RUN이다.

다음 좁은 질문: IC01~07을 충족한 경우에 한해, 철회 결과는 불명으로 유지하고 확인 업무만 ‘확인 불가’로 종결하는 원칙을 채택할까요? 숫자·담당·권한·보유 계약은 별도로 확정한다.

기존 COS·REC001~087·정본·과거 자료 보존. 공동체14/CA162/MVP34 유지. 부분 복원본이며 코드·DB·GitHub 변경 없음.

## r140 후속 상태

[REC-088](RECOVERY_DECISIONS.md#rec-088-결과-불명-시-확인-업무의-한정-종결)로 조건 충족 시 확인 업무만 종결하는 원칙을 한정 합의했다. 이 문서의 세부 문구·기한·권한·검증 조건 전체가 합의된 것은 아니다. 원래 제안은 이력으로 보존한다.
