## 이번부터 적용할 진행 방식

사용자가 승인한 ‘3~4회 통합 검토’에 따라 이번을 첫 번째 검토로 삼고 총 네 묶음으로 정리한다. 문서 작성 횟수와 개발 준비 완료를 구별한다. 실제 운영 자료가 없거나 중요한 미결이 남으면 완료를 선언하지 않는다. 이미 합의한 원칙은 되묻지 않으며 새로운 정책은 한 묶음의 결정 카드로 제시한다. 이번 승인으로 새 기간/조직/권한/거절 사유를 확정하지 않는다.

| 검토 | 범위 | 종료 기준 | 현재 상태 |
|---|---|---|---|
| 1 기존 코드 연결 | 결과/감사/키/본인 권한과 기존 구현 대조 | 재사용·추가 설계·승계 금지 구분 및 구현 과제 연결 | 이번 문서에서 정적 대조 수행 |
| 2 시간·자료 수명 | 조회/조사/결과/감사/오류/실행 보호·삭제/백업 | 사건·기간·사본·예외별 통합 후보와 기존 합의 충돌 점검 | 다음 검토; 숫자 미확정 |
| 3 운영 권한 | 선임·배정·개시·종결·정정·회수·공백 | 최소 역할표와 실제 운영 근거의 미확인 사항 분리 | 후속 검토; 실제 담당 미확인 |
| 4 개발 인계 통합 | 명령·조회·기기·장애·권한·수명 연결 | 누락/충돌 목록·필수 결정/후속/출시 검증의 최종 구분 | 후속 검토; 구현/파일럿 시작 안 함 |

기준 자료는 [REC 원문](RECOVERY_DECISIONS.md), [M1 명령](LEADER_INTRO_M1_COMMAND_CONTRACT_DRAFT.md), [최소 기록 분리](LEADER_INTRO_INTEGRATED_REVIEW_1_CODE_MAPPING.md), [통합 결정표](LEADER_INTRO_PREDEVELOPMENT_DECISION_MATRIX.md)다. 과거 자료는 삭제하지 않고 현재 결론을 이 문서로 연결한다.

보존된 canonical v2.6의 [postgres.ts](../canonical/ChurchOS_Canonical_v2.6/services/church-core/src/postgres.ts), [app.ts](../canonical/ChurchOS_Canonical_v2.6/services/church-core/src/app.ts), V005/V007/V008/V014/V015 파일을 정적으로 대조했다. r126의 정적 조사도 재사용한다. 실제 배포/운영 DB 계보·카탈로그와 동일하다는 보장은 없다. 쿼리/앱 테스트를 실행하지 않았으며 아래 평가는 기술 설계 인계다.

## 이번 검토에서 정리된 것과 남은 것

정리된 것은 기존 코드 연결에 대한 정적 매핑이다. 모델 방향 M1·실행/무변경 결과·내구 근거·오류 분리 등 REC001~095는 유지한다. 신규 정책 합의는 없다. 실제 grant/운영 계보/처리 부하/복원 경로는 미확인이고 기술 세부·권한·수명 게이트는 해소되지 않았다.

다음 두 번째 통합 검토에서는 숫자를 한 항목씩 묻기보다 사건·기간·자료군·사본·예외를 한 장의 후보표로 묶는다. 합의된 기간은 원문 범위로 유지하고, 미합의 숫자는 추천/대안/필요 근거로 표시한다. 운영 담당이나 실제 사본 상한이 필요한 값은 사용자 정책 동의만으로 검증 완료 처리하지 않는다.
