# 철회 설계 통합 검토 3/4 — 운영 권한·책임·공백 대응

2026-11-01 / r159 / OPERATING_AUTHORITY_DRAFT / PARTIAL_RECOVERY / 실제 실행 NOT_RUN

[REC 원문](RECOVERY_DECISIONS.md)의 REC079~081·088/089를 따른다. [통합 검토1](LEADER_INTRO_INTEGRATED_REVIEW_1_CODE_MAPPING.md), [통합 검토2](LEADER_INTRO_INTEGRATED_REVIEW_3_OPERATING_AUTHORITY.md), [내부 확인 흐름](LEADER_INTRO_INTERNAL_RESOLUTION_DRAFT.md)을 연결한다. 아래 논리 역할표는 실제 인력 선임이나 권한 부여가 아니다. 기존 합의 외의 역할 조합·승인 세부는 제안이다.

## 현재 권위

별도 담당 지정·건별 최소 접근, 자기선임/자기배정/충돌 자기승인 금지, 실제 운영 주체의 확인 가능한 최초 지정 근거와 다른 적격자의 확인은 기존 합의다. 조건부 확인 불가 종결과 재검토 사유도 합의됐다. 누가 그 운영 주체인지·실제 적격자·겸임 조합·종결 승인·기술 접근·대행·예외의 실제 권한은 미확인/OPEN이다. 대표/목회자/교회 관리자/DB 소유자라는 직함만으로 자동 부여하지 않는다.

## 최소 논리 역할표

| ID/역할 후보 | 허용 목적 후보 | 필요한 지정/범위 | 자동 부여되지 않는 권한 |
|---|---|---|---|
| OA01 운영 책임 근거 확인 | 최초/후임 책임 지정 근거와 적격 검토의 확인 | 실제 운영 주체·근거·다른 적격 검토자 확인 | 자기선임·포괄 개인정보 열람 |
| OA02 건별 배정/인계 | 현재 적격자에게 한정 과제 배정 | 대상 건·목적·허용 항목·유효기간·충돌 확인 | 자기배정·기술 DB 접근 |
| OA03 접수/안내 | 현재 본인/요청 관계와 최소 접수·안내 | 건별 배정과 현재 권한 | 대리 철회·재검토 개시 승인·원문 열람 |
| OA04 기술 근거 확인 | 해당 요청의 내구 결과/시각 한계 조사 | 별도 기술 자격·승인된 최소 도구/필드·건별 범위 | 포괄 DB 덤프·직접 업무 변경·타제품 원문 |

| OA06 정리/복원 운영 | 목적별 정리·복원 격리/최신 상태 재적용 | 실제 운영 작업 권한·범위·승인/검증 | 근거 없이 보호 종료·사용자 업무 정정 |
| OA07 제한 점검 | 지정/접근/정리의 최소 이력 확인 | 점검 목적·대상·유한 접근 | 전체 기록 열람·자기 충돌 해제 |

일곱 역할은 일곱 직원 채용 요구가 아니다. 겸임 가능 범위는 실제 인력과 충돌 위험을 보고 별도 결정해야 한다. 기존 합의의 다른 적격자 확인을 ‘한 사람이 역할 이름만 바꾸어 승인’으로 대체하지 않는다. 실제 조직을 이번 문서에서 조이넥스/지저스랩 등으로 추정 지정하지 않는다.

## 행위별 최소 권한 판정

| 행위 | 현재 확인할 조건 | 범위/실패 처리 |
|---|---|---|
| 담당 선임/후임 지정 | 유효한 지정 근거·다른 적격 검토 | 근거 없으면 활성화하지 않음; 최초 로그인 자동 권한 금지 |
| 건 배정/인계 | 배정자 권한·수임자 적격·충돌·목적/기간 | 기존 범위 이외 자료를 인계에 추가하지 않음 |
| 근거 열람 | 유효 지정+건별 범위+현재 자격+필드 허용 | 메뉴 숨김만이 아니라 서버/자료 접근 경로 재검증 |
| 종결 판정 | 현재 종결 권한·IC01~07·실제 실행/보호 관계 | 미충족을 기한 도달로 덮지 않음 |
| 재검토 개시 | 현재 개시 권한·REC089 사유·한정 과제·유한 시간 | 접수나 같은 주장 반복만으로 자동 개시 금지 |
| 오류 정정 | 별도 정정 권한·근거·현재 대상/버전 | 조사 권한만으로 원래 업무 결과 수정 금지; 실제 명령 계약 OPEN |
| 자료 정리 | 현재 작업 권한·목적별 기산·예외/보호 | 일괄 수명 적용·관련 자료의 무기한 연장 금지 |
| 권한 회수 | 지정/기간/소속 자격·충돌 등 변경의 확인 | 다음 접근/확정에서 차단하도록 설계; 실제 전파/경합 미검증 |

권한 회수 전에 읽은 화면·다운로드·기기 캐시의 재노출 방지는 별도 구현/실행 점검이 필요하다. 이미 적법하게 확정된 과거 업무 결과를 담당 회수 때문에 소급 실패로 바꾸지 않는다. 판정 도중 회수·동시 인계는 실제 확정 지점의 재검증/경합 계약을 채워야 한다.

## 대행·공백·충돌

| 상황 | 권고 운영 경계 | 실제로 채울 것 |
|---|---|---|
| 휴가/부재 | 미리 적격 확인된 대행자에게 범위/기간 제한 인계 | 대행 지정 근거·효력 기간·건별 배정 |
| 담당 자격 상실 | 현재 접근 차단·최소 인계; 복귀해도 옛 권한 자동 부활 금지 | 회수 사건·대행 책임·전파/확정 경합 |
| 자기 사건/이해충돌 | 다른 적격자가 충돌과 배정을 판단 | 신고/검토/교체 절차·실제 검토자 |
| 최초 책임자/후임 공백 | REC081 근거 확인 절차로 선임 | 운영 주체·다른 적격 검토 확보 |
| 적격자가 전혀 없음 | 해당 내부 조사/판정 운영 준비 차단으로 기록 | 책임 주체의 인력/범위 해결; 무권한 비상권한 생성 금지 |
| 조사 중 실제 실행 진행 발견 | 실행 책임·유한 수명 계약으로 인계 | 실제 실행 주체·진행/종료 근거 |

내부 담당 공백을 이유로 이미 허용된 본인 철회 자체를 관리자 승인제로 바꾸지 않는다. 정상 본인 명령과 일반 결과 확인은 각 계약대로 동작해야 한다. 지원/종결이 필요한 예외를 처리할 적격 운영이 없다면 관련 운영 준비는 미완료다. 앱 장애/안전 문제에 대한 출시 제한은 별도 운영 판단이며 이번 문서가 서비스를 실제 중지한 것은 아니다.

## 시간 후보와 결속

r159 TL03의1차24시간/총336시간 등은 미합의 후보다. 이를 약속하려면 OA02~05 실제 인력·부재대행·접수 범위·상향 전달·유한 종료와 실행 보호가 충족돼야 한다. 인력이 없는데 자동 종결로 숫자만 맞추지 않는다. 대행/새 문의번호/재검토로 원래 접수·최종 시각을 초기화하지 않는다.

TL05/07 조사/감사 보유와 TL10/11 사본/실행 보호도 실제 책임과 목적 종료 근거가 필요하다. 운영 권한표 작성은 후보 기간 승인이나 실제 삭제/복원 가능성의 증거가 아니다.
