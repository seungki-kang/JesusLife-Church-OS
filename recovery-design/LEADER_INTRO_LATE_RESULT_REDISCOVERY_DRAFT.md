# 늦게 확정된 본인 철회 요청의 최소 재발견 경로

2026-10-31 / r133 / REQUEST_REDISCOVERY_DRAFT / PARTIAL_RECOVERY / 실행 NOT_RUN

## 범위

[REC-085 적용](LEADER_INTRO_RESULT_WINDOWS_AGREED_HANDOFF.md)의 미확정/최종 유한 확인 창 분리와 [REC-084 권한](LEADER_INTRO_MINIMUM_RESULT_AGREED_HANDOFF.md), [r125 요청 결속](LEADER_INTRO_WITHDRAWAL_REQUEST_BINDING_DRAFT.md), [r129 누락 처리](LEADER_INTRO_RESULT_MISSING_VALUE_HANDLING_DRAFT.md)를 연결한다. 이번은 해당 요청의 참조를 다시 찾는 경로 후보다. 새 목록/알림 기능·조회 기간·기기 보존을 확정하지 않는다.

[REC 원문](RECOVERY_DECISIONS.md)을 보존하고 E 장기 증빙 조회는 후속으로 유지한다. [r128 공개 상한](LEADER_INTRO_RESULT_DISPLAY_LIMIT_PROPOSAL.md)은 여전히 OPEN이다. REC-084/085를 모든 과거 요청 이력의 탐색권으로 확대하지 않는다.

## 문제와 설계 목표

최종 결과 확인 창이 있어도 본인이 요청 참조를 잃으면 그 결과를 찾기 어렵다. 로그아웃/계정 전환 때 참조를 정리하는 기존 기기 원칙을 위반해 영구 보관하는 방식으로 해결하지 않는다. 서버 참조가 없는 첫 응답 유실과, 받은 참조를 나중에 잃은 경우도 구분한다.

원문·사진·명칭·교인 명단·이메일 일치로 대상을 추측하지 않고, 현재 본인과 서버에 결속된 특정 철회 요청만 찾는 것이 목표다. 찾을 수 있는 유효한 근거가 없으면 그 한계를 알리며 복원/확정 사실을 만들어내지 않는다.

## 경로 후보 대조

| 경로 | 조건·입력 | 허용 범위 후보 | 한계/새 결정 |
|---|---|---|---|
| RF-A 기존 참조로 직접 확인 | 같은 계정·I/K 또는 R가 적법하게 남음 | 현재 인증/본인/요청 결속과 유효 창 검증 후 해당 결과만 | 참조 보유가 권한은 아님·기기 수명/재로그인 정리 필요 |
| RF-B 본인 한정 재발견 색인 | 참조 소실·다른 기기, 서버의 정확한 본인 결속 근거 유효 | 아직 허용된 확인 목적 안의 W 요청 참조만 제한적으로 재발견하는 후보 | 새 목록 능력·최소 필드/발견 창/건수/페이지·권한 합의 필요 |
| RF-C 제한 지원 확인 | 직접 확인 불가, 적법한 최소 근거 잔존 | 별도 지정/건별 배정 담당의 제한 확인 | 실제 접수/담당/자격/유한 종결 필요·대리 철회 금지 |
| RF-D 외부 알림/전달 | 별도 허용 채널·현재 계정/기기 결속 확인 | 최소 확인 가능 알림 후보, 실제 조회시 다시 인증 | 채널/수명/분실/계정 전환/동의·실패 대응 미결 |

RF-A는 유효 참조가 있는 경우의 우선 경로다. **RF-A만으로 참조가 없는 본인의 REC-085 최종 확인 기회가 해결됐다고 주장하지 않는다.** RF-B는 비교 후보이며 채택되지 않았다. RF-C만 두면 담당 공백이 일반 결과 확인의 장벽이 될 수 있다. RF-D는 보조 수단이며 푸시/메일 전달 실패를 결과 확인 불가의 최종 해소로 보지 않는다.

## RF-B를 채택하려면 필요한 최소 계약

계정별 전체 감사/업무 이력을 노출하는 검색이 아니라 **본인이 실제 제출한 W 요청의 제한 참조 투영**을 검토한다. 이 기능은 현재 구현돼 있지 않으며 REC-084 한 건 조회권에서 자동 파생하지 않는다. 일반 Q의 현재 소속 요건을 완화해 RF-B를 대신하지 않는다.

- 색인 원천: 현재 계정 본인과 I/K/R/T/F가 실제로 결속된 최소 기록이어야 한다. 다른 제품/교회 자료에서 추론하지 않는다.
- 포함 조건: 목적별 현재 자격·유효 확인 창·본인 요청만. 아직 상태별 발견 창/미확정 만료와 늦은 최종 사이의 포함 조건은 미결이다. 필요조건이 없으면 운영에 내보낼 수 없다.
- 공개 최소: 참조/처리 상태 등 후보만 검토하고 명칭·원문·사진·상세 사유·전체 건수를 추가하지 않는다. r128 공개 상한 자체도 OPEN이다.
- 복수 건 모호성: 번호/시각만으로 의미를 구분하지 못할 수 있다. ‘최근/첫 항목’을 자동 선택해 철회 실행하거나 다른 동의 상태로 결합하지 않는다. 재발견은 결과 읽기이며 쓰기가 아니다.
- 접근: 현재 인증·목적·본인 결속을 페이지/직접 조회마다 확인한다. 교회 탈퇴 후도 허용된 본인 W에 한정하되 다른 교회 업무는 제외한다. 커서/정렬/캐시로 타인 존재가 새지 않아야 한다.
- 수명: 색인/프로젝션도 사본이다. 원래 사건/기산·조회 종료·결과 기록 정리·백업·옛 원천 차단과 연결한다. 편리한 재발견을 위해 새로운 영구 요청 목록을 만들지 않는다.

건수 제한·페이지 규격·서버 조회 경로·필드/응답·색인 저장/조인 방식·키/권한은 OPEN이다. 필터링 없는 전체 이력을 클라이언트로 보낸 뒤 화면에서만 숨기지 않는다.

## 알림·링크의 제한

‘결과를 확인할 수 있습니다’ 같은 최소 알림도 특정 교회 관계/행위가 추론될 수 있으므로 채널별 공개·잠금화면·수신자/기기 현재 결속을 검토한다. 번호/서명 링크를 로그인 대체 권한으로 쓰지 않는다. 열기/조회시 서버가 현재 본인·목적·기한을 다시 확인한다.

알림 전송/재전송·새 기기 등록이 최종 확인 창을 재시작하지 않는다. 탈퇴/정지·기기 회수 뒤 전달 큐를 어떻게 차단할지는 실제 계약과 검증이 필요하다. 이번에 RF-D를 채택하거나 푸시/메일을 발송하지 않았다.

## 검증 인계 — 실제 실행 아님

같은/다른 계정·탈퇴 교회·C1/C2·첫 응답 유실·로그아웃/재설치·미확정 창 만료/늦은 최종·최종 만료/정리·지연 알림·타인 커서/번호를 합성 자료로 대조한다. 정상 경로 접근과 비허용 결과/존재 미노출·조회 중 쓰기 미발생을 관측해야 한다. RF-B/C/D가 미선정이면 기대 기능 자체도 선택 후 정해야 한다.

기존 CA144/159~162와 WRV/WB/RCV·MV 조건을 구체화하는 인계이며 새 CA/실행 성공 수를 만들지 않는다. 모두 NOT_RUN이다. 실제 앱/계정/DB/백업/제공자/알림 채널을 사용하지 않았다.
