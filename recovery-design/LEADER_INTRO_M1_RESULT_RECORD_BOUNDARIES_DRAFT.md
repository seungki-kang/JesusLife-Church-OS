# M1 철회 명령의 결과 의미·내구 기록 경계표

2026-10-31 / r153 / RESULT_BOUNDARY_DRAFT / PARTIAL_RECOVERY / 실제 실행 NOT_RUN

[REC094 인계](LEADER_INTRO_NO_CHANGE_RESULT_AGREED_HANDOFF.md), [M1 명령 초안](LEADER_INTRO_M1_COMMAND_CONTRACT_DRAFT.md), [REC 원문](RECOVERY_DECISIONS.md)을 잇는다. 실제 철회와 최소 내구 무변경 결과의 방향은 합의됐지만, 아래 결과 분류·거절 기록·저장 경계는 초안이다. 정식 상태명·응답 코드·새 스키마를 확정하지 않는다.

## 서로 다른 세 축

업무 결과는 해당 요청이 무엇을 확정했는지, 관찰 확실성은 그 결과를 현재 입증할 수 있는지, 조회 권한은 지금 누구에게 무엇을 보여줄 수 있는지다. 업무 성공 근거가 있어도 현재 조회 권한이 없으면 공개하지 않는다. 조회 실패나 기간 종료는 업무 실패가 아니다. 확인 업무 종결/재검토도 이 세 축을 대신하지 않는다.

## 최종 거절 기록을 채택하기 전

1. 현재 본인·특정 요청/입력·동의 세대가 검증된 건인지 확인한다. 무권한 탐색을 요청 결과로 등록하지 않는다.
2. 허용할 업무 거절 사유를 한정하고 그 사유가 추가 변경 없음을 어떤 원자 경계에서 보장하는지 명시한다.
3. 변경 트랜잭션 롤백 뒤 별도 기록을 남긴다면, 사이의 경합·다른 요청의 실행·원래 COMMIT 불명과 구별할 근거가 필요하다. 단순 오류 핸들러의 별도 INSERT로 최종 거절을 보장했다고 주장하지 않는다.
4. 거절 근거 저장 실패/확정 불명 시 최종 거절을 공개하지 않는다. 저장된 사실을 확인하되 새 철회 명령을 자동 실행하지 않는다.
5. 조회·키 충돌·시각·수명·복원에서 성공/무변경 결과와 같은 본인 관계를 검증한다. 입력 원문이나 토큰을 증빙에 복사하지 않는다.

M1 안에서 변경 없이 결과만 확정하는 분기의 상세 트랜잭션 설계는 가능하지만 실제 방식은 미선정이다. 별도 선접수/후속 실행 책임을 도입하면 REC092의 M1 범위를 벗어나는지 재검토한다.

## 시각과 상태를 연결할 때

RB01은 이번 요청의 실제 변경 확정, RB02는 이번 무변경 판정 확정, RB03은 검증된 거절 확정이라는 서로 다른 의미를 가진다. RB02의 확정 시각을 과거 철회 실행 시각으로 표시하지 않는다. 정식 처리 상태의 의미와 시각 설명은 함께 계약해야 한다. 실제 사건/시각 권위·조회 기간 숫자·최종 창 기산은 OPEN이다.

확정 사실은 검증됐으나 정확한 시각이 불명인 경우와 최종 결과 자체가 불명인 경우를 구별한다. 시각을 임의 생성하지 않으며 조회 유효성 판정을 생략하지 않는다. 사후 발견 시각·응답 시각·자원 created_at을 누락값 대체로 사용하지 않는다.

## 반복/동시 요청과 조회

같은 요청 재조회는 기존 결과를 읽으며 새 결과나 새 최종 시각을 만들지 않는다. A가 실제 철회를 실행하고 B가 같은 세대의 이미 철회됨을 판정했다면 A는 RB01, B는 RB02의 의미로 구별한다. 동일 키 충돌은 A의 원래 결과를 RB03으로 바꾸지 않는다. 이전 동의 세대에 대한 요청을 최신 세대로 재결속하지 않는다.

통신 실패 뒤 같은 명령을 다시 보내는 것과 읽기 전용 결과 조회는 다르다. 실제 키/입력·참조 복구·새 키 반복 제한·기록 정리 이후 옛 명령 재생은 여전히 상세 계약이 필요하다. 결과표 작성으로 그 조건이 해결된 것은 아니다.

## 인수 조건과 남은 결정

정상 철회/무변경, 사전 인증 실패, 입력 충돌, 업무 거절, 감사/결과 저장 실패, COMMIT 불명, 동시 다른 요청, 새 동의, 조회 만료/권한 회수를 각각 대조한다. 최종 오류를 과거 업무 결과로 덮어쓰지 않고 결과·확실성·권한의 세 축을 구별하는지 확인해야 한다. 기존 CA144/159~162의 세부 인계이며 새 성공 수를 추가하지 않는다. 전부 NOT_RUN이다.

다음 좁은 결정은 **최종 업무 거절 결과를 남길 때, 본인·요청·대상이 검증되고 변경 없음과 거절 확정의 근거가 확보된 건으로 한정하며 인증 실패·키 충돌·통신 불명을 그 요청의 최종 거절로 저장하지 않는 원칙**이다. 실제 거절 사유 목록/기술/수명은 별도 설계다.
