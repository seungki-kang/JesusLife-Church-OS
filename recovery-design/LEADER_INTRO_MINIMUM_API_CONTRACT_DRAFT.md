# 리더 소개 최소 데이터·API 계약 후보

2026-10-30 / r84 / TECHNICAL_DRAFT / PARTIAL_RECOVERY / 실행 NOT_RUN

## 권위와 근거

[통합 상태표](LEADER_INTRO_STATE_RECONCILIATION.md)의 LI01~14 및 LT01~04를 [요청 식별 계약](COMMAND_IDEMPOTENCY_STATUS_CONTRACT_DRAFT_2026-10-27.md), [접수/실행/확정 초안](ACCEPT_EXECUTE_FINALIZE_DRAFT.md), [기기/영수증 연결](SUBMISSION_RECEIPT_BINDING_DRAFT.md)과 연결한다. 정책 근거는 REC-060~075다. 새로운 정책 합의/REC를 추가하지 않는다. 아래 영어 필드명·행위명·HTTP 경로는 검토용 후보이며 API 확정/구현/운영 계약이 아니다. ChurchOS 소유의 교회별 소개만 다루고 다른 제품 원문을 받지 않는다.

## 실제 v2.6 코드 대조

확인 파일: [postgres.ts](../canonical/ChurchOS_Canonical_v2.6/services/church-core/src/postgres.ts).

| 항목 | 코드에서 확인한 것 | 소개 후속 설계와 차이 |
|---|---|---|
| 동일성 | 검증 actor_ref+tenant+route_key+Idempotency-Key로 잠금/영수증 조회, 입력 fingerprint 대조 | 소개 행위별 경로/자원/버전 결속 추가 필요; 전역 key로 변경 금지 |
| 성공 기록 | 업무변경·감사·성공 영수증을 트랜잭션 안에 기록하는 방식 | 동의저장/게시 부분실패·확정실패/미확정 최소 기록 미구현 |
| 수명 | now()+24 hours, 기존행 만료409 | 168시간 최소 결과조회와 별개; 24시간 뒤 물리삭제 허가 아님 |
| 버전 | mutate fingerprint에 expectedVersion 포함; 현재 row_version 불일치시412, 재생변경시 REPLAY_SUPERSEDED | 소개 초안/공개본/동의/사진 세대의 다중버전 미구현 |
| 조회 | 기존 notices/events 상세 조회 | 소개 본인 최소결과/현재공개·사진상태 조회와 다름 |

재생 성공이 현재 소개/사진 공개의 증거가 아니다. 기존 성공 응답을 연장/복제해서 새 상태조회로 삼지 않는다. 본문 request_id와 범용 commands 실행기를 별도 도입하지 않는다. 후보 내부 실행 시도 참조는 별도 중복방지 체계가 아니라 기존 요청 동일성에 종속된다.

## 최소 기록 후보

논리 기록 단위이며 반드시 일곱 테이블을 만들라는 설계가 아니다. 정본 참조/권한과 최소 투영을 먼저 정하고 중복 원문을 만들지 않는다.

| 기록 | 최소 후보 필드 | 소유/접근 | 미결 |
|---|---|---|---|
| 소개 정체성 | intro_ref, tenant_ref, community_ref, subject_membership_ref, appointment_ref | ChurchOS·정확한 교회/공동체/본인; 직함은 실제 지정 참조 | 자격상실/재지정시 식별 연속성 |
| 편집 초안 | draft_version, 선택 short_bio/photo_ref, 표시이름 정본 참조 | 본인 편집; 관리자는 별도 제안권만 | 이름정본/입력제약·명시비우기·원본참조 수명 |
| 확인 묶음 | checked_draft_version, audience_policy_version, appointment_version, consent_generation, photo_visibility_generation | 서버 검증용 불투명 참조 후보 | 위변조 방지·유효기한·명단 자연변동 감지 단위 |
| 현재 공개 투영 | published_version, 허용 필드/사진참조, 근거 동의/직함 참조 | 현재 유효 참여자에게 현재 허용 필드만 | 사진차단시 필드별 투영/원자성 |
| 소개 동의/철회 | consent_ref, 범위/버전, 현재상태, 최소확정근거 | 본인의 동의·철회; 관리자 임의복원 금지 | 문구·증빙필드·실제시각 증거·보유 |
| 사진 공개 제어 | photo_ref, visibility_generation, blocked/publish_intent 참조 | 본인 비공개/명시재공개 | URL/파생/공유참조·삭제/보유·전파 |
| 요청 결과 최소 투영 | confirmation_ref, scope+route+key 연결, 입력동일성 검증 참조, 결과/접수/최종확정 근거 | 본인 최소조회, 현재 계정/교회/소속/기한 확인 | 접수/실패영속성·5항목 응답·168h 적용/삭제후 중복차단 |

scope+route+key와 동일성 증거는 내부 전용이며 일반 참여자 소개나 최소 결과조회에 노출하지 않는다. 원문/사진바이트/토큰/연락처를 요청 결과·감사·이벤트에 복제하지 않는다. 검증용 fingerprint도 추측 가능한 개인정보 해시를 공개하는 수단으로 쓰지 않으며 보호/접근 제한을 정한다. 사진이 존재하는 것과 현재 공개 허가는 다르다.

## 행위별 API 후보

아래 {intro}는 서버가 교회/공동체/본인과 결속을 검증할 자원 참조다. /api/v1/church/leader-intros/{intro} 기준의 자원별 후보이며 기존 배포 경로가 아니다. 모든 쓰기는 기존 Idempotency-Key를 출발점으로 검토한다. 읽기를 쓰기 재전송으로 구현하지 않는다.

| ID | 후보 행위/경로 | 입력/조건 후보 | 결과/차단 |
|---|---|---|---|
| LA01 | PATCH .../{intro}/draft | 본인·초안 expected_version, 변경할 선택필드 | 초안만 저장·공개 안 함; 생략/비우기/오류 구분 |
| LA02 | GET .../{intro}/preview | 본인·현재초안/직함/대상 참조 | 확인용 내용과 버전묶음; 미게시 본문을 일반참여자에 제공 금지 |
| LA03 | POST .../{intro}/publish | checked_ref, 유효동의·현재자격, 명시반영 | 확인버전만 반영·구버전/철회/종료 차단 |
| LA04 | POST .../{intro}/consent-withdrawals | 본인·해당소개 동의범위 | 현재소개 중단·대기 옛게시 차단·직함해제 아님 |
| LA05 | POST .../{intro}/consent-and-publish | 최신확인·본인새동의·명시반영 | 한화면 의미와 서버처리 단계 구분; 부분실패 계약 필요 |
| LA06 | POST .../{intro}/photo-visibility-withdrawals | 본인·현재소개 사진범위 | 사진만 차단·나머지 유효소개 유지·원본삭제 별도 |

| LA09 | 읽기전용 본인 결과/연결 조회·정확한 경로 OPEN | 기존 route/key와 내구접수 연결/확인ID·현재 조회권한 | 기존요청결과와 현재공개를 분리; 미존재/만료로 미처리 추정 금지 |

LA05의 동의/게시 두 의미를 LA03과 별개 독립 실행체계로 만들지 않는다. 공통 게시 도메인 검증/동일성에 연결하는 기술 후보다. LA05와 LA03/LA07의 다른 경로 키를 전역 하나로 합치거나 각 경로로 중복 실행을 허용하지 않도록 공개 의도 참조/허용 전이를 설계해야 한다. 재시도 전용 쓰기 경로는 추가하지 않았다. 확정실패 재시도는 아래 비교 항목을 해결하기 전 구현하지 않는다. 모든 경로/메서드와 버전 헤더의 정확한 형태는 DRAFT다.

## 결과와 현재 상태 응답 경계

본인 최소결과 공개의 기존 합의 다섯 의미는 확인ID·상태·실제접수시각·최종확정시각(존재시)·조회기한이다. 영어 JSON명은 초안이며 내부 동의세대/키/원문/에러원문/사진URL을 여섯번째 공개항목으로 덧붙이지 않는다. 168시간 일반업무 합의가 소개 게시/사진 행위 각각에 적용되는지와 근거 기록 수명은 OPEN으로 대조해야 한다.

현재 공개 조회는 최소결과 조회와 별도 자원/권한/목적이다. 일반참여자에게 본인 동의 증빙/요청결과/초안을 제공하지 않는다. 본인도 과거 성공만 보고 현재 공개중이라고 판단하지 않는다. 이 둘을 한 응답으로 제공할지 여부는 응답 최소화/권한 계약을 먼저 정해야 하며 이번 초안에서 확정하지 않는다.

RESULT_UNKNOWN은 앱이 결과를 모르는 상태이며 서버 REJECTED가 아니다. PROCESSING/REVIEW_REQUIRED/COMMITTED/REJECTED는 기존 일반요청 초안의 후보명이고 소개용 enum 확정이 아니다. AUTH/입력 오류 전체를 영속 실패기록으로 만들지 않는다. 404/기록없음/만료는 미실행 증거가 아니다. 소개 쓰기에서 200/201/202/409/412 등 세부 코드·오류 필드는 미결이고 기존 자원 API 코드를 덮어쓰지 않는다.

## 접수/동의/게시 일관성 후보와 재시도 문제

기존 TxA 최소 내구접수→TxB 업무/감사/영수증/최종결과 후보를 소개에 대입해 검토하되 선정 완료로 기록하지 않는다. 동의와 게시를 한 확정 단위로 묶는 후보는 동의만 성공하는 상태를 줄일 수 있다. 별도 동의확정을 허용하는 후보는 REC-073의 동의저장 후 확정 게시실패를 표현하지만 결과기록·경합/복구가 복잡하다. 한화면 버튼만으로 어느 저장구조도 강제되지 않는다.

TxA 접수 성공은 동의 저장 성공도 게시 성공도 아니다. 커밋 여부를 모르면 실패 확정하지 않는다. 실제 확정 시각은 now()/created_at/클라이언트시간으로 자동 대체하지 않는다. 최종쓰기에서 현재동의·직함·확인버전·사진차단을 일관되게 확인하고 옛작업의 커밋 가능성을 차단할 필요가 있다. 정확한 DB 잠금/펜싱/시계 계약은 OPEN이다.

확정 실패를 불변 최종결과로 기록했다면 같은 키를 다시 보내 작업을 재실행하는 방식과 충돌한다. 반대로 새 키만 주면 같은 의도 동일키 원칙/중복차단을 깨뜨릴 수 있다. 해결 후보는 본인의 새 재시도 의도를 이전 실패와 명시적으로 연결하고 이전 시도 미반영/더이상 커밋불가·현재조건 동일유효를 검증하는 것이다. 실행 시도와 사용자 의도의 정확한 구분·실행키 발급 주체/원자성은 미결이다. 초안이 새 키 발급을 승인하거나 기존 최종실패를 성공으로 덮어쓰는 규칙을 만들지 않는다.

## 수명과 호환성 게이트

24h 성공재생, 168h 최소조회, 동의증빙/업무원문/사진/기기참조/백업은 각각 별도 수명이다. 소개 확장용 기록을 삭제한 뒤 같은 키가 신규 실행으로 빠지지 않도록 만료/삭제후 재사용 차단과 복원시 최신철회 재적용 계약이 필요하다. 새 보유기간을 제안하거나 기존 JOIN/SSO의 7일/30일/1년을 자동이식하지 않는다.

구클라이언트 지원 감지·계약 버전·실패재사용 의미·새 경로와 기존 route_key 충돌/길이·마이그레이션 계보·원문/사진 ACL을 구현 전 정한다. 관리자 웹이나 다른 제품 인증/서버 변경을 요구하지 않는다. canonical 스냅샷/기존 API를 이번 문서로 변경하지 않는다.

## 인계 검증과 남은 것

CA123은 같은 범위/키의 변경입력·구버전/철회·공개상태 조회를, CA124는 실패최종성/재시도 식별 및 만료/삭제후 중복 위험을 검증할 조건이다. LT01~04는 일부 후보를 작성했지만 완료가 아니다. 후속 작업은 재시도 실행 동일성 비교안과 조회수명 적용 범위, 동의/게시 확정 단위, 사진 미디어 접근을 차례로 상세화한다. 정책 선택이 필요한 사항만 별도 OPEN으로 제시한다. 모든 실제 실행은 NOT_RUN이다.
