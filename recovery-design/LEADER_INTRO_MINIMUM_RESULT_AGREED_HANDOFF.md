## 인계 시 오해 방지

‘재가입 불필요’는 현재 인증 불필요가 아니다. 조회 때마다 해당 목적에 유효한 계정과 정확한 본인 요청 관계를 확인해야 한다. 다른 계정·다른 교회·새 동의 세대로 참조를 바꾸어 결과가 반환되지 않아야 한다. DB의 교회 격리만으로 요청 소유 관계가 보장된다고 보지 않는다.

이 합의는 상태 확인의 원칙이다. 실제 서버에 W/WR 경로가 존재하거나 계정 종료 상태가 전파된다는 뜻이 아니다. 기존 canonical의 영수증과 새 최소 결과 확인을 결속하는 저장/권한 명세가 필요하다. 소속 상실 뒤 과거 교회 화면을 다시 열거나 일반 Q 목록에 들어가게 하지 않는다.

첫 서버 응답을 못 받아 확인 번호가 없는 경우도 남은 필수 기술 조건이다. 최초 의도 참조와 내구 접수/최종 기록의 연결이 필요하다. 조회 불가를 자동 새 철회 요청으로 전환하지 않는다. 새 동의 C2가 생겼다면 C1 결과 확인이 C2에 영향을 주지 않는다.

## 남은 설계 순서

1. 본인/의도/동의 세대와 결과 참조의 결속·최초 응답 유실·참조 누락·다른 계정 치환을 하나의 계약으로 작성한다.
2. 최소 응답과 현재 자격, 결과 불명·만료 안내를 한정해 결정한다. 장기 증빙 E로 확장하지 않는다.
3. 조회 기산/기간·실제 보유·기기 참조·멱등 보호·삭제/백업 상한을 목적별로 정한다. 관련 기존 게이트는 유지한다.
4. 구현을 재개할 때 실제 권한/기존 API/DB 계보를 확인하고 격리 정상 대조·실패 주입으로 검증한다. 현재는 모든 실행 NOT_RUN이다.

다음 작업은 1번의 **최초 의도 참조→서버 접수→동의 세대→최종 결과 결속**이다. 참조가 없거나 만료됐을 때 없는 사실을 만들지 않는 분기까지 설계한다. 이번에는 기간 숫자나 특정 API/DDL을 선택하지 않았다.
