# 본인 철회 최소 내구 결과·오류 기록 분리 계약 초안

2026-10-31 / r156 / RECORD_SEPARATION_DRAFT / PARTIAL_RECOVERY / 실제 실행 NOT_RUN

[REC094 내구 무변경 결과](LEADER_INTRO_NO_CHANGE_RESULT_AGREED_HANDOFF.md), [REC095 오류 분리](LEADER_INTRO_FINAL_REJECTION_AGREED_HANDOFF.md), [r156 사유 후보](LEADER_INTRO_MINIMUM_RESULT_ERROR_RECORDS_DRAFT.md), [REC 원문](RECOVERY_DECISIONS.md)을 따른다. 논리적 기록 목적을 분리하는 기술 초안이다. 새 물리 테이블·DB계정·필수 칼럼·기간을 확정하지 않는다.

## 목적별 기록 경계

| 기록 | 목적 | 생성 조건 | 열람/공개 | 수명 경계 |
|---|---|---|---|---|
| DR01 최소 업무 결과 | 특정 요청의 실제 철회/무변경 판정 재확인 | 검증한 요청·세대와 결과의 내구 확정 | 본인은 현재 권한/유효 창·REC090 상한; 내부도 목적별 권한 | 결과 확인 창과 검증에 필요한 수명 계약, 숫자 미결 |

같은 저장소를 사용하더라도 목적/권한/정리 기준은 구별해야 한다. 반대로 무조건 다섯 테이블이나 다섯 서비스를 만들라는 뜻은 아니다. 물리 분리는 실제 조회·권한·삭제/복원 동작에 따라 검토한다. 오류 기록을 업무 결과의 대체 정본으로 사용하지 않는다.

## DR01 공통 최소 항목 후보

| 논리 항목 | 필요 이유 | 제한 |
|---|---|---|
| 불투명 요청 참조 | 같은 요청을 조회로 찾음 | 번호 소지는 권한 아님 |
| 본인/교회·동의 세대 결속 | 정확한 요청 대상과 현재 본인 관계 검증 | 이름/이메일 자동 연결 금지·외부 추가 공개 아님 |
| 고정 입력 의미 결속 | 같은 키 다른 입력 충돌 판정 | 원문/사진/토큰 복사 금지; 해시 방식 미선정 |
| 결과 의미 | 실제 철회와 이미 철회됨의 무변경 판정 구별 | 과거 실행 성공으로 소급 금지 |
| 업무 판정 버전/근거 참조 | 상태 관찰과 결과가 일치했는지 검증 | 자원 전체 스냅샷·개인 원문 보존 불필요 |
| 검증된 사건·시각 의미 | 접수/최종 근거와 기간 계산 | 실제 COMMIT 시각을 확보했다고 가정하지 않음 |
| 유효 조회·정리 근거 | 현재 허용 범위와 수명 관리 | 기간 숫자·정리기산·예외는 미결 |
| 감사와 필요한 결속 | 원자 결과·감사 일관성 | 내부 감사 전체를 응답으로 복사하지 않음 |

이는 필요한 논리 관계의 후보이며 모두 별도 칼럼으로 복제하라는 뜻이 아니다. 일부를 정본 참조로 해결할 때는 참조 대상의 정리 후에도 남는 결과가 본인/세대·시각을 검증할 수 있는지 대조해야 한다. 검증 관계를 잃은 고아 결과를 임의 공개하지 않는다. 반대로 검증 편의 때문에 원문을 영구 보유하지 않는다.

## DR03 오류 기록 후보와 금지 항목

후보는 오류 분류·발생 사건/시각 의미·해당 기능/계약 버전·권한 있는 진단에 필요한 최소 추적 참조다. 계정/요청 참조는 필요성과 접근을 따로 판단하며 인증 실패 때 타인 존재/본인 관계를 이미 검증한 것처럼 저장하지 않는다. 단순 연관 ID만으로 과거 실행을 입증하지 않는다.

토큰·쿠키·비밀번호·전체 헤더/본문·소개 원문/사진·교인 명단·타제품 기록·원본 SQL 매개변수를 일반 오류 로그에 복사하지 않는다. 예외 객체/추적 로그가 자동으로 입력을 포함하지 않는지 실제 검증이 필요하다. IP·기기 식별자 등 추가 보안 항목은 필요 근거/접근/유한 수명을 별도로 정하며 기본 수집 목록으로 확정하지 않는다.

DR03에서 통신 오류를 발견해도 DR01에 최종 거절을 만들지 않는다. 기존 최종 결과가 있으면 이후 오류로 덮어쓰지 않는다. DR03에 기록이 없거나 기록 자체가 실패했다고 원래 업무가 실행되지 않았다고 단정하지 않는다.

## 기록 실패와 원자성

실제 철회/무변경 결과·감사는 M1의 일관된 확정 경계가 필요하다. 어느 기록을 반드시 같은 트랜잭션에 포함할지, 필수 감사 기록 실패 시 어떻게 처리할지는 구체 계약으로 정한다. 결과/감사 중 일부만 확정하고 정상 성공을 안내하는 방식은 허용하지 않도록 인계한다.

오류 기록 저장 실패를 이유로 이미 확정된 업무 결과를 실패/거절로 바꾸지 않는다. 확정되지 않은 업무를 오류 로그의 성공으로 대체하지 않는다. 업무 COMMIT 불명과 오류 로그 COMMIT 불명을 독립적으로 구별하고 근거 조회는 읽기 경로로 수행한다. 로그 장애 시 운영 관측/제한 처리도 미결이며 민감한 덤프를 대체 기록으로 남기지 않는다.

## 삭제·사본·복원

공개 조회 종료, 결과 기록 삭제, 감사 목적 종료, 오류 기록 정리, 조사 이력 정리, 옛 실행 보호 종료는 같은 사건이 아니다. 각각 목적·기산·유한 상한·예외·사본/백업·복원 시 최신 삭제/권한 재적용을 정해야 한다. 기존24시간/168시간/7일/30일/1년을 모든 기록에 일괄 적용하지 않는다.

DR01 정리로 DR03을 비공식 영구 결과 저장소로 남기지 않는다. 공유 추적 참조가 여러 기록군을 연결하더라도 가장 긴 수명을 모든 기록에 승계하지 않는다. 백업/복원 후 목적별 삭제와 권한을 다시 적용할 실제 증거가 필요하다. 이 문서로 삭제/복원 보호가 구현됐다고 주장하지 않는다.
