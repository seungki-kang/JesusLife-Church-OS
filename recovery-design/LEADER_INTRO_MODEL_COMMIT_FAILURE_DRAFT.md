# 리더 소개 최소 논리모델·확정단위·실패표

2026-10-30 / r88 / TECHNICAL_DRAFT / PARTIAL_RECOVERY / 실행 NOT_RUN

## 범위와 근거

[개발전 결정표](LEADER_INTRO_PREIMPLEMENTATION_DECISION_TABLE.md)의 LD01/LD02와 LT01/LT02를 구체화한다. [최소 API 후보](LEADER_INTRO_MINIMUM_API_CONTRACT_DRAFT.md), [재시도 동일성](LEADER_INTRO_RETRY_IDENTITY_DRAFT.md), [결과 조회](LEADER_INTRO_RESULT_QUERY_APP_DRAFT.md), [접수/확정 후보](ACCEPT_EXECUTE_FINALIZE_DRAFT.md), REC-060~075가 근거다. 이 문서의 명칭/레코드/확정단위는 모두 기술후보이며 새 결정·DDL·마이그레이션을 만들지 않았다. ‘후보 비교 작성’과 ‘검증된 구현 선정’을 구분한다.

이는 일곱 테이블이나 원문 복제본을 요구하지 않는다. 원문 정본과 참조·최소 투영을 구분한다. 일반참여자 API에는 초안/동의증빙/내부키/숨긴사진/개인연락처를 넣지 않는다. 동의/사진/직함 세대와 내용버전은 내부 일관성 검사 후보이며 최소결과 다섯 공개항목을 늘리는 근거가 아니다.

## 동의와 게시 확정의 두 후보

요청 내구접수 후보 TxA는 동의저장이나 게시성공과 다르다. TxA를 도입할지 및 최초접수 증거는 기존 초안의 미결을 유지한다. 아래 C-A/C-B는 TxA/TxB라는 기존 일반 처리 후보와 다른 비교축, 즉 새동의와 게시의 확정 단위를 비교한다.

| 후보 | 새동의/게시 확정 | 장점 | 남는 실패/의미 |
|---|---|---|---|
| C-A 함께 확정 | 현재조건 검증·동의근거·게시·감사/영수증/결과를 한 업무확정 단위로 묶는 후보 | 동의만 성공하는 중간상태 감소 | 동일단위 롤백이면 새동의도 미저장; 실제 범위/DB공존/철회차단 검증 필요 |
| C-B 별도 확정 | 동의저장 확정 뒤 게시 확정; 양쪽 근거를 연결 | REC-073의 동의저장 후 게시실패 상태를 직접 표현 | 중간장애/철회 경합·두 결과 표시/복구·증빙 보유 복잡 |

두 후보 미선정이다. REC-073은 동의저장 성공/게시실패가 확인되는 경우의 UX 합의이지 C-B 저장구조 강제가 아니다. C-A에서도 이전에 별도로 유효하게 저장된 동의가 있는지와 이번 새동의를 구분해야 한다. C-A 신규동의 저장이 롤백됐는데 유효동의가 남았다고 표시하지 않는다. 단일화면/버튼은 후보 어느 쪽도 자동 선택하지 않는다.

소개전체 철회와 사진만 비공개는 각 제어상태/최소감사/결과를 일관되게 확정해 옛게시 차단에 연결하는 후보로 설계한다. 잠금 대기 후 현재 동의/직함/내용/대상/사진세대를 재검증해야 한다. 실제 잠금순서·유일성·조건부쓰기/펜싱·캐시 경계와 종료시각 판정은 미결이다.

## 읽기/캐시와 데이터 보유

공개본 참조가 남아도 현재동의/지정/사진차단을 적용한 허용필드만 제공하는 조회 후보를 검토한다. 일반참여자에는 숨긴사진URL을 내려보낸 뒤 UI에서만 감추는 방식으로 구현하지 않는다. 기존 URL 재사용 차단·캐시정리/오프라인/외부사본은 별도 LD06 계약이다. ‘서버 비공개 확정’과 ‘모든 사본 회수완료’를 같은 상태로 표시하지 않는다.

초안/공개본/사진원본·파생/동의증빙/요청결과/내부실행근거는 별도 목적과 수명이 필요하다. 삭제시 현재상태·부모후속 중복차단 근거를 무심코 없애지 않되 영구보유를 자동선택하지 않는다. 24h재생·168h조회와 물리삭제/백업은 별개·소개 적용기간 OPEN이다. 감사/이벤트에 개인본문/사진/토큰을 복제하지 않는다.

## 인계 검증과 상태

CA129는 C-A/C-B의 동의/게시 확정/롤백/커밋불명 구분과 MI02/07/08을 검증할 조건이다. CA130은 철회/사진차단/구버전/복원 MF07~12 및 MI03~06을 검증할 조건이다. 두 항목 모두 실제 DB/앱 테스트가 아니며 NOT_RUN이다.

LD01/02는 최소 모델/실패표 후보 작성 단계까지 진행했지만 선정/원자성/시각 검증은 미완료다. 다음은 C-A/C-B 선택조건과 LD03 요청동일성의 호환을 좁힌 기술비교표다. LD04~08의 정책/기간/접근권한을 이번 문서로 확정하지 않는다. 코드/DDL·GitHub 변경 없음.
