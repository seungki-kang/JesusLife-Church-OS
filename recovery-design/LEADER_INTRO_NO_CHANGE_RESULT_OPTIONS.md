# 이미 철회됨 — 내구 무변경 결과와 읽기 안내 비교

2026-10-31 / r151 / RECOMMENDED_NOT_ADOPTED / PARTIAL_RECOVERY / 실행 NOT_RUN

[REC093 합의](LEADER_INTRO_ALREADY_WITHDRAWN_AGREED_HANDOFF.md), [M1 명령 초안](LEADER_INTRO_NO_CHANGE_RESULT_OPTIONS.md), [REC 원문](RECOVERY_DECISIONS.md)을 잇는다. 같은 세대의 이미 철회됨 안내와 과거 실행 사실 분리는 합의됐다. 이번에는 그 안내 근거를 어떤 범위로 남길지 비교한다. 새 저장 모델·수명·결과 상태를 채택한 것이 아니다.

## 권고

실제 철회 명령으로 제출됐고 현재 본인·같은 대상 세대·입력/키 관계가 검증된 경우에는 **N1: 이번 요청에서 추가 효력 변경 없이 이미 철회 상태를 확인했다는 최소 내구 결과를 남기는 방향**을 우선 권고한다. 응답 유실 뒤 현재 상태를 다시 읽는 것과 그 요청의 판정 결과를 확인하는 것을 구별할 수 있기 때문이다. 이는 과거 철회 실행 증명이 아니다. 일반 상태 조회를 할 때마다 명령 결과를 생성하지 않는다.

N1은 M1 동기 보완 안에서 상태 판정과 최소 무변경 결과/감사를 일관된 경계로 확정하는 후보다. 선접수 큐를 추가하는 안이 아니다. 실제 저장·감사·경합·수명 계약을 채우기 전에는 구현 가능/안전 완료로 간주하지 않는다.

| 비교 | N1 최소 내구 무변경 결과 | N2 읽기 안내만 제공 |
|---|---|---|
| 의미 | 이번 요청이 같은 세대의 이미 철회됨을 확인했고 추가 효력 변경하지 않았음 | 현재 허용된 조회에서 이미 철회 상태를 관찰했음 |
| 응답 유실 후 | 같은 요청의 검증된 판정 결과를 유효 기간에 확인 가능하도록 설계 | 해당 응답의 과거 판정은 재현 불가; 새 조회는 새 관찰 |
| 다른 요청/키 | 각 요청 결속·반복 기록 제한 필요 | 명령 결과 없이 현재 관찰만 제공 |
| 변경량 | 결과/감사·유한 수명·키 호환·정리 설계 추가 | 저장은 줄지만 명령 접수/최종 의미와 앱 안내를 분리해야 함 |
| 과거 실행 | 과거 철회자/철회 시각을 이번 요청 결과로 소급하지 않음 | 마찬가지로 과거 실행 증거가 아님 |
| 일반 상태 읽기 | 기존 읽기 경로에서 새 명령 결과 생성 금지 | 읽기 목적에 적합하나 새 명령의 결과와 혼용 금지 |

N2를 택해도 원래 결과가 저장되지 않았다는 이유로 미실행·재실행 안전을 보장할 수 없다. N1을 택해도 현재 상태를 언제까지나 증명하거나 모든 복사본 삭제를 보장하지 않는다.

## N1에 필요한 최소 계약

| 항목 | 필요한 조건 | 미결 |
|---|---|---|
| 본인/요청 | 현재 본인과 해당 I/K/R/T의 정확한 결속 | 실제 필드·정규화·호환 |
| 판정 대상 | 명시한 같은 동의 세대가 이미 철회됐는지 확인 | 행 잠금/버전/불변 세대 모델 |
| 결과 의미 | 추가 효력 변경 없음과 이번 판정 사실 | 정식 상태/응답 코드·감사 형식 |
| 내구 경계 | 검증한 상태와 결과/감사의 일관된 확정 | 실제 트랜잭션/제약·실패 처리 |
| 시간 | 이번 판정 확정과 과거 철회 사건을 구분 | 검증 가능한 시각 의미·조회 기산 |
| 수명 | 유한 결과 조회·최소 보유와 옛 실행 보호 분리 | 숫자·삭제/백업/예외·기기 정리 |

이미 철회된 상태라는 뜻을 ‘이번 요청이 철회를 실행했다’는 성공 값으로 축약하지 않는다. 내부 결과 종류를 세분하더라도 외부 공개는 REC090의 다섯 종류 상한을 유지한다. 추가 설명이 필요하면 처리 상태의 의미/정적 안내로 계약하되 원문·사진·다른 요청 이력을 추가하지 않는다. 실제 문구는 미선정이다.

## 동일 요청 재조회와 새 요청

같은 요청의 결과가 이미 있으면 현재 권한과 유효 조회 창을 검증해 그 결과를 읽는다. 조회마다 새 판정 결과를 저장하거나 최종 시각을 갱신하지 않는다. 동일 키의 입력 변경은 충돌로 다룬다. 새로운 키가 왔다고 이전 요청의 불명을 덮거나 무제한 새 확인 기록을 만들지 않는다.

반복 전송/남용의 제한·오류 의미·유한 중복 탐지·접수 상한은 OPEN이다. 제한하려고 모든 개인 기록을 영구 보유하거나 서로 다른 요청의 판정 근거를 부정확하게 합치지 않는다. 요청을 제한한 응답은 과거 철회 요청의 최종 거절로 소급하지 않는다.

## 경합과 장애

A가 실제 철회를 먼저 확정하고 B가 같은 세대의 이미 철회됨을 확인했다면 A의 실행 결과와 B의 무변경 판정을 각각 구별해야 한다. B의 판정 중 새 동의 세대가 생겨도 그 새 세대를 변경하지 않는다. 상태 관찰과 결과 기록 사이의 경합을 방지할 실제 경계가 필요하다.

판정/감사/결과 기록이 실패하면 내구 무변경 결과가 확정됐다고 응답하지 않는다. COMMIT 결과 불명은 조회로 검증하며 ROLLBACK 시도만으로 실패를 확정하지 않는다. 기록 부재·만료는 미실행 증거가 아니다. REC088/089 유한 확인·재검토 경계를 유지한다.

## 검증 인계와 다음 결정

합성 조건은 동일 요청 재조회·서로 다른 두 요청·새 동의와 경합·결과/감사 저장 실패·COMMIT 응답 유실·키 만료/삭제·권한 회수·조회 창 만료·반복 새 키다. 기존 CA144/159~162 세부 인계이며 모두 NOT_RUN이다. 별도 새 CA나 성공 수를 추가하지 않는다.

다음 좁은 결정은 **실제 철회 명령으로 제출된 건의 이미 철회됨 판정을 이번 요청의 최소 내구 무변경 결과로 남기는 방향**이다. 일반 조회마다 기록을 생성하지 않으며 과거 실행 사실로 소급하지 않는다. 실제 저장·감사·시간·수명·반복 제한은 별도로 확정해야 한다.
