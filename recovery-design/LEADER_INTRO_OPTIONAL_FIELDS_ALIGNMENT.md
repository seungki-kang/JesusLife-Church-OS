# 리더 소개 선택 항목과 공개 흐름 대조

2026-10-30 / r80 / DESIGN_ALIGNMENT / PARTIAL_RECOVERY

## 근거와 판정

[REC-062](RECOVERY_DECISIONS.md#rec-062-리더-소개-표시-항목과-연락-동의-분리)는 사진·짧은 소개를 본인 선택으로 정한다. CA91에 이미 미선택/자동 전재 금지 조건이 있다. REC-066~073의 미리보기·게시·철회·재동의·재시도와 이 조건을 연결하는 교차 검증이 부족해 CM10과 CA115/116에 명시했다. 기존 문서에서 사진 필수라는 반대 합의는 확인되지 않았다. 이번 검토는 해당 결정과 CM10/CA91/96/97/101/103 및 게시 후속 설계를 대상으로 하며 전 저장소의 의미적 완전성을 보증하지 않는다.

## 화면→행위→조건 대조

| 화면/행위 | 기존 합의로 적용할 조건 | 근거 | 상태 |
|---|---|---|---|
| 소개 편집 | 사진·짧은 소개 미선택 허용; 계정 프로필 사진/가입 연락처 자동 복사 금지 | REC-062/065 | AGREED_SCOPED |
| 미리보기/공개 | 사진·짧은 소개가 없어도 동의한 표시이름/현재직함을 확인하고 명시적 공개반영 가능; 기본필드도 동의 없이 공개 금지 | REC-062/066 | AGREED_SCOPED |
| 편집 중 일반 참여자 열람 | 유효 기존공개본과 초안 구분; 사진 미선택과 동의철회를 혼동하지 않음 | REC-063/067 | AGREED_SCOPED |
| 미리보기 뒤 변경 | 사진/소개를 바꾼 경우 구확인으로 게시하지 않고 최신재확인 | REC-068 | AGREED_SCOPED |

사진 없이 보여줄 중립 아이콘/이니셜·빈 영역 레이아웃·접근성 문구는 UX_DRAFT다. 계정 사진을 대체 이미지로 자동 가져오는 방식은 기존 합의에 어긋난다. 사진/소개 미선택을 참여나 직함 부적격으로 취급하지 않는다.

## 빈 값과 삭제를 구분할 기술 과제

사진/소개 생략(수정하지 않음), 명시적 비우기(공개본에서 제거하려는 의도), 업로드/저장 실패를 구별하는 API/미디어 계약은 TECHNICAL_DRAFT다. 새 초안에서 사진을 비우는 것과 공개 중인 사진의 즉시 철회는 동일 행위로 단정하지 않는다. 필드별 철회 UI/효력 시점·사진 정리/보유·공개본 교체/캐시·실패 시 안내는 OPEN이다. 전체 소개 동의철회/직함종료 시 기존 공개본 중단이라는 합의는 그대로 유지한다. 사진 업로드 실패가 무조건 사진 없는 게시로 전환된다고 가정하지 않는다.

## 개발 인계와 검증

CM10·MVP16·CA115/116에 연결했다. CA115는 선택필드 없이 정상 게시/재동의 경로가 막히지 않는지, CA116은 다른 프로필에서 자동 채움/선택필드 강제/실패를 미선택으로 오인하지 않는지 확인할 조건이다. 문서상 검증 조건이며 실제 화면/API/사진/재시도 테스트는 NOT_RUN이다. 기존 COS/REC 결정, canonical v2.6, Git 및 과거 리비전 증거는 보존했다. 새 REC ID나 보유기간을 만들지 않았다.
