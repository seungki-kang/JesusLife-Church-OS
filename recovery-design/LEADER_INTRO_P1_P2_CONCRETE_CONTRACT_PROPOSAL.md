# P1/P2 통합 계약안 — 본인 소개 철회 명령과 결과 조회

2026-11-01 / r161 / PROPOSED_CONTRACT / PARTIAL_RECOVERY / 실제 실행 NOT_RUN

[r161 인계 판정](LEADER_INTRO_P1_P2_CONCRETE_CONTRACT_PROPOSAL.md)의 P1/P2를 구체화한다. [r125 식별 역할](LEADER_INTRO_WITHDRAWAL_REQUEST_BINDING_DRAFT.md), [M1 명령](LEADER_INTRO_M1_COMMAND_CONTRACT_DRAFT.md), [REC 원문](RECOVERY_DECISIONS.md)을 따른다. 새로운 독립 미결 목록을 만들지 않고 선택할 기술 계약을 한 묶음으로 제안한다. 아래 경로·필드·처리 순서는 미승인 제안이며 코드/DDL/운영값이 아니다.

## 이번 제안의 핵심

새 본인 철회 명령에서는 **클라이언트 의도 참조 I를 기존 Idempotency-Key K와 같은 값으로 사용**하고 본문에 별도 request_id 실행기를 만들지 않는 안을 권고한다. 서버가 확정한 결과에는 별도 불투명 요청 참조 R을 부여한다. 대상은 이름이 아닌 정확한 동의 세대 T로 고정한다. 응답을 못 받으면 같은 명령 재호출 대신 **현재 본인 인증을 거친 읽기 전용 조회**로 I/K→R/결과를 확인한다.

I=K는 새 명령의 제안이다. 기존 일반 생성/변경 API의 키 의미·경로·입력 계약을 바꾸지 않는다. 기존 키가 새 범위로 재사용되지 않도록 명령 종류/교회/본인/대상 세대와 결속한다. 물리 테이블을 공유할지 별도 결과를 둘지는 다음 상세 저장 설계에서 결정한다.

## 최소 인터페이스 제안

| 행위 | 경로 후보 | 입력 후보 | 동작 |
|---|---|---|---|
| 명시 철회 | POST /api/v1/self/intro-withdrawals | 현재 인증, Idempotency-Key, consentGenerationRef, contractVersion | 특정 세대에 대한 M1 판정/원자 결과 확정 |
| 서버 참조로 결과 확인 | GET /api/v1/self/intro-withdrawals/{requestRef} | 현재 인증·R | 기존 결과 읽기; 업무 실행 없음 |
| 첫 응답 유실 확인 | POST /api/v1/self/intro-withdrawal-results/lookup | 현재 인증·intentKey·consentGenerationRef·contractVersion | 읽기 전용 I/K 결속 확인; 명령 생성/재실행 없음 |
| 참조 전부 소실 | GET /api/v1/self/intro-withdrawals | 현재 인증·불투명 커서 | REC086 범위의 유효 창 안 본인 요청만 제한 재발견 |

lookup의 POST는 키를 URL에 노출하지 않기 위한 경로 후보이며 쓰기 의미가 아니다. 요청 본문/헤더 로그에서 키/인증값 노출 방지가 필요하다. 정식 HTTP 코드·캐시 헤더·속도/페이지 제한은 기술 명세로 채워야 한다. 네 개 경로 전체가 구현되거나 승인된 것은 아니다.

본문에 actor/tenant 권한 주장, 소개 원문/사진, 탈퇴 사유, 타제품 기록을 요구하지 않는다. consentGenerationRef는 현재 서버의 본인 관계를 검증하는 대상 참조이며 권한 토큰이 아니다. 서버가 해당 세대의 교회 범위를 결정하고 본문/현재 교회 선택값만 믿지 않는다. contractVersion은 지원 계약 버전만 허용하며 입력 비교 방식 변경에 따른 혼용을 막는다.

## 현재 권한 판정

명령과 읽기 모두 현재 유효한 공통 계정과 해당 요청/동의 세대의 본인 관계를 서버에서 검증한다. 교회 소속/직함 종료만으로 관리자 승인·재가입을 요구하지 않는다. 다른 일반 교회 API의 ACTIVE 소속 요건을 제거하는 안이 아니다. 기존 역할 조회를 우회해 교회 전체 자료를 반환하지 않는다.

현재 계정 정지/탈퇴·서비스 이용 종료 등 예외는 P1에 남아 있다. 본인 관계 정본이 소속 종료로 소실되는 구조라면 어떤 최소 관계를 유한하게 유지할지 P3와 연결해야 한다. 관계를 잃었다고 이메일/이름으로 자동 연결하거나 과거 토큰으로 통과시키지 않는다. 지원 담당에게 대리 철회권을 부여하지 않는다.

## 명령 처리 순서 제안

1. 현재 인증·지원 계약 버전·최소 입력을 검증하고 명령 범위/본인 관계를 확인한다.
2. 해당 의도 키와 고정 입력의 기존 결속을 확인한다. 동일 키 변경 입력은 차단하고 기존 결과를 덮어쓰지 않는다.
3. 이미 확정된 같은 요청이면 현재 읽기 권한/유효 창 안에서 기존 결과를 제공한다. 창 밖 재전송을 새 실행으로 전환하지 않으며 정식 오류 의미는 수명 계약과 함께 정한다.
4. 새 의도이면 정확한 동의 세대를 잠금/버전 조건 등 선정한 경합 방식으로 재검증한다. 새 세대로 자동 재결속하지 않는다.
5. 유효 공개 동의면 실제 철회, 이미 철회된 같은 세대면 추가 효력 변경 없는 판정을 하며 최소 결과/키 결속/감사를 일관되게 확정한다. 구현상의 키 검사·세대 판정·현재 권한 회수 사이 경합을 해결해야 한다.
6. COMMIT 확정을 확인한 결과만 반환한다. COMMIT 불명은 성공/거절로 임의 확정하지 않고 읽기 조회 경로로 안내한다.

실제 row lock/advisory lock의 대상/순서·고유 제약·재시도 범위·deadlock 처리·권한 회수 직렬화는 상세 저장 계약에서 채워야 한다. 지연 재처리 워커나 선접수 트랜잭션을 암묵적으로 넣지 않는다.

## 결과 의미 제안

| 상태명 후보 | 뜻 | 기록/시간 경계 |
|---|---|---|
| WITHDRAWAL_APPLIED | 이번 요청이 해당 세대 철회를 실제 확정 | 실제 변경과 최소 결과의 확정 근거 필요 |
| ALREADY_WITHDRAWN_NO_CHANGE | 이번 요청이 같은 세대의 이미 철회됨을 검증하고 추가 변경 없음 | 이번 판정의 내구 결과; 과거 철회 실행/시각으로 소급 금지 |
| 최종 거절 | 아직 허용 사유/저장 경계 미채택 | 범용 REJECTED를 모든 예외에 사용하지 않음 |
| 확인 불명/조회 불가 | 현재 확정 근거 또는 조회 조건을 확인할 수 없음 | 이를 최종 업무 결과로 저장하지 않음 |

상태명은 제안이다. 공개 결과는 REC090에 따라 requestRef, processingState, acceptedAt, finalizedAt, queryExpiresAt의 최대 다섯 종류로 매핑하는 안이다. 미검증 사건/시각을 채우지 않는다. 같은 트랜잭션에서 수용/최종이 성립해도 동일 시각을 임의 채우지 않는다. 실제 시각 의미·누락/null 표현·기간·만료 판정은 P3와 함께 채워야 한다. 현 단계에는 운영 가능한 완성 응답 스키마가 아니다.

## 읽기 전용 확인의 분기

| 관찰 | 허용 동작 | 금지 |
|---|---|---|
| 본인/요청/입력 결속과 최종 근거·창 검증 | 최소 기존 결과 반환 | 재조회로 새 결과/시각 생성 |
| I/K는 있으나 R 응답 유실 | 읽기 결속 확인으로 기존 R/결과 찾기 | lookup에서 결과 새로 생성/명령 재실행 |
| 결속/권한/유효 창 검증 실패 | 존재를 드러내지 않는 제한 응답 | 일부 필드 노출·다른 요청 탐색 |
| 결과 부재/만료·정리 | 현재 확인 불가의 한계 안내 | 미실행 확정·새 키 자동 실행 |
| 서버 근거 일부만 존재/불일치 | 제한 확인 절차와 최소 진단 | 현재 소개 상태로 과거 요청 성공 구성 |
| 참조 모두 소실 | 유효 창 안 본인 제한 재발견 | 전체 업무 이력·원문/사진 복구 |

M1에서 별도 A가 없는 구간은 서버 내구 접수 상태가 없을 수 있다. 이 조회가 요청 도착만으로 가짜 접수/처리 중 기록을 생성해서는 안 된다. 미확정 창의 실제 기산은 P3에 남으며 장시간 미처리 작업이 없다는 이유로 COMMIT 불명도 없다고 주장하지 않는다.

## 저장·수명/보호 의존과 개발 인계 한계

선택할 최소 결과 저장은 R·I/K·본인·T·고정 입력·판정·감사 결속과 사건 의미를 유지해야 한다. 기존 성공 영수증24시간·response_created_at·현재 row_version 재전송만으로 이 결과 조회를 대체하지 않는다. 공개 원문 스냅샷은 만들지 않는다. 키 정리 뒤 옛 요청·복원·계정 연결 변경의 보호는 P4 미결이다.

따라서 이번 안은 P1/P2의 구체 제안이지 준비 완료가 아니다. P1 제한 계정 예외/본인 관계 수명, P2 실제 원자 저장/키 호환/경합, P3 사건·기간·수명, P4 실행/복원, P5 운영 권한 계약은 같은 다섯 묶음에 남긴다. 새 독립 미결 ID를 늘리지 않는다.

## 검증 인계·선택 범위

동일 키 동일 입력·변경 입력·서로 다른 키 동시 철회·새 세대·회수 경합·첫 응답 전 종료·COMMIT 불명·lookup 읽기 비실행·만료/정리·제한 재발견을 확인해야 한다. 기존 CA144/159~162 상세이며 모두 NOT_RUN이다.

선택을 요청할 묶음은 **새 철회 명령의 I=K 단일 의도 참조, 서버 R 별도 결속, 응답 유실 시 읽기 전용 결속 조회**라는 방향이다. 경로/필드명·저장 구조·기간·예외 전체의 일괄 승인이 아니다. ‘진행해줘’는 이 선택의 합의가 아니며 다음 답변에서 범위를 명시해 기록한다.

기존 COS·REC001~095·정본·과거 자료·작업14/CA162/MVP34·다른 MVP33행·18B/DG/FD/RV 보존. 코드·DB·GitHub 변경 없음. PARTIAL_RECOVERY·실제 실행 NOT_RUN.
