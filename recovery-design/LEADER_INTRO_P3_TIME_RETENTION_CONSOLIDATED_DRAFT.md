# P3 시간·보유·삭제 기준 — M1/S2 통합 보완안

2026-11-01 / r166 / CONSOLIDATED_POLICY_DRAFT_NOT_AGREED / PARTIAL_RECOVERY

[시간 후보 원문](LEADER_INTRO_INTEGRATED_REVIEW_2_TIME_RETENTION.md), [S2 방향 확정](LEADER_INTRO_S2_STORAGE_DIRECTION_AGREED_HANDOFF.md), [REC 기록](RECOVERY_DECISIONS.md)을 잇는다. r158의 TL01~11을 보존하면서 M1/S2에서 실제로 성립할 사건과 조회·정리 조건을 구분한다. ‘진행해줘’는 수치나 새 정책 합의가 아니다. 법정 보유기간이나 운영 실측을 주장하지 않는다.

## 이번 대조에서 드러난 핵심 공백

1. M1의 단일 트랜잭션이 최종 결과와 함께 확정된다면 별도 선접수 A가 없을 수 있다. 도착 로그·기기 전송 시각으로 A를 만들면 REC091의 내구 근거 원칙과 충돌한다.
2. 업무 최종 F와 결과 발견 시각은 다르다. 결과를 늦게 발견해도 새로운 F나 조회 창을 만들지 않는다. 한편 트랜잭션 안에서 찍은 일반 created_at을 정확한 COMMIT 시각이라고 부를 수도 없다. 실제 사건 시각의 구현 근거가 필요하다.
3. 결과 조회 종료·운영본 삭제 D·옛 실행 보호 종료 G는 서로 다른 사건이다. 결과를 숨긴 직후 모든 결속을 지우거나 백업 30일만 지나면 재생 위험이 사라진다고 가정할 수 없다.
4. 게시 차단은 불필요 사본 삭제와 구별해야 한다. 다른 유효 목적의 원본까지 무조건 삭제하거나, 반대로 ‘다른 목적’이라는 말만으로 철회된 공개 사본을 계속 제공해서는 안 된다.
