# 미확정 조회 종료와 늦은 최종 사이의 목록 포함 경계

2026-10-31 / r136 / PENDING_GAP_DISPLAY_PROPOSAL / PARTIAL_RECOVERY / 실제 실행 NOT_RUN

## 범위

[REC-086 재발견](LEADER_INTRO_REDISCOVERY_AGREED_HANDOFF.md), [REC-085 상태별 유한 창](LEADER_INTRO_RESULT_WINDOWS_AGREED_HANDOFF.md), [r130 목적별 수명](LEADER_INTRO_RESULT_LIFETIME_DEPENDENCIES_DRAFT.md)을 따른다. [REC 원문](RECOVERY_DECISIONS.md)은 보존한다. 이번은 **미확정 확인 창이 종료됐지만 실제 최종 결과가 없는 공백 구간**의 일반 목록/직접 조회/안내만 제안한다. 기간 숫자·정확한 기산·내부 종결·보유·필드·기술은 아직 미결이다. r128 공개상한 질문도 OPEN이다.

미확정 창이 끝났다는 사실과 업무 최종 결과는 다르다. 목록에서 안 보이는 것이 미접수·철회 실패·자료 완전 삭제를 뜻하지 않는다. 실제 최종 결과가 없는 상태에 최종 창을 임의로 만들지 않는다.

|---|---|---|---|
| G-A 일시 제외 — 권고 | 개별 요청을 제외, 실제 최종 확정 뒤 유효 최종 창에서 다시 포함 | 미확정 조회 상한을 유지·영구 대기 행 방지 | 빈 목록의 의미·실제 재등장·내부 유한 종결 필요 |

G-A를 우선 권고한다. 일반 조회를 끝내고도 내부 업무는 별도 책임/수명으로 처리할 수 있다는 구분을 유지하기 위해서다. 이 권고는 아직 합의가 아니다. 미확정 기간 자체가 미정인 상태에서 실제 목록에 적용하지 않는다. G-B/C를 금지 정책으로 확정한 것도 아니다.

## G-A 선택시 판정표 후보

| 조건 | 목록/직접 조회 | 일반 안내 | 내부 처리 |
|---|---|---|---|
| 미확정 창 유효·실제 접수 근거 있음 | 현재 자격/본인/목적 검증 후 허용 범위 | 검증된 미확정 의미 | 실제 처리/복구 근거 유지 |

| 시각/기한/계정 관계 불명 | 보호 결과 공개 보류 | 최소 일반 확인 불가 | 가짜 시각/결과 대신 제한 조사 |

미확정/최종 기간의 경계 포함/제외와 시각 권위는 별도다. 순간 경합에서는 실제 판정 근거와 일관된 결과가 필요하며 ‘그때쯤 끝났을 것’이라는 기기 추정으로 처리하지 않는다. 이미 최종이 확인됐는데 지연된 목록이 계속 숨기는 문제도 구현 검증 대상이다.

## 표시를 끝내도 남는 책임

목록 제외는 실행 취소·소속/직함 변경·철회 취소·내부 기록 삭제 명령이 아니다. 최종 근거가 없는 것을 실패/거절로 자동 종결하지 않는다. 실제 처리 또는 조사에 필요한 최소 기록과 적격 담당·대행·상향 전달·유한 내부 종결/해결 불가 안내가 필요하다. 내부 미종결 상한/보유/삭제는 이번에 정하지 않았다.

후속 내부 경로가 없으면 G-A가 준비 완료됐다고 보지 않는다. 요청을 숨기는 것만으로 무기한 처리 중/영구 보유가 해결되지 않는다. 반대로 내부 처리 필요를 근거로 본인 일반 목록에 개별 요청을 무기한 표시하지 않는다. 담당의 별도 지정·건별 접근·대리 철회 금지는 유지한다.

## 공백 구간 안내 제안

목록의 고정 도움말 후보: “이 목록에는 현재 확인 가능한 본인 철회 요청만 표시됩니다. 보이지 않는 요청이 없었거나 실패했다는 뜻은 아닙니다. 늦게 최종 결과가 확정되면 허용된 확인 기간에 다시 표시될 수 있습니다.”

이 문구는 개별 숨김 요청의 존재·건수·교회·만료 사유를 추가로 공개하는 응답이 아니다. 고정 도움말로 제공할지와 최종 문구는 미결이다. 실제 재등장 기능/기간이 준비되지 않았는데 가능한 것처럼 운영 안내를 내보내지 않는다.

직접 링크/번호 조회가 안 될 때에도 일반 안내를 유지하고 숨긴 행의 번호·시각을 목록 빈 상태의 보조 데이터로 보내지 않는다. 전체/숨김 건수·배지·커서/정렬 위치로 숨긴 관계가 새지 않아야 한다. 문의 경로가 있더라도 삭제된 원문/명칭/백업을 복원하거나 종료된 일반 조회를 자동 연장하지 않는다.

## 늦은 최종 재등장 조건

현재 유효 본인·정확한 요청 관계·실제 최종 결과·정해진 최종 조회 창을 검증해야 한다. C1 요청은 C2 새 동의와 결합하지 않는다. 목록 선택/재조회는 읽기이며 새 키·철회 쓰기·재게시를 실행하지 않는다.

미확정 목록에서 빠졌다는 이유로 최소 결과 참조를 먼저 삭제해 재등장을 불가능하게 만들지 않는다. 필요한 기록/투영과 수명·삭제/복원 보호를 실제로 연결해야 한다. 재등장·새 기기·재로그인·알림 전달로 F/최종 창을 다시 시작하지 않는다. 푸시/메일은 아직 별도 미선정이며 재등장의 필수 수단으로 정하지 않는다.

## 실패/경합 인계 조건

- 미확정 마감 직전/경계/직후와 같은 순간 최종 확정: 서버 판정이 일관되고 현재 유효한 결과를 잘못 숨기거나 만료 결과를 노출하지 않아야 한다.
- 공백 중 오래된 화면/직접 번호/페이지 커서: 목록 제외를 다른 조회로 우회하지 않아야 한다. 기기 전환/로그아웃 후 늦은 응답을 폐기한다.
- 실제 최종이 늦게 생김: 원래 요청 참조/세대와 최종 창으로 재발견하고 전체 과거 이력을 재노출하지 않는다.
- 기록 정리/옛 백업/복제 승격·색인 지연: 최신 목적/권한/기간을 재적용하고 옛 요청 실행/공개가 부활하지 않아야 한다.
- 아무 최종도 안 생김: 내부 무기한 보유/가짜 완료로 끝내지 않아야 한다. 실제 운영 종결 계약이 없으면 미해소로 남긴다.

기존 CA144/159~162·WRV/WB/RCV·MV·r133 인계 조건을 구체화한 것이며 새 CA나 실제 통과 수를 추가하지 않는다. 모두 NOT_RUN이다. 앱/API/DB/계정/알림·실환경에 접속하거나 변경하지 않았다.
