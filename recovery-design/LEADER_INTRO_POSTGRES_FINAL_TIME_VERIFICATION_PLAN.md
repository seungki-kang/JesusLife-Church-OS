# PostgreSQL 최종 확정 시각 후보와 검증 계획

2026-11-09 / r169 / VERIFICATION_PLAN_DRAFT / PARTIAL_RECOVERY

[REC-098](RECOVERY_DECISIONS.md#rec-098-최종-결과-168시간-조회와-선접수-표시-경계)와 [r168 시각·조회 초안](LEADER_INTRO_FINAL_TIME_PROOF_QUERY_BOUNDARY_DRAFT.md)을 잇는다. 기존 v2.6의 보존 소스에서 일반 API 영수증의 자원 시각·24시간 만료와 COMMIT 경로를 대조했다. 새 철회에 쓸 확정 시각 제공 방식과 운영 설정은 확인되지 않았다. 공식 문서 조회는 이번 환경에서 결과를 받지 못했으므로 아래 PostgreSQL 기능명은 검증 대상으로만 기록한다. 실험·운영 접속·코드 작성·DDL·GitHub 변경 없음.

## 후보와 시험 순서

| 후보 | 입증할 가설 | 실패 또는 탈락 조건 |
|---|---|---|
| T1 트랜잭션 확정 메타데이터 | track_commit_timestamp 및 pg_xact_commit_timestamp 후보로 원 확정 트랜잭션의 시각을 조회하고, 같은 내구 결과에 결속할 수 있는지 먼저 평가 | 값 유실/미제공, 식별자 재사용·복원 혼선, 운영 권한/설정 미지원, 장애 복구 한계로 필요한 기간에 시각을 회수하지 못함 |
| T2 논리 변경 스트림의 확정 이벤트 | COMMIT 이벤트의 시각과 같은 트랜잭션의 결과 변경을 대조하고, 재전달 시 원래 시각만 투영할 수 있는지 평가 | 처리 지연·슬롯/이벤트 유실·장애 전환으로 필수 구간에 근거 복구 불가, 개인정보/권한/비용 경계 미충족, 독립 실행·정본 필요 |
| T3 시작·쓰기·응답·최초 발견 시각 | 확정 전후 시각이 F와 다를 수 있음을 보여주는 대조군 | REC-098의 F를 입증하는 방식으로 채택하지 않음. 다른 제품 정책으로 전환하려면 별도 검토 |

**순서 권고:** 격리 환경에서 T1을 먼저 평가한다. 운영 설정·권한·보존 수명 또는 복구 조건을 충족하지 못하면 T2를 평가한다. T2도 조건을 충족하지 못하면 시간 계약을 출시 전 차단 항목으로 유지하고, 기존 168시간 합의를 바꿀 대안은 별도 결정으로 올린다. 이 순서는 T1의 성능·적합성 확정이나 운영 설정 변경 지시가 아니다.

## 결속과 장애 복구 계약의 검증 포인트

- 요청과 결과의 불변 참조, 확정 트랜잭션 증거, 그 증거를 해석할 DB 계보/복원 범위가 같은 사건을 가리키는지 시험한다. 트랜잭션 번호만을 교회·DB·복원본 전역 식별자로 가정하지 않는다. 수정 가능 행의 현재 버전으로 옛 확정 트랜잭션을 추정하지 않는다.
- 내구 업무 결과는 S2의 원래 한 트랜잭션에서만 확정한다. 확정 후 시각 사본이 필요한 후보라면 동일 결과에 대한 재시도 가능한 투영만 허용할지 검토한다. 동일 근거 재처리는 동일 시각, 상충 근거는 격리·조사, 원 근거 부재는 시각 미확인이다. 투영 지연은 조회 창을 다시 시작하지 않는다.
- 원천 근거를 언제까지 회수할 수 있는지와 시각 사본을 언제까지 볼 수 있는지는 따로 측정한다. 커밋 직후 장애부터 필요한 최대 복구 지연까지 원천이 보존되지 않으면, 이미 투영된 사례가 성공했어도 채택 기준을 충족하지 않는다. 가용성 목표·최대 복구 지연·허용 시계 오차는 실측 후 정한다.
- 자료 최소화: 실험에는 합성 식별자만 사용한다. 운영 후보가 실제로 필요한 범위보다 많은 테이블·행·사용자 원문을 읽어야 한다면 접근 방식부터 재설계한다. DB 관리자 권한을 앱 런타임 권한으로 승계하지 않는다.

## 실행 순서와 합격 기준

| ID | 격리 환경에서 재현할 조건 | 관찰과 합격 기준 | 상태 |
|---|---|---|---|
| VT01 | 설정 켜짐/꺼짐, 일반 앱 역할과 제한된 관찰 역할 | 버전·설정·최소권한별 성공/거절을 기록. 무권한 역할로 다른 결과의 시간 증거를 열람할 수 없음 | NOT_RUN |
| VT02 | 트랜잭션 시작→의도적 지연→커밋·롤백 대조 | 지연된 커밋의 F는 시작/행 생성값에 종속되지 않음. 롤백 요청에는 최종 결과·시각이 생기지 않음. 독립 관찰의 확정 전후 범위와 대조 | NOT_RUN |
| VT03 | 커밋 직후 응답 유실·프로세스 종료·시각 투영 전 종료 | 재시작 후 읽기 전용 경로가 같은 결과와 같은 F를 복구. 재실행 없음. 복구 실패 시 불명 처리·공개 보류 | NOT_RUN |
| VT04 | 동일 요청 재조회, 같은 세대의 다른 요청, 동시성 | 최초 결과 F 불변. 별개의 무변경 결과에는 그 요청의 시각을 결속. 키/트랜잭션 증거 혼선 없음 | NOT_RUN |
| VT05 | 지연 누적·정리·유지보수·재시작·스트림 재전달 | 지연·재전달·보존 한계를 기록. 시각을 찾을 수 없는 경우 임의 기산 금지. 상충 투영을 자동 덮어쓰지 않음 | NOT_RUN |
| VT06 | 복원본·장애 전환·DB 계보 변경 | 같은 사건임을 증명할 때만 원래 F 사용. 계보 충돌, 최신 삭제/권한 상태 불명은 공개 보류. 만료 기록이 되살아나지 않음 | NOT_RUN |
| VT07 | 종료 직전/정확히 종료/직후, 시계 앞뒤 점프·권한 회수 | 신뢰 시계와 현재 권한을 사용. 정확히 종료부터 차단. 확인되지 않은 시계 변경으로 영구 삭제·재노출·창 초기화 없음 | NOT_RUN |

먼저 실제 시간 168시간을 기다리지 않는 제어 시계 시험으로 경계 계산을 검증하고, 실제 DB 시계·장애·정리 시험은 따로 수행한다. 가속 정리/실험만으로 운영 보존 수명을 입증했다고 기록하지 않는다. 시계 오차가 경계를 가르는 경우의 보류는 사용자에게 조회기간을 보장하지 못하는 운영 영향이 있으므로 빈도·복구 시간도 관찰한다.

## 검증 증거와 인계 판정

실험별로 DB 버전·이미지 식별자·설정·역할·계보, 시험 입력(합성 식별자), 명령·종료 코드, 기대값·관측값, 원인과 재현 순서, 원천 시각과 투영 시각의 차이를 기록한다. 후보 채택에는 공식 근거, 운영 후보의 설정·권한, VT01~07 결과, 보존/복원 근거가 필요하다. 일부 성공을 전체 승인으로 집계하지 않는다. 필요한 원천이 운영 후보에서 확인되지 않으면 그 조건을 차단으로 기록한다.

r169는 시험 계획에 한정된다. REC001~098·기존 게이트·정본을 보존한다. 시간 출처·물리 저장·보유/삭제 및 복원 방식은 미결. 다음 안전한 작업은 **T1에 대한 합성 데이터 격리 실험 명세를 만들고, 실행에 앞서 공식 근거와 후보 환경을 확인하는 것**이다.
