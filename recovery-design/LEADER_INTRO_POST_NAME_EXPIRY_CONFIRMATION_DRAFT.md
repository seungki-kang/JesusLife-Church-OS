# 명칭 보유 종료 후 본인 철회 결과의 최소 확인·안내

2026-10-30 / r119 / UX_CONTRACT_DRAFT / PARTIAL_RECOVERY / 실행 NOT_RUN

## 적용과 한계

[r118 정책 결정 자료](LEADER_INTRO_RETENTION_DECISION_PACKET.md)의 P02/03/07과 [r114 기간 후보](LEADER_INTRO_POST_WITHDRAWAL_RETENTION_OPTIONS.md)를 구체화한다. 30일 명칭·90일 최소 확인은 여전히 미합의다. 아래 흐름은 **그와 같이 목적별 기간을 나누는 경우**의 조건부 초안이다. 기간·새 열람 권한·조회 API·저장 필드를 확정하지 않는다.

[REC 결정](RECOVERY_DECISIONS.md)의 REC-076~078은 본인이 철회할 대상을 식별하는 제한된 절차다. 이미 철회된 결과를 나중에 확인하는 이번 흐름과 다르다. [REC-031의 일반 업무 결과 다섯 항목](STATUS_DISPLAY_ALLOWLIST_PROPOSAL_2026-10-27.md)은 별도 현재 계정/교회 소속과 168시간 조회 계약을 따른다. 이를 탈퇴 후 90일 조회 API로 자동 확대하지 않는다.

## 세 화면의 목적을 분리

| 화면 | 허용 목적 | 경계 |
|---|---|---|
| 철회 전 대상 선택 | 현재 허용된 본인의 특정 동의를 구분하고 직접 철회 | REC-077/078 최소 명칭·현재 소유 관계 검증, 삭제된 명칭 복원 금지 |
| 일반 업무 처리 확인 | 허용된 요청의 최소 상태 다섯 항목 확인 | REC-029~032 기존 자격·시계, 업무 상세/새 권한 추가 금지 |
| 철회 완료 증빙 확인 후보 | 보유 목적 안의 특정 철회 결과를 본인 범위로 확인 | 새 목적·자격·조회 창·필드 계약 미결, 재철회/재게시 버튼 없음 |

확인 창이 끝나도 아직 유효한 다른 동의의 철회권이 없어지는 것은 아니다. 직함 종료만으로 철회가 확정됐다고 표시하지 않는다. 서버 철회 확정은 모든 사진 사본의 물리 삭제 완료와도 다르다.

## 최소 표시 후보

원문·사진·연락처·교회/공동체 명칭·이전 명칭·구성원·역할 이력·업무 내용은 표시하지 않는다. 범용 상태 응답에 새 항목을 몰래 추가하지 않는다.

| 후보 항목 | 표시 조건 | 한계 |
|---|---|---|
| 불투명 확인 번호 | 해당 결과와 본인 결속을 서버가 확인하고 조회 목적 유효 | 권한 증명이 아니며 번호만으로 교회/대상 의미를 알 수 없음 |
| 철회 확정 상태 | 실제 해당 동의 세대의 서버 확정 근거 존재 | 다른 동의·현재 전체 게시·물리 삭제 완료를 보증하지 않음 |
| 실제 확정 시각 | 원래 시각 근거가 확인됨 | 시각이 같아도 같은 대상이라는 뜻 아님 |
| 확인 가능 종료 시각 | 해당 증빙의 목적별 정책과 기산이 확정됨 | 기존 요청 상태 168시간과 다름, 아직 API 필드 미채택 |

이 네 항목은 이번 증빙 화면만의 비교 후보이며 REC-031의 다섯 항목을 네 개로 수정한 것이 아니다. 명칭을 지웠다고 연결 참조가 익명 정보가 되는 것도 아니다. 목록/개별 조회/지원 도구는 각각 필요한 현재 자격·범위를 검사한다.

## 화면·행위·실패 처리

| 단계 | 화면과 허용 행위 | 서버/권한 조건 | 실패·불명 처리 |
|---|---|---|---|
| UX01 진입 | 본인 확인 뒤 제한된 확인 메뉴로 이동하는 후보 | 현재 계정과 해당 목적 자격, 탈퇴/정지 별도 기존 경로 존중 | 이전 화면/로컬 캐시로 선노출하지 않음 |
| UX02 결과 선택 | 허용된 확인 참조의 최소 카드 | 본인·동의 세대 결속·현재 목적 기한 | 명칭 없는 카드를 임의 최신/첫 요청으로 선택하지 않음 |
| UX03 결과 열람 | 특정 참조의 서버 확정 사실만 확인 | 매 조회/복귀에 현재 권한·기한 재검증 | 응답 유실은 ‘확인하지 못함’, 재철회/재게시 자동 실행 없음 |
| UX04 구분 불가 | 추가 확인 안내, 최소 문의 접수 후보 | 기존 별도 지정/건별 배정·필요 최소 근거 | 직원의 원문/명칭 복원·대리 철회·무제한 접근 금지 |
| UX05 창 종료 | 개인별 종료 사실을 알려도 되는 자격/근거가 있으면 제한 안내 | 별도 최소 근거와 유효 목적, 그 보유도 별도 유한 계약 | 근거가 없으면 존재/만료/삭제를 추측하지 않고 일반 안내 |
| UX06 종료/전환 | 보호 화면 닫기, 계정/교회 전환시 분리 | 현재 세션/기기 정책과 결속 | 기기 참조를 영구 보유하거나 다른 계정에 노출하지 않음 |

퇴사/탈퇴 후 증빙 확인 자격은 REC-076의 철회 실행 권한에서 자동 파생하지 않는다. 공통 계정 정지/탈퇴·서비스 탈퇴 시 새 우회 경로를 만들지 않는다. 실제 자격/API 계약 확정 전 구현 시작 조건은 미충족이다.

## 사용자 문구 초안

- 해당 참조를 실제 확인한 경우: “이 확인 번호의 소개 동의 철회가 확정되었습니다. 다른 동의나 모든 사본의 삭제 완료를 뜻하지 않습니다.”
- 명칭이 목적에 따라 정리된 것이 실제 확인된 경우: “명칭 보유기간이 끝나 대상 이름은 표시하지 않습니다. 확인 번호와 시각만으로 대상을 구분하기 어려우면 추가 확인을 요청할 수 있습니다.” 실제 지원 경로가 마련되지 않았다면 존재하는 버튼처럼 약속하지 않는다.
- 대상을 구분하지 못한 경우: “이 정보만으로 어느 대상인지 확인할 수 없습니다.” 임의 추정/일괄 철회를 제안하지 않는다.
- 권한/기한/대상 존재를 구분해 안내할 근거가 없는 경우: “현재 이 결과를 확인할 수 없습니다.” 이어 일반 도움말만 제공하며 404를 철회 미실행·삭제 완료로 해석하지 않는다.
- 통신 실패: “결과를 확인하지 못했습니다. 연결 후 다시 확인해 주세요.” 서버 업무 실패나 재실행 필요로 표시하지 않는다.

문구는 최종 UX 합의가 아니다. 만료 사유를 설명하려고 새로운 영구 만료 원장을 만들지 않는다. 직접 조회에서 타인 번호·다른 교회·기한 초과를 구분하는 오류로 존재 여부가 새지 않아야 한다. 상세 실패 원인은 목적 제한된 운영 기록과 분리한다.

## 명칭 없이 식별할 수 없는 경우

확인 번호를 본인이 보관한 참조와 대조할 수 있는 경우만 정확한 결속의 보조가 된다. 번호나 시각만으로 모든 사용자가 대상을 기억한다고 가정하지 않는다. 여러 철회가 같은 시각에 이루어졌다면 ‘첫 번째·최근 항목’으로 업무 대상을 대신 지정하지 않는다.

추가 확인 담당도 적법하게 남은 해당 건 최소 근거만 사용한다. 실제로 구분할 근거가 소실됐으면 **식별 불가**로 안내한다. 삭제된 명칭·원문·사진·백업·다른 제품 기록·교인 명단을 복원/검색하지 않는다. 자유 서술에 민감정보를 제출하도록 유도하지 않는다. 지원은 새로운 철회 승인이나 대신 철회할 권한을 만들지 않는다.

새로 만든 영구 별칭·명칭 해시·대상 상세가 담긴 푸시/메일 영수증으로 명칭 보유 종료를 우회하지 않는다. 사용자 기기 저장/외부 내보내기 기능은 아직 별도 미결이며 기본 자동 발급하지 않는다. 기기 참조가 없다는 이유만으로 본인 철회권 자체를 박탈하지 않는다.

## 경계 검토 — 실행 결과 아님

1. 화면을 연 상태에서 접근 목적 종료: 화면 복귀/재조회에 최신 상태 적용, 만료 자료를 캐시로 다시 표시하지 않음. 정확한 열린 화면 즉시 차단 기술은 후속 검증.
2. 같은 계정의 철회 두 건: 카드가 구분되지 않으면 추가 확인, 이름을 자동으로 붙이지 않음.
3. 남의 확인 번호/다른 교회 참조: 본인 관계·목적 실패시 내용/존재 노출 금지. 번호 소지만으로 허용하지 않음.
4. 조회 종료 뒤 문의: 일반 문의와 유효한 다른 동의 철회는 가능하되 종료 증빙의 복원을 약속하지 않음.
5. 재동의 C2 존재: C1의 완료를 C2 철회나 현재 게시 중단으로 안내하지 않음.
6. 백업/캐시 일부 삭제 실패: 철회 확정과 사본 정리 상태를 혼동하지 않고 전체 삭제 완료로 표시하지 않음.
7. 원래 T0/기한 근거 불명: 현재 시각/기기 시각으로 새 기한 생성 금지, 최소 근거 조사와 제한 안내.
8. 지원 담당 회수/배정 종료: 열린 접수에서 접근 차단·별도 인계, 기존 담당이 대신 철회하거나 조회 창을 연장하지 않음.

기존 CA159~162·r117 VT 검증 인계와 함께 대조하는 설계 조건이다. 새 CA 수로 계산하지 않았으며 어떤 조건도 실제 실행하지 않았다.

## 개발 전 남은 결정과 다음 작업

보유 후보 선택, 새 증빙 확인 자격·계정 종료 경계, 허용 필드/조회 목적 종료, 물리 삭제/백업 상한, 실제 추가 확인 경로는 OPEN이다. 이 화면의 최소 표시 후보를 합의한 것으로 기록하지 않는다. REC-031 일반 업무 조회의 허용 항목/168시간은 그대로다.

다음은 이 증빙 확인 후보와 **일반 철회·일반 요청 상태·추가 확인 접수의 권한/응답 경계**를 비교해, 새 API가 필요한 부분과 기존 계약을 유지할 부분을 정리한다. 코드·경로·스키마 구현이나 기간 선택 전에 계약 충돌을 먼저 확인한다.
