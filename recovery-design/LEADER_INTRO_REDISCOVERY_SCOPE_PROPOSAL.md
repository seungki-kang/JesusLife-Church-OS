# 참조 소실 시 본인 철회 요청 재발견 — 범위 결정안

2026-10-31 / r134 / REDISCOVERY_SCOPE_PROPOSAL / PARTIAL_RECOVERY / 실제 실행 NOT_RUN

## 범위·근거

[r133 경로 비교](LEADER_INTRO_LATE_RESULT_REDISCOVERY_DRAFT.md), [REC-084 본인 결과 확인](LEADER_INTRO_MINIMUM_RESULT_AGREED_HANDOFF.md), [REC-085 상태별 유한 창](LEADER_INTRO_RESULT_WINDOWS_AGREED_HANDOFF.md)을 이어 RF-B의 제품 범위를 좁힌다. [기존 REC 원문](RECOVERY_DECISIONS.md)은 보존한다.

이번에는 **참조를 잃은 유효 계정 본인에게 아직 확인 가능한 본인 소개 철회 요청을 찾는 제한 경로를 둘지**만 제안한다. 일반 업무 전체 목록·계정 전체 감사·장기 증빙 E·다른 제품 기록 탐색을 승인받는 질문이 아니다. r128 공개 다섯 항목 상한은 별도 OPEN이다. 실제 기간/기산/포함 조건·필드·API·DB·기기/알림을 확정하지 않는다.

## 좁은 선택지

| 선택 | 의미 | 장점/부담 |
|---|---|---|
| RF-B 제한 재발견 — 권고 | 현재 본인에게 결속되고 유효 확인 창 안에 있는 W 요청만 찾는 경로 | 새 기기/재로그인에서 참조가 없어도 확인 가능성을 확보. 목록 권한·필드/창·사본 정리 계약 필요 |
| 참조 직접 확인+제한 지원만 | 참조가 있으면 직접 확인, 없으면 담당의 제한 지원 | 새 재발견 목록을 줄임. 담당 공백/지연·동일 본인 확인 역량·대체 수단 확보가 필요 |

RF-B 권고 이유는 REC-085의 최종 확인 기회가 기기 참조 하나의 소실로 사라지지 않도록 하기 위해서다. 편의만으로 전역 이력 권한을 넓히지 않는다. 선택 전 RF-B를 이미 합의·구현된 기능으로 표시하지 않는다.

## 제안하는 경계

| 항목 | RF-B 범위 후보 | 제외/미결 |
|---|---|---|
| 이용자 | 현재 목적에 유효한 공통 계정의 본인 | 정지/탈퇴/서비스 종료 예외 미부여 |
| 요청 | 본인이 실제 제출한 특정 소개 동의 철회 요청 | 다른 업무/타인 요청·동의 자체를 요청처럼 소급 생성 금지 |
| 교회 관계 | 해당 W의 본인 결속으로 확인, 재가입/관리자 승인 불필요 방향 | 과거 교회 홈/명단/자료 열람권 없음 |
| 기간 | 아직 허용된 유한 확인 창 안의 요청 | 미확정/최종 창 숫자·경계·중간 공백 포함 조건 미결 |
| 출력 | 다시 확인할 본인 요청의 최소 참조/상태 후보 | 원문·사진·명칭·상세 사유·전체 건수 제외, 정확한 필드 미결 |
| 행위 | 요청 선택과 결과 조회만 | 선택=재철회/재게시/새 키 발급 아님 |
| 소실 처리 | 서버의 정확한 본인-요청 근거가 실제 남은 범위 | 삭제된 기록/명칭/백업 복원·이메일/이름 추정으로 재구성 금지 |
| 보유 | 원래 목적/기산·기록/사본 정리 계약 준수 | 재발견 편의를 위한 영구 색인/보유 연장 금지 |

이 표는 제품 경계 후보다. 선택되더라도 현재 계정·본인 관계·기한·허용 필드를 서버에서 검증할 기술 계약이 필요하다. 같은 기기·같은 이메일·표시 이름·번호 소지는 본인 요청 관계의 대체 근거가 아니다.

## 유효 창·늦은 결과의 포함 조건

미확정 확인 창은 끝났지만 최종 결과가 아직 없는 요청을 계속 표시할지, 숨겼다가 최종 창이 실제 열릴 때 다시 찾게 할지는 미결이다. 최종 창이 생겼다고 모든 과거 요청을 재노출하지 않는다. 포함 조건의 정본/시각이 불명확하면 공개를 보류하고 제한 안내한다.

만료 직전 페이지 요청/다음 페이지 커서·열린 화면에서 기한을 넘기는 경우도 서버 현재 판정이 필요하다. 오래된 커서가 권한/기간을 동결하는 통행증이 되지 않아야 한다. 새 로그인·다른 기기·조회/재발견·정렬/페이지 요청이 기산을 초기화하지 않는다.

유효한 최종 창 안의 참조가 실제 찾을 수 있으려면 서버 최소 결과·색인/조회 정본이 그 창을 뒷받침해야 한다. 기존24시간 성공 영수증만으로 가능하다고 선언하지 않는다. 조회 기록/보호 참조·삭제/백업 수명은 별도다. 기간 숫자는 이 제안의 동의로 정해지지 않는다.

## 화면/오류의 최소 흐름 후보

1. 현재 본인 인증 후 제한된 철회 결과 찾기로 진입한다. 일반 Q나 교회 업무 전체 목록을 통과하지 않는다.
2. 서버에서 허용된 본인 W만 최소 형태로 제공한다. 클라이언트 전체 데이터 필터링으로 대체하지 않는다.
3. 본인이 요청을 골라 결과를 조회한다. 직접 조회 때도 현재 본인/요청/목적/기한을 다시 확인한다.
4. 번호/시각만으로 어느 요청인지 알 수 없으면 임의 최근/첫 요청을 선택하지 않는다. 제한 지원/확인 불가 안내를 검토하며 원문/사진·교회명 복원으로 식별하지 않는다.
5. 빈 목록/부재/만료/관계 불명은 내부 사실과 공개 안내를 구분한다. ‘결과가 안 보임’이 과거 요청 없음·철회 실패·안전 재실행을 뜻하지 않는다.
6. 계정 전환/로그아웃·목적 상실·화면 종료 뒤 지연 응답/캐시는 현재 계정에 적용하지 않는다. 기기 저장·알림은 별도다.

위 흐름은 아직 앱 화면/API 구현이 아니다. ‘전체 요청이 없습니다’ 같은 전역 단정이나 전체 건수·숨겨진 교회별 카운트로 관계가 새지 않아야 한다. 새 목록 권한을 지원/교회 관리자에게 포괄 부여하지 않는다.

## 검증 인계와 미결

다른 계정·타교회·C1/C2·미확정 만료/늦은 최종·최종 만료·기록 정리/복원·재로그인/새 기기·커서 치환·화면 전환 늦은 응답을 합성 자료로 대조할 계획이다. 목록과 직접 조회의 허용 범위가 같고 조회가 쓰기를 만들지 않는지 확인해야 한다. 실제 실행 NOT_RUN이다.

기존 CA144/159~162·r133 검토 조건을 세분화한 계획이며 새 CA/실행 PASS를 추가하지 않는다. 목록 행위 선정 전 페이지 규격/인덱스/정렬·조회 창/필드·인증/실효DB권한을 임의로 구현하지 않는다. r128 공개상한 질문·미확정 기간·최종 기간·정확한 기산·수명/백업·알림은 OPEN이다.

## 한 질문 — 답변 전 OPEN

**참조를 잃어도, 유효한 공통 계정의 본인이 아직 확인 가능한 자신의 소개 철회 요청만 다시 찾는 제한 경로를 둘까요?**

권고는 RF-B다. 다른 업무/전체 이력·교회자료를 열지 않고 허용된 본인 철회 요청의 재발견에 한정한다. ‘네’는 이 제품 범위에만 적용하며 기간·목록 필드/페이지·스키마·알림·계정 제한 예외·r128 공개상한까지 승인한 것으로 기록하지 않는다. 답변 전 새 REC를 만들지 않는다.

이 자료로 재발견 범위 선택의 준비를 마친다. 다음은 명시 답변 반영 또는 다른 독립 MVP 미결의 대조다. 기존 COS/REC001~085·정본·과거 이력 보존. 작업14/CA162/MVP34·18B/DG/FD/RV 유지. 코드·API·DB·GitHub 변경 없음. PARTIAL_RECOVERY·실제 실행 NOT_RUN.
