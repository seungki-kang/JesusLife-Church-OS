# 본인 철회 최소 결과 화면 — 공개 상한·근거 누락 안내 제안

2026-10-31 / r128 / DISPLAY_LIMIT_PROPOSAL / PARTIAL_RECOVERY / 실제 실행 NOT_RUN

## 이번 결정의 범위

[REC-084 적용](LEADER_INTRO_MINIMUM_RESULT_AGREED_HANDOFF.md)의 본인·특정 요청 확인 권한과 [r127 계약 카드](LEADER_INTRO_MINIMUM_RESULT_FIELDS_TIME_CARD.md)를 따른다. [r126 시각/구현 한계](LEADER_INTRO_SYNC_ACCEPTANCE_MODEL_COMPARISON.md), [r125 요청 결속](LEADER_INTRO_WITHDRAWAL_REQUEST_BINDING_DRAFT.md), [기존 결정](RECOVERY_DECISIONS.md)을 보존한다.

이번 제안은 **화면에 무엇까지 보여줄지와 근거 없는 값을 채우지 않을 원칙**에 한정한다. 정식 JSON 키·서버 상태명·HTTP 코드·정확한 시각 사건·조회기간·서버/기기 보유·삭제/백업·처리 모델의 합의를 함께 받지 않는다. E 장기 증빙 조회는 후속 기능이며 일반 Q의 자격·다섯 항목·168시간 계약은 변경하지 않는다.

## 공개 상한 제안 — 최대 다섯 종류

| 번호 | 화면 항목 후보 | 표시 전제 | 빠졌을 때의 후보 안내 |
|---|---|---|---|
| D01 | 요청 확인 번호 | 현재 본인과 해당 요청의 정확한 결속 검증 | 번호를 만들거나 타인/최신 요청으로 대체하지 않음 |
| D02 | 처리 결과/상태 | 해당 요청에 대해 서버가 확인한 근거 존재 | 결과를 확인하지 못했다고 안내, 실패·미실행으로 단정하지 않음 |
| D03 | 서버 접수 시각 | 실제 내구 접수 사건과 시각 의미를 검증 | 그 시각을 확인할 수 없다고 안내, 기기 전송시각 사용 금지 |
| D04 | 서버가 확인한 최종 결과 시각 | 최종 결과와 그 기록 시각의 실제 의미 검증 | 모르는 시각을 넣지 않음, 미확정은 최종 시각 표시 안 함 |
| D05 | 결과 확인 종료 시각 | WR의 조회 정책/기산/기간·계산이 확정되고 해당 요청에 적용 가능 | 아직 정하지 않은 기간을 생성하지 않음, 계약 미완성으로 인계 |

‘최대 다섯 종류’는 모든 응답에 다섯 값을 강제로 채우라는 뜻이 아니다. 현재 권한·목적·관계 확인이 실패하면 번호/시각을 부분적으로 먼저 보여주지 않는다. 서버 접수가 실제로 없거나 불명확하면 화면 빈칸을 메우려고 내구 접수 기록을 소급 생성하지 않는다.

D04는 **실제 커밋 성공 시각을 항상 확보한다는 약속이 아니다.** 최종 결과의 근거와 그 시각이 어떤 사건을 뜻하는지 기술 계약에서 검증해야 한다. 자원 created_at·조회 now()를 최종 결과 시각으로 대체하지 않는다. 구체 사건이 확정되면 사용자 문구를 그 의미에 맞춰야 하며 ‘정확한 실제 커밋 시각’처럼 과장하지 않는다. 일반 Q의 기존 용어를 이 제안으로 변경하지 않는다.

D05가 미결인 현재는 운영에 적용 가능한 완성된 화면 계약이 아니다. 사용자에게 ‘미정이라 무기한 조회 가능’이라고 제공할 수 없다. 여기서는 필드 상한을 검토하며 조회기간은 다음 독립 결정으로 남긴다.

## 추가 공개를 막는 경계

소개 원문/사진·교회/공동체 이름·명단·연락처·역할 이력·상세 거절 사유·업무 입력/수정 전후·내부 교회/소개/동의 세대 식별자·타인/다른 요청·전체 건수·감사 전문·토큰·타제품 기록을 결과 화면에 추가하지 않는 안이다. 내부적으로 필요한 대상/세대 참조는 현재 본인과 요청을 결속하는 데 쓰되 화면 공개 권한으로 바뀌지 않는다.

화면 밖 JSON 여분 필드·접근성 레이블·검색 미리보기·분석 로그·푸시/메일·클립보드·기기 영구 캐시로 같은 내용을 우회 노출하지 않는다. 이 항목들을 금지 목록으로만 구현해 새 필드가 자동 공개되는 방식보다 해당 목적의 허용 목록을 검증하는 계약이 필요하다. 기술 구현은 아직 선정하지 않았다.

## 근거가 없을 때의 안내 분기

| 상황 | 사용자 안내 후보 | 서버/앱 처리 경계 |
|---|---|---|
| 실제 최종 철회 근거 확인 | ‘해당 철회 요청이 확정되었습니다.’ | 모든 사본 삭제 완료/다른 동의 철회로 확대하지 않음 |
| 실제 변경 없는 최종 거절 근거 확인 | ‘해당 요청은 변경 없이 거절되었습니다.’ | 권한 없는 참조/인증 실패를 본인 업무 거절로 기록하지 않음 |
| 내구 접수만 검증 | ‘접수는 확인됐지만 최종 결과는 아직 확인되지 않았습니다.’ | 구현에 내구 접수가 없으면 이 상태를 만들어내지 않음 |
| 요청 관계는 확인, 결과 근거 모순 | ‘결과에 추가 확인이 필요합니다.’ | 오류를 임의 성공/실패로 정정하지 않음 |
| 존재/권한/기한/부재를 구분해 알릴 근거 없음 | ‘현재 이 결과를 확인할 수 없습니다.’ | 타인 요청/관계 존재를 구분하는 추가 설명 금지 |
| 결과 근거 유효, 시각만 불명 | ‘이 시각은 확인할 수 없습니다.’ | 정확한 결과 사실까지 무조건 없다고 하지는 않으며 시각을 조작하지 않음 |
| 통신 실패 | ‘결과를 확인하지 못했습니다. 연결 후 다시 확인해 주세요.’ | 업무 재전송 대신 결과 재확인, 자동 새 키/의도 금지 |

위 문장은 검토용 고정 안내 후보이며 상세 사유의 여섯 번째 공개 필드를 허용한 것이 아니다. 결과 상태 또는 앱의 일반 확인 불가/통신 안내에 해당한다. 어느 요청이 만료됐는지 설명하려고 새 영구 만료 원장을 만들지 않는다. 사용자에게 허용되지 않은 원인·개인 관계가 문구 차이로 드러나지 않도록 오류 계약을 검증한다.

## 화면별 적용 제안

- 해당 요청 화면: 검증된 D01~05 범위의 값만 표시한다. 소속 종료 후 과거 교회 홈/명단으로 복귀하는 링크를 결과 확인에 요구하지 않는다.
- 결과 미확인 화면: 다시 확인은 조회다. 재철회/재게시/담당 대리 처리를 묶지 않는다.
- 근거 누락 화면: 일반 안내와 허용된 최소 지원 경로를 구분한다. 실제 지원 자격/경로가 미준비면 제공되는 것처럼 버튼을 만들지 않는다.
- 계정 전환/로그아웃: 현재 보호 값을 정리하고 늦은 응답을 새 계정에 반영하지 않는다. 기기 참조·백업 수명은 별도 계약이다.

전체 요청 목록을 새로 제공하는 기능을 승인하는 제안이 아니다. 첫 서버 응답을 못 받은 경우의 I/K→R 결속 조회도 기존 r125 계약이 필요하다. 짧은 번호/동일 시각만으로 사람에게 모든 대상을 구분할 수 있다고 보장하지 않는다. 이 화면은 원문과 명칭을 재표시하는 대상 선택 화면이 아니다.

## 독립 검토 항목과 수용 조건

| 검토 항목 | 이 제안에서 좁힐 것 | 이번에 확정하지 않을 것 |
|---|---|---|
| 공개 상한 | D01~05 안에서만, 근거 없는 값은 임의 대체 금지 | JSON/필수/생략/null·상태명/HTTP |
| 현재 관계 | REC-084 본인/특정 요청 경계 유지 | 계정/서비스 정지·탈퇴의 예외 자격 |
| 시각 신뢰 | 실제 사건 의미/근거가 확인되는 범위만 표시 | 커밋 사건/시계/정밀도 구현 선택 |
| 결과 안내 | 모르는 결과를 실패로 단정하지 않고 한정 안내 | 지원 처리기한/보유기간·실제 담당 |
| 조회 수명 | 기한 필드의 의미와 조건을 구분 | 기존24h/168h/30·90일 자동 적용 |

합성 검토는 D01~05 외 데이터가 정상/오류 응답·캐시·접근성·분석에 새지 않는지, 실제 결과는 있으나 시각만 없는 경우 조작하지 않는지, 권한 없는 참조의 존재 노출이 없는지, 통신 실패가 업무 재실행을 만들지 않는지를 확인해야 한다. 이 조건들은 기존 CA144·WRV/WB/RCV를 구체화하며 새 CA 수를 추가하지 않는다. 실제 실행은 모두 NOT_RUN이다.

## 한 질문 — 답변 전 OPEN

**본인 철회 결과 화면은 ‘요청 확인 번호·처리 상태·서버 접수 시각·서버가 확인한 최종 결과 시각·결과 확인 종료 시각’ 다섯 종류 이내로 제한하고, 근거 없는 값은 임의로 채우지 않는 원칙으로 정할까요?**

권고 이유는 결과 확인에 필요한 최소 정보만 제공하면서 근거 없는 시간/완료 추정과 교회 내부정보 노출을 줄이기 위해서다. 대안으로 더 넓은 대상/사유 설명을 넣을 수 있으나 별도 목적·권한·보유와 관계 노출 검토가 추가된다. 실제 필드가 없거나 조회기간이 미정인 현재 구현 완료를 주장하지 않는다.

‘네’가 있으면 이 공개 상한/근거 없는 값 대체 금지 원칙만 기록한다. 위 문구/정식 상태/시각 사건·기술 선정·조회기간·서버/기기 보유·삭제/백업 전체를 승인한 것으로 기록하지 않는다. 답변 전 새 REC를 만들지 않는다.
