## 조회 기산 후보 대조

| 후보 | 산정 의미 | 장점 | 남는 문제 |
|---|---|---|---|
| QT-A 접수 기준 고정 창 | 실제 내구 접수 A부터 유한 P | 시작과 최대 일반 조회 창이 단순 | 창 끝 직전/뒤 최종 확정 결과를 본인이 확인할 기회가 짧거나 없음 |
| QT-B 상태별 창 | 미확정은 A+P, 최종은 실제 F+Q | 늦게 확정된 결과의 별도 확인 기회 | 미확정 창 종료 이후 처리/최종 전달·종결·기록 수명 필요 |
| QT-C 최종 기준만 | 최종 결과 F부터 유한 Q | 최종 확인 목적이 명확 | F가 없으면 시작도 없어 미확정 내부 보유가 무한해질 수 있음 |

QT-B를 우선 비교하되 선정하지 않는다. Q 일반 계약이 상태별168시간을 쓴다는 사실만으로 WR도 QT-B/168시간이 정해지지 않는다. QT-A/QT-C를 택하더라도 본인 결과 미확인과 내부 미종결 문제를 별도 해결해야 한다.

A는 내구 접수가 실제 존재할 때만 정의된다. 동기 M1에서 별도 A가 없으면 자원 created_at로 억지로 채우지 않는다. F의 사건/시각 권위도 r126/127에서 미결이다. 재조회·응답 재전달·새 로그인·담당 인계·새 동의·정책 이관으로 원래 A/F를 초기화하지 않는다.

## 목적별 의존 조건 — 숫자보다 먼저 정할 것

1. 약속한 LQ 유효 창 안에는 해당 결과를 판정할 최소 LR 근거가 이용 가능해야 한다. 전제가 같다면 결과용 기록을 조회 마감보다 먼저 자동 삭제하지 않는다. 보안상 계정 차단 등으로 접근이 먼저 종료될 수 있어도 보유 종료와 혼동하지 않는다.
2. QT-B라면 최종 확정 시점에 F+Q를 뒷받침할 기록이 필요하다. 미확정 조회 만료만으로 아직 실행 중인 업무의 결과 근거를 지워서는 안 된다. 반대로 최종이 안 났다는 이유로 무기한 보관을 허용하지 않는다.
3. LR 목적이 종료되면 정리 대상과 유한 LD 실행 마감을 정한다. 정책상 조회 종료와 실제 삭제 성공을 같은 타임스탬프로 표기하지 않는다. 정리 실패도 전체 완료로 표시하지 않는다.
4. LR 삭제 뒤에도 LK/LB의 필요한 보호를 유지하되 각각 유한 상한·퇴역 근거를 갖춘다. 보호 자료를 본인 화면의 장기 E 조회로 공개하거나 영구 복제하지 않는다.
5. LC가 먼저 정리돼도 서버 업무 효력은 유지된다. 참조 재발견 경로를 설계하지 않았다면 이름/시간 기반 전체 이력 조회로 임의 복구하지 않는다.
6. 기존 서비스/공통 탈퇴 삭제 계약과 겹치면 자료 목적·기여·최소 종료 이력을 분리한다. WR 조회 편의를 이유로 개인 소개 원문의 기존 삭제를 늦추지 않는다. 모든 관계를 한꺼번에 cascade 삭제하지도 않는다.

## 미확정 내부 종결과 예외

미확정 조회가 끝났는데 내부 실행/조사가 끝나지 않은 경우에는 실제 담당·대행·상향 전달·최대 확인/종결 조건·해결 불가 안내·기록 수명이 필요하다. 아직 숫자/담당/정정 권한을 선정하지 않았다. ‘확인 필요’라는 상태만으로 영구 보관하지 않는다. 현재 철회 효력과 과거 요청 결과의 확정 불명을 구분한다.

제한 예외는 정당한 특정 목적·대상/필드·적격 승인·유한 종료와 정리 근거가 필요하다. 지원 접수/이의 제기/재시도 자체로 모든 시계를 중단·연장하지 않는다. 예외 보유가 일반 본인 조회를 자동 연장하거나 이미 삭제된 명칭/원문을 복원하게 하지 않는다. 기존 COS 예외 규칙을 새 WR에 그대로 이식하지 않는다.
