## 현재 합의와 이번 범위

[REC-084](LEADER_INTRO_MINIMUM_RESULT_AGREED_HANDOFF.md)의 본인·특정 요청 결과 확인 권한은 유지한다. [r128 공개 상한 제안](LEADER_INTRO_RESULT_MISSING_VALUE_HANDLING_DRAFT.md)의 질문에는 아직 명시 답변이 없다. 이번 ‘진행해줘’는 공개 다섯 항목이나 새 정책의 동의로 기록하지 않는다. [r127 근거/시각 카드](LEADER_INTRO_MINIMUM_RESULT_FIELDS_TIME_CARD.md)를 바탕으로 값이 없을 때의 독립적인 실패 처리 초안만 정리한다.

## 응답을 해석하는 순서 후보

1. 현재 계정·목적·특정 요청 관계를 확인할 수 있는지 판단한다. 실패하면 보호 필드를 부분 노출하지 않는다.
2. 허용된 관계가 확인되면 해당 요청의 실제 결과 근거를 판정한다. 현재 자원 상태만으로 과거 결과를 구성하지 않는다.
3. 각 시각의 근거/의미를 따로 확인한다. 결과는 확정됐지만 특정 시각이 없을 수 있다.
4. 조회 계약·기산/기간이 있어 유효하게 결과 제공 가능한지 확인한다. 시각 값을 화면에 표시하지 못하는 것과 조회 기간 판정 자체가 불가능한 것은 다르다.
5. 앱은 그 응답의 계정·대상·요청·화면 세대가 아직 일치하는지 확인한 후 표시한다. 통신 실패·옛 응답을 업무 결과로 저장하지 않는다.

순서는 논리 검토용이다. 실제 권한 판정/기간 확인과 응답 사이 경합을 어떻게 제어할지는 기술 명세가 필요하다. 단계 숫자가 별도 네트워크 호출 다섯 번을 뜻하지 않는다.

## 사용자 행동과 복구

- ‘다시 확인’은 같은 요청의 허용된 조회다. 새 키·새 철회 의도·재게시를 만들지 않는다. 결과가 미확정이어도 무제한 자동 폴링을 기본값으로 두지 않는다.
- 최초 응답 전혀 없음은 I/K와 실제 서버 기록의 결속이 필요하다. 기기 참조가 없으면 이름·시각으로 최근 요청을 임의 선택하거나 전체 이력 목록을 새로 공개하지 않는다.
- 지원 요청은 실제 마련된 최소 자격/별도 지정·건별 배정을 따른다. 담당 공백을 대리 철회/원문·사진 복원으로 해결하지 않는다. 문의 자체가 조회/보유 시계를 연장하지 않는다.
- 로그아웃·계정 전환 뒤 옛 결과를 캐시/접근성 트리·오류 보고에 남기지 않도록 실제 기기 계약을 검증한다. 화면 캡처 방지나 기기 완전 삭제가 구현됐다고 약속하지 않는다.
- 현재 C1 철회 상태만 남은 경우와 이 요청의 F가 남은 경우를 구분한다. C2 새 동의는 C1 조회의 대체 대상이 아니다.
