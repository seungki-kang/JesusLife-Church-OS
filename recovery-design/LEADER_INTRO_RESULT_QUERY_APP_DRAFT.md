# 요청·후속 결과와 현재 공개의 앱 조회 계약 초안

2026-10-30 / r86 / TECHNICAL_UX_DRAFT / PARTIAL_RECOVERY / 실행 NOT_RUN

## 범위와 근거

직전 대화에서 환경 제약으로 미저장한 표를 [r85 재시도 동일성 후보](LEADER_INTRO_RETRY_IDENTITY_DRAFT.md)에 연결해 저장한다. [최소 API 후보](LEADER_INTRO_MINIMUM_API_CONTRACT_DRAFT.md), [기존 최소 조회 계약](COMMAND_IDEMPOTENCY_STATUS_CONTRACT_DRAFT_2026-10-27.md), [통합 상태표](LEADER_INTRO_STATE_RECONCILIATION.md), REC-026~032/068~075가 근거다. 후보B는 여전히 미선정이다. 아래 화면/응답 구성과 문구는 UX/TECHNICAL_DRAFT이며 신규 정책/조회기간/공개항목을 확정하지 않는다.

## 분리할 세 사실

| 사실 | 기준 | 혼동 금지 |
|---|---|---|
| 요청 결과 | 정확히 그 요청의 내구 확정 근거 | 앱 통신오류는 서버 실패가 아님 |
| 후속 결과 | 원 실패에서 정식 연결된 요청의 결과 | 연결 존재는 성공이 아니고 부모 실패를 덮어쓰지 않음 |
| 현재 공개 | 현재 동의/직함/대상/사진차단에 따라 허용된 공개본 | 과거 성공/사진 원본 존재는 현재공개 증거가 아님 |

세 사실을 한 화면에 놓는 후보는 가능하지만 서버 응답·권한·조회기간은 독립적으로 검증한다. 부모와 후속의 관계를 앱에 제공하는 자체가 기존 5항목 공개 합의를 자동 확장하지 않는다.

## 앱 표시와 행위 후보

| ID | 확인된 상황 | 문구 후보 | 허용/차단 |
|---|---|---|---|
| LQ01 | 송신 뒤 응답 못 받음 | 처리 결과를 확인하고 있습니다 | 기존 참조로 읽기조회·새 키/새 게시 자동생성 금지 |
| LQ02 | 해당 요청 성공 확인·현재상태 미조회 | 요청은 반영되었습니다. 현재 공개 상태를 확인해 주세요 | 현재 공개중이라고 단정하지 않음 |
| LQ03 | 과거 성공·현재 철회/직함종료로 비공개 확인 | 요청은 반영됐지만 현재는 비공개입니다 | 예전요청 재생으로 복구 금지 |
| LQ04 | 게시실패 확정·동의저장/동일조건 유효 | 게시되지 않았습니다 | 본인 공개반영 다시시도; 서버 현재조건 재검증 |
| LQ05 | 정식 후속 존재·현재 조회허용 확인 | 재시도 요청의 결과를 확인합니다 | 기존 후속을 조회; 다른 후속 자동생성 금지 |
| LQ06 | 결과조회 실패/404/기록없음/만료 | 이 요청의 결과를 확인할 수 없습니다 | 미처리/실패 단정금지·자동재실행 금지 |
| LQ07 | 현재공개만 조회 성공·요청결과는 미확인 | 현재 공개상태와 요청결과를 따로 안내 | 공개본 존재만으로 이번요청 성공 단정금지 |
| LQ08 | 다른 계정/교회로 전환·현재권한 상실 | 현재 계정·교회에서 확인할 수 있는 정보를 안내 | 이전응답/본문/참조 화면유출 차단·쓰기권한 자동부여 금지 |
| LQ09 | 사진만 차단 상태 | 사진은 비공개입니다 | 나머지 유효소개 유지; 전체소개 비공개와 구분 |

LQ05의 후속 발견/이동 UI는 공개관계 계약이 정해진 뒤에만 구현한다. 사용자에게 내부 key/세대/잠금 설명을 요구하지 않는다. 이 문구들은 법적 동의 전문이나 테스트 통과 화면이 아니다.

## 읽기 전용 계약과 공개 최소화

기존 합의의 본인 최소결과 다섯 의미는 확인ID·상태·실제접수시각·최종확정시각(존재시)·조회기한이다. 내부 부모참조/후속참조·멱등키·사진URL·원문·에러원문·동의세대/직함버전을 이 응답에 임의 추가하지 않는다. 상세 JSON명/HTTP 코드/경로는 미결이다.

현재 소개/사진 공개 조회는 별도 목적과 현재권한으로 검증한다. 그 응답도 초안/개인연락처/숨긴사진/다른제품 원문을 포함하지 않는다. 최소결과 조회가 가능하다고 공개본문/원본사진 조회가 허용되지는 않는다. 과거 업무역할 종료 후 본인 최소조회 합의와 현재 쓰기재시도 권한을 구분한다.

서버 확인ID를 못 받은 응답유실은 기존 [송신참조/확인ID 연결 초안](SUBMISSION_RECEIPT_BINDING_DRAFT.md)을 따른다. 읽기연결을 위해 쓰기를 재전송하지 않는다. key 자체를 공개 확인ID/접근권한으로 사용하지 않는다. 계정·선택교회·본인소속·해당범위·조회기한을 확인하고 참조의 추측가능성/타인존재 누출을 방지한다.

## 후속 연결 노출의 두 후보

| 후보 | 동작 | 남는 문제 |
|---|---|---|
| Q-A 각 요청의 5항목 조회와 기기 내부 연결 | 이미 안전하게 결속된 후속참조로 별도조회 | 첫응답 유실·다른기기에서는 후속발견 불가; 기기정보만으로 서버관계 증명 불가 |
| Q-B 서버의 본인전용 연결해결 응답 | 서버가 부모/정식후속을 검증해 현재허용 참조를 찾음 | 관계/참조 공개가 기존5항목/발견범위 합의에 미치는 영향·응답 최소화 추가 결정 필요 |

두 후보 모두 미선정이다. 기기 내부 연결을 현재 5항목 응답에 덧붙이는 방식으로 합의를 우회하지 않는다. Q-B의 권한·필드·존재비공개·수명 계약 없이는 원실패→후속 자동탐색을 운영기능으로 약속하지 않는다. 후보 선택 전에도 기존참조로 결과 확인을 우선하고 자동새후속 금지는 유지한다.

## 응답 순서/기기 전환 기술 후보

앱의 계정/교회/소개/조회요청 세대와 화면 생명주기를 결속해 늦게 도착한 다른 계정/교회 응답을 현재 화면에 적용하지 않는다. 같은범위 응답도 확인된 서버 버전/확정근거 없이 더 최신 상태라고 추정하지 않는다. 구성 변경/재시작 이후 최소참조 복구·기기참조 삭제기준은 기존 계약과 대조하며 서버상태 삭제로 간주하지 않는다.

두 별도 조회는 동일시점 스냅샷이 아닐 수 있다. 따라서 성공결과 조회 직후 철회가 일어나면 현재공개가 달라질 수 있음을 표현한다. 한 조회응답으로 모든 사실을 원자적으로 확정했다고 주장하지 않는다. 정렬/갱신세대·오류표시·접근성·화면캐시/서버최신성은 기술초안이다.

## 조회기간과 보유의 경계

일반업무 최소조회 합의는 미확정 실제접수+168시간·최종 실제확정+168시간이고 재조회/알림/조사담당변경/백업복원은 기산을 다시 시작하지 않는다. 소개 게시/사진/부모/후속 각각에 적용할 범위와 증거저장은 여전히 OPEN이다. 적용하기로 결정되더라도 부모와 후속은 각자의 사실에 근거해야 하며 후속생성으로 부모조회 창을 연장하지 않는다.

부모조회 불가·후속조회 가능 같은 조합은 후보 검토 시나리오이며 실제 기간 적용 합의가 아니다. 조회가 막혔다고 실패/미반영을 뜻하지 않으며 미확정조회 종료 뒤 늦은 최종확정의 새 조회창이라는 일반 합의를 임의 폐기하지 않는다. 24시간 성공재생·168시간 최소조회·실행가능기한·사진/동의증빙/기기/백업 보유는 서로 다르다. 새 숫자/물리삭제기간을 정하지 않는다.

## 인계 수용 조건

CA127: 원실패 보존·후속 조회와 현재공개 분리; 옛 성공응답이 늦게 도착해도 철회/사진차단 상태를 공개중으로 덮어쓰지 않음; 후속연결 존재를 성공으로 표시하지 않음.

CA128: 다른계정/교회로 전환한 뒤 지연응답·서버확인ID 없는 유실·404/만료/부모후속 부분조회 실패에서 자동새키/새후속/재게시 및 원문/관계누출이 없음. 구체 읽기연결/세대/접근성/조회기간 검증은 NOT_RUN이다.

## 미결과 다음 작업

후속 발견관계 응답 범위·REC-026 재시도의도 호환성·소개행위 조회기간 적용·끝내 미확인인 요청 수동확인 담당/권한·동의/게시 확정단위·미디어 전파는 미결이다. 후속 작업은 이 항목을 구현 전 선택표로 묶고, 기존 증거로 판단 가능한 것과 정책 답변이 필요한 것을 분리한다. 신규API/코드/운영검증 완료를 주장하지 않는다.
