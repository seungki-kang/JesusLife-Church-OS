## 읽기와 결정 권위

[r114 기간 후보와 RC01~05](LEADER_INTRO_POST_WITHDRAWAL_RETENTION_OPTIONS.md), [r115 사본 CP01~10·종결 FG01~06](LEADER_INTRO_COPY_CLEANUP_FINAL_GUARD_DRAFT.md), [r116 기술 GS01~05](LEADER_INTRO_BOUNDED_RESTORE_EXECUTION_OPTIONS.md), [r117 환경 EN01~09·시험 VT01~12](LEADER_INTRO_RESTORE_EVIDENCE_VERIFICATION_HANDOFF.md)를 하나의 결정 자료로 연결한다. 기존 [REC 결정](RECOVERY_DECISIONS.md)은 보존한다. 이 문서의 권고는 새 합의가 아니며 기간·담당·예외·기술 선정이나 시행을 승인하지 않는다.

대상은 **이미 철회 확정된 특정 소개 동의 세대**의 당시 명칭과 최소 철회 확인 증빙이다. 유효 동의·직함만 종료된 잔존 동의·계정/서비스 종료 이력·지원/감사·미확정 요청 전체에 확장하지 않는다. REC-076의 본인 철회, REC-079~081의 담당 제한, REC-082의 자료 분류를 다시 묻지 않는다.

## 결정·확인·검증은 서로 다른 일

- 정책: 무엇을 왜 얼마 동안 허용할지는 설계상 선택할 수 있다. 실제 지원 수요·최소성 근거 없이 숫자가 적정하다고 주장하지 않는다.
- 환경 사실: 실제 사본·지연 작업·복구 원천의 존재와 최대 수명은 문서 작성이나 사용자 동의로 사실이 되지 않는다. 범위가 확인된 메타 근거가 필요하다.
- 기술 계약: 시계·세대·권한·마감·삭제 결과를 어떻게 결속할지는 명세가 필요하다. 명세 합의가 구현·실환경 검증 완료를 뜻하지 않는다.

이번에 할 수 있는 것은 정책 선택지를 구체화하고 환경이 없어도 검토 가능한 논점을 분리하는 일이다. 실제 운영 자료 수집·시험·개발·파일럿은 수행하지 않는다.

## 기간 선택지와 권고의 한계

| 조합 | 당시 명칭 | 최소 철회 확인 | 결정에 필요한 설명 |
|---|---|---|---|
| R-A | T0+30일 | T0+30일 | 30일 이후 확인 한계를 수용할 수 있는가 |
| R-B 우선 검토 | T0+30일 | T0+90일 | 명칭이 없어진 뒤에도 최소 참조로 안전한 확인을 제공할 수 있는가 |
| R-C | T0+90일 | T0+180일 | 더 긴 관계 정보 보유가 필요한 구체 목적이 있는가 |

R-B는 먼저 명칭을 줄이는 비교안이다. 30/90일의 실증적 적정성·법적 충분성은 확인하지 않았다. 이 문서는 법률 판단 자료가 아니다. 긴 기간을 정한다고 지원/삭제 역량이 생기지 않으며 짧은 기간을 정해도 복원 안전성이 자동 확보되지 않는다.

정책 기간만 먼저 합의할 경우에도 상태는 ‘범위 한정 설계 합의, 시행 조건 미충족’이어야 한다. 유한 삭제 실행 마감·백업 상한·정리 실패 처리·기존 자료 정책이 없는 채로 완성된 보유정책이라고 표시하지 않는다. 이번에는 기간 합의나 새 REC를 만들지 않는다.

OPEN은 무기한 보관 허용값이나 0일 즉시 파기 명령이 아니다. 실제 시스템에 임의 기본값으로 넣지 않는다. 24시간 멱등 영수증과 168시간 상태 조회를 이 카드의 보유기간으로 대체하지 않는다. 기존 계정/서비스 탈퇴의 대상 개인 원문 7일 삭제와 해당 백업 30일 등은 각각의 기존 범위·기산을 따른다.

## 경계 예시 — 모두 합성 설계이며 실행하지 않음

1. T0가 확인된 C1 철회: R-B를 나중에 채택한다면 30일에 명칭 일반 접근 종료, 90일에 확인 증빙 목적 종료를 적용한다. 각 물리 삭제/백업 완료 시각은 별도 계약과 실제 결과로 판단한다. 해당 C1 게시 차단은 90일에 풀리지 않는다.
2. 29일에 추가 확인을 접수: 접수만으로 30/90일 시계를 다시 시작하지 않는다. 제한 예외가 별도 확정되지 않았다면 이름을 기한 뒤 계속 보관할 권한이 생기지 않는다. 남은 최소 근거로 가능한 안내와 불가 사유를 구분한다.
3. T0가 누락된 기존 자료: 다운로드·이관일을 새 T0로 만들지 않는다. 원래 근거 확인과 제한 접근·처리 책임·유한 정리 계획이 필요하다. 임의 즉시 전체 파기나 무기한 확인 대기를 결정하지 않는다.
4. 20일에 서비스 탈퇴: 철회 확인 후보 90일로 개인 소개 원문의 기존 7일 삭제를 늦추지 않는다. 최소 종료 이력과 소개 증빙이 각각 보유할 수 있는 필드를 분류하며 중복 보관을 자동 허용하지 않는다.
5. 95일에 옛 백업/큐가 발견됨: 지났다는 이유로 안전하다고 단정하지 않는다. 원래 상한·현재 근거·실행 차단을 검증하고 복원 공개를 보류한다. 발견/재복사 시각으로 백업 수명을 초기화하지 않는다.
6. C2 새 동의가 생김: C1의 기산/삭제를 연장하거나 C1 정리를 C2 삭제로 연결하지 않는다. 새 토큰·새 키만으로 C1의 옛 의도를 현재의 새 게시 의도로 보지 않는다.

기존 CA159~162와 VT01~12의 조건을 정책 선택과 대조한 예시이지 시험 실행 결과나 새 CA가 아니다.
