## 확정과 미결

| 항목 | 합의 범위 | 아직 미결 |
|---|---|---|
| 새 근거 | 새로운 검증 가능 근거를 개시 심사 사유로 인정 | 실제 출처·형식·검증 방법 |
| 판단 오류 | 명백한 판단 오류를 개시 심사 사유로 인정 | 오류 입증/정정 권한·판정 기준 |
| 절차 누락 | 필수 절차 누락을 개시 심사 사유로 인정 | 누락 확인 방법·별도 조치 |
| 반복 문의 | 같은 주장/근거만으로 자동 개시하지 않음 | 반복 제한·이의 안내·예외 |
| 개시 | 접수/사유 해당과 승인 구별 | 실제 승인 주체·기한·범위 |

심사 사유를 갖췄다는 사실이 철회 성공/실패나 재검토 승인 결과를 뜻하지 않는다. 원래 요청/동의 세대·본인 관계와 현재 권한을 검증해야 한다. 기존 종결을 지우거나 재검토로 새 철회 요청을 자동 실행하지 않는다.

## 개발 인계의 유지 조건

- 현재 적격 역할·건별 범위·충돌 검증 없이 근거 열람/판정하지 않는다.
- 원래 접수·최종 확정·조회 기산을 유지한다. 별도 유한 재검토 시간 계약은 OPEN이다.
- 실제 진행 중 실행이 발견되면 기존 조건에 따라 처리 책임으로 인계하고 확인 종결로 취소하지 않는다.
- 근거가 소실됐다는 이유로 원문/사진이나 만료 백업을 복원하지 않는다. 최소 근거가 부족하면 그 한계를 기록한다.
- 일반 조회 종료를 지원 안내나 재검토 화면으로 우회하지 않는다. 늦게 발견한 최종 결과도 원래 확정 시각을 사용한다.

위 조건은 실제 구현 완료나 운영 인력 확보를 뜻하지 않는다. CA144/159~162의 세부 인계를 유지하고 새 테스트 성공을 추가하지 않는다. 작업14/CA162/MVP34·18B/DG/FD/RV와 다른 MVP33행은 유지한다.

## 다음 설계

남은 담당/권한·시간·자료 수명 결정을 한 묶음의 개발 전 결정표로 정리한다. 각 항목에 필요한 사용자 정책 결정과 실제 운영 근거를 구별해, 같은 질문을 반복하거나 문서 추가만으로 개발 차단 조건이 해소됐다고 표시하지 않도록 한다. 이번 합의로 특정 운영 책임자·시간 숫자·기술을 선정하지 않았다.
