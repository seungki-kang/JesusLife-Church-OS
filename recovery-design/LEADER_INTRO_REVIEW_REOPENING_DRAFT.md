# 확인 업무 종결 후 재검토 — 근거·권한 초안

2026-10-31 / r141 / PROPOSED / PARTIAL_RECOVERY / 실제 실행 NOT_RUN

[REC-088](RECOVERY_DECISIONS.md#rec-088-결과-불명-시-확인-업무의-한정-종결)과 [합의 인계](LEADER_INTRO_INCONCLUSIVE_CLOSURE_AGREED_HANDOFF.md)를 이어간다. 확인 불가 종결 뒤, 같은 요청에 관한 새 근거 또는 검토 오류가 생긴 경우의 최소 절차를 제안한다. 재검토 허용 사유·권한을 이번 문서로 합의하지 않는다.

## 접수와 재검토 개시를 구별

문의 접수는 재검토 승인이나 새 철회 실행이 아니다. 현재 본인 관계를 확인하고 기존 요청·동의 세대·종결 건과 결속한 뒤, 추가 확인의 필요를 판단한다. 접수 번호나 제출자가 알고 있는 요청 번호만으로 존재/내용을 공개하지 않는다. 지원 담당의 기존 지정·건별 범위는 기술 근거 열람이나 종결 정정 권한으로 자동 확대되지 않는다.

| 사유 후보 | 필요한 최소 설명/근거 | 판정 경계 |
|---|---|---|
| RR01 새로운 검증 가능 근거 | 기존 조사에서 확인하지 못한 특정 요청의 서버 결과 참조·검증 가능한 출처/사건 | 나중에 발급한 문의번호나 현재 소개 상태만으로 과거 성공을 입증하지 않음 |
| RR02 기존 판단의 명백한 오류 | 잘못 연결한 요청/세대·판독 오류·근거와 결론의 불일치 위치 | 오류가 있다는 주장만으로 업무 결과를 덮어쓰지 않음 |
| RR03 필수 절차 누락 | RR01~05 중 누락 조건과 확인 가능한 관련 참조 | 당시 적격성/실행 보호 누락은 별도 점검; 누락 발견 자체가 철회 실패는 아님 |
| RR04 동일 주장·같은 근거 반복 | 기존 확인 건과 동일성 | 기존 건에 연결하고 차이를 안내; 새 실행·새 조사 시계 자동 생성 금지 |
| RR05 본인/요청 관계 미확인 | 제한된 관계 확인에 필요한 최소 정보 | 타인 요청 존재 비공개; 포괄 검색/원문 복원으로 해결하지 않음 |

RR01~03은 개시 심사 후보이며 자동 개시/승인 목록이 아니다. 근거 파일을 무조건 업로드하도록 요구하지 않는다. 요청 원문·소개 사진·토큰·전체 로그·다른 제품 개인 기록 대신 목적에 필요한 참조와 설명을 우선한다. 첨부 도입 여부·허용 형식·악성 파일 처리·보유는 별도 계약이다. 이미 삭제한 원문이나 만료한 백업을 재검토 때문에 복원하지 않는다.

## 역할·허용 행위

| 논리 역할 | 허용할 업무 후보 | 별도 권한이 필요한 행위 |
|---|---|---|
| 접수/분류 | 현재 본인·건 관계 검증과 차이 분류 | 전체 운영 기록 검색, 재검토 승인 |
| 개시 판정 | 사유·범위·근거 접근·유한 종료 조건 확인 | 실제 철회/직접 DB 수정 |
| 근거 확인 | 승인된 범위의 검증·기존 판단과 대조 | 원문/사진 수집, 타제품 접근 |
| 종결 검토 | 결과 근거 또는 미입증 한계와 정정 관계 판정 | 새 동의 세대 변경, 조회 창 임의 연장 |

실제 담당/겸임/독립 검토와 권한은 OPEN이다. 자기선임·자기배정·이해충돌 자기승인 금지를 유지한다. 원래 판단에 직접 관여한 사람의 충돌 검사는 후보 기준이며 일률 겸임 금지를 이번 초안으로 확정하지 않는다. 담당 회수/부재는 현재 적격자에게 최소 인계하되 기산과 기존 종결 기록을 보존한다. 적격자가 없으면 운영 차단 조건으로 남기고 임의 권한을 부여하지 않는다.

## 개시→확인→종결

1. 원래 요청/세대·확인 종결 건과 연결하고 기존 정보에 없는 차이를 최소 기록한다.
2. 현재 적격 역할이 개시 사유·한정 과제·접근 범위·유한 검토/예외 조건을 판단한다. 접수만으로 개시 상태가 되지 않는다.
3. 허용 근거를 대조한다. 진행 중 실행이 드러나면 유한 처리 책임으로 인계하며 조사 종결로 취소하지 않는다.
4. 실제 최종 결과를 검증했으면 검증된 결과와 원래 확정 시각을 연결한다. 여전히 미입증이면 RR01~05 충족 여부를 다시 확인한 뒤 확인 업무 종결 후보로 둔다.
5. 과거 종결을 덮어쓰지 않고 새 근거·판단·관계를 최소 정정 이력으로 연결한다. 잘못된 개인정보의 표시/삭제 처리와 필요한 최소 정정 이력의 보존은 각각 계약을 정한다. 원래 오류가 있었다고 원문을 영구 보관하지 않는다.

이 단계들은 논리 흐름이며 API/테이블 이름이나 실제 운영 기능 구현이 아니다. 여러 담당이 동시에 재검토/종결하면 검토 중인 건의 버전과 현재 권한을 서버에서 다시 검증하고 상충 덮어쓰기를 차단하도록 인계한다. 특정 잠금 방식이나 정정 명령은 선정하지 않았다.

## 시간·안내·자료 경계

원래 접수·확정·조회 기산은 그대로 둔다. 승인된 재검토 작업에는 구별되는 개시 사건과 유한 기한이 필요하지만, 이것을 원래 조사 상한을 반복 초기화하는 수단으로 삼지 않는다. 인정 사유·원래 건과 누적 상한의 관계·반복 신청 처리·예외 승인·기록 수명은 OPEN이며 무기한을 기본값으로 채우지 않는다. 기존24시간/168시간을 자동 적용하지 않는다.

REC-087에 따른 일반 조회의 재표시는 실제 최종 근거와 유효한 최종 창이 있을 때만 현재 본인 권한을 검증한다. 최종 결과를 늦게 발견했다고 발견 시각으로 새 창을 열지 않는다. 재검토 접수/개시 안내는 일반 조회 재개와 구별하며 안내 경로·필드·기간·통지 실패 처리는 별도 결정한다. 계정 정지/탈퇴의 예외를 새로 허용하지 않는다.

## 검증 인계

| 조건 | 금지할 결과 |
|---|---|
| 동일 근거 반복/새 접수번호 | 무제한 조사 연장·원래 시각 초기화 |
| 새 서버 근거·현재 자원 상태만 잔존 | 서로를 같은 증거로 처리 |
| 요청/세대 착오·타인 번호 | 타인 존재 공개·다른 동의 정정 |
| 담당 회수·이해충돌·동시 판정 | 과거 권한 유지·자기승인·상충 덮어쓰기 |
| 늦은 최종 발견·조회 창 만료 | 발견 시각으로 조회 기산 변경 |
| 자료 만료·백업 잔존 | 조사 목적의 원문 복구·무기한 보유 |
| 실제 실행 진행 확인 | 조사 종결을 업무 취소/재실행 허용으로 처리 |

기존 CA144/159~162의 세부 인계이고 새 CA/테스트 성공을 추가하지 않는다. 전부 NOT_RUN. 기존 COS·REC001~088·정본·과거 자료·작업14/CA162/MVP34 보존. 코드·DB·GitHub 변경 없음.

다음 좁은 결정은 **새로운 검증 가능 근거·명백한 판단 오류·필수 절차 누락을 재검토 개시 심사 사유로 두고, 동일 주장 반복만으로 자동 개시하지 않는 원칙**이다. 실제 개시 권한·기한·반복 제한·기술은 별도 결정한다.
