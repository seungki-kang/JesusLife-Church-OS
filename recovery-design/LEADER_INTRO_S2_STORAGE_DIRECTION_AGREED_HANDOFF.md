# S2 최소 결과 저장 방향 확정과 후속 인계

2026-11-01 / r165 / AGREED_SCOPED / DESIGN_DIRECTION / PARTIAL_RECOVERY

## 확정 범위

사용자의 r164 질문에 대한 ‘네’를 근거로 REC-097을 기록했다. 새 본인 소개 철회 최소 결과는 기존 일반 API 영수증과 별도 목적의 저장 단위로 둔다. 한 실행 경로에서 효력 변경 또는 무변경 판정, 필요한 의도 결속, 최소 결과와 감사를 하나의 동기 원자 경계로 확정하는 방향이다.

별도 단위는 별도 서버·DB·큐·두 번째 실행기를 뜻하지 않는다. 두 저장 기록이 각각 성공을 판정하는 이중 정본을 만들지 않는다. 기존 일반 API의 계약·코드·마이그레이션은 이번 작업에서 변경하지 않았다. 기존 24시간을 새 결과 보유기간으로 승계하지 않는다.

[REC-097](RECOVERY_DECISIONS.md#rec-097-s2-별도-목적-최소-결과-저장-방향), [원래 비교 자료](LEADER_INTRO_RESULT_STORAGE_OPTIONS_RECOMMENDATION.md), [통합 인계 판정](LEADER_INTRO_INTEGRATED_REVIEW_4_HANDOFF_VERDICT.md)을 함께 읽는다.

## 미결 조건과 검증 인계

| 묶음 | 남은 설계 | 실제 검증 |
|---|---|---|
| P1 | 현재 본인 자격·정확한 세대·제한 계정·권한 회수 경합 | NOT_RUN |
| P2 | 물리 테이블·결속 제약·잠금 순서·API 스키마·감사 실패와 최초 응답 유실 처리 | NOT_RUN |
| P3 | 접수/최종 사건·조회 및 목적별 보유·기기 정리·삭제와 백업 | NOT_RUN |
| P4 | 기록 정리 후 옛 요청 재생·복원·유한 보호 종료와 실제 DB 계보 | NOT_RUN |
| P5 | 담당자 자격·위임·충돌·확인불가 종결과 재검토 | NOT_RUN |

P1/P2가 완료됐다는 뜻이 아니다. 실제 DDL·권한 부여·보유 숫자·복원 보호 방식·코드 착수는 승인하지 않았다. 추가 DB 도입이나 다른 제품 자료의 중앙 수집도 승인하지 않았다. 기존 18B/DG/FD/RV는 닫지 않는다.

다음은 P3의 시간·보유 기준을 통합 대조한다. M1에는 별도 내구 접수 사건이 없을 수 있으므로 도착 시각을 접수 시각으로 꾸미지 않는다. 최종 결과 조회, 오류 기록, 감사, 문의, 재생 보호와 백업의 목적을 분리한다. r158의 숫자는 여전히 미합의 후보이며 다음 검토에서 비교 후 결정할 사항이다.

정적 문서·참조·CSV·해시·ZIP 검증만 수행한다. 실제 앱/API/DB/SSO·삭제·복원 검증은 NOT_RUN. 기존 원본과 누적 기록을 보존한다.
