# 리더 소개 통합 상태표와 개발 전 미결

2026-10-30 / r83 / DESIGN_RECONCILIATION / PARTIAL_RECOVERY

## 범위와 읽는 법

근거는 [복원 결정 REC-060~075](RECOVERY_DECISIONS.md), [공동체 계약](COMMUNITY_LIFECYCLE_CONTRACT_DRAFT.md), [선택 항목 대조](LEADER_INTRO_OPTIONAL_FIELDS_ALIGNMENT.md), CM10 및 CA87~120이다. 결정 원문을 덮어쓰지 않는다. 아래는 기존 합의를 함께 적용한 정리이며 새로운 상태 enum/API/운영 권한의 확정이 아니다. 실제 화면/API/DB/경합 검증은 NOT_RUN이다.

## 독립적으로 보아야 할 상태

| 축 | 구분해야 할 사실 | 혼동하면 생기는 오류 |
|---|---|---|
| 편집 초안 | 저장한 내용/사진 참조와 본인이 확인한 버전 | 저장을 게시 성공으로 표시 |
| 공개본 | 실제 반영 버전과 현재 허용되는 공개 필드 | 미게시 초안/차단된 사진 노출 |
| 소개 동의 | 현재 유효 여부·범위·철회 이후 새 동의 | 옛 동의/영수증으로 재공개 |
| 직함/자격 | 실제 현재 지정과 소속/참여·본인 권한 | 종료 직함을 소개 문구로 복구 |
| 사진 공개 | 미선택/비공개/본인 확인 후 공개·파일 존재는 별개 | 원본 존재를 사진공개 허가로 사용 |
| 실행/인지 | 서버의 확정 결과와 앱의 결과 미확인 | 통신 오류를 확정 실패로 단정 |
| 열람 대상 | 현재 유효 참여자와 대상 정책 | 교회전체/인터넷/다른 공동체 자동 확대 |

하나의 ‘공개/비공개’ 값만으로 모든 축을 대신하지 않는 기술 모델이 필요하다. 이것은 구현 후보이며 DB 컬럼 설계 완료가 아니다. 아래 유지/중단은 현재 서버 유효 조건 기준이며 캐시/외부 사본 즉시 회수의 보장이 아니다.

## 통합 전이표

모든 행은 본인·교회·공동체 경계 및 현재 권한을 전제로 한다. 관리자 업무상 검토 권한은 별도이며 자동 획득하지 않는다.

| ID | 시작/행위 | 일반 참여자에게 보이는 결과 | 재확인/실패 처리 | 근거 | 검증 조건 |
|---|---|---|---|---|---|
| LI01 | 비공개에서 편집/저장 | 자동 공개 없음 | 초안과 공개본 구분 | REC-062/065/066 | CA91/97~100 |
| LI02 | 유효 공개본을 편집 | 새 게시 전 기존 유효본 유지 | 초안 필드/사진 먼저 노출 금지 | REC-067 | CA101/102 |
| LI03 | 미리보기 후 내용/대상/직함 변경 | 구확인으로 새 게시 금지 | 최신 재확인; 기존본도 현재조건 유지 | REC-068 | CA103/104 |
| LI04 | 본인 명시적 공개 반영 | 현재 조건을 만족해 확정된 버전만 공개 | 현재 동의/직함/버전 검증 방식은 기술초안 | REC-066/068/069 | CA99/103~106 |
| LI05 | 전체 소개 동의 철회 확정 | 해당 소개 전체 중단 | 직함/업무권한 자동해제 아님 | REC-063/069 | CA93/94/105/106 |
| LI06 | 직함 종료/재지정 | 종료면 현재소개 중단; 재지정만으로 복구 없음 | 본인 재확인; 철회도 있었다면 새동의 필요 | REC-064/071 | CA95/96/109 |
| LI07 | 게시와 철회 경합 | 게시 먼저라도 후속철회시 중단; 철회 먼저면 옛게시 차단 | 버튼/도착순서 아닌 서버 유효확정; 원자성 미검증 | REC-069 | CA105/106 |
| LI08 | 게시 응답 유실 | 과거 결과와 현재 공개를 구분 | 미확인 안내·기존요청/현재상태 조회·자동재게시 금지 | REC-070 | CA107/108 |
| LI09 | 철회 후 다시공개 | 본인 최신확인/새동의/명시반영 후에만 공개 | 단일화면·확인란·결합버튼; 옛요청 자동재개 금지 | REC-071/072 | CA109~112 |
| LI10 | 동의저장 후 게시실패 확정 | 미게시; 다른 유효본은 기존규칙 적용 | 동일유효조건이면 재동의 반복없이 본인 명시 재시도 | REC-073 | CA113/114 |
| LI11 | 사진/짧은소개 미선택 | 동의한 기본 이름/현재직함으로 게시 가능 | 타프로필 자동채움/선택항목 강제 금지 | REC-062 | CA91/115/116 |
| LI12 | 본인이 사진만 비공개 확정 | 사진 중단·나머지 유효소개 유지 | 전체철회/직함종료면 전체중단; 원본삭제 별도 | REC-074 | CA117/118 |
| LI13 | 비공개 사진 다시공개 | 본인 사진/대상 재확인·사진공개반영 후 공개 | 전체소개 동의/직함 유효·옛사진 요청 자동복원 금지 | REC-075 | CA119/120 |
| LI14 | 관리자 수정 제안 도착 | 기존 공개상태 자동변경 없음 | 직접덮어쓰기/자동적용/대신동의 금지 | REC-065 | CA97/98 |

전이의 서버 원자성/실제 허용 상태 조합을 검증한 표가 아니다. CA121/122는 이 전이를 연속 수행할 때 정책이 충돌하지 않는지 확인할 인계 조건이며 실제 실행은 하지 않았다.

## 중복 규칙의 적용 순서와 후속 해소

| 과거 미결/겹쳐 보이는 규칙 | 현재 적용할 해석 | 남는 미결 |
|---|---|---|
| REC-066 편집중 기존본 유지 미결 | REC-067로 유효 기존본 유지; REC-074로 비공개 사진은 제외 | 스냅샷/사진 참조/원자적 교체 |
| REC-068/069 재동의 UX 미결 | REC-071/072 최신확인·새동의·결합화면으로 한정 해소 | 문구/기본선택/접근성/증빙 |
| REC-072 부분실패 재시도 미결 | REC-073의 확정실패·동일유효조건에만 재동의 생략 | 실패분류/실행키/멱등 최종성 |
| REC-074 사진재공개 미결 | REC-075의 본인확인·명시반영; 옛요청 자동복원 금지 | 사진별 동의문구/재시도/API |
| 기존본 유지와 전체철회/직함종료 | 전체 중단 사유가 있으면 기존본 유지로 우회 금지 | 캐시/미디어 전파 및 경합 보장 |
| 과거 성공과 현재 비공개 | 과거 성공 취소로 덮어쓰지 않고 현재 공개상태 별도 확인 | 최소 결과필드/조회수명/현재버전 대응 |

과거 결정의 OPEN 문장은 당시 기록으로 보존한다. 현재 미결 판단은 이 표와 후속 REC를 함께 읽는다. 문서 통합을 이유로 기존 결정 ID를 삭제/병합하거나 새 합의를 만들어내지 않았다.

미결은 구현으로 해결됐다고 보고하지 않는다. 소개만으로 전체 기본 MVP 개발준비가 완료됐다는 판정도 하지 않는다. 개인기도/일기/관계 원문·타제품 완료상태는 이 흐름에 새로 도입하지 않는다.

## 다음 작업

새 질문을 늘리기 전에 LT01~LT04를 기존 멱등/조회 설계와 대조해 최소 기술 계약 후보를 작성한다. 업무 상태와 앱의 인지 상태를 분리하고, 필요한 정책 선택만 OPEN으로 제시한다. 코딩·파일럿·원격 변경은 수행하지 않는다.
