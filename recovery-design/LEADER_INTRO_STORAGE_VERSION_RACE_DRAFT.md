# 저장 경계·참조키·버전·동시 요청 계약 후보

2026-10-30 / r90 / TECHNICAL_DRAFT / PARTIAL_RECOVERY / 실행 NOT_RUN

## 범위와 가정

[r89 확정방식 비교](LEADER_INTRO_COMMIT_OPTION_RECOMMENDATION_DRAFT.md)의 조건부 C-A와 CG01/CG02를 [r88 모델/실패표](LEADER_INTRO_MODEL_COMMIT_FAILURE_DRAFT.md)에 연결한다. [최소 API 후보](LEADER_INTRO_MINIMUM_API_CONTRACT_DRAFT.md)의 LA01~09에 공통 적용할 후보이며 실제 DB/DDL/API 변경이 아니다. C-B와 재시도 의도/키 계약은 미선정 상태를 유지한다.

소개 정본/동의/사진공개제어/최소감사·영수증·결과를 같은 ChurchOS PostgreSQL 확정경계에서 처리할 수 있다는 가정 아래 작성했다. 실제 저장소 배치와 기존 지정/소속 변경경로가 이 경계를 준수한다는 증거는 아직 없다. 외부 인증 Core/다른 제품/파일저장소를 같은 DB로 옮기는 제안이 아니다.

## 저장영역과 성공확정 범위

| 영역 | 논리 기록 후보 | 성공확정 시 포함할 것 | 경계 밖/남은 것 |
|---|---|---|---|
| 교회 업무정본 | IntroScope·DraftVersion·PublicationVersion | 현재범위/권한·공개할 참조의 조건부 변경 | 실제 지정/소속 원본과 공통 경합검사 연결 필요 |
| 소개 공개제어 | ConsentState·PhotoVisibility | 유효동의/철회/사진차단 세대와 허용버전 | 동의문구/증거필드/보유 OPEN |
| 처리근거 | 최소감사·기존멱등영수증·RequestResult | 업무 성공과 같은 확정 의미의 결과/참조 | 내구접수 TxA 및 확정시각 증거 미선정 |
| 외부파일/배포 | 사진원본/파생/URL/CDN·앱캐시 | DB에는 허용된 최소참조/차단근거 후보 | 실제파일 삭제·기존URL 회수·캐시전파는 DB와 원자적이지 않음 |
| 외부계정 | 공통인증 정지/탈퇴·토큰상태 | 현재 인증계약의 검증결과/최신성 조건 | 로컬트랜잭션만으로 외부정지 동시성 보장 불가 |

사진 업로드가 끝났다는 이유로 게시 성공을 확정하지 않는다. 반대로 DB게시 확정 뒤 캐시전파가 실패했다고 과거 DB성공을 롤백으로 기록하지 않는다. 외부효과의 차단/재전파/운영대응 계약은 별도 미결이다.

## 참조키와 최소 유일성 후보

| 결속 | 후보 제약의 의미 | 주의 |
|---|---|---|
| 소개→공동체/본인소속/지정 | tenant가 일치하는 참조와 실제 소속/지정의 관계 검증 | 단순 UUID 존재/FK만으로 본인·현재유효 관계 증명 불가 |
| 초안/공개본→소개 | intro_ref와 tenant 결속·내용버전별 참조 | 한소개 초안을 다른공동체 공개본에 연결 금지 |
| 동의→소개/대상범위 | 본인/범위·동의세대 결속 | 같은사람의 다른제품/교회 동의를 대체 사용 금지 |
| 사진공개제어→소개/사진참조 | 사진 현재상태/세대·본인확인 참조 | 미디어공유 참조의 존재와 해당소개 공개허가 구분 |
| 영수증→행위/범위 | 기존 tenant+검증actor+route_key+key 유지 | 다른경로를 전역키로 합치지 않음·원문/키 공개 금지 |
| 후보후속→부모실패 | 같은범위·정식직계후속 유일연결 | LD03 미선정이며 전체재시도 횟수1회 정책 아님 |

실제 복합FK/unique 인덱스/정본ID 연속성·기존 스키마 계보 호환은 후속 DDL 전 검토한다. 참조키를 설계했다고 기존 RLS가 필드별/공동체별 접근까지 보장하는 것은 아니다.

## 확인 버전 묶음 후보

확인묶음은 초안 내용버전·공개대상 정책버전·실제지정 참조/버전·동의세대·사진공개세대 및 정확한 소개범위를 결속하는 서버 검증용 참조 후보다. 클라이언트가 보낸 ‘검증완료’ 값은 신뢰하지 않는다. 결속 위변조/만료·표시이름 정본의 변경 버전은 OPEN이다.

초안 내용과 공개제어는 독립 축이다. 사진만 비공개로 전환됐을 때 초안 내용이 같더라도 이전 사진공개세대에 기대어 게시하지 않는다. 전체철회/직함종료 후 내용버전이 같다는 이유로 재공개하지 않는다. 명단 구성원 자연변동과 대상 정책변경의 감지단위는 아직 미결이며 현재열람자 자격은 매번 검증한다.

## 공통 충돌순서 후보

여러 행위를 임의로 별도 락 체계에서 실행하면 검증 후 철회/직함종료가 끼어드는 문제가 생긴다. 후보 S는 권한/공개에 영향을 주는 행위가 공유하는 잠금/조건부쓰기 규칙을 설계하는 방식이다. 다음은 검토용 순서이며 실행검증된 deadlock-free 순서가 아니다.

1. 인증/선택교회·입력 최소검증 후, 기존 actor+tenant+route+key의 동일성 직렬화를 검토한다. 입력다름은 충돌, 기존성공은 현재권한/기존재생계약에 따라 결과 확인과 구분한다.
2. 권한/공개에 영향을 주는 공통 원본을 전역적으로 정한 순서로 보호한다. 후보 순서는 교회/해당소속→해당지정→소개제어→내용버전→감사/영수증/결과다. 각 행위의 필요한 보호집합과 기존경로의 선취잠금을 조사해야 한다.
3. 잠금 대기 뒤 현재 소속/지정·동의/사진세대·확인내용/대상을 다시 판정한다. 요청접수/미리보기 당시 검증을 현재검증으로 대체하지 않는다.
4. 기대버전/세대가 맞을 때만 해당 행위의 쓰기와 최소감사/영수증/결과를 같은 업무확정 경계에 결속한다. 구실행자는 같은 조건을 통과하지 못하도록 한다.
5. 실제 확정 결과가 확인된 뒤 응답한다. COMMIT불명은 미확정/결과조회이며 실패로 단정하지 않는다. 외부 알림/파일/캐시 효과는 커밋전 성공처럼 발행하지 않는다.

락 종류/공유·배타 모드/키 범위·조건부쓰기·교착감지/재시도 정책은 미선정이다. 모든쓰기를 같은 큰락으로 영구직렬화하라는 확정안이 아니다. tenant/소속/지정 변경자와 소개작성자가 서로 다른 actor/route/key를 써도 같은 관련상태를 보호해야 하므로 멱등락만으로는 부족하다.

## 반드시 함께 대조할 변경경로

LA01 초안수정, LA03/05 소개게시/새동의게시, LA04 전체철회, LA06 사진차단, LA07 사진재공개 외에 소속상실/정지·직함종료/재지정·대상정책변경·복원/수동수정 경로를 포함한다. 이 중 하나가 공통 규칙을 우회하면 게시전 검사만으로 정책을 보장하지 못한다. 관리자 임의 DB수정 권한이나 공개제어 우회권을 이번 문서로 추가하지 않는다.

## 남은 핵심 한계

트랜잭션 시작 now()로 마지막 권한검사/커밋 사이 만료를 해결하지 않는다. 현재시각 검사만 했다고 자연만료 순간의 확정경계가 증명되지 않는다. 서버 실제확정시각 증거와 만료차단의 일관성은 아직 OPEN이다. 외부계정 상태 확인 직후 정지되는 경합도 로컬락으로 해결됐다고 주장하지 않는다.

내부세대/차단기록 물리삭제 및 백업복원으로 구확인이 다시 유효해지는 문제를 막아야 하지만 세대기록 영구보유를 승인하지 않는다. 최소증거/보유·삭제후중복차단은 LD05/06과 연결한다. 일반7일/30일/1년 자동적용이나 최소결과5항목 추가공개를 하지 않는다.

## 검증 인계와 후속

CA133은 동일교회참조/다른actor·route의 게시·철회·직함종료/사진차단 보호집합 일치를, CA134는 구버전/외부정지·자연만료/교착·복원에서 허위성공/자동재실행이 없는지를 검증할 조건이다. 실제 테스트가 아니며 NOT_RUN이다.

CG01/02는 후보문서가 추가됐지만 저장경계 입증/전경로조사/실패주입 검증은 미완료다. 다음은 후보 S가 기존코드의 어느 쓰기경로와 연결돼야 하는지 구현대조표를 만들고 누락된 변경경로/권한을 추적한다. 새운영정책/기술선정/DDL/코드/GitHub 변경은 없다.
