# 소개 철회 추가 확인 담당의 선임·배정·권한회수 초안

2026-10-30 / r102 / POLICY_PROPOSAL + TECHNICAL_DRAFT / PARTIAL_RECOVERY / 실행 NOT_RUN

## 목적과 기존 경계

[REC-076~078](RECOVERY_DECISIONS.md#rec-076-종료-후-본인-소개-동의-철회), [추가 확인 NC01~05](LEADER_INTRO_NAME_CHANGE_DISAMBIGUATION_DRAFT.md), [변경 명령 계약](LEADER_INTRO_COMMAND_END_TO_END_CONTRACT_DRAFT.md), [DG04/05·FD02/05](LEADER_INTRO_STAGE_GATE_CLASSIFICATION.md)을 따른다. 담당은 철회를 허가하는 심사자가 아니라 모호한 본인 대상의 정본 관계를 확인하는 사람이다. 본인이 대상을 식별할 수 있는 일반 철회는 이 절차를 거치지 않는다.

이번 문서는 담당 체계를 제안한다. 기존 교회 가입 승인 담당·공동체 위임 담당의 소속/수락/기간 규칙을 플랫폼 담당에게 그대로 이식하지 않는다. 운영 주체·실제 담당자·정본 조회 API·런타임 권한은 아직 확인/구현하지 않았다. 새 REC 합의 없이 실제 열람권을 부여하지 않는다.

## 권장 조직안 S-A

ChurchOS 운영 주체가 이 업무용으로 별도 지정한 확인 담당 후보군을 두고, 유효한 후보 중 특정 접수 건에 배정된 담당자만 필요한 최소 참조를 확인하는 안이다. 교회 관리자·목회자·가입 승인 담당·일반 고객 상담원·공통 인증 보안 담당이라는 직함만으로 이 권한을 얻지 않는다. 운영 담당도 다른 제품 개인 원문이나 공통 계정의 모든 이용 내역을 볼 수 없다.

| 역할 후보 | 허용 업무 | 제한 |
|---|---|---|
| 본인 | 최소 대상 선택·추가 확인 요청·설명 확인·명시 철회 | 타인 동의/다른 제품 관계 접근 없음 |
| 선임/권한 관리 책임자 | 자격 확인·업무범위 지정·회수·배정 책임 관리 | 이 역할만으로 접수 상세/원문/동의 변경 접근 없음 |
| 배정 조정 담당 | 최소 접수 메타로 적격자 배정/인계 | 대상 명칭/동의 이력 전체를 볼 필요 없음; 임의 자격 선임 불가 |
| 건별 확인 담당 | 배정 건의 본인-대상·명칭 관계 확인·최소 설명 제공 | 대신 철회·동의/소속 정정·계정 연결/복구·원문/사진 열람 불가 |
| 별도 예외 책임자 | 인력 부재/근거 부족/이해충돌의 최소 조정 | 근거 없이 본인·대상 확정하거나 삭제자료 복원 불가 |

이는 논리 책임 분리다. 모든 역할을 서로 다른 사람으로 구성한다는 결정을 추가하지 않는다. 겸임·자기 선임·자기 배정·본인/밀접 관련 건 처리·승인 분리는 별도 이해충돌 정책으로 정한다. 특히 선임/배정/감사 기능을 가진 사람이 실무 상세 접근까지 자동 획득하는 구조로 만들지 않는다. 소수 운영 인력이라는 이유로 무제한 통합 권한을 기본값으로 주지 않는다.

## 선임과 접근 조건

| 단계 | 명시할 계약 후보 | 완료 전 경계 |
|---|---|---|
| SP01 후보 자격 | 현재 유효 운영자 신원·업무관계·보호교육·비밀유지/최소접근 책임 확인 | 단순 관리자 플래그로 자격 취득 금지 |
| SP02 선임 | 허용 업무/필드·유효 시작/종료·선임 책임·철회/인계 규칙 기록 | 기간·범위 없는 포괄 지정 금지 |
| SP03 수락/활성 | 업무범위 확인 및 명시 수락 후보, 유효 인증/자격 확인 | 수락 기한/실제 임기 미결; 교회 담당의 168시간/1년 자동 적용 금지 |
| SP04 건별 배정 | 유효 후보 중 해당 건 배정·이해충돌 확인·대행 범위 명시 | 후보군 자격만으로 미배정 건 열람 불가 |
| SP05 매 접근 | 현재 인증·선임·배정·목적·건 상태·필드 권한 재검증 | 과거 로그인/과거 배정/클라이언트 필터에 의존 안 함 |
| SP06 종료/회수 | 자격·배정·접근 상태 차단, 필요한 미종결 건 별도 인계 | 재선임/복귀 시 옛 건 접근 자동 복원 금지 |

선임 기록과 건별 배정은 서로 다르다. 배정만으로 선임 기간을 늘리거나 건이 미종결이라는 이유로 종료된 자격을 유지하지 않는다. 선임 수락·임기·대행의 정확한 자격/기간/책임자는 후속 미결이다. S-A 선택을 이 세부 모두의 일괄 승인으로 해석하지 않는다.

## 최소 열람 행렬 — 후보

| 정보/행위 | 배정 조정 담당 | 해당 건 확인 담당 | 본인 화면 |
|---|---|---|---|
| 접수 참조·정형 사유·진행 상태·배정 가능 여부 | 업무상 필요한 최소 | 배정 건 | 본인 접수의 허용 상태 계약 필요 |
| 본인-소개-동의 소유 결속 | 판정 상세 불필요 | 필요한 참조·검증 결과만 | 타인 관계 미공개 |
| 해당 교회/공동체·동의 범위/상태 | 기본 상세 접근 없음 | 관계 확인에 필요한 최소 | REC-077 항목만 |
| 적법한 동의 당시 명칭·동일 정본 개명 관계 | 기본 상세 접근 없음 | 그 건 확인에 필요한 최소 | REC-078에 따른 당시 이름; 현재명칭 병기 미결 |
| 동의 시각/버전·최소 증거 참조 | 기본 상세 접근 없음 | 필요성 검토 후 필드별 허용 후보 | 새 공개 항목으로 자동 추가 안 함 |
| 소개 원문·사진·연락처·다른 교인 명단·정지/징계 사유 | 불허 | 불허 | 불허 |
| 다른 제품 일기/기도/관계/코칭·SSO 전체 내역 | 불허 | 불허 | 이 절차에서는 불허 |
| 대신 철회·게시·소속/역할 변경·계정 병합 | 불허 | 불허 | 본인 명시 철회만 기존 계약 |

원시 테이블 전체 SELECT나 DB 소유자/BYPASSRLS 역할을 지원 담당에게 주지 않는다. 기존 테넌트 RLS만으로 건별 목적/필드 보호가 된다고 주장하지 않는다. 서비스가 허용 필드로 투영하고 서버에서 자격·배정을 검증하는 기술 계약이 필요하다. 참조에 해시/불투명 ID를 썼다는 사실만으로 개인정보가 사라지거나 권한 검증이 면제되지 않는다.

## 배정·대행·회수와 처리 중 상태

| 사건 | 동작 후보 | 업무 상태/사용자 영향 |
|---|---|---|
| 배정 전 | 최소 메타로 대기·배정 필요 표시 | 접수됨과 대상 확인 완료를 구분 |
| 배정 변경 | 새 담당의 자격·배정 확정 후 제한 접근, 옛 담당 접근 종료 | 최초 접수/이미 도래한 안내 기한을 새로 만들지 않음; 기한 값은 OPEN |
| 일시 대행 | 대행자도 독립된 유효 자격+건별 배정 필요 | 원담당 계정 공유·임의 재위임 불가 |
| 자격 상실/정지/퇴사·배정 해제 | 이후 조회/설명 확정 차단·기기 세션/미완료 작업 정리 연결 | 처리 중 건은 인계 필요; 자동 종결/실패/철회로 변경 안 함 |
| 종결·요청 취소 | 업무상 처리 접근 종료; 예외 보관/감사 열람은 별도 목적 | 종결 후 영구 조회권 없음; 취소 정책/잔존 기록은 OPEN |
| 다시 선임/배정 | 현재 상태·자격·명시 배정을 새로 검증 | 옛 권한/옛 작성 안내 자동 공개 금지 |

회수 효력은 서버의 현재 권한 검증과 확정 경계로 설계한다. 회수 뒤 옛 담당의 지연 요청/열린 화면/재시도가 자료를 새로 조회하거나 안내를 확정하지 못하도록 검증 조건을 둔다. 이미 전달된 최소 설명까지 기기에서 회수 완료했다고 주장하지 않는다. 통제 가능한 진행 응답·기기 저장·캐시 제거의 기술 방식/상한은 미결이며 SSO 특정 60초 전파 규칙을 모든 담당 업무에 일반화하지 않는다.

다른 담당이 바꾼 대상 설명을 옛 담당의 응답으로 덮지 않도록 접수/설명 버전과 배정을 확인한다. 확인 담당의 관계 판정은 본인의 철회 명령이 아니다. 이미 전달된 설명 뒤 대상/동의 세대가 달라졌다면 본인 실행 시 다시 검증한다. 근거 부족 또는 배정 불가일 때 일반 교회 관리자에게 원문을 보내 해결하거나 본인 철회 권한을 박탈하지 않는다.

## 기록·안내·운영 미결

선임/회수·배정/인계·허용 조회·설명 확정/거절 관측에는 필요한 actor·접수/대상 참조·시각·업무 코드·결과만 검토한다. 원문/사진·연락처·개인 신앙 평가·토큰을 감사에 복제하지 않는다. 열람 감사와 실제 소개 동의 철회 이력은 목적이 다르다. 열람 로그 보유가 동의 증빙 영구 보관의 근거가 되지 않는다.

실제 선임 주체·직원/외부 위탁 자격·필수 교육·확인 수단·겸임/이해충돌·선임 수락 기한·임기·첫 안내/정기 안내/상향 전달·정정/이의제기·기록 보유/삭제/백업은 OPEN이다. 실제 운영 체계 미확보 시 이 확인 기능의 활성화 게이트를 해소하지 않는다. 본인이 이미 대상을 식별할 수 있는 일반 철회까지 운영 인력 확보를 선행 조건으로 붙이지 않는다.

교회나 플랫폼 관리자라는 명칭만으로 실제 책임자가 배정됐다고 보고하지 않는다. 현재 자료는 합성 설계이며 사용자 증빙 수집·지원 담당 지정·권한 부여·DB 변경·코딩·파일럿을 수행하지 않았다.

## 이번 단일 정책 질문

이 추가 확인 업무는 ChurchOS 운영 주체가 별도로 지정한 담당 중 해당 건에 배정된 사람만 최소 정보를 확인하도록 하고, 교회 관리자·일반 상담 담당자에게 자동 권한을 주지 않는 S-A 기준을 채택할까요? 담당은 대신 철회할 수 없다. 선임 책임자의 구체 자격·겸임·기간·보유·처리 기한은 별도 결정으로 남긴다.

## r103 후속 결정 — REC-079

[REC-079 추가 확인 담당의 별도 지정과 건별 최소접근](RECOVERY_DECISIONS.md#rec-079-추가-확인-담당의-별도-지정과-건별-최소접근): 추가 확인은 ChurchOS 운영 주체가 별도로 지정하고 해당 건에 배정한 담당자만 최소 정보로 수행한다. 교회 관리자·일반 상담 담당자의 자동 조회권, 대리 철회, 소개 원문·사진 열람은 허용하지 않는다. 배정해제/자격상실 후 접근차단·별도인계 원칙도 유지한다. 위 r102 S-A 질문은 당시 이력이며 체계만 AGREED_SCOPED다. 역할별 실제선임·선임책임자/겸임·임기/기한/보유·API 기술후보는 DRAFT/OPEN이다. 실행 NOT_RUN.
