# 최초 선임·배정 책임자의 지정 근거와 교체·공백 처리 초안

2026-10-30 / r106 / GOVERNANCE_PROPOSAL + TECHNICAL_DRAFT / PARTIAL_RECOVERY / 실행 NOT_RUN

## 범위와 기존 근거

[REC-079](RECOVERY_DECISIONS.md#rec-079-추가-확인-담당의-별도-지정과-건별-최소접근), [REC-080](RECOVERY_DECISIONS.md#rec-080-선임배정의-자기확정-금지와-이해충돌-분리), [책임분리 초안](LEADER_INTRO_SUPPORT_SEPARATION_CONFLICT_DRAFT.md)을 따른다. 최초 책임자의 ‘지정 근거가 아직 시스템에 없다’는 문제를 자기선임 예외로 해결하지 않는 계약을 제안한다. 현재 ChurchOS 운영 법인/조직의 실제 권한 규정·인사 결정·당사자 신원·전자서명·실운영 계정은 확인하지 않았다. 사용자나 특정 개인을 실제 책임자로 지정한 문서가 아니다.

권장 B-A는 운영 주체의 검증 가능한 별도 지정 결정에 근거해 최초 선임/배정 책임자를 등록하고, 대상자 본인과 다른 권한 있는 사람의 실제 확인을 요구하는 방식이다. 시스템 운영 계정이나 DB 소유권은 그 지정 권위의 대체 근거가 아니다. 이 정책은 아직 PROPOSED다.

## 네 단계의 책임 분리

| 단계 | 근거/검증 후보 | 부여되는 것 | 부여되지 않는 것 |
|---|---|---|---|
| BG01 운영상 지정 | 운영 주체의 유효 권한 근거·결정 주체·대상 운영자·역할/범위·시작/종료·이해충돌 확인 | 선임/배정 책임을 맡길 근거 | 소개 원문·지원 접수 상세·대리 철회 권한 |
| BG02 대상자 확인 | 대상자 본인과 다른 권한 있는 확인자가 결정의 유효성·신원·범위 대조 | 등록할 책임/범위 확인 | 자기선임·대표 직함만으로 자기확정 |
| BG03 기술 등록 | 확인된 결정과 등록 actor·운영자 식별자·버전 결속; 대상자 수락/활성 후보 | 지정 범위의 책임 역할 활성 조건 | DB/배포 권한을 업무 권한으로 전용 |
| BG04 실제 배정 | REC-079/080의 자격·해당 건 배정·자기확정 금지 재검증 | 해당 역할/건의 최소 업무 | 모든 과거 접수 열람·다른 제품 권한 |

이 네 단계가 네 명의 별도 인력을 요구한다는 결정은 아니다. 다만 대상자 본인이 운영 주체 대표·기술 관리자 역할까지 겸하더라도 자기 권한 확정을 혼자 끝낼 수 없다. 적격한 다른 확인자가 없으면 이 추가확인 운영 권한의 활성화를 보류하고 별도 인력 확보/확인 절차를 마련하는 안이다. 일반 사용자가 식별 가능한 자기 소개 동의를 철회하는 기능과 기존 공개 차단은 계속 별개다.

## 지정 근거의 최소 계약 후보

업무 규정·적법한 운영상 위임·지정 결정을 어떤 형식으로 입증할지, 누구에게 그 결정 권위가 있는지는 실제 조직 체계로 확정해야 한다. 단순 이메일 도메인·저장소 owner·대표라는 자기진술·직함·DB 최고권한을 결정 근거로 자동 승인하지 않는다. 계약서/이사회 문서 등 특정 법정 양식을 필수라고 단정하지 않는다. 이 문서는 법적 적합성 확인이나 운영 법인 확정을 수행하지 않는다.

필드 후보는 지정 결정 참조, 결정/확인 주체의 검증된 운영자 참조, 대상자 참조, 역할/허용 범위, 유효 시작/종료, 상태/버전, 확인 결과와 필요한 최소 근거 참조다. 신분증 사본·주민번호·개인 연락처·서명 이미지 원본을 일반 지원 저장소에 복제하지 않는다. 실제 본인확인 수단과 원본 근거를 보관할 정본/열람자·보유기간은 별도 미결이다. 최소 참조만으로 증빙이 충분하다고 자동 선언하지 않는다.

본인 수락·임기·재선임·위탁 자격·신뢰할 확인자 선정·서명 검증 수단은 후속 계약이다. 기존 교회 위임의 168시간/1년을 플랫폼 책임자에게 자동 적용하지 않는다. 최초 지정은 일반 업무의 셀프 가입 승인이나 공개 API ‘최초 요청자 관리자’ 로직으로 구현하지 않는다.

## 교체와 공백 상황

| 상황 | 처리 제안 | 금지/제약 |
|---|---|---|
| 계획된 책임자 교체 | 새 지정 근거/다른 적격 확인·현재 제한 검증·등록; 옛 책임 역할 종료 시점과 업무 인계 결속 | 신임 자동승계·원임자의 임의 재위임·기존 개인 자격/건별 배정 복사 금지 |
| 책임자 자격 상실·퇴사·정지 | 현재 권한 차단·미종결 선임/배정 작업을 따로 점검 | 대체자 부재 때문에 옛 접근 유지 안 함 |
| 모든 선임/배정 책임자 공백 | 운영 주체의 별도 지정/다른 적격 확인 근거로 책임 복구 | 일반 교회 관리자·상담자·DB 관리자에게 포괄 업무권한 자동 부여 금지 |
| 지정 결정 충돌/진위 미확인 | 새 권한 활성/확대 보류·별도 확인 | 확인 중이라는 이유만으로 무관한 기존 유효 담당 전체 해제·사용자 계정 정지하지 않음 |
| 기존 접수 담당은 유효하나 배정 책임자만 공백 | 기존 건 접근은 실제 현재 선임/배정 조건으로 판정; 새 배정/변경 권한은 따로 처리 | 책임자 공백만으로 모든 건 자동 종결/자동 권한연장 안 함 |
| 지원 권한 사고 의심 | 영향 범위 차단·근거 확인·별도 권한 복구 검토 | 공격 의심자에게 자기복구 승인 또는 긴급 조회권 제공 안 함 |

업무 권한과 기술 사고 대응 권한을 구분한다. 시스템 격리·서비스 중단·토큰 회수 같은 기술적 차단은 새로 개인정보 조회권을 주는 행위가 아니다. 실제 수행 주체/범위/증거·긴급 복구 계약은 미결이며 사고를 이유로 기록을 삭제하거나 대리 철회를 실행하지 않는다. 기록에 지정한 책임 역할을 명시했다고 사고 대응 준비가 완료된 것은 아니다.

책임자 교체와 확인 담당의 개별 선임, 개별 접수 배정은 세 개의 다른 상태다. 책임자 교체가 적법한 모든 담당 선임/배정을 일괄 취소하거나 자동 복사하는 이벤트가 되지 않도록 현재 근거와 영향을 분리한다. 유효기간 종료·회수·보안 제한 등 각자의 조건은 그대로 적용한다.

## 지연 작업·복원·운영 안내

현재 책임자의 변경 권한과 지정/배정 대상 버전은 최종 확정 때 다시 확인한다. 예전 책임자의 열린 화면·지연 요청·재시도로 선임/배정이 바뀌지 않도록 계약을 연결한다. 변경 확정 결과를 받지 못하면 결과 미확인으로 안내하고 새 책임자의 권한이 생겼다고 추정하지 않는다. 실제 DB 경합·확정 단위·멱등/결과 조회는 DG02/03/06 후속 검증이다.

권한 복구는 업무 역할의 새 유효 등록이지 삭제된 개인정보·종료된 동의·옛 소개 공개를 복원하는 절차가 아니다. 백업 복원 시 최신 책임자/담당/배정 회수·삭제·동의 차단을 먼저 재적용한다. 인사 결정 원본이 오래됐다는 이유로 옛 역할을 자동 활성화하지 않는다. 실제 운영/지원 복구 리허설은 RV에서 검증한다.

미종결 접수에는 담당 확보/추가 확인 중 등 사실에 맞는 최소 상태를 안내해야 한다. 내부 인사·지정 근거 문서·이해충돌 내용을 본인에게 과도하게 공개하지 않는다. 책임자 교체/전달로 최초 접수 시각과 이미 정해질 안내 기한을 초기화하지 않는다. 첫 안내/주기/상향 전달/최종 처리 기한·재검토·취소·보유는 아직 OPEN이다. 기존 다른 업무의 24/72/168시간이나 30일을 자동 가져오지 않는다. 공백 안내만으로 장기 미해결을 정당화하지 않으며 실데이터 운영 전 실효적 대응을 마련해야 한다.

## 검증 인계와 미결

| ID | 검증 조건 | 실행 |
|---|---|---|
| CA151 | 최초 책임자 등록에 지정 근거/다른 적격 확인/현재 신원·범위 결속이 필요하고 자기선임·최초접속자관리자·DB권한 전용·계정변경 우회를 막음 | NOT_RUN |
| CA152 | 계획교체/공백/충돌/지연요청/복원에서 역할·담당선임·건별배정을 구분하고 옛권한 부활/포괄자동승계/기한초기화/대리철회 없음 | NOT_RUN |

전체152개는 미실행 설계 조건이다. 기존 REC001~080 및18B·DG/FD/RV 보존. 아직 실제 조직 지정 권위·책임자·자격·초기 등록 수단·동의 수락/기간·기한·기록 보유/삭제·구현/운영 증거는 미확인이다. 이 문서 자체를 최초 지정 근거로 사용하거나 운영 권한을 부여하지 않는다.

## 단일 정책 질문

최초 선임·배정 책임자도 운영 주체의 검증 가능한 별도 지정 근거와 대상자 본인이 아닌 적격자의 확인을 거쳐 등록하고, 이후 교체·공백 복구도 같은 기준을 따르도록 정할까요? 본인의 대표/관리자 직함이나 기술권한만으로 자기 권한을 확정하지 않는 B-A가 권장안이다. 실제 지정 주체의 자격·근거 형식·등록 방식·기간·처리 기한·보유는 별도 미결로 남긴다.
