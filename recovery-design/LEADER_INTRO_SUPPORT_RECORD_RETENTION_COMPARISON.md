# 소개 철회·추가 확인 기록의 목적별 보유·삭제·복원 대조

2026-10-30 / r109 / SOURCE_COMPARISON + RECORD_CONTRACT_DRAFT / PARTIAL_RECOVERY / 실행 NOT_RUN

## 권위와 결론

[r108 통합인계 P05](LEADER_INTRO_WITHDRAWAL_SUPPORT_CONSOLIDATED_HANDOFF.md), [기존 기록별 보유 대조 R01~R16](RECORD_RETENTION_COMPARISON_2026-10-27.md), [영역별 보유 대조](CROSS_DOMAIN_RETENTION_REVIEW.md), [계정·소속·서비스 계약](../docs/operations/ecosystem-v1/ACCOUNT_MEMBERSHIP_SERVICE_SCOPE_CONTRACT.md)을 대조했다. REC-076~081은 자격/최소표시/담당체계의 합의이며 새 기록의 보유기간 합의가 아니다.

소개 철회에 필요한 기록도 목적이 다르므로 ‘전부 7일 삭제’ 또는 ‘전부 1년 보관’으로 묶을 수 없다. 기존 수치가 적용되는 대상과 소개/지원 기록의 새 정책 미결을 분리한다. 이번 문서는 설계/근거 대조이며 법적 보유의무나 적법성을 새로 판정하지 않는다. 새 REC·수치 승인·실제 삭제/보유 변경은 없다.

## 삭제 순서·복원 의존관계 — 기술 초안

1. 삭제대상/범위/세대·정본/사본계보·유효한별도보관근거를 먼저 확인한다. 보관예외 신청이나 분쟁미해결만으로 자동연장하지 않는다. 소개/지원기록에 예외승인자를 새로 지정한 것은 아니다.
2. 현재공개/권한/자동재시도·늦은작업 차단을 적용한다. 캐시/서명URL/검색/큐/외부사본 통제범위를 기록하고 물리삭제 대기 중 원문열람을 허용하지 않는다.
3. 운영본·파생/검색/캐시·기기·처리자/백업을 각각 확인한다. 어떤 사본이 지워졌는지, 이미 지운사본의 백업상한이 무엇인지 구분한다. 새 사본이나 늦은 확인으로 원래기한을 초기화하지 않는다.
4. 원문/명칭 증빙 삭제 후에도 남겨야 할 실행보호/복원필터는 최소목적·수명을 먼저 설계한다. 모든자료를 먼저 지워 복원차단근거가 사라지는 순환을 만들지 않는다. 원문을 필터에 복제하거나 무기한계정식별을 남기는 대안은 금지한다.
5. 복원은 비공개 격리 상태에서 최신철회/삭제/담당회수/세대·멱등확정 상태를 재적용한 뒤 검증한다. 필터/권한근거를 확인할 수 없으면 공개를 보류하고 원문/옛권한을 자동 활성화하지 않는다. 실제서버 복원성공은 아직 미검증이다.
6. 필요한절차의 실제종결 근거를 기록한다. 큐비움/접수취소/담당확인완료/운영본일부삭제/조회만료만으로 전체종결하지 않는다. 장기미해결의 수명/안내/예외는 별도정책으로 정하고 무기한상태를 기본값으로 채택하지 않는다.

명칭증빙이 없어도 본인철회권 자체를 없애지는 않지만 안전한대상결속이 불가능하면 추측철회를 실행하지 않는다. 이충돌은 적정한최소증빙수명/복원보호참조/제한확인 계약으로 해소할 개발전 과제이며 삭제원문 복원으로 해결하지 않는다. LR03과LR12의 수명은 서로 종속될 수 있어 함께 결정해야 한다.
