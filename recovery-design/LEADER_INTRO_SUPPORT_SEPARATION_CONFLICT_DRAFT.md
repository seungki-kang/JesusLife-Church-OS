# 추가 확인 담당의 책임 분리·이해충돌·대행 초안

2026-10-30 / r104 / POLICY_PROPOSAL + TECHNICAL_DRAFT / PARTIAL_RECOVERY / 실행 NOT_RUN

## 출발점

[REC-079](RECOVERY_DECISIONS.md#rec-079-추가-확인-담당의-별도-지정과-건별-최소접근)의 별도 지정·건별 배정·최소접근은 유지한다. [r102 선임/배정 초안](LEADER_INTRO_SUPPORT_ASSIGNMENT_ACCESS_DRAFT.md)의 SP01~06에서 미결이었던 자기 선임·자기 배정·겸임·이해충돌·대행을 구체화한다. 본문은 권장 정책이며 아직 AGREED가 아니다. 실제 선임/배정·코드·DB·GitHub 변경은 수행하지 않았다.

핵심은 역할 이름을 여러 개 만드는 것보다 한 사람이 자기 권한의 생성·확대·예외 승인을 끝내지 못하도록 하는 것이다. 이 업무는 본인 철회의 허가 심사가 아니며 인력 부족이나 이해충돌 때문에 일반 본인 철회에 새 승인 단계를 붙이지 않는다.

## 권장안 C-A: 자기 권한 확정과 자기 건 처리를 분리

| 행위 | 권장 통제 | 금지/남은 세부 |
|---|---|---|
| 확인 담당 선임·재선임 | 대상자와 다른 현재 유효한 선임 책임자가 범위를 확정 | 자기 선임·스스로 임기 연장/범위 확대 금지; 최초 책임자 설치 계약은 OPEN |
| 건별 배정 | 현재 적격 담당에게 배정 권한자가 확정 | 배정 권한자가 자기 자신에게 건을 배정하려면 다른 적격 배정 책임자가 확정; 본인 클릭만으로 접근 활성화 금지 |
| 겸임 | 같은 사람이 업무 역할 여러 개를 맡는 것 자체는 가능 후보 | 자신의 선임/자기 배정을 자기 권한으로 확정하지 못함; 역할 하나로 모든 상세 열람 불가 |
| 이해충돌 신고 | 당사자/대상 조직과 업무상 이해관계·기존 관련 판단을 최소 코드로 표시하고 다른 담당 검토 | 자기 이해충돌 해소를 스스로 승인 금지; 신앙/관계 자유서술 수집 금지 |
| 해당 건 실무 | 본인 요청/직접 이해관계 건은 회피하고 다른 적격 담당에게 배정 | 본인 건을 지원 권한으로 처리·설명 확정하지 않음; 일반 본인 철회 권한은 별도 유지 |
| 대행 지정 | 대행자도 현재 유효 선임+독립 건별 배정 확인 | 계정 공유·원담당 임의 재위임·자격/범위 복사 금지 |
| 권한 회수 | 권한 관리 책임자가 필요한 최소 차단·기록·미종결 인계 수행 | 회수 실행 때문에 대체 담당 선임 완료를 기다리지 않음; 긴급 회수 주체/시각 보장은 별도 기술계약 |

모든 일에 서로 다른 세 명을 요구하는 안은 아니다. 논리 역할을 겸임해도 자기 권한의 생성/확대를 다른 사람이 유효하게 확인해야 한다는 후보이다. 다른 사람의 확인은 형식적 버튼이 아니라 자격·범위·기간·배정 및 충돌을 실제로 확인하는 작업이다. 신청자와 승인자를 계정만 바꿔 동일인이 수행하는 것으로 분리를 충족했다고 보지 않는다.

교회 관리자나 고객 상담자라는 이유로 ‘다른 적격 책임자’를 대체하지 않는다. 확인 담당에게 유효한 자격이 있어도 선임/배정 확정 권한을 자동 부여하지 않는다. 책임자의 실제 자격·지정 권위·첫 운영자 등록·외부 위탁/휴직/퇴사/대체 구조는 별도 미결이다.

## 이해충돌의 최소 판단과 회피

| 상황 | 처리 후보 | 주의 |
|---|---|---|
| 담당 본인의 철회 요청 | 지원 담당 배정 제외·다른 적격 담당으로 연결 | 본인으로서 REC-076 철회는 허용; 지원자격으로 자기 확인을 완료하지 않음 |
| 해당 교회의 현재 관리자·관계 판단의 직접 당사자 | 적격 충돌 판단을 거쳐 해당 건 회피·재배정 | 같은 교회에 속했다는 사실만으로 전역 영구 결격을 자동 부과하지 않음 |
| 가족/계약 등 직접 이해관계가 있다고 신고 | 최소 코드와 해당 건 범위로 다른 책임자 검토·임시 접근 보류 후보 | 상대방 신원·사생활·가족관계 증명 자료를 기본 수집하지 않음 |
| 담당이 문제의 소유/명칭 연결을 과거 직접 확정 | 기존 자료 제공과 재확인 판단 분리 | 자기 오류를 자기가 최종 재확인하는 구조 방지 |
| 근거 없는 신고/지연 목적 의심 | 별도 책임자가 최소 사실과 필요 범위를 확인 | 신고만으로 계정 정지/담당 전역 해임·본인 철회 차단 금지 |

정확한 충돌 분류·이의제기 주체/기한·사실 확인 필드·접근 보류 조건은 정책 미결이다. 본문 사례를 자동 탐지/자동 제재 규칙으로 구현하지 않는다. AI가 사람 관계를 추론하거나 다른 제품 개인 기록을 조회해 충돌을 판정하지 않는다. 충돌 사실을 교회 관리자나 다른 교인에게 통지하는 기본 기능을 만들지 않는다.

## 대행·재배정과 공백

| 단계 | 조건/결과 후보 | 실패 경계 |
|---|---|---|
| CO01 회피/대행 필요 접수 | 최소 사유 코드·기존 건 참조 유지 | 별도 새로운 철회 요청/새 접수 기산으로 바꾸지 않음 |
| CO02 기존 담당 차단 | 회수/배정 종료의 유효 확정 상태를 서버 반영 | 대행 부재를 이유로 자격 상실자의 접근 유지 안 함 |
| CO03 적격 대행 확보 | 선임·현재 인증·범위·충돌·배정 권한 검증 | 일반 상담원/교회 관리자로 임의 대체 안 함 |
| CO04 건별 대행 확정 | 원담당/대행자·허용 작업/필드·기간·인계 상태 결속 | 원담당이 임의로 재위임하거나 자기 대행을 확정하지 않음 |
| CO05 본인 안내 | 담당 확인 중/인계 중 등 사실에 맞는 최소 상태 안내 | 내부 인사·충돌 세부·타인 정보를 공개하지 않음 |
| CO06 완료/대행 종료 | 대행 목적 종료 후 접근 차단·미종결 건 별도 인계 | 옛 접근 자동 복구/임기 자동 연장 없음 |

동시에 유효한 실무 담당을 몇 명까지 두는지, 교체 시 작업 잠금·설명 버전·읽기/확정 권한은 기술 계약으로 확정해야 한다. 대행 중 원담당이 복귀해도 옛 배정을 자동 살리지 않는다. 지연 응답/열린 화면/재시도는 현재 배정·권한 검증을 통과해야 한다. 이 문서가 실DB 회수 경합을 이미 보장했다는 뜻은 아니다.

적격한 다른 사람이 없으면 추가 확인 건은 인력 확보/예외 책임 조정 상태로 안내한다. 한 명뿐이라는 이유로 자기 선임/자기 배정·이해충돌 자기승인을 허용하거나 무권한 대리 철회를 실행하지 않는 안을 권장한다. 다만 실제 인력 확보·상향 책임자·첫 안내/주기/최종 처리 기한은 OPEN이며 영구 대기를 정상 처리로 정한 것이 아니다. 실데이터 운영 전에 공백 대응과 지연 안내를 마련해야 한다.

일반 본인 철회는 식별 가능한 경우 기존 권한으로 진행하고, 이미 직함 종료/동의 철회로 중단된 공개는 인계 중에도 중단 상태를 유지한다. 지원 인력 부족을 이유로 공개를 복원하거나 원문/사진 제출을 요구하지 않는다.

## 기술·감사·보유 경계

선임/배정/겸임/충돌/대행은 actor·대상 건·권한 목적·현재 버전·근거 코드·유효 시작/종료·처리 결과를 최소로 연결하는 모델 후보다. 자기 확정 금지의 actor 동일성은 이름/이메일 문자열 비교가 아닌 검증된 운영자 식별 관계로 판단한다. 역할 관리자의 DB 계정이 광범위 DML을 유지하면 앱 화면 제약만으로 우회를 막았다고 주장할 수 없다. 기존 최소권한 이행·현재 권한·경합 게이트 DG06과 검증을 연결한다.

처리 코드만으로도 관계 정보가 될 수 있으므로 접근·보유를 별도로 정한다. 신고 자유서술·개인 기도/일기/관계 원문·토큰을 감사에 남기지 않는다. 원문 참조와 최소 결정 근거를 구분하고 과거 판단을 덮어쓰지 않는다. 담당 교체/대행/회피로 최초 접수 시각이나 이미 정해질 안내 기한을 초기화하지 않는다. 아직 없는 기한 값을 만들어 적용하지 않는다.

기간·수락 기한·대행 상한·관계 기록 수명·예외 승인/열람·복원 검증은 OPEN이다. 168시간/1년 등 교회 위임 업무 정책이나 공통 탈퇴 24시간 규칙을 운영 담당에게 자동 적용하지 않는다. 복원 시 최신 담당 자격/배정 회수·삭제 상태를 공개 전에 적용하는 검증이 필요하다. 실제 운영 담당자나 책임자가 확보됐다고 기록하지 않는다.

## 검증 인계와 단일 질문

| ID | 설계 검증 조건 | 실행 |
|---|---|---|
| CA149 | 자기 선임/임기연장/범위확대·자기 배정·겸임 계정이 다른 적격 책임자 확인 없이 권한을 활성화하지 못함; 직함 자동권한/계정 바꾼 동일인 우회 점검 | NOT_RUN |
| CA150 | 본인/직접 이해관계·재확인 충돌·대행 부재·복귀/지연응답·배정경합에서 자기승인/임의재위임/대리철회/기한초기화 없음 | NOT_RUN |

전체150개는 미실행 시나리오다. REC001~079·기존18B 및 DG/FD/RV는 보존한다. 새합의/실제권한/코드/DB/GitHub 변경 없음.

질문: 자기 선임·자기 배정과 이해충돌 자기승인을 금지하고, 필요한 경우 다른 적격 책임자의 확인·재배정을 거치도록 하는 C-A 기준을 채택할까요? 역할 겸임 자체는 허용 후보로 남기되 자기 권한을 스스로 확정할 수 없도록 한다. 적격 인력 부재는 무권한 예외로 해결하지 않고 별도 인력 확보/지연 안내로 다룬다. 구체 책임자 자격·기간·기한·보유는 별도 결정한다.

## r105 후속 결정 — REC-080

[REC-080 선임·배정의 자기확정 금지와 이해충돌 분리](RECOVERY_DECISIONS.md#rec-080-선임배정의-자기확정-금지와-이해충돌-분리): 추가 확인 담당의 자기 선임·자기 배정·이해충돌 자기승인을 금지하고 다른 적격 책임자의 확인·재배정을 거치는 책임 분리 기준을 확정했다. 대행자도 유효 자격과 건별 배정이 필요하며 인력 부재를 무권한 처리로 해결하지 않는다. 위 r104 C-A 질문은 당시 이력이며 책임분리 기준만 AGREED_SCOPED다. 구체자격·겸임·최초책임자·충돌사례 판단/이의제기·기간/기한/보유·기술후보는 OPEN이다. 실제선임/검증 NOT_RUN.
