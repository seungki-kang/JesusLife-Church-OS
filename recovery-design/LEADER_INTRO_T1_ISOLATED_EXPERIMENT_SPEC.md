# T1 합성 데이터 격리 실험 명세

2026-11-09 / r170 / EXPERIMENT_SPEC_READY_FOR_REVIEW / PARTIAL_RECOVERY

[r169 검증 계획](LEADER_INTRO_POSTGRES_FINAL_TIME_VERIFICATION_PLAN.md)의 T1 검증을 실행 절차로 내린 초안. 목적은 PostgreSQL이 기록한 커밋 시각을 철회 결과에 결속해, 응답 유실·재시작 뒤에도 같은 168시간 기산점으로 쓸 수 있는지 판정하는 것이다. 후보 채택·배포·실행 승인은 아니다.

## 실험 전 확인 결과

| 항목 | 현재 근거 | 판정 |
|---|---|---|
| 기존 DB 계열 | 보존된 canonical v2.6의 tools/postgres/Dockerfile은 postgres:16을 참조한다. 정확한 마이너 버전·이미지 다이제스트는 실험에서 기록한다. | 기준선 확인 |
| 공식 기능 의미 | 공식 자료 조회를 시도했으나 결과를 받지 못했다. 설정 적용 시점, 식별자 자료형, 값 부재/오래된 값 처리, 유지 수명, 재시작·복원 특성은 실행 전에 문서와 대상 버전에서 확인한다. | 미확인 |
| 실행 도구 | 현재 작업 환경에서 docker·psql·initdb 실행 파일을 찾지 못했다. 사용자 PC 상태는 이 점검으로 판단하지 않는다. | 현재 환경 실행 불가 |
| 실제 시험 | DB 시작·접속·SQL 실행을 하지 않았다. 제품 DB·계정·원문·키를 사용하지 않는다. | NOT_RUN |

공식 확인 대상: [서버 정보 함수](https://www.postgresql.org/docs/16/functions-info.html), [복제 설정](https://www.postgresql.org/docs/16/runtime-config-replication.html), [날짜·시간 함수](https://www.postgresql.org/docs/16/functions-datetime.html). 이 링크는 후속 확인 위치이며 이번에 읽어 검증한 증거가 아니다.

## 준비와 안전한 종료

1. PostgreSQL 16의 정확한 버전·이미지 다이제스트를 고정한다. disposable A(추적 설정 off)와 B(on)를 독립 데이터 디렉터리로 만든다. A에서 생성한 사건을 B로 옮겨 on 대조군으로 삼지 않는다.
2. 운영 연결문자열·볼륨·백업을 재사용하지 않는다. 실험 DB 이름, 클러스터 식별 증거, 테스트 전용 스키마와 계정을 확인한다. 시작 전 환경·역할·설정 확인에 실패하면 중단한다. 관찰 역할은 최소 접근으로 설정하고 앱 역할과 분리한다.
3. 연결 두 개 이상을 사용한다. W는 합성 효력/결과/감사를 같은 트랜잭션에 쓰고, O는 별도 연결에서 가시성과 커밋 시각을 확인한다. 장애 주입 시험에서만 추가 제어 연결을 사용한다.
4. 결과 파일에는 환경 식별·예상과 실측·원인만 남긴다. 토큰·암호·연결문자열을 포함하지 않는다. 최종적으로 이번 실험에서 만든 자원만 정리한다.

## 시험 입력과 기본 절차

합성 대상 T001과 T002, 교회 A/B, 요청 R101(효력 적용), R102(롤백), R103(이미 철회된 세대의 새 무변경 요청), R104(응답 유실)를 사용한다. 결과 행은 테스트에서 불변으로 취급한다. 트랜잭션 결속 증거는 별도로 기록하고, 행의 현재 버전이나 짧은 트랜잭션 번호만으로 운영 정본 관계를 판단하지 않는다.

- 세션별 사전 확인: 서버 버전, 데이터베이스 이름, 현재 역할, 시계 설정과 추적 설정을 수집한다. 확인 후보 SQL은 SHOW server_version, SHOW track_commit_timestamp, SHOW TimeZone, SELECT current_database(), current_user 이다.
- W: R101의 BEGIN 뒤 합성 효력·결과·감사를 모두 쓰고, 후보 xid와 쓰기 시각을 기록한다. 커밋 전 의도적으로 몇 초 대기한다. O는 새 스냅샷으로 커밋 전에는 결과 행을 볼 수 없는지 확인한다. W는 COMMIT, O는 커밋 뒤 결과와 증거 결속을 읽고 후보 pg_xact_commit_timestamp(xid)를 대조한다. 함수·인자 형태는 앞서 확인한다.
- DB와 시험 관찰 시계가 비교 가능함을 별도로 확인한다. 커밋 직전 관측과 최초 가시 관측 사이에 기록 시각이 들어오는지 비교하고, 트랜잭션 시작·행 생성·응답 시각도 대조한다. 이 전후 범위는 관찰 증거이며 정확한 시각의 대체값이 아니다.
- R102는 동일 절차에서 ROLLBACK 한다. R103은 이미 철회된 상태를 유지한 채 그 요청의 무변경 결과·감사만 확정한다. R101의 시각을 R103에 승계하지 않아야 한다.

## 실행 판정표

| 실험 | 조작 | 합격 기준 | 상태 |
|---|---|---|---|
| E01 환경·권한 | A/B 설정, 앱/관찰 역할별 접근 비교 | off에서 증거를 만들지 않음. on에서 결과 확인을 시도할 수 있고, 앱에 임의 xid·타 교회 결과가 드러나는 경로를 확인해 차단 방법을 제시함. 역할 설정만으로 보호된다고 가정하지 않음 | NOT_RUN |
| E02 확정·롤백·무변경 | R101~103 실행 | R101/103은 각자의 결과·시각 결속. R102는 효력·결과·감사 모두 없음. 지연으로 시작/쓰기 시각과 확정 시각을 구분할 수 있음 | NOT_RUN |
| E03 응답 유실·프로세스 종료 | R104 커밋 뒤 HTTP 응답 또는 시각 사본 기록을 막음. 별도로 COMMIT 응답을 모르는 시나리오를 커밋/롤백 양 갈래로 재현 | 실제 확정된 결과만 동일 F로 회수하며, 다시 쓰지 않음. 미확정/증거 부재는 시각 미확인으로 처리. 서버 재시작 뒤도 비교 | NOT_RUN |
| E04 근거 수명 | 시각 사본을 만들지 않은 상태에서 지연·유지보수 전후 반복 조회. 별도로 사본 기록 후 근거가 없어지는 경우 확인 | 원천 회수 가능 기간과 사본 수명을 구분. 짧은 실험 성공을 168시간 운영 보장으로 확대하지 않음. 원천 부재 시 임의 시각으로 복원하지 않음 | NOT_RUN |
| E05 복원·출처 혼선 | 실험용 복원본과 독립 클러스터의 결과/증거 교차 입력. 복원 전후 최신 권한·삭제 적용 확인 | 계보가 불명확한 결속을 거부. 동일 사건 증명과 최신 권한/삭제 확인이 모두 충족되어야 공개. 물리 복원·논리 재적재·실제 장애 전환은 각각 별도 판정 | NOT_RUN |
| E06 조회 비교 | 제어 시계로 f 직전/f/종료 직전/종료/직후와 권한 회수·시계 점프를 주입 | 모든 조회 경로가 검증된 UTC 기준에서 f 이상, f+168시간 미만만 허용. 정확히 종료 시점부터 차단. 불신 시계로 만료 확정/삭제/재노출 없음 | NOT_RUN |

E03에서 COMMIT 이후 응답만 차단하는 대조군은 **커밋 불명 전체의 대체 증거가 아니다**. 커밋 여부를 실행자가 알 수 없는 시험을 별도로 재현하고, 관찰 증거로 실제 분기를 구별한다. 제어 시계로 수행한 E06은 경계 계산 근거이며 실제 DB 시계 동기화·장애 복구의 근거가 아니다.

## 결과 기록과 다음 판단

각 실행에 실험 ID, 버전/다이제스트, 설정·역할·계보, 합성 요청, 명령·종료 코드, 기대값·실측값, 시각 근거 출처, 증거 파일 위치, PASS/FAIL/NOT_RUN을 남긴다. 결과가 잘못 결속되거나 운영 후보에서 수명·권한·복원 요건을 충족할 근거를 얻지 못하면 T1 채택을 보류하고 r169 T2 검토로 넘긴다. 다음 실행 단위는 **A/B 설정 확인 및 E01~E02 기본 실험**이다. 실제 실행 가능한 격리 환경이 먼저 확인돼야 한다.
