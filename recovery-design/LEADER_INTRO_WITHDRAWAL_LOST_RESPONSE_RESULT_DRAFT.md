# 소속 종료 후 본인 철회의 응답 유실·최소 결과 확인 계약 초안

2026-10-31 / r123 / MINIMUM_RESULT_CONTRACT_DRAFT / PARTIAL_RECOVERY / 실행 NOT_RUN

## 권위와 목적

[REC-083 후속 분리](LEADER_INTRO_EVIDENCE_DEFERRED_SCOPE_HANDOFF.md), [REC 결정 원문](RECOVERY_DECISIONS.md), [r120 W/Q/E/S 경계](LEADER_INTRO_WITHDRAWAL_QUERY_SUPPORT_BOUNDARIES.md)를 따른다. E 장기 증빙 확인은 후속 기능으로 유지한다. 이번 WR은 W 본인 철회의 응답 유실에 필요한 **특정 요청의 최소 결과 확인** 후보다. 별도 장기 이력 목록·교인 전용 자료·철회 증명서 기능이 아니다.

교회 탈퇴/직함 종료 후도 유효 공통 계정 본인의 특정 소개 동의 철회는 REC-076 범위다. 그러나 일반 요청 조회 Q는 현재 유효 소속을 요구한다. 이 공백을 Q의 자격 면제로 해결하지 않고, 해당 W 요청에만 결속한 조회 권한을 검토한다. 새 조회권·기간·API는 아직 합의하지 않았으며 구현하지 않았다.

## 권고 후보 — 요청 단위로 한정

| 후보 | 범위 | 판단 |
|---|---|---|
| WR-A 특정 W 결과 확인 | 현재 계정 본인과 정확히 결속된 하나의 철회 의도/동의 세대 결과만 확인 | 우선 검토. 소속 재가입/관리자 승인 없이 W의 불확실성 해소를 목표로 함 |
| WR-B Q 자격 확대 | 탈퇴자에게 일반 업무 결과 목록/조회를 개방 | 비권고. 다른 업무·교회 관계·기존 REC-029~032까지 넓어짐 |
| WR-C 지원만으로 해결 | 모든 응답 유실을 담당자에게 넘김 | 단독 기본안 비권고. 본인 일반 철회에 담당 공백이 새 장벽이 될 수 있음 |

WR-A의 제품 권한 원칙부터 검토하며 구체 인증 수단·경로·필드·기간·실제 저장 구조는 별도다. WR-A를 택해도 담당자가 대신 철회하거나 소속 정지/서비스·공통 계정 종료의 예외를 새로 여는 것은 아니다.

## 입력·서버 결속 후보

| 요소 | 요구되는 검증 | 금지하는 추정 |
|---|---|---|
| 현재 인증 | 해당 목적에 유효한 공통 계정·현재 세션 상태·API 대상 확인 | 과거 JWT/기기 로그인 흔적만으로 허용 |
| 요청 참조 | 서버 결과 참조 또는 최초 클라이언트 의도 참조를 인증된 actor와 검증 | 번호/멱등 키 소지만으로 접근 권한 인정 |
| 대상 결속 | ChurchOS의 교회·소개·동의 세대·요청 행위·본인 관계 연결 확인 | 이름·시각·같은 교회·최신 동의로 임의 대체 |
| 동일 의도 | 원래 입력/세대와 변경된 요청을 구분 | 새 키/토큰이 원래 요청 결과를 대신함 |
| 현재 자격 | 허용된 W 결과 확인 범위와 종료/회수 상태 재검증 | W 실행권이 모든 기록 열람권을 생성함 |

첫 서버 응답을 전혀 못 받아 서버 발급 참조가 없는 경우를 반드시 지원 설계에 포함한다. 최초 전송 전에 만든 의도 참조/기존 키와 서버의 내구 기록을 연결할 수 있는지 조사해야 한다. 아직 그런 참조나 기록이 구현돼 있다고 주장하지 않는다. 클라이언트 참조만 있고 서버 기록이 없으면 실행되지 않았다고 단정하지 않는다.

키/번호를 경로·쿼리·로그·분석·푸시·클립보드에 무제한 복사하지 않는다. 위치/형식·검색 상한·속도 제한·오류 일관성은 기술 명세로 정한다. 번호 난독화나 서명만으로 현재 권한 검증을 대체하지 않는다.

## 최소 응답 후보와 의미

| 항목 | 후보 의미 | 공개하지 않을 것 |
|---|---|---|
| 불투명 요청 확인 번호 | 해당 요청과 결속된 최소 참조 | 실제 교회/소개/동의 세대 식별자를 화면에 그대로 표시 |
| 처리 상태 | 서버 근거로 확인한 미확정/철회 확정/변경 없이 거절/확인 필요 | 실제 근거 없는 성공·실패 추정 |
| 최초 서버 접수 시각 | 내구 접수가 증명되는 경우 원래 시각 | 기기 전송 시각을 서버 접수 시각으로 대체 |
| 최종 확정 시각 | 해당 요청의 실제 최종 결과 확정시 | 현재 동의 상태 확인 시각을 원래 커밋 시각으로 표시 |
| 결과 확인 종료 시각 | WR 전용 목적/기산/기간이 확정될 때 표시 | Q 168시간이나 보유 후보90일 자동 상속 |

다섯 항목은 Q와 같은 최소 형태를 검토하는 **WR 후보**다. REC-031의 권한·기간을 확대하는 확정 계약이 아니다. 소개 원문/사진·교회/공동체명·명단·연락처·상세 사유·다른 요청 목록·전체 건수·원본 동의 문구를 넣지 않는다. HTTP 코드/JSON 키/상태 열거형은 미선정이다.

현재 동의가 철회 상태라는 관측과 이 요청이 철회를 확정했다는 사실은 다르다. 기존에 이미 철회됐거나 다른 유효 요청이 먼저 확정했을 수 있다. 별도 근거가 없으면 ‘이 요청으로 철회 완료’라고 응답하지 않는다. 새 동의 C2가 있더라도 C1의 결과를 C2 철회로 안내하지 않는다.

| 단계 | 행위 | 판정·안내 |

일정한 재조회 횟수/간격·백오프·최대 확인 창은 미결이다. 화면 진입/복귀·지연 응답에서 계정/대상 결속과 현재 권한을 재검증한다. 로그아웃·계정 전환은 해당 화면/참조를 정리하고 다른 계정에 지연 응답을 적용하지 않는다. 같은 계정의 교회 전환 격리와 과거 참조 접근은 기존 기기 정책 및 WR 목적 계약을 함께 검토한다.

## 응답 유실 지점별 진실의 범위

| 관측 지점 | 알 수 있는 사실 | 해서는 안 되는 것 |
|---|---|---|
| 서버 접수 전후 불명 | 전송 결과 불명 | 404/네트워크 오류로 미접수 확정 |
| 내구 접수 증명·미확정 | 접수 사실, 최종 결과는 아직 불명 | 접수를 업무 완료로 표시 |
| COMMIT 응답 불명 | 실제 커밋이 성공했을 수도 있음 | catch에서 ROLLBACK을 시도했다고 원래 업무 실패 확정 |
| 최종 확정 기록 있음 | 해당 요청·세대의 증명된 최종 결과 | 모든 소개/사진/다른 동의의 상태로 확대 |
| 영수증 만료·기록 정리·기한 종료 | 그 조회로 현재 확인 불가 | 원래 요청 미실행·철회 효력 소멸·안전 재실행 가능 단정 |
| 현재 동의만 조회 가능 | 현재 상태에 대한 제한된 관측 | 과거 특정 요청의 결과를 소급 구성 |

최초 응답 유실과 기록 만료 후의 분기를 구분한다. 기존 동일 의도/키로 확인 가능한 결과가 있으면 우선 확인한다. 기록이 없다는 이유로 새 철회 요청을 자동 생성하지 않는다. 새 명시 의도가 필요한 경우에는 현재 본인/대상/세대와 기존 미확정 여부를 판정하는 별도 명세가 필요하다. 장기 증빙(E)을 임시로 다시 제공하지 않는다.

## 수명·기존 구현의 호환 조건

canonical v2.6의 Idempotency-Key, tenant/actor/경로/키 범위, 24시간 성공 영수증, 만료 키 거절은 보존된 구현 사실이다. WR 엔드포인트나 소속 종료 후 조회가 이미 있다는 뜻은 아니다. 24시간 영수증이 끝나면 WR 확인을 어떻게 유지/종료할지, 실제 내구 접수/결과 정본을 무엇으로 삼을지는 OPEN이다.

WR 결과 확인 창·접수/최종 기산·서버 보유·기기 참조·멱등 보호·감사·삭제/백업은 서로 다른 수명이다. 기존 Q의 접수/최종168시간, E의 미합의30/90일을 WR 값으로 자동 사용하지 않는다. 유한 조회 창과 물리 삭제 마감·백업 상한·보호 종료를 함께 정하기 전 완성된 수명 계약이라고 부르지 않는다.

서버 결과 기록이 없어도 현재 효력 정본과 보호 참조는 각 목적에 필요한 상태를 유지해야 한다. WR 조회를 제공하려고 원문·사진·명칭을 재수집하거나 보호 자료를 본인/지원 메뉴에 전부 노출하지 않는다. 기록 청소/복원 후 옛 요청 재실행 방지는 기존 GS/FG 계약을 따로 검증한다.

## 남은 결정과 다음 질문 범위

WR-A 제품 원칙, 대상/의도 결속과 현재 인증 자격, 최소 응답, 조회 창/수명, 영수증 부재·최종 불명 처리, 실제 경로/권한/원자성은 OPEN이다. REC-083을 뒤집거나 E 후속 분리를 다시 묻지 않는다. 다음은 WR-A의 제품 권한 원칙을 좁게 확인한 뒤 기술/기간을 별도로 정하는 것이다.

검토 질문 후보: **유효한 공통 계정 본인은 교회 소속이 끝난 뒤에도, 본인이 제출한 특정 소개 철회 요청의 최소 결과만 확인하도록 할까요?** 이는 다른 업무 조회·장기 증빙·정지/탈퇴 계정 예외·보유기간의 일괄 허용이 아니다. 이번 ‘진행해줘’는 이 질문의 답으로 기록하지 않았다.

기존 COS/REC001~083·정본/이력 보존. 총 작업14/CA162/MVP34·18B/DG/FD/RV 유지. 새 REC·기간·권한 합의·코드·DB·GitHub 변경 없음. PARTIAL_RECOVERY, 실제 앱/API/SSO/조회/삭제/복원 NOT_RUN.
