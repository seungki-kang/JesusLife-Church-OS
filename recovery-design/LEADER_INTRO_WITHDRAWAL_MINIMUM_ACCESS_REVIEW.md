# 소속·직함 종료 후 본인 소개 철회 최소 접근 검토

2026-10-30 / r96 / POLICY_PROPOSAL / PARTIAL_RECOVERY / 실행 NOT_RUN

## 목적과 근거

[단계 게이트 DG04](LEADER_INTRO_STAGE_GATE_CLASSIFICATION.md), [변경 명령 CMND04/05](LEADER_INTRO_COMMAND_END_TO_END_CONTRACT_DRAFT.md), [기존 결정 REC-063/064](RECOVERY_DECISIONS.md#rec-063-리더-소개-공개-동의-본인-철회), [계정·소속·서비스 계약](../docs/operations/ecosystem-v1/ACCOUNT_MEMBERSHIP_SERVICE_SCOPE_CONTRACT.md)을 대조한다. 이번 검토는 접근 경로의 정책 제안이며 새 REC 합의나 실행 증거가 아니다.

## 이미 확정된 것과 이번 미결

직함 종료에 따른 현재 소개 중단은 이번 답변을 기다리지 않는 기존 설계다. 본인이 나중에 잔존 동의를 명시 철회하는 절차는 그 자동 중단과 목적이 다르다. 이미 삭제된 원문을 복원하거나 새 동의 자료를 만들 필요는 없다. 실제 구현의 자동 차단 여부는 아직 검증하지 않았다.

## 권장안 W-A — 유효 공통 계정의 본인 철회 전용 경로

교회 소속이나 직함은 종료됐지만 공통 계정과 ChurchOS의 해당 최소 처리 이용 자격이 유효한 경우, 서버에서 과거 해당 소개 동의의 소유 관계를 확인하고 본인에게 철회만 허용하는 경로를 제안한다. 이 권장안은 미합의이며 기존 일반 조회의 유효 교회 소속 조건(REC-029)을 바꾸지 않는다. 별도 목적 권한을 정의해야 한다.

앱의 논리적 진입점 후보는 ‘내 소개 공개 관리’다. 최종 화면명·API·토큰 범위·추가 인증 수단은 미선정이다. 소속 종료된 교회의 메뉴나 명단으로 들어가게 하지 않는다. 공통 로그인 성공만으로 다른 계정의 동의나 모든 과거 교회 관계를 열람할 수 없다.

| 단계 | 입력·검증 후보 | 허용 결과 | 금지/실패 경계 |
|---|---|---|---|
| W01 진입 | 현재 유효 인증·서비스 상태·철회 목적 권한 확인 | 철회 전용 절차 안내 | 구 세션/교회 관리자 확인만으로 본인 확정 금지 |
| W02 대상 확인 | 서버가 검증한 본인·교회·소개 동의 범위의 불투명 참조 | 본인이 선택할 최소 대상 식별 | 클라이언트 account/tenant 값 신뢰·이름/이메일 자동 연결 금지 |
| W03 명시 철회 | 선택 범위와 동작 확인; 최신 소유 관계 재검증 | 해당 범위 동의 철회·관련 공개 차단 | 새 동의/재게시/소개 편집/직함 복구 금지 |
| W04 결과 | 최소 결과와 현재 처리 상태를 분리 | 확인됨/확인 중 등 사실에 맞는 안내 | 응답 유실을 성공/실패로 단정하거나 자동 새 요청 금지 |
| W05 종료 | 목적 권한·기기 참조 정리 계약 | 일반 교회 기능으로 권한 확장 없음 | 소개 원문·사진·명단의 로컬 재저장 금지 |

대상 선택에 필요한 교회/공동체 표시명, 마스킹, 목록 발견 방식과 보유기한은 DG05/FD02/03에서 최소 필드를 확정한다. 기존 요청 결과의 다섯 공개 항목(REC-031)에 임의로 대상 명단/관계 참조를 추가하지 않는다. 원문·사진 없이 대상을 안전하게 구분할 수 없는 경우 추측 실행 대신 제한 확인으로 전환한다. ‘내 소개 공개 관리’가 전체 과거 이력을 무기한 열람하는 보관함이 되어서는 안 된다.

## 명령·감사·경합 연결

CMND04는 전체 해당 소개 동의 철회, CMND05는 사진만 공개 차단으로 구분한다. 이번 질문은 CMND04의 소속/직함 종료 후 최소 접근에 한정한다. 사진만 차단의 종료 후 전용 접근, 다른 공개 범위 일괄 철회, 짧은 소개 필드별 철회까지 자동 합의하지 않는다.

권한은 본인-대상 동의 결속으로 검증하고 현재 리더 자격을 요구해 철회를 막지 않는다. 게시 명령의 직함/소속 조건을 철회 명령에 복사하지 않는다. 동시에 들어온 게시/재지정/철회는 기존 서버 확정 순서와 새 동의 확인 규칙을 따르도록 기술 계약을 연결한다. 철회 전에 접수된 옛 게시가 나중에 공개를 되살리는 경로는 허용하지 않는다.

감사에는 필요한 동의/행위 참조·시각·처리 결과만 검토하며 원문·사진·토큰을 복제하지 않는다. 업무 철회 확정과 감사/결과의 일관성은 기존 커밋 후보에서 검증한다. 무권한 거절 관측은 별도 목적이며 철회 성공으로 기록하지 않는다. 중단과 물리 삭제·백업 만료는 분리하고 168시간/30일/1년을 새 소개 자료 수명으로 자동 적용하지 않는다.

## 검증 조건 및 다음 결정

CA141에 다음 조건을 연결한다: 종료된 직함을 게시 자격으로 복구하지 않고 본인 철회만 처리, 타인/다른 교회 참조 변경 거부, 원문/사진/명단 미공개, 계정 정지·탈퇴 세션 차단, 이미 철회/삭제된 대상 재생성 금지. CA142에는 응답 유실·재지정/철회 경합·복원 시 최신 차단 재적용을 연결한다. 전체 142개 시나리오는 그대로이며 실행은 모두 NOT_RUN이다.

단일 결정 질문: 공통 계정과 해당 최소 처리 이용 자격이 유효한 본인에게, 교회 소속·직함 종료 후에도 관리자 승인 없이 해당 소개 동의만 철회하는 전용 접근을 허용할까요? 권장 W-A. 교회 자료 열람·편집·재게시·다른 제품 권한은 주지 않으며 정지/탈퇴 계정은 별도 절차로 남긴다. 답변 전 상태는 PROPOSED다. 이 질문으로 DG04 전체가 해소되지는 않는다.

## r97 후속 결정 — REC-076

[REC-076 종료 후 본인 소개 동의 철회](RECOVERY_DECISIONS.md#rec-076-종료-후-본인-소개-동의-철회): 공통 계정이 유효한 본인은 교회 소속·직함 종료 후에도 관리자 승인 없이 자기 소개 동의를 철회하는 전용 접근을 허용한다. 교회 자료 열람·편집·재게시 권한은 부여하지 않고 정지·탈퇴 계정은 별도 절차로 유지한다. 위 r96 PROPOSED/질문은 당시 검토 이력이다. 현재 합의는 REC-076의 좁은 범위이며 W01~05의 필드/API/재인증/기간 후보 전체를 확정하지 않는다. DG04 일부만 합의·실행 NOT_RUN.
