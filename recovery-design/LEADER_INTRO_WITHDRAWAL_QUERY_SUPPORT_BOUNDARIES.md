Q를 소속 종료 후 확대하거나 168시간을 90일로 늘려 E를 대신 구현하지 않는다. W는 이미 철회된 결과를 무기한 조회하는 권한이 아니다. S는 Q/E가 거절한 데이터를 일반 상담 메뉴로 다시 가져오는 우회 통로가 아니다.

|---|---|---|---|---|

| S | 접수 목적·보유 중인 허용 참조·최소 확인 정보 후보 | 접수 자격과 지원 필요, 담당은 지정/배정/충돌을 별도 검증 | 최소 지원 건 생성/확인, 동의 효력 자체는 변경 안 함 | 접수 성공이 철회 성공 아님·무한 시계 연장/대신 철회 금지 |

서버가 인증한 actor를 본문 actor_id로 바꾸지 않는다. 대상/세대는 이름·시간·짧은 코드만으로 추론하지 않는다. 같은 계정이어도 다른 교회/소개/세대 요청을 혼합하지 않는다. Q/E/S의 조회나 지원 종결이 W를 호출하는 자동 연결은 두지 않는다.

## 응답·오류의 의미를 섞지 않기

- 서버 접수: 요청을 받았다는 사실만이다. 지원 접수의 성공은 철회 확정이 아니다.
- 철회 확정: 해당 동의 세대의 업무 확정이다. 이미지 저장소/백업/처리자 사본의 물리 삭제 완료를 뜻하지 않는다.
- 결과 미확인: 네트워크/커밋 결과 관측 실패다. 업무 미실행·실패로 단정하지 않는다.
- 조회 불가: 권한/기한/대상 부재를 구분할 근거가 없으면 일반 안내를 사용한다. 404만으로 과거 철회 없음·삭제 완료를 주장하지 않는다.
- 지원 확인 완료: 허용 근거로 가능한 확인 범위를 안내한 것이다. 담당이 동의를 대신 철회하거나 정정할 권한이 생기지 않는다.

정확한 HTTP 코드와 내부 오류 종류는 미선정이다. 외부 응답에는 존재/소속/개인 관계를 탐색할 차이가 없어야 하고, 내부 사유도 목적·최소 필드·접근·유한 보유가 필요하다. 모든 경우 무조건 같은 코드를 쓰겠다고 현재 API를 바꾸는 결정은 아니다. 각 계약의 오류/성공 스키마 검토가 필요하다.

## 기존 구현과 호환성

canonical v2.6의 기존 Idempotency-Key·교회/actor/경로/키 범위·24시간 영수증·만료 키 거절을 사실로 보존한다. 이것은 새로운 W/S가 이미 구현됐다는 뜻이 아니다. Q의 합의 조회 창과 저장 영수증 수명도 별개이며 별도 기록/보유 계약이 필요하다.

현재 구현의 TENANT_ADMIN 쓰기 권한을 본인 W 권한으로 재사용하지 않는다. RLS의 교회 격리는 본인/지원 목적 제한을 대신하지 않는다. 기존 API를 범용 명령 경로로 일괄 교체하거나 보존된 마이그레이션을 수정하지 않는다. W/S의 기존 경로·멱등·전용 명령 사용 여부는 호출자/실효 DB 권한 이행표와 맞춰 후속 확정한다.

한 테이블/참조를 쓴다고 목적이 합쳐지지 않는다. 반대로 목적을 나눴다고 사용자 원문을 새 DB 여러 곳에 복제하지 않는다. 실제 정본·참조·부분 삭제·감사 원자성·사본 상한은 미결이다.

## 다음 작업 — 결정 목록을 좁히기
