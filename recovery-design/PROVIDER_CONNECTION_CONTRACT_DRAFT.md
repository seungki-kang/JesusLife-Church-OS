# 제공자 연결·앱내 사용·이동·철회 계약 초안

2026-10-28 / TECHNICAL_DRAFT / PARTIAL_RECOVERY / PROVIDER_APPROVAL_PENDING / NOT_RUN

## 적용 범위

[기존 근거 대조](PROVIDER_BASELINE_ALIGNMENT.md)와 [r33 설정/배포](WHITE_LABEL_SETTINGS_DISTRIBUTION_DRAFT.md)를 잇는다. 기존 제품 방향·COS/REC 합의를 유지하며 아래 상태명·필드·기술 방식은 제안이다. 새 기간·새 공유·제공자 계약 승인을 확정하지 않는다.

사용자 결과는 “자기 교회 앱에서 허용된 기도·말씀을 쓰고, 통독/교육/실천은 필요한 제품으로 안전하게 이동하고 돌아온다”이다. 개인 제품 독립 사용은 교회 가입·Academy 도입을 의무화하지 않는다. CHGO는 사용자 SSO 대상 여섯 제품에 추가하지 않는다.

## 1. 연결을 하나의 ON/OFF로 합치지 않는다

| 축 | 정본과 의미 | 서로 대체하지 않는 것 |
|---|---|---|
| 교회 도입 | ChurchOS 교회 연결 선택 + 제공자 교회 등록/계약 | 개인 이용 시작·동의·수강·비공개 열람권 |
| 제공자 준비 | 협의된 버전/기능/운영 상태 | 앱 메뉴가 있다는 사실 |
| 공통 인증 | 검증된 계정·세션·제품 대상 토큰 | 제품 이용권·교회 역할·개인 공유 |
| 개인 제품 이용 | 해당 제품의 시작/정지/종료 | 교회 도입·유료 비용 지급 |
| 교회 소속/역할 | ChurchOS 현재 유효 근거, 제품 측 필요한 재검증 | 제공자 기도방·학습·개인 기록 권한 |
| 개인 공유/권리 | 기록 소유 제품의 대상·목적·기간·철회, 콘텐츠 판본별 이용권 | SSO·교회 관리자 직함 |
| 화면 준비 | 허용 데이터만 표시 가능한 앱 버전/렌더러 | 서버의 실제 권한 검사 |

UI 상태 후보는 미도입/준비중/이용설정필요/재인증필요/이용가능/일시불가/접근종료로 나누되 내부 차단 사유로 다른 사람의 기록·계정 존재를 노출하지 않는다. 빈 목록·접근 거부·제공자 장애·권리 미확보를 모두 데이터0건으로 표시하지 않는다.

## 2. 인증·호출·비밀 경계

- 공통 로그인 세션을 재사용해 반복 입력을 줄이되 실제 제품별 클라이언트/issuer/audience/scope/현재 상태 검사를 거친다. ChurchOS API 토큰을 그대로 모든 제품에 전달하지 않는다.
- 앱 직접 제공자 호출 또는 전용 중계 중 실제 구현 방식은 OPEN이다. 중계 도입 시에도 업무 원본·동의 원장을 ChurchOS에 복제하지 않는다. 앱용 공개 클라이언트와 서버용 비밀 클라이언트를 분리한다.
- 개인정보용 scope와 교회 운영용 scope를 분리하고, 요청 대상 교회를 앱 전달값만으로 신뢰하지 않는다. 제공자는 안정적 계정 매핑·현재 교회/제품 자격을 검증한다. 이전 표시 이름/이메일/기기 로컬 owner로 자동 귀속하지 않는다.
- 토큰·서명URL·개인 기도문·일기·답변을 일반 로그/분석/푸시/클립보드에 넣지 않는다. 민감 화면의 디버그/오류 첨부·화면 캡처 취급도 별도 검증한다.
- 기존 COS-SSO의 최대60초 차단은 그 결정이 정한 정지/탈퇴·새 공유 열람/통제 가능한 전송 범위에 적용한다. 모든 결과의 보관 시간이나 쓰기 허용 유예가 아니다. 최신성 확인 불가 시 민감 조회/쓰기를 허용하지 않는 방식의 세부 계약·장애 동작은 검증 대상으로 둔다.

## 3. 앱내 열람과 작성

개인 기도수첩 화면은 JLPrayer가 본인임을 확인해 허용한 필드만 임시 표시한다. 개인 수첩의 서버 저장·버전 충돌·응답/수정/삭제·공유는 JLPrayer 책임이다. ChurchOS 일반 DB/공지 검색/교회 감사에 원문을 쌓지 않는다. 개인화 기능을 위한 중계 캐시·오프라인 원문 저장은 승인 전 제공하지 않는다. 앱 종료/로그아웃/계정 전환 시 잔여 상태를 정리하고 진행 응답은 계정/세션 문맥에 결속한다. 교회 전환 시 공동체 화면과 요청을 분리하며 개인 화면의 유지/초기화 방식은 제공자 계정 문맥을 포함해 확정한다.

본인 기록을 공동기도로 옮기는 동작은 별도 게시 요청이다. 개인 수첩 공개 범위를 자동 변경하지 않고, 대상 교회/기도방·표시 범위·검토 여부를 사용자가 확인한다. 정확한 게시 필드·검토 정책·신고/철회 담당은 OPEN이다. 기도방 탈퇴·기도 요청 철회·개인 수첩 삭제·교회 탈퇴는 다른 동작이다.

성경/찬송은 판본·콘텐츠 버전·기능별 권리를 제공자가 판정한다. 글자 크기 같은 기기 표시 설정과 북마크/마지막 위치/통독 원장을 분리한다. 권리 없는 가사·악보·녹음·다운로드를 다른 웹사이트 수집으로 대신하지 않는다. 캐시 기간/회수 방식은 권리 계약별 OPEN이며 공지의7일 또는 요청168시간을 복사하지 않는다.

## 4. 전문 앱 이동과 복귀

기존 handoff 요구: 단회·최대10분·정확히 등록한 return URI·주체/교회/제공자/기능 결속·제공자 재검증. bearer 토큰을 URL로 전달하지 않는다. 서버 저장 시 원 토큰 대신 해시를 사용한다. 앱의 원시 return URL 입력을 신뢰하지 않는다.

추가 후보: 요청 앱/세션과 돌아올 화면을 민감 본문 없는 opaque 참조로 결속하고, 외부에서 전달한 임의 경로를 실행하지 않는다. handoff 사용은 제품 이용 시작·교회 승인·개인 공유 승인을 대신하지 않는다. 만료/취소/이미 사용은 새 사용자 동작으로 재시작하며 같은 토큰을 재사용하지 않는다. 브라우저/앱 취소·미설치·다른 계정 로그인·교회 전환 후 복귀를 검증한다. 외부 앱 설치가 성경/찬송 기본 열람의 필수가 되어서는 안 된다. 제공자 미준비 시 실제 앱내 기능이 되는 것처럼 외부 링크로 위장하지 않는다.

복귀 성공 신호는 기록 작성/과제 완료/수료의 증거가 아니다. 특히 생명일기의 복귀 파라미터·분석 이벤트·알림에서 작성 여부/회차/날짜를 우회 수집하지 않는다. 원래 앱 문맥이 사라지면 안전한 홈/재선택으로 안내하는 후보이며 임의 계정에 결과를 붙이지 않는다.

## 5. 이벤트·중복·늦은 응답

최소 교환 후보: schema_version, event_id, 발생 시점, 제공자/대상, 목적별 opaque 참조와 상태 버전. 실제 필드/서명/순서/재전송/수명은 양측 계약 전 DRAFT. 개인 원문을 범용 payload에 넣지 않는다. 이벤트는 현재 권한의 대체 증명서가 아니다. 지연·중복·역순 전달을 처리하고 옛 연결/옛 교회 응답을 새 화면에 표시하지 않는다.

제품 쓰기는 제공자 멱등/충돌 계약이 필요하다. ChurchOS 영수증24시간이나 일반 조회168시간을 제공자에 강제 승계하지 않는다. 응답이 없으면 결과 불명으로 두고 해당 제품에서 결과 확인 후 재시도한다. 앱 재시작·타임아웃·연결 해제 직전 전송을 이유로 자동 중복 작성하지 않는다. [접수/실행/확정 설계](ACCEPT_EXECUTE_FINALIZE_DRAFT.md)의 공통 원칙과 실제 제공자 계약 차이를 명시한다.

## 6. 연결 해제·서비스 종료·장애

| 사용자 동작/사건 | 처리 경계 |
|---|---|
| 교회가 메뉴를 감춤 | 표시 설정. 계정/수강/개인 데이터 삭제나 공유 철회 아님 |
| 개인 연결 해제 | 새 연결 토큰/상태 갱신·미사용handoff·연결용 최소 캐시 처리. 제품 계정 종료 아님 |
| 교회 제공자 도입 종료 | 교회 연결 범위 중단과 개인 독립 이용 분리. 진행 중 수강/교회 자료 인계는 제공자 계약 필요 |
| 교회 탈퇴/역할 해제 | 해당 교회 근거 재검증. 다른 교회·개인 수첩·개인 통독 포괄삭제 금지 |
| 개인 공유 철회/정지 | 소유 제품이 현재 권한/전송 차단을 책임지고 ChurchOS 잔여 표시 제거. 이미 전달된 외부 사본의 일괄 회수 보장 금지 |
| 제품 탈퇴/공통 탈퇴 | 기존 COS-SSO별 기산점·대상·삭제/백업·최소 이력 규칙 적용. 연결 끊기를 탈퇴 완료로 표시하지 않음 |
| 제공자 장애/회복 | 카드·기능별 격리. 권한/만료가 불명인 민감 캐시로 우회하지 않음. 회복이 공유 재동의/자동 재실행을 뜻하지 않음 |

철회/해제와 경합하는 요청은 제공자 측 최종 권한·확정 결과로 판정하며 시간만으로 성공/실패를 추정하지 않는다. 처리 중 작업 취소 가능 여부·실제 전달된 입력 회수·외부 처리자 보유/삭제 증거는 별도 계약이다. 모든 연결 해제에7일삭제/30일백업을 일괄 부여하지 않는다.

## 7. 제공자 인수 전 필수 증거

실제 운영 주체와 확인 시점, 계약 버전·지원 기능, API/이벤트 schema, 토큰 대상/클라이언트, 계정/교회 식별, 권한 최신성/철회, 원본/최소 캐시/삭제·복원, 앱 링크/복귀, 오류·중복·충돌, 콘텐츠 권리, 장애/지원 담당을 제공자별로 확인한다. 샘플 토큰/개인 원문/비밀을 ZIP에 첨부하지 않는다.

문서가 있어도 양측 승인→검증 환경→실제 연동 검증→운영 준비를 구분한다. 이번 문서는 소비자 설계 초안이며 API 경로·scope·운영 제공자 선정은 확정하지 않는다.
