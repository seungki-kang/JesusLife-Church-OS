# 일반 업무 요청 기록의 목적별 수명·삭제 설계

> 현재성 안내: 부분 합의·과거 제안·기술 초안을 구분합니다. [결정 색인](RECOVERY_DECISIONS.md)과 [현재 상태](../START_RECOVERY_CURRENT.md)을 함께 읽으세요. 상단 AGREED가 모든 기술 항목의 승인을 뜻하지 않습니다.

2026-10-27 / 목적별 보유·삭제 기준 분리 원칙 AGREED / 실제 기간·기술 세부 PROPOSED 또는 OPEN / 구현·실행 NOT_RUN

확정 근거: 사용자가 목적별 수명 분리 원칙에 “네”로 동의했다. 조회용 데이터·중복 방지·업무 원본·감사·기기 참조·조사 기록을 목적별로 구분하고, 조회 168시간을 일괄 삭제 기한으로 적용하지 않는다. 실제 보유 기간·삭제 시한·백업 상한의 일괄 승인이 아니다.

## 1. 범위와 대조 근거

누적 r21을 이어 일반 업무 요청 처리 기록을 분류한다. 기존 계정·교회 탈퇴 정책을 이번 설계로 변경하지 않는다. 직접 확인한 ACCOUNT_MEMBERSHIP_SERVICE_SCOPE_CONTRACT.md의 COS-JOIN-055/058/059 및 COS-SSO-011/032는 특정 정정·종료 처리 이력에 대한 별도 범위다. 그 1년·7일·30일을 모든 일반 업무 기록의 보유 기한으로 확대하지 않는다. 이 문서는 법정 보유 기간을 정하거나 적법성을 판정하는 문서가 아니다. 부분 복원 유지.

## 2. 여섯 종류의 기록

| 종류 | 목적과 최소 범위 | 현재 확정 또는 신규 제안 | 미결 |
|---|---|---|---|
| 일반 사용자 상태 조회용 데이터 | 본인 요청의 다섯 공개 항목 | 미확정 최초 접수+168시간, 최종 실제 확정+168시간 조회 차단은 AGREED | 물리 분리·실제 삭제 완료 시한 |
| 중복 방지 기록 | 같은 요청의 재실행 차단에 필요한 보호된 키·검증 참조·실행 확정 여부 | 조회용 데이터와 분리하고 공개 API로 노출하지 않는 안 | 실행 유효 기한·보유 상한·키 만료·삭제 후 안전성 |
| 업무 원본 | 교회 업무의 실제 변경 결과 | 조회 화면 만료로 자동 삭제하지 않는 기존 취지 유지 | 업무 종류별 수명·탈퇴 후 소유/삭제 경계 |
| 일반 업무 감사 기록 | 누가 어떤 허용 행위를 언제 확정했는지 최소 추적 | 원문·전체 요청·응답 복제 금지, 별도 권한 제안 | 목적·필드·기간·예외 승인·삭제 시한 |
| 기기 확인 참조 | 앱 재시작 후 본인 결과 조회 연결 | 로그아웃·다른 계정 전환 제거, 교회 전환 격리 AGREED | 기기 보유 상한·정리 실패·백업 제외 기술 |
| 조사 중 확인 기록 | 결과 불명·보안 이상을 조사 | 업무/원문 전체 복사 없이 필요한 참조만 한정하는 안 | 조사 권한·담당·종결 기준·보유 상한 |

조회용 데이터란 일반 사용자에게 제공하는 논리적 범위다. 별도 테이블 구현을 이미 선택했다는 뜻이 아니다. 동일 저장소를 사용해도 목적별 접근·기한·삭제 대상을 구분해야 하며, 한 필드의 만료가 다른 목적의 보유 권한을 자동 생성하지 않는다.

## 3. 권장 수명 분리 원칙

조회 168시간이 지나면 직접 조회·발견 목록·페이지·캐시·늦은 응답 모두에서 해당 상태의 일반 공개를 중단한다. 배치 삭제가 늦어도 공개 차단을 늦추지 않는다. 공개를 막았다고 물리 삭제가 완료됐다고 표시하지 않는다.

상태 조회용 데이터만 제거하는 경우, 별도 승인 목적과 유효 기한이 있는 중복 방지·업무 원본·최소 감사 기록을 자동 연쇄 삭제하지 않는다. 반대로 다른 기록이 남아 있다는 이유로 일반 사용자 조회를 연장하거나 내용 전체를 감사 기록에 복제하지 않는다.

별도 목적·접근 주체·기산점·상한·정리 방식이 결정되지 않은 기록을 무기한 보유하지 않는다. 필요한 보유 계약과 구현 검증이 끝나기 전 해당 기능을 운영 적용하지 않는다. 이 설계에서 ‘미결’은 영구 보관 허가가 아니다.

## 4. 중복 방지와 삭제의 선행 조건

최소 중복 방지 기록을 지운 뒤 과거 요청을 새 요청으로 실행하면 안 된다. 삭제 전에는 해당 요청이 이후 도착·재전송·복원돼도 실행될 수 없다는 조건을 계약과 서버로 강제해야 한다. 후보는 서버가 검증할 실행 유효 기한과 보호된 최소 재사용 차단 표식이다. 특정 기법은 아직 확정하지 않는다.

‘기록 없음=최초 요청’ 가정은 기록 손실·만료·복구 환경에서 안전하지 않다. 최초 접수 여부와 실행 안전성을 확인하지 못하면 신규 실행을 차단하고 수동 확인한다. 다른 새 요청 식별자를 발급하는 것으로 중복 실행 위험을 해결했다고 간주하지 않는다.

## 5. 삭제 사건별 영향

| 사건 | 즉시 필요한 경계 | 자동으로 일어나면 안 되는 일 |
|---|---|---|
| 일반 조회 기간 만료 | 일반 공개 차단 | 업무 실패 확정·원본 삭제·키 재사용 허용 |
| 기기 참조 제거 | 기기 접근 정리·늦은 응답 차단 | 서버 취소·서버 삭제·자동 재실행 |
| 업무 권한 해제 | 미확정 쓰기 차단 및 후속 실행 제한 | 합법적으로 이미 확정된 업무의 자동 삭제 |
| 계정·교회 소속 무효/확인 불가 | 최소 상태 존재까지 비공개 | 단순 확인 장애를 탈퇴 확정으로 처리 |
| 서버가 탈퇴 확정 | 기존 탈퇴 범위·기한·예외 계약 적용 | 이번 일반 요청 정책으로 기존 삭제 의무를 우회 |
| 조사 목적 종료 | 승인된 보유 상한과 정리 절차 적용 | ‘나중에 필요할 수 있음’만으로 무기한 연장 |

## 6. 백업·복원

일반 업무 요청 데이터의 백업 잔존 상한을 이번 문서에서 임의로 새로 정하지 않는다. 기존 COS-JOIN-059의 운영본 삭제 후 최대 30일은 그 조항의 정정 최소 이력에 적용한다. 다른 기록에 적용하려면 별도 결정이 필요하다.

복원 공개 전에 최신 삭제·계정·소속·권한·요청 실행 확정 상태를 재적용해야 한다. 요청 상태 조회 기간도 실제 원래 접수·확정 시각으로 판정하며 복원 시각으로 초기화하지 않는다. 유효성 확인 전 조회·명령 재실행·알림 발행을 보류한다. 삭제 표식 및 재실행 차단 자료의 보호·수명도 함께 설계해야 한다.

## 7. 개발 전 필수 수명 계약표

각 기록마다 데이터 소유 주체, 수집 목적, 최소 필드, 일반 사용자/운영자 접근, 기산 사건, 보유 상한, 물리 삭제 완료 시한, 예외 근거·승인·종료, 백업 상한, 복원 필터, 삭제 확인 근거를 작성한다. 전체 원문이나 토큰을 삭제 증거에 넣지 않는다.

미확정 일반 조회 만료 뒤 조사가 계속되는 경우 담당·한정 목적·종결 기준·검토 주기가 필요하며 공개 화면 만료를 조사 종결로 조작하지 않는다. 최초 장애부터 24시간 내 수동 확인 이관 합의는 그대로 유지한다.

## 8. 설계 검토 조건 — 실행 테스트 아님

- 조회 차단과 물리 삭제 완료를 구분해 보고한다.
- 일반 조회 만료가 중복 방지 키 재사용을 허용하지 않는다.
- 감사·조사 기록에 원문·전체 요청을 무분별하게 복제하지 않는다.
- 탈퇴 시 기존 삭제 범위·기한을 일반 요청 정책으로 무효화하지 않는다.
- 백업 복원으로 공개 기한·권한·삭제된 상태가 되살아나지 않는다.
- 수명 미결을 무기한 보유 기본값으로 구현하지 않는다.
