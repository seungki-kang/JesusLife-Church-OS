## 확정 공개 항목

| 화면 항목 | 서버 의미 | 표시 조건 |
|---|---|---|
| 요청 확인 번호 | 한 요청을 구분하는 불투명 식별자 | 유효한 본인·선택 교회 소속 확인 후 |
| 처리 상태 | 서버가 확인한 현재 상태 | 미확정은 완료·실패로 추정하지 않음 |
| 서버 접수 시각 | 실제 최초 서버 접수 시각 | 기기의 송신 시각과 구분 |
| 최종 확정 시각 | 실제 최종 결과 확정 시각 | 최종 완료·거절일 때만 |
| 현재 상태 조회 종료 시각 | 현재 상태에 적용되는 기한 | 미확정은 접수+168시간, 최종은 확정+168시간 |

화면 항목에 대한 제안이며 정확한 JSON 키·ID 형식·시각 정밀도·스키마는 미결이다. 확인 번호를 짧게 보여줄 경우 서로 다른 요청이 같은 것으로 보이지 않는 표시 규칙이 필요하며, 짧은 번호를 권한이나 유일 식별자로 사용하지 않는다.

## 공개하지 않는 항목

이 화면에는 업무 종류·업무 제목·대상 이름·대상 식별자·명단·본문·첨부·수정 전후 값·자유 서술·상세 거절 사유·전체 감사 이력·다른 사람의 요청·전체 건수를 넣지 않는 안을 권장한다. 원문 요약·AI 요약·검색 결과 미리보기로 우회 노출하지 않는다. 개인 기도·일기·문답·교육 참여 정보를 결합하지 않는다.

교회 관리자 또는 유효한 업무 권한을 가졌더라도 이 응답을 확장하지 않는다. 업무 상세가 필요하면 별도 현재 권한을 검증하는 업무 화면으로 이동한다. 결과 확인 화면 자체는 복구·취소·정정·재실행 버튼을 제공하지 않는다.

## 상태 표기와 예외

- 처리 중: 서버 접수 이후 최종 결과를 아직 확인하지 못함.
- 완료: 실제 업무 확정 성공. 이 표기만으로 업무 상세 접근 권한은 생기지 않음.
- 처리 안 됨: 변경 없이 거절된 최종 결과가 확인됨. 상세 사유는 이 화면에서 제외.
- 확인 필요: 운영 확인 필요 상태. 실패 확정이나 다시 저장하라는 의미가 아님.
- 통신 단절: 서버 상태를 임의 변경하지 않고 ‘결과를 확인하지 못했습니다’라는 앱 안내로 구분.

정확한 상태명과 문구는 여전히 초안이다. 서버 접수·최종 확정 시각을 신뢰할 수 없으면 현재 시각으로 대체하지 않는다. 복구·조사 절차로 넘긴다. 정렬·페이지 커서 등의 기술 필드는 화면 공개 항목과 분리하고 데이터 누출 없이 검토한다.

## 조회 경계

매 조회·페이지 이동·화면 복귀에 필요한 현재 계정·교회 소속 검증을 수행한다. 소속 상실이나 확인 불가이면 확인 번호·상태·시각도 공개하지 않는다. 기존 화면의 보호 데이터를 재사용해 먼저 보여주지 않는다. 권한 검증과 응답 전달 사이 변경의 기술 제어는 후속 계약이다.

기기 확인 기록은 결과 캐시가 아니므로 이번 공개 항목을 기기에 영구 저장하도록 승인하지 않는다. 로그·푸시·오류 수집에 그대로 복제하지 않는다. 표시 시간은 교회 기준, 기기 현지 시각은 필요한 경우 보조 표시다.

## 설계 검토 조건 — 실행 결과 아님

동일 요청의 목록·직접 조회가 서로 다른 내용을 공개하지 않아야 한다. 최종 확정 전에는 최종 확정 시각이 없어야 한다. 조회 만료 및 소속 상실 뒤에는 항목을 다시 공개하지 않아야 한다. 같은 시각에 여러 요청이 있어 구분하기 어려워도 이름·내용을 자동으로 추가하지 않아야 한다. 이런 경우 실제 업무 확인이나 허용된 수동 확인으로 연결한다.
