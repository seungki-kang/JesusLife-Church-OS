# 처리 확인 공통 항목과 미확정 조회 기간

> 현재성 안내: 부분 합의·과거 제안·기술 초안을 구분합니다. [결정 색인](RECOVERY_DECISIONS.md)과 [현재 상태](../START_RECOVERY_CURRENT.md)을 함께 읽으세요. 상단 AGREED가 모든 기술 항목의 승인을 뜻하지 않습니다.

2026-10-27 / 미확정 일반 조회 기간 AGREED / 다섯 공개 항목은 후속 REC-031 AGREED / 필드명·기술 세부 DRAFT / 구현·실행 NOT_RUN

확정 근거: 사용자가 직전 ‘최초 서버 접수부터 168시간’ 확정 질문에 “네”로 동의했다. 미확정 조회 만료 이후에도 실제 최종 확정이 발생하면 그 실제 확정 시각부터 기존 최종 조회 168시간을 적용한다. 응답 필드·서버 보유·기기 수명·운영 기술은 이번 확정 범위가 아니다.

## 1. 이어받는 기준

누적 r17의 본인 요청 발견 범위 및 기존 직접 최소 상태 조회 합의를 유지한다. 이번 문서는 미확정 기한은 REC-030, 다섯 공개 항목은 후속 REC-031 합의이며 정확한 필드명은 DRAFT다. 다른 제품·가입 심사·개인 기록 조회로 확대하지 않는다. 부분 복원 상태 유지.

## 2. 공통 응답·화면 후보

| 항목 후보 | 목적 | 조건 |
|---|---|---|
| request_id | 같은 요청을 식별 | 확인 번호로 표시, 권한 증거 아님 |
| status | 처리 중·확정 완료·확정 거절·확인 필요 구분 | 상태명은 기존 계약 후보, 미확정을 완료로 바꾸지 않음 |
| accepted_at | 서버 최초 접수 시각 | 기기 송신 시각과 다름. 실제 서버 접수 기록이 있을 때만 |
| confirmed_at | 실제 최종 확정 시각 | 확정 완료·거절에만 제공, 미확정에는 없음 |
| query_expires_at | 현재 상태의 조회 종료 시각 | 아래 기간 제안에 따라 서버 계산 |

목록과 직접 조회에 같은 공개 상한을 적용하는 안이다. 별도 업무 권한이 있어도 이 화면의 응답에 업무 내용·이름·대상·변경 값·거절 상세를 덧붙이지 않는다. 업무 상세는 현재 권한으로 별도 조회한다. 본인·교회 참조를 응답마다 중복 노출할 필요는 없으며 서버는 인증된 계정과 교회 컨텍스트로 검증한다.

r10의 status_expires_at 및 r16의 submitted_at은 과거 후보 필드다. 이번에는 서버 실제 접수와 기기 제출을 구분하기 위해 accepted_at과 query_expires_at을 후보로 제안한다. 기존 API를 개명하거나 호환성을 변경한 것이 아니다. 실제 필드명·스키마 버전·기존 호출자 대조는 아직 OPEN이다.

## 3. 미확정 조회 기간 — AGREED

서버에서 실제 최초 접수를 확인한 시각부터 최대 168시간 동안 미확정 최소 상태를 직접 조회하거나 발견 목록에서 찾을 수 있도록 한다. 처리 중·수동 확인 필요 상태에 같은 기산점을 사용한다. 조회·로그인·기기 변경·알림·재시도·운영 이관으로 시간을 초기화하지 않는다.

서버 접수를 확인하지 못한 앱의 결과 불명은 이 기산점을 임의 생성하지 않는다. 서버가 접수를 확인할 수 없거나 복구 중이면 요청 존재·결과를 추정하지 않고 일반 확인 안내와 허용된 수동 확인 경로를 제공한다.

168시간 제안의 목적은 사용자 화면에서 무기한 요청 활동 목록을 유지하지 않으면서 통신 장애·재로그인 후 확인할 시간을 제공하는 것이다. 실제 운영 자료로 산정한 수치는 아니며 2026-10-27 사용자 동의로 채택한 설계 정책이다. 장애 해결 시간을 7일로 늘리는 제안이 아니다. 기존 24시간 내 수동 확인 이관 원칙은 유지한다.

## 4. 최종 확정 전후의 두 기한

| 상태 | 기산점 | 조회 종료 |
|---|---|---|
| 미확정 | 실제 최초 서버 접수 | 접수 + 168시간: 이번 합의 |
| 최종 확정 | 실제 최종 서버 확정 | 확정 + 168시간: 기존 합의 |

미확정 조회가 만료돼도 실제 업무·조사·중복 방지 기록을 자동 종료·삭제하지 않는다. 최종 결과가 나중에 실제 확정되면 그 실제 확정 시각부터 기존 최종 조회 기한을 적용한다. 이는 실제 사건에 따른 상태 전이이며 재시도에 의한 기한 초기화가 아니다. 실제 최종 확정 기록을 임의 재작성해 기한을 연장할 수 없다. 이미 최종 확정된 요청을 미확정으로 되돌리거나 재접수해 기산점을 바꾸지 않는다.

예: 서버 접수 후 8일 동안 최종 결과가 확정되지 않았다면 미확정 일반 조회에서는 제외한다. 9일째 실제 최종 결과가 확정됐다면 그때부터 168시간 동안 유효한 본인·교회 소속 검증 후 최소 최종 상태를 조회할 수 있다. 조사 담당자의 최소 접근·보유·정리·연락 절차는 별도 계약이며 무기한 보유 허용을 뜻하지 않는다.

## 5. 만료와 안내

일반 안내는 ‘조회할 수 있는 처리 결과가 없습니다. 저장 여부를 단정하지 말고 현재 업무 상태를 확인해주세요.’를 후보로 둔다. 타인·타 교회·미존재·기간 만료를 비인가자에게 구분해 알려주지 않는다. 접근 확인 불가 시 목록을 빈 성공 응답으로 처리하기보다 접근 확인 안내를 제공하는 명세가 필요하다. 정확한 HTTP 코드는 미결이다.

조회 종료가 실제 업무 실패·원본 삭제·요청 키 재사용 허용·재실행 승인으로 해석되지 않게 한다. 요청 원문이 확인 화면·로그·문의 자동 첨부로 다시 노출되지 않게 한다. 서버 기록이 없어 중복 여부를 증명하지 못하면 새 실행을 차단하고 현재 권한으로 확인한다.

## 6. 기존 정책과 관계

- 권한 해제만으로 유효 계정·소속인 본인의 최소 상태 조회를 모두 차단하지 않는 기존 원칙 유지.
- 계정·교회 소속이 무효하거나 확인 불가하면 기한이 남아도 요청 존재·시각·개수 비공개.
- 교회 기준 시간으로 표시하되 상대 168시간은 실제 경과 시간으로 계산.
- 기기 확인 기록·서버 감사·중복 방지·백업의 보유 기간을 이 숫자로 일괄 지정하지 않음.
- 상세 기술·운영 담당자·확정되지 않은 장애 판정 수치는 여전히 OPEN.

## 7. 설계 수용 조건 — 실행한 테스트 아님

- 접수 + 168시간과 같은 시각부터 미확정 일반 조회 차단.
- 최종 확정 + 168시간과 같은 시각부터 최종 일반 조회 차단.
- 미확정 조회 만료 후에도 업무 상태를 거절·완료로 조작하지 않음.
- 실제 뒤늦은 최종 확정은 실제 시각으로만 최종 기한 계산.
- 목록·직접 조회·다음 페이지가 같은 기간·소속 경계를 적용.
- 재로그인·교회 전환·재시도·이관이 어느 기산점도 초기화하지 않음.

## 8. 확정 질문과 답변

미확정 요청의 일반 조회 기간을 ‘최초 서버 접수부터 최대 168시간’으로 정할까요?

답변: 네. 2026-10-27 설계 합의. 실제 최종 확정 뒤에는 기존 합의대로 그 확정 시각부터 168시간을 적용합니다.

이 질문은 미확정 일반 조회 기간과 실제 최종 전환 시 기존 기한을 적용하는 운영 결과에 한정한다. 응답 필드·서버 보유·조사 담당자·기기 수명·API 기술 전체를 확정하지 않는다.

출처 주의: 일반 장애 24시간 수동 이관의 근거 범위는 [결정 색인](RECOVERY_DECISIONS.md)의 REC-017 항목을 단일 기준으로 따른다.
