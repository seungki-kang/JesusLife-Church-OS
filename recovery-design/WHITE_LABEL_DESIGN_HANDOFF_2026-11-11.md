# ChurchOS 화이트라벨 기획·첫 버전 화면 설계 인계

2026-11-11 · 설계 검토용 · 앱/API 구현과 실제 사용성 검증 미실행

이 문서는 교회별 디자인 제공, 쉬운 설정, 방문 안내, 첫 버전 화면 설계를 한곳에 모은 인계용 요약이다. 기존 [화이트라벨 설정 계약](WHITE_LABEL_SETTINGS_DISTRIBUTION_DRAFT.md)과 [교회 소개 게시 인계](CHURCH_INTRO_RELEASE_HANDOFF_DRAFT.md)의 승인·미결 범위를 유지한다.

## 1. 제품 방향과 교회별 디자인

- 공용 ChurchOS 앱을 기본으로 제공한다. 앱 안에서 교회의 이름·로고·대표색·사진과 사역이 먼저 보이게 한다. 휴대폰에 설치되는 앱 이름과 아이콘은 공용 앱 기준이다. 교회 전용 앱은 별도 배포 검토다.
- 교회는 첫 화면의 목적과 콘텐츠를 선택한다. ChurchOS는 공통 버튼·카드·메뉴 사용법, 글자·간격·오류 표시·접근성·권한을 관리한다. 세 추천 구성은 같은 부품의 순서만 다르게 제안한다.
- 담임목사는 도입과 목회 방향을 결정한다. 설정·편집·게시는 해당 교회에서 현재 권한을 받은 담당자가 수행한다. 직함만으로 권한을 주지 않는다.
- 기존 설계 결정 COS-CHURCH-041에 따라 목회철학·사명·비전은 각각 추가하거나 생략할 수 있다. 셋 다 작성하지 않아도 시작할 수 있다. 추가한 콘텐츠의 공개 범위와 게시 여부는 별도로 설정한다.
- 기본형은 교회가 직접 설정하고, 도입 지원형은 같은 앱에서 자산 정리와 초기 시안을 돕는 제안이다. 지원량·가격과 전용 스토어 배포는 아직 확정하지 않는다.

## 2. 첫 화면과 대상별 추천 구성

| 공통 부품 | 적용 기준 |
|---|---|
| 현재 교회 상단 | 이름을 읽을 수 있어야 한다. 로고·사진이 없거나 로딩에 실패하면 같은 교회 이름으로 표시한다. 다른 교회의 자산을 대체로 쓰지 않는다. |
| 핵심 행동 | 해당 대상이 실제 이용할 수 있는 게시 콘텐츠가 있을 때 버튼 한 개를 우선한다. 자료가 없으면 승인된 대안만 표시하고, 대안도 없으면 영역을 접는다. |
| 보조 카드 | 선택된 공개 설교·예배 안내·교회 소개 또는 권한 있는 교인용 공지·일정을 표시한다. 같은 목적지를 중복 배치하지 않는다. |
| 공통 메뉴 | 교회 설정으로 필수 계정·복구·탈퇴 경로를 없애지 않는다. |

| 추천 구성 | 방문자·가입 대기자 첫 행동 | 유효 교인 첫 행동 |
|---|---|---|
| 예배 중심 | 예배 시간과 장소 | 예배 시간과 장소 |
| 말씀 중심 | 최근 공개 설교 | 열람 가능한 최근 설교 |
| 공동체 중심 | 예배 안내 | 열람 가능한 교회 일정 |

추천을 변경해도 기존 글·예배 시간·공개 대상은 바뀌지 않는다. 교회가 고르고, 현재 게시되어 있고, 대상이 열람할 수 있는 콘텐츠만 표시한다. 카드 제목·요약·개수·직접 링크에도 같은 기준을 적용한다. 방문자와 가입 대기자에게 내부 공지나 교인 전용 일정을 보이지 않는다. 대표색은 대비가 확인된 방식으로 적용하고, 부족하면 대체색을 먼저 보여준다. 긴 교회명·큰 글자·작은 화면·스크린리더를 검수한다.

## 3. 담당자의 쉬운 설정

1. **교회 확인:** ‘우리 교회 화면 꾸미기’에서 교회 이름을 확인한다. 로고·사진·대표색은 나중에 추가할 수 있다.
2. **추천 화면 선택:** 예배·말씀·공동체 중 시작 구성을 제안한다. 추천은 미리보기에만 반영한다. 선택하지 않은 항목을 자동 게시하거나 빈 카드로 내보내지 않는다.
3. **미리 보고 적용:** ‘지금 화면 / 바뀔 화면’과 ‘방문자 / 교인’을 비교한다. ‘로고만 변경’처럼 바뀌는 내용을 보여준다. 초안은 나중에 이어서 할 수 있고, 게시 직전에는 교회·현재 권한·검토 버전을 다시 확인한다.

설명이 필요한 곳에 무엇이 바뀌는지, 누가 볼 수 있는지, 다음에 무엇을 하면 되는지를 짧게 표시한다. 예: “홈에서 빼면 교회 소개에서는 계속 볼 수 있어요. 게시를 끝내면 기존 링크로도 볼 수 없어요.” 권한이나 연결 상태를 확인할 수 없으면 완료로 표시하지 않는다. 게시 응답이 끊겨도 새 게시를 자동 실행하지 않는다.

## 4. ‘우리 교회 방문 안내’

- 첫 버전은 **공개 예배 안내 한 곳을 홈과 상세에서 함께 읽고, 관리자가 ‘처음 온 사람처럼 열어보기’로 교회 이름→예배 시간·장소를 확인하는 흐름**을 우선한다. 교회가 원할 때만 켠다. 게시한 정보가 없으면 빈 카드나 예시 일정을 실제 화면에 내보내지 않는다.
- 초대 링크와 인쇄 주보 QR은 설치 유무·설치 후 교회 연결·동명 교회 구분을 검증한 뒤 제공한다. QR에 시간을 고정해 넣는 대신 안정적인 공개 안내를 가리키는 제안이다. 안내 링크를 열었다고 가입을 승인하거나 권한을 부여하지 않는다. 별도 공개 웹을 전제로 삼지 않는다.
- ‘오늘만 달라요’ 예배 안내, 절기 강조 카드, 자동 종료는 후속 검토다. 평소 예배 시간을 덮어쓰지 않고 날짜와 시간대를 명시하며, 만료된 안내가 남지 않는 동작을 검증한 뒤 도입한다.

## 5. 실행 전 검증 과업

아래 12개는 기존 화면 설계 과업을 요약한 것이다. 실행 상태는 모두 미실행(NOT_RUN)이다.

| ID | 통과 기준 |
|---|---|
| HOME-WL-01 | 로고·사진·소개 세 항목 없이도 교회 이름과 공개 예배 안내를 확인한다. |
| HOME-WL-02 | 세 추천 구성에 공통 부품이 사용되고 우선순위만 바뀐다. |
| HOME-WL-03 | 내부 일정·공지·건수는 열람 권한이 있는 교인에게만 보인다. |
| HOME-WL-04 | 게시된 자료가 없을 때 미리보기에서만 대안을 안내하고 실제 홈에는 빈 버튼이 없다. |
| HOME-WL-05 | 현재 공개본을 읽는 온라인 홈과 상세의 예배 시간이 일치한다. |
| HOME-WL-06 | 게시 종료 후 새 열람에서 기존 안내가 되살아나지 않는다. |
| HOME-WL-07 | 비교 미리보기는 실제 게시·권한·소속을 변경하지 않는다. |
| HOME-WL-08 | 교회·권한·검토 버전이 달라지면 기존 미리보기로 게시하지 못한다. |
| HOME-WL-09 | 교회 전환 중 늦은 응답이 현재 교회 화면에 섞이지 않는다. |
| HOME-WL-10 | 연결 실패를 정보 없음으로 처리하지 않고 보호 자료를 노출하지 않는다. |
| HOME-WL-11 | 작은 화면·큰 글자·긴 이름·스크린리더에서 교회와 핵심 행동을 찾을 수 있다. |
| HOME-WL-12 | 구성 변경 후에도 기존 글·공개 범위·필수 계정 메뉴가 유지된다. |

## 6. 다음 작업과 범위

다음은 동일한 화면 부품으로 세 추천 구성을 **직접 눌러볼 수 있는 시안**으로 만드는 단계다. 처음 온 사람이 예배 시간과 장소를 찾는지, 담당자가 안내문 없이 구성을 고르고 변경 내용을 설명할 수 있는지를 관찰한다. 시안 결과와 실제 운영 검증은 구분한다.

게시 위임의 세부 범위, 소개 본문 온라인 확인과 기존 공개 캐시의 경계, 기록 보유·삭제 기한은 기존 초안의 미결을 유지한다. 이 문서의 추가로 앱 구현이나 운영 정책 승인 상태가 바뀌지 않는다.
