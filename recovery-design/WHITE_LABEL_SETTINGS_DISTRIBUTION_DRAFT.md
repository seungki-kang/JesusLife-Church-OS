# 화이트라벨·교회 설정·배포·업데이트 계약

2026-10-28 / 기존 제품 방향 유지 + TECHNICAL_DRAFT / PARTIAL_RECOVERY / 실제 설정·배포 NOT_RUN

## 경계와 근거

[현재 구현 대조](WHITE_LABEL_BASELINE_ALIGNMENT.md), [기존 제품 관계](../docs/operations/ecosystem-v1/PRODUCT_RELATIONSHIPS.md), [앱 전용 운영](../docs/operations/ecosystem-v1/APP_ONLY_OPERATIONS.md), [가입/관리자 계약](ONBOARDING_APP_STATE_CONTRACT_DRAFT.md)을 따른다. ChurchOS는 교회 앱의 진입점이며 최종 브랜드명은 미정이다. 지저스라이프 원은 내부 생태계 이름으로 앱명·스플래시·로그인·메뉴에 노출하지 않는다. 독립 제품/서버·API·개인 데이터 소유는 그대로다.

두 배포 유형과 공통 코드 사용은 기존 방향이다. 아래 설정 상태·권한 세부·버전/출시/복구 방식은 후속 후보이며 새 운영 정책 승인·공급자 선정·실제 출시 준비 완료가 아니다. 교회 일상 관리에는 별도 웹을 필수로 두지 않지만 서버 운영·서명·스토어 계정·보안 배포를 교인 앱 업무로 노출하지 않는다.

## 배포 유형과 책임

| 유형 | 사용자 경험과 변경 범위 | 운영 책임 후보 |
|---|---|---|
| 공용 앱 INSTANT | 하나의 배포 앱에서 선택 교회의 앱 내 이름/로고/색/허용 메뉴를 적용. 설치 앱 자체 이름/아이콘과 구분 | 플랫폼은 공통 앱 빌드/보안·배포, 교회는 허용 설정/관리 권한·연락 창구 |
| 교회 전용 DEDICATED_NATIVE | 같은 소스/검증된 빌드 설정을 기반으로 교회별 배포 리소스/식별을 분리 | 교회/플랫폼의 계정 명의·서명/권리·비용·지원·인계·종료 책임을 별도 계약 |

전용 앱이 별도 영상 호스팅·전용 서버·개인 데이터 소유권을 자동 포함하지 않는다. 영상 직접 업로드/독립 구축형은 기존 별도 서비스 범위다. 전용 앱의 기본 교회 연결과 다중 교회 전환 허용 범위는 미결이며, 설치 앱 표지만으로 다른 교회/계정 권한을 부여하지 않는다. 실제 스토어 심사·자격·제출 절차·비용·지역별 지원은 배포 시점 공식 근거 확인 과제로 남긴다.

## 변경 종류와 실행 주체

| 종류 | 교회 앱에서 할 수 있도록 설계할 것 | 자동으로 바뀌지 않는 것 |
|---|---|---|
| 교회 표시/소개·색·로고 | 현재 관리자 또는 별도 명시 브랜드 설정 권한으로 초안/미리보기/반영 | 교인 소속/권한·기존 콘텐츠·개인 기록 |
| 메뉴/연결 표시 | 제품 준비/교회 선택·본인 자격을 대조해 허용 항목 표시 | 제품 가입·개인 공유·API scope·수강/수료 |
| 언어·시간대 | 지원 언어/확인된 교회 시간대 선택, 영향 안내 | 기존 확정 행사/임기 시각 재계산·미지원 번역 자동 제공 |
| 설치 이름/아이콘/배포 식별 | 변경 요청과 상태 확인 | 원격 appLabel만으로 설치 리소스/서명/스토어 등록 완료 |
| 도메인/앱 링크/인증 복귀 | 필요 시 소유 검증된 설정 요청 | 교회 관리자 입력 URL을 인증 제공자/JWKS/서버 목적지로 신뢰 |
| 서비스·앱 배포/DB | 교회에는 영향/일정/상태 안내 | 교회 설정 권한을 플랫폼 배포/비밀 접근 권한으로 확대 |

교회별 appLabel/displayAliases는 표시 값이다. 토큰 issuer/audience·서버 API 주소·테넌트 식별·실행 코드·외부 스크립트·권한을 주입하는 통로가 아니다. 임의 URL/HTML을 표시명/별칭에 넣어 실행하지 않는다. 배포 유형/앱 식별자의 변경은 별도 검증 작업으로 다루고 단순 UI 토글로 기존 교회 연결을 이동하지 않는다.

## 교회 설정의 정본과 버전

교회 ID는 안정된 정본 참조이며 이름/도메인/앱 표시명 변경으로 새 소속·이력을 만들지 않는다. 운영 사실·브랜드 문서·배포 리소스·개인별 언어 선호를 구분한다. 교회 시간대의 운영 정본은 서버가 확인한 단일 기준으로 관리하고 brand locale timezone과 core tenant timezone이 충돌하도록 방치하지 않는다. 어느 저장 위치를 주 정본으로 삼고 파생값을 어떻게 일관 반영할지는 계약/마이그레이션 설계가 필요하다.

버전 축을 분리한다: 브랜드 schemaVersion, 게시한 설정 revision, 설정 문서 동시성 version, 앱 릴리스/플랫폼 빌드 번호, API 계약, DB migration, 제공자 capability. 각 숫자는 다른 의미이며 하나를 바꿨다고 다른 층이 호환되거나 검증된 것이 아니다. 정확한 버전 필드·범위·서명/전달 형식은 OPEN이다.

기존 1.0 메뉴 키를 현재 5개 UX에 연결할 의미 매핑은 명시한다. ‘말씀/기도’가 schema navigation enum에 없다는 이유로 임의 키를 추가하거나 ‘COMMUNITY’를 다른 권한 의미로 바꾸지 않는다. 새 스키마/이행을 설계해야 하며 모르는 필드는 안전하게 처리한다. 기존 예제를 수정해 새 기능 검증 근거로 승계하지 않는다.

## 설정 작성→검사→미리보기→반영

1. 현재 선택 교회의 현재 브랜드 관리 자격·개설/서비스 상태와 기존 게시 설정 revision을 확인한다. 목회자 직함·가입 심사 담당자·일반 콘텐츠 편집 권한을 브랜드 변경 권한으로 자동 확대하지 않는다.
2. 최소 허용 필드만 초안으로 수정한다. 이미지 권리·안전한 형식·교회 소유·업로드 실패/고아 파일 정리는 별도 자산 계약으로 검증한다. 로고 참조를 NOTICE/EVENT 자산 권한에 임의 연결하지 않는다.
3. 구조 스키마뿐 아니라 의미를 검증한다: 공백 이름/내부 명칭·대비/읽기·지원 번역·실제 시간대·메뉴 의미/필수 경로·모듈 준비·자산 소유·지원 배포 유형·도메인 소유. 검사 실패는 자동 수정/자동 적용하지 않고 항목별 안내한다.
4. 같은 앱에서 미리보기한다. 미리보기는 별도 뷰 상태이며 서버 권한/실제 운영 설정을 바꾸지 않는다. 계정/교회 전환 때 다른 교회 설정이 섞이지 않게 한다.
5. 정확한 revision/권한·영향·호환성을 재검증하고 명시 반영한다. 동시 수정은 기존 버전과 비교해 충돌 안내하며 자동 덮어쓰기 금지. 결과 불명은 기존 처리 확인을 우선하고 새 revision을 자동 재발행하지 않는다.
6. 반영된 설정과 자산 참조를 일관된 묶음으로 읽는다. 이름은 새 설정인데 로고/메뉴는 다른 교회/이전 무효 설정인 조합을 만들지 않는다. 렌더링 중 실패는 마지막 호환 설정 또는 안전한 최소 화면으로 처리한다.

초안·검증됨·반영됨·대체됨·실패는 기술 상태 후보다. 설정 반영과 네이티브 앱 배포 완료/스토어 승인을 같은 성공으로 표시하지 않는다. 교회 기본 정보나 브랜딩 수정에 개설 증빙 재심사가 필요한 변화(대표·교단 등)를 포함하면 기존 심사 계약으로 별도 보낸다. 단순 이름/로고 변경과 대표권 확인을 혼동하지 않는다.

## 모듈·제품 연결·필수 경로

enabled 설정은 가시성과 준비 상태를 표현할 수 있지만 서버 역할·개인 공유·이용권·제품 이용 상태의 정본이 아니다. 켠 메뉴도 현재 개인 자격/동의를 다시 확인하고, 끈 메뉴가 개인 제품 기록을 삭제하거나 SSO 이용을 종료하지 않는다. Academy 미선택으로 교회 기본 기능을 제한하지 않는다.

설정으로 내정보·로그아웃·교회 전환의 허용 경로·계정 복구/탈퇴·필수 안내를 모두 숨겨 사용자를 가두지 않도록 필수 진입 정책을 정의한다. 기존 스키마의 navigation3~5/모듈 boolean만으로 이를 보장하지 못한다. 정확한 필수 메뉴 배치/표현은 DRAFT이며 허용되지 않은 서버 기능을 노출해 해결하지 않는다.

## 언어·시간대·접근성

스키마의 4개 locale 값은 번역/콘텐츠/개인정보 안내/지원 인력의 완성을 뜻하지 않는다. 현재 Flutter UI는 ko만이므로 미지원 언어를 준비 완료로 안내하지 않는다. 일본·영어·멕시코·도미니카 등 목표 지역마다 언어/날짜/시간/서식·콘텐츠 권리·지원 범위가 필요하며 es-MX 하나를 모든 스페인어권 완료로 대체하지 않는다.

교회 확인 시간대·서버 정확 시각·기기 현지 보조 표시를 구분하고 설정 변경으로 이미 확정된 일시/권한 만료를 이동하지 않는다. 이름 길이·큰 글자·스크린리더·색 대비·오류 상태의 텍스트 표현을 검사한다. 색상 HEX 패턴 통과는 접근성 검증 완료가 아니다. 규격의 수치·시험 도구·최소 지원 OS는 후속 근거/검증으로 확정하며 이번에 임의 약속하지 않는다.

## 전달 실패·캐시·복원

브랜드 캐시와 보호된 교회 콘텐츠·세션·권한을 분리한다. 이름/로고 설정의 마지막 호환본이 있어도 내부 공지/명단/권한을 오프라인 허용하지 않는다. 브랜드 캐시 상한·서버 freshness·원문/로고 회수·OS 백업은 OPEN이고 공개 소개7일/상태조회168h를 일괄 적용하지 않는다.

설정 fetch 실패는 호환·소유가 확인된 이전 설정으로만 표시하는 후보를 둔다. 안전성/교회 연결을 확인할 수 없으면 중립 최소 화면을 제공하고 다른 교회 로고/이전 계정 정보를 보여주지 않는다. 설정 장애가 무권한 기본값/데모 관리자 역할을 활성화하지 않는다.

롤백은 이미 검증된 구성의 내용을 새 배포 revision으로 다시 반영하는 방향을 권장한다. 숫자를 뒤로 돌려 오래된 단말/요청의 재적용을 허용하지 않는다. 과거 자산 권리·삭제·현재 권한·연결이 무효하면 그 부분까지 되살리지 않는다. 호환 예외/롤백 실패·복구 책임자와 권한은 미결이다. 설정 롤백으로 DB·역할·탈퇴·개인 공유를 복원하지 않는다.
